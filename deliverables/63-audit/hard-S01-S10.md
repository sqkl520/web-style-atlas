## ② 逐案详述

### S01 红黑斜排报 —— 不 hard

**判据**：H1 / H2 / H3 都不满足。

**代码证据**

- 版式唯一来源是写死的四栏比例，不读任何条目数据：
  `prototypes/S01-red-wedge-broadsheet/style.css:195`
  ```css
  grid-template-columns: 5fr var(--bar) 4fr var(--bar) 4fr var(--bar) 3fr;
  ```
- 楔形是百分比坐标，与内容无关：
  `style.css:145` `clip-path: polygon(42% 0, 73.6% 0, 45.6% 89.3%);`
  窄屏另给一套：`style.css:451` `clip-path: polygon(0 90%, 100% 0, 100% 100%, 0 100%);`
- 铅条是固定 24px：`style.css:26` `--bar: 24px;`
- 行业字面量**只出现在文案层**，且不被排版消费：
  `index.html:151-154`（本版制版单，四行统计）
  ```html
  <tr><th scope="row"><code>1</code></th><td><code>1240</code></td><td><code>6</code> 格</td></tr>
  ... `<code>980</code>` / `<code>760</code>` / `<code>430</code>`
  ```
  这张表是《本版制版单》，删掉它版面不变（`.makeup` 只是一个 `margin-top: 22px` 的块，`style.css:315`）。
- 脚本里也没有任何按数据定位的逻辑：`index.html:316-330` 的 `pick()` 只按元素 `getBoundingClientRect().top` 判断当前栏号，是通用的滚动读数。

**反事实检验**（换成 8 道菜）

- 会失效的：`index.html:49`「本栏 1 240 字」、`index.html:151-154` 制版单 —— 这些数字会变成假话；`index.html:67-71` 的「按姓氏重排 / 互见号」叙事与菜谱无关。
- 不会失效的：楔形角度、24px 铅条、5:4:4:3 四栏、折角 96×96、栏号跳变 —— 全部照跑。8 道菜按 2 条/栏塞进 4 栏即可。
- 唯一的真限制是**数量必须正好 4 组**：`.columns` 只有 4 条内容轨道，第 5 条会掉到第二行网格，`.lead-bar` 的 3 条也按 `nth-of-type` 只在 4 栏下成立（`style.css:200-202`）。这是 `degrades`（数量）而不是 `hard`（语义）。
- 作者自己在 `_specs/S01.md:35` 写的可移植性判断是：「栏宽比与 11° 角度绑定**报头文字的实际长度**，换一个品牌必须重排栏宽」。**是文案长度，不是行业数据。** 这条自述与 `hard=false` 一致。

**置信度：高。**

### S02 鎏金对称厅 —— 不 hard

**判据**：H1 不满足（阶梯只读序号）；H2 只有擦边（台账编号与阶梯的 1:1 对应，见 ④「半硬」）；H3 不满足。

**代码证据**

- 中缝对切是写死的三轨：`style.css:92` `grid-template-columns: 1fr 2px 1fr;`
- 阶梯的「逐级抬升」只依赖 **序号** `--i` 与 **总数** `--n`，与器物是什么无关：
  `style.css:205`
  ```css
  background-position: center calc(-1 * (var(--n) - 1 - var(--i)) * var(--step-h)), 0 0;
  ```
  `style.css:214-215` 同理（横向缩进）。
  `--n` / `--i` 是逐条内联写死的序号：
  `index.html:36` `<ol class="ladder ladder-left" style="--n:7">`
  `index.html:37-43` `style="--i:0"` … `style="--i:6"`
  `index.html:62-71` 右侧 `--n:9` / `--i:0`…`--i:8`
- 「同一张烫金版 180° 相位」是一张位图 + 一个 CSS 变换，与内容零关系：
  `style.css:121` `transform: scaleX(-1) translateY(-28px);`
  `index.html:215` 页脚自述也承认：「镜像由 CSS 变换产生，不由位图预设，因此该关系在结构上必然成立」——**正因为与内容无关，所以在结构上必然成立**，这正是「不 hard」的证明。
- 脚本只按视口宽度切级数，不按数据切：`index.html:242-245` `return w >= 1440 ? 9 : w >= 768 ? 7 : 5;`
- 漏金缺口位置由日期取模，与数据无关：`index.html:235-239` `LEAK_SLOTS` 7 个百分比点，`index.html:277-285` 用 `day % 7` 选点。

**反事实检验**（换成 5 个产品）

- 会失效的：`index.html:95-110` 的 16 行台账（实测尺寸、版次、漏金位置）；`index.html:80`「编号连续，唯一的缺号是第 5 级」——5 个产品凑不出 7+9 级阶梯，`--n` 要重写；`index.html:41` 那个「第 5 级空缺」是内容里的一个洞，不是机制。
- 不会失效的：中缝 2px、镜像相位、`100:3` 位移比、击凸的两道 `inset` 边、级差 56/40px —— 只要给够 16 条、编号写成 No.01–No.16，任何器物都成立。
- 结论：**约束是「16 条、编号连续、有一条空缺」，属数量 + 编号格式，不是行业结构。**

**置信度：高。**

### S03 长曝光观测站 —— hard（前轮「证伪」只对一半）

**判据**：**H3 满足**（`index.html:234-235` 的年份数组是行业专属字面量、不由数据推导、换内容即失效）；同时 **H1 也满足**（带高由曝光秒数的具体值决定），但这一层被写成了手打字面量。

**代码证据**

1. 年代轴：五个年份 + 五个漂移量是**纯字面量**，只被下面 15 行用来画 5 个年份标签和 5 枚齿孔：
   `prototypes/S03-long-exposure-observatory/index.html:233-235`
   ```js
   /* 齿孔编号：每 5 年一枚，累计偏移 0.3mm（约 1.13px），偏移取自当年校准漂移值 */
   var years = [1957, 1962, 1967, 1972, 1977];
   var drift = [0, 1.13, 2.26, 3.02, 4.15];
   ```
   消费方 `index.html:236-250`：`t.setAttribute("y", 640 - i * 128 - 4)` —— 纵坐标只由 `i` 决定，与 `years[i]` 的数值无关（就算写成 1900/1901/1902/1903/1904，位置一模一样）。
2. 刻度线是固定循环，与数据无关：`index.html:229-232`
   ```js
   for (var y = 640; y >= 0; y -= 8) {
     var major = (640 - y) % 40 === 0;
     line(major ? 176 : 208, y, 264, y, major ? 1.5 : 1);
   }
   ```
3. 轴的容器是 640px 定高 + `sticky`：`style.css:129-131` `height: 640px; position: sticky; top: 24px;`；轴宽 264px 定死：`style.css:17` `--axis-w: 264px;`。轴与右侧影像带只是同一个 grid 的两个单元格（`style.css:124`），**轴的刻度从不与任何一条带对齐**。
4. **8 条影像带的高度**：内联 `--h` 手打，逐条写死。
   `index.html:71` `--h:28px` / `:75` `--h:42px` / `:79` `--h:14px` / `:83` `--h:56px`
   `:87` `--h:19px` / `:91` `--h:37px` / `:95` `--h:84px` / `:99` `--h:23px`
   消费方 `style.css:149` `.band img { ... height: var(--h); ... }`
   对应的秒数写在图注里：`index.html:73` `30 s` / `:77` `45 s` / `:81` `15 s` / `:85` `60 s` / `:89` `20 s` / `:93` `40 s` / `:97` `90 s` / `:101` `25 s`。
   **我逐条算过比值**：28/30、42/45、14/15、56/60、84/90 都是 0.9333；19/20=0.95、37/40=0.925、23/25=0.92。
   即 `h = round(秒数 × 28/30)`，8 条**全部吻合**（19=round(18.67)、37=round(37.33)、23=round(23.33)）。
   所以「高度即曝光时长」在**数值上确实是成立的**——但没有任何一行代码把秒数换算成高度，8 个 `--h` 是人手算完打进去的。
5. 读数表也是字面量：`index.html:113-120` 八行 `<samp>1957-11-04</samp> … <samp>18.4 nT</samp>`，与 8 条带靠日期字符串人眼对应，无代码连接。
6. 二级硬编码：读数卡逐条右缩的阶梯也是拍死的 6 条：
   `style.css:276-281` `tr:nth-child(2) … :nth-child(6)` 分别 `padding-right: 12/24/36/48/60px`。

**反事实检验**（换成 8 道菜）

- **会失效的（签名）**：8 条带的 `--h` 全部失去依据。菜名/菜价/烹饪时长里没有「曝光秒数」这种 0–90 的连续标量，`--h` 只能变成随机值 → 「高度即曝光时长」这条被反复写在标题（`index.html:50` 「观测记录：高度即曝光时长」）和正文（`:51`）里的断言，立刻变成谎言。若要保留，必须为每道菜找一个标量（价格？出餐秒数？），即**数据 schema 必须换**。
- **会失效的（轴）**：`years = [1957…1977]` 照旧画出来，但它会变成一排与内容毫无关系的 1957–1977；而且数据末端已经在 1978（`index.html:101` `1978-11-30`），轴却停在 1977——**这条轴现在就已经与数据错位 1 年**，换内容只会更荒谬。
- **不会失效的（版式）**：`.chrono` 的 `264px + 1fr` 两列（`style.css:124`）、`.band` 的普通块流 + 4px 间隙（`style.css:145-146`）、四角减光（`style.css:151-155`）、颗粒（`style.css:156-162`）、sticky 轴——8 道菜照样排得下。
- 所以退化的位置很精确：**「版式」不死，「高度即数据」这条签名死。**

**置信度：中高。** 判「hard」的依据是 H3（年份数组 + 手打 `--h` 都是非推导的行业字面量），这一条我有把握；
可能存在争议的是：如果把「hard」严格限定成「代码里必须存在读取数据的语句」，那 S03 的实现确实一句都没有（见下方专项）——这种情况下 H1 不成立，只剩 H3 支撑，判决不变但理由变窄。

### S04 芒果拼贴墙 —— 不 hard

**判据**：H1 不满足（**偏移量根本没有进入 CSS**）；H2 不满足；H3 不满足（行业字面量只在偏移表与说明文案里）。

**代码证据**（本案有一处硬发现）

1. 12 列隐网格 + 逐块内联跨度，数量约束而非语义约束：
   `style.css:78` `display:grid; grid-template-columns:repeat(12,minmax(0,1fr));`
   `style.css:82` `grid-column:span var(--span);`
   `index.html:41` `style="--span:5;--span-m:4;--ar:0.862;--r:-1.1deg;--lift:-16px;…--order:1;--ri:5px;--rj:3px;…"`
2. **机制断链（重要）**：规格反复讲的「每块色版偏移量各自不同、3/4/5/6/7px 五档」，在 CSS 里**没有任何消费者**。
   `style.css:41-137` 九个 `.slip` 都内联了 `--ri` / `--rj`，但我全库检索 `var(--ri)`、`var(--rj)`：**0 处**。
   ```powershell
   (Select-String -Path "...\S04-mango-collage-wall\style.css" -Pattern "var\(--ri|var\(--rj").Count
   → 0
   ```
   这些偏移实际是在**构建期烘进位图**的：
   `build/make-plates.py:63` `for (kind, box, cov, ang, dx, dy, colour) in shapes:`
   `build/make-plates.py:95` `img.alpha_composite(layer, dest=(max(0, dx), max(0, dy)))`
   `build/make-plates.py:100-102` 连「1px 油墨挤压痕」也是按 `dx,dy` 画死的。
3. **另一处断链**：`style.css:84` `transform:rotate(var(--rot));` —— `--rot` **全站没有定义**（内联写的是 `--r`，`index.html:41` 起九处；`style.css:207` 只定义了 `--rot-k`）。所以在 JS 加了 `.js` 类之后，`.slip` 的 `transform` 计算值无效 → 回退 `none`，「旋转限 ±1.2°」这一条**实际没有渲染**。
4. 5 档偏移表在 HTML 里只是一张说明表，不被任何布局逻辑读取：
   `index.html:191-195`
   ```html
   <tr><td>第一档</td><td><code>3px</code></td>…
   <tr><td>第五档</td><td><code>7px</code></td>…
   ```
5. 有数据消费的只有「缺口方向」这种纯序号：
   `style.css:107` `transform:rotate(calc(var(--order) * 72deg));` —— `--order` 是 1–9 的序号（`index.html:41` 起），与内容无关。

**反事实检验**（换成 5 个产品 / 8 段文字）

- 会失效的：`index.html:191-195` 的偏移表（写着具体作品名）；`index.html:149`「九张纸里有四张的绿版是上过网的」——这句是对**具体九张图**的陈述。
- 不会失效的：12 列隐网格、`--span` 跨度、撕边遮罩、批注层、缺口 72° 递增 —— 全是数量与序号。
- 关键判断：**因为偏移量是烘在图里的，换内容时「每块纸偏移不同」这条签名不会「退化」，而是会「整体换成新图的偏移」——它压根不是从数据来的，所以也谈不上被数据绑死。**

**置信度：中。** 中是因为第 3 条（`--rot` 未定义）意味着现在实际渲染与规格不符；若以「规格描述的机制」而非「代码实际行为」为判定对象，结论仍是 不 hard（规格里也没有读数据的环节）。

### S05 像素冷库台 —— 不 hard（**半硬**：版面层不硬，读数组件擦边 H2）

**判据**：H1 / H2 在**版面层**不满足；H3 不满足。但读数组件（5×7 点阵字模）对数据形态有真实要求，见 ④。

**代码证据**

- 8 块面板的位置是写死的坐标 —— 这是**数量/优先级**约束，不是行业数据：
  `style.css:245-253`
  ```css
  /* 分区定位：5 列主库 ／ 2 列除霜 ／ 1 列告警拉高两倍 */
  .panel--main       { grid-column: 1 / 6; grid-row: 1; }
  .panel--defrost    { grid-column: 6 / 8; grid-row: 1; }
  .panel--alarm      { grid-column: 8 / 9; grid-row: 1 / 3; }
  .panel--bay2       { grid-column: 1 / 4; grid-row: 2; }
  .panel--compressor { grid-column: 4 / 6; grid-row: 2; }
  .panel--probe      { grid-column: 6 / 9; grid-row: 2; }
  .panel--marks      { grid-column: 1 / 5; grid-row: 3; }
  .panel--switch     { grid-column: 5 / 9; grid-row: 3; }
  ```
  母网格 8 列：`style.css:195` `grid-template-columns: repeat(8, minmax(0, 1fr));`
- 点阵读数**在运行期是由字符串生成的**，不是逐字写死：
  `index.html:303-311`
  ```js
  function paint(svg, text, label) {
    var keys = glyphsFor(text);
    ...
    for (var i = 0; i < keys.length; i++) html += '<use href="#dg-' + keys[i] + '" x="' + (i * 6) + '"/>';
    svg.setAttribute('viewBox', '0 0 ' + (keys.length * 6 - 1) + ' 7');
  ```
  → 换成任何数字串都能画。这是「不 hard」的强证据。
- 拨杆位置由数值算出（唯一一处真·读值）：
  `index.html:322` `bay.style.setProperty('--pos', String((Number(input.value) + 22) / 4));`
  `style.css:315` `transform: translateY(calc(var(--pos, 1) * 76px));`
  —— 但它映射的是「温控档位 −22…−18℃」，是**一个控件**，不是页面骨架。

**置信度：中。** 中是因为「两组可排序数值」到底算不算 H2 的「特定数据形态」，任务书没有给边界例子（H2 举的是层级/时间戳/坐标/双射）。我倾向算：第 4 栏的「价格序对照」与主排序构成一个**双射**（同一批 N 家，两种次序），这正是 H2 列出的「双射关系」。

## ③ S03 专项：前轮审计的「证伪」只对了一半

### 3.1 前一轮的说法

> S03 的 `hard` 被它自己的代码证伪：年代轴是 `index.html:234-235` 的字面量数组 `years=[1957,1962,...]` 画出来的，与 8 条影像带零关联，机制根本不读数据。

### 3.2 逐条核

**（1）那个数组是什么？谁在用？**

`index.html:234-235` 的 `years` / `drift` 只被紧随其后的 `index.html:236-250` 使用：画 5 个年份标签（`text.scale-year`）和 5 枚齿孔（`rect`）。纵坐标 `y = 640 - i * 128 - 4`（`:239`）**只与索引 `i` 有关**，与 `years[i]` 的数值无关；横坐标 `x = 168 - drift[i]`（`:238`）用 `drift`，但这 5 个数也是字面量。
→ **前轮这一半完全正确**：这根轴是静态装饰，与 8 条带零数据关联。旁证：
- 轴的刻度是固定循环（`:229-232`），与年份无关；
- 轴容器 640px 定高 + `sticky`（`style.css:129-131`），不参与内容高度；
- 轴的 5 个年份（1957–1977）与 8 条带的 8 个日期（1957/1958/1960/1969/1972/1973/1974/1978）没有任何一条对齐；
- 轴停在 1977，数据到 1978-11-30（`index.html:101`）—— **差 1 年，说明轴压根不是从数据推的。**

**（2）8 条影像带的高度是怎么算的？读不读数据？**

不读。高度来自逐条内联的 `--h`（`index.html:71/75/79/83/87/91/95/99`），CSS 只做 `height: var(--h)`（`style.css:149`）。
**但这 8 个数不是随手写的**：它们精确等于 `round(曝光秒数 × 28/30)`（28/30 是规格给的「30 秒＝28px」）。
我逐条验：45→42 ✓、15→14 ✓、60→56 ✓、20→18.67→19 ✓、40→37.33→37 ✓、90→84 ✓、25→23.33→23 ✓。
→ **所以「高度即曝光时长」在数值层是真的，只是「换算」发生在作者脑子里，没有一行代码。**
这正是 H3 描述的形状：行业字面量（曝光秒数、年份）直接写在 `index.html` 里，不是从数据推导的。

**（3）换成 8 个完全无关的条目（8 道菜），版式还成立吗？**

| 部件 | 8 道菜下的结果 |
|---|---|
| `264px + 1fr` 两列（`style.css:124`） | **成立** |
| `.band` 块流 + 4px 间隙（`style.css:145-146`） | **成立**（8 条随便排） |
| sticky 轴 640px（`style.css:129-131`） | **成立**，但刻度 0–640 与「8 道菜」毫无关系 |
| 5 个年份标签 1957–1977（`:234-235`） | **照画**，变成一排荒谬的年份 |
| 8 条带高 28/42/14/… | **失效**：菜没有「曝光秒数」这个连续标量，`--h` 只能随机；标题「高度即曝光时长」（`index.html:50`）与正文（`:51`）变成假话 |
| 读数表 8 行 nT（`:113-120`） | **失效**：要整表换语义；`style.css:276-281` 的 6 级右缩还在，但表头没意义 |

→ 准确的结论：**版式骨架成立，签名机制（高度＝数据）不成立。**

### 3.3 我的判定与前轮的差别

- 前轮：轴不读数据 → **所以 hard=false**。
- 我：轴不读数据 **成立**；但「带高＝曝光」是另一半机制，它虽然在代码里没读数据，却**在数值上严格等于数据**，且实现方式是「把行业数值手打进 HTML」——这恰好命中 H3（判据原文举例就是「年份数组」）。
- 差别在于**取证范围**：前轮只查了 `years` 数组那一处（轴），没有查 `--h`（带）。**把半张机制当成全部机制，是过度外推。**
- 所以：**`hard` 应当保留，但记录里的理由必须改写。** 现在 `build-prompts.mjs:83` 只有一句 `hard: true`，与 `_specs/S03.md` 无任何对应（S03 没有「最难被复用」那句）—— 这叫「结论对、依据空」。

### 3.4 一句话

> 轴是假的（真·不读数据），带是真的（真·数据值，手打进去）。警告仍然该给，但给它的理由不该是「读数据」，而是「行业数值被手写成了版面尺寸」。

## ④ 你可能没想到的几件事

### 4.1 有一半案子是「一半 hard、一半不硬」

按**页面骨架 / 单个区块**两层分开看，S02、S05、S08、S09、S10 都是混合体：

| 案 | 骨架层（不 hard） | 区块层（擦边 hard） |
|---|---|---|
| **S05** | 8 面板 5:2:1 面积 + 6px 凹槽 + 扫描线显影＝数量与优先级（`style.css:245-253`、`:195`） | 点阵读数：字模只有数字 + `dash/dot/pct/deg/C` + 12 个西文字母（`index.html:21-50`），**没有汉字**；拨杆把 −22…−18℃ 写进算式（`index.html:288`、`:322`） |
| **S02** | 阶梯只读 `--i`（`style.css:205`） | 台账与阶梯的 **1:1 编号双射**，且故意留一个缺号在第 5 级（`index.html:80`「编号连续，唯一的缺号是第 5 级」；`:41` `is-vacant`；`:99` 表格同一行） |
| **S09** | 斜排 + 三列流 + `--start`（`style.css:270/276/284`） | 双线描边＋小数点右对齐（`--price-w: 124px`，`style.css:34`）依赖「有价格」；三层黑漆改价史（`index.html:80-86`）是唯一不可换的叙事 |
| **S08** | 等距轴 2:1、层号位移、侧壁 6→10px、视差（`style.css:177/122`、`index.html:306`） | 六条 **首尾相接的瓶体剖面**（`index.html:58/72/86/99/113/127`，y 268→250→150→96→60→40）+ `build-assets.py:16` 的 `bottle()` 注释「底足、瓶身、肩、颈、口」 |
| **S10** | 五栏 6:7:9:8:5 + 1.5px 错位（`style.css:151`、`:248-252`） | 第 4 栏「价格序对照」＝第二套排序（`index.html:132/141/150…`）、第 5 栏连号（`:112`、`:262`） |

→ **S08 是「一半 hard」最清楚的一例**：骨架吃层号（可移植），内容吃「同源六层」（不可移植）。
所以「hard」不能当成整案的二元属性来用；如果保留这个字段，它至少应该带**范围**（「哪一块」）。

### 4.2 `hard` 与 `degrades` 会被混淆，而且这两个案子正好是一对反向样本

两件事**测的不是一个东西**：
- `degrades`：**数量**少了会不会留洞（单元位置写死 → 删条目留空位）。判据落纸在 `deliverables/60-minitems-degrade-audit.md`。
- `hard`：**换一套同数量的内容**，机制还成不成立（读不读数据值 / 要不要特定结构）。判据是本次任务书 H1–H3。

**反向样本 A —— S04（`degrades=yes`、`hard=false`）**
它「内容少了会留洞」是真的：9 块纸块各自内联 `--span`/`--lift`/`--order`（`index.html:41-137`），删到 5 块，12 列网格的错位节奏就断了（`style.css:78-84`），缺口 72° 递增也断（`style.css:107`）。
但它「机制绑死行业数据」是**假的**：偏移量烘在 PNG 里（`build/make-plates.py:95`），CSS 变量 `--ri/--rj` **零消费者**。**它压根不读数据，所以谈不上被数据绑死。**
→ 这就是「把数量约束写成语义绑死」的典型。`degrades=yes` 是对的，`hard` 不给是对的。

**反向样本 B —— S03（`degrades=no`、`hard=true`）**
删掉 3 条带，`.stream` 只是变短（`style.css:144-149` 块流），**不留洞**，`degrades=no` 成立。
但换内容，8 个 `--h` 全部失去依据，**签名直接死**，`hard=true` 成立。
→ 同一案上两个字段指向相反方向，**证明它们正交，不能互相替代**。

**一句话区分**：
> `degrades` 问「**够不够**」（数量够不够填满写死的格子）；`hard` 问「**对不对**」（内容对不对得上机制的假设）。
> S04 是「不够就难看」；S03 是「够也不对」。

### 4.3 三处「机制根本没接上」的实现缺陷（与 hard 无关，但影响判定可信度）

1. **S04 `--rot` 未定义**：`style.css:84` `transform:rotate(var(--rot))`，而全站只有 `--r`（`index.html:41` 起）与 `--rot-k`（`style.css:207`）。
   → 计算值无效 → 回退 `none`。规格「旋转限 ±1.2°」**实际没渲染**。
2. **S04 偏移变量零消费者**：`var(--ri)` / `var(--rj)` 检索 0 命中；九块纸的 `--ri/--rj` 全是死变量。
3. **S09 描边十行完全相同**：`<path>` 只在 `index.html:21-22` 定义一次，十行 `<use>` 同一个。规格说「缺口位置固定不在同一边」，实现里是「每行都一样，行内两个缺口不同边」。

这三条不改变 hard 判决，但说明：**规格里的「机制」与代码里的「机制」已有偏差，判定应以代码为准**（本报告即如此）。

### 4.4 一条与标注直接冲突的证据

`hard` 只在 3 案为 true，且这 3 案的「认知门槛」都是**中**（`_specs` 字段头：S03 中 / S05 中 / S10 中）；
而 21/30 案有作者自写的「最难被复用之处」，S01–S10 里**只有 S01 有**（`_specs/S01.md:35`），偏偏 S01 的 `hard=false`。
→ `hard` 与「作者自述的可移植性」不是同一套来源，**它没有逐案依据可复核**。这也解释了为什么 S05 会被误标成 `hard`：那实际上是 `degrades`（8 块写死坐标）；而 S08 被漏标：它的六层同源证据藏在 `build-assets.py`，不在 `style.css` 里。

## ⑤ 我判不出的案子

**S08 原本判不出，已解**（记在这里，因为过程本身是个教训）。

一开始我把 S08 列为「判不出」，依据是：`index.html` 里每块板都是独立的 `.plate` div，`style.css` 只吃 `--l` 层号，

### 唯一仍判不出的：S10 的「双序」算不算 H2

这不是证据缺失，是**判据没有边界例**。证据齐了（见 ②）：
`index.html:411-418` 的 `keyOf()` 读 `data-lead`/`data-price` 两套键；
`index.html:132/141/150…` 第 4 栏是同一批 N 家的第二种次序（「第 N 位 · 高 X%」）；
`index.html:112/262` 第 5 栏是连号 41207–41233。

争议在定义：任务书 H2 的举例是「唯一编号 / 层级 / 时间戳 / 坐标 / **双射关系**」。
- 按「算」：同一批 N 个对象上两套全序（到货周期序 vs 报价序）+ 一个连号，正是一组**双射**。→ hard（我判边界偏硬）。
- 按「不算」：须是跨表/跨图的一对一（如 S29 的「图上 07 号 = 表第 7 行」）。→ 只是「表格里有两列可排序数字」，不 hard。

**这一点请以口径裁定，不是证据不足。** 我在 ② 里按第一种判了「边界」，并把两种读法的后果都写了。
