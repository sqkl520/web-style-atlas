## ② 逐案详述

### S11 铁窗打字本 —— 不 hard（判据：都不满足）

**机制**（`_prompts/mechanisms.mjs:21`）：「章号悬挂在版心外 56px、正文压到 34 字行长，标题叠三层重影，横向错位 0.5 / 1.5 / 3px、第三层 12% 不透明——层级由错位量承担，位置交给悬挂编号。」

**代码证据**

- `prototypes/S11-samizdat-typewriter/style.css:18`　`--hang: 56px;             /* 章号悬挂栏宽 */`
- `prototypes/S11-samizdat-typewriter/style.css:21`　`--measure: 34em;          /* 正文行长 34 个汉字 */`
- `style.css:23-26`　`--ghost-1: 0.5px;` / `--ghost-2: 1.5px;` / `--ghost-3: 3px;` / `--ghost-3-a: 0.12;`
- `style.css:180-182`　三层重影是**固定三个** `<p>`，值与变量写死：
  `.carbon-line.l3 { transform: translate(var(--ghost-1), 0); }`
  `.carbon-line.l5 { transform: translate(var(--ghost-2), var(--proof-gap)); opacity: 0.62; mix-blend-mode: multiply; }`
  `.carbon-line.l7 { transform: translate(var(--ghost-3), calc(var(--proof-gap) * 2)); opacity: var(--ghost-3-a); mix-blend-mode: multiply; }`
- `style.css:299-310`　12 条 `main > .chapter:nth-child(N) { --ch: N; }` —— **只依赖"第几个"，不依赖内容**。
- `style.css:494`　`transform: translate(calc(var(--ch, 1) * -0.4px), calc(var(--ch, 1) * 0.4px));` —— 签名墨渍的漂移量由序号算，`--ch` 缺省回 1。

**反事实**：换「8 道菜」——悬挂章号照挂、34 字行长照压、三层重影照错位，机制**全部成立**，唯一失效的是 `nth-child(9..12)` 那四条规则用不上（第 9 章以后墨渍不再继续漂）；换「3 篇文章」——章号退化成 3 个，重影仍是 3 层，**零失效**。反过来说，若真有 13 章，`--ch` 无定义会回退到 1，墨渍全部重叠——这是**数量上限**的缺陷（count），不是行业绑定。

**置信度：高。** 三条判据均不成立：不读数据值（H1 否）、不要求数据有特殊结构（H2 否，任何条目都能排成章节）、CSS 与 HTML 里除了「复写纸/检修手册」这类文案层字面量外，没有驱动版式的行业字面量（H3 否，`style.css:180-182` 的错位值是工艺常量）。

### S12 青柠挖空墙 —— 不 hard（判据：都不满足）

**机制**（`mechanisms.mjs:25`）：「七个挖空块按 3/2/1/1 递减错位落位，斜边只走 45° 与 135°、切角 30px，间隙取 12/28/44px 三级，内侧压 0.5px 翻边——分区靠硬边挖空，不靠投影。」

**代码证据**

- `style.css:19`　`--cut: 30px;`；`style.css:23-25`　`--g1: 12px;` / `--g2: 28px;` / `--g3: 44px;`
- `style.css:212-214`　`clip-path: polygon(var(--cut) 0, calc(100% - var(--cut)) 0, 100% var(--cut), calc(100% - var(--cut)), …` —— 顶点只由 `--cut` 一个变量生成，**任何矩形都能切**。
- `style.css:263-269`　七个洞口**逐槽写死**位置与高度：
  `.op-01 { grid-column: 5 / 7; grid-row: 1; height: 214px; margin-top: 28px; margin-right: var(--g3); }`
  `.op-03 { grid-column: 1 / 5; grid-row: 1; height: 322px; margin-right: var(--g2); --cut: 36px; }`
  `.op-07 { grid-column: 1 / 2; grid-row: 4; height: 136px; margin-top: var(--g3); --cut: 16px; }`
- `style.css:270-271`　`--i: 0` … `--i: 6` 逐槽编号（入场上台顺序）

**关键区分**：这是「逐槽手工排定」的典型——**位置是手写的，但手写依据是槽号，不是内容值**。第 3 个洞口占 1–5 栏、高 322px，跟洞里写"青柠管道"还是写"第 5 号产品"毫无关系。

**反事实**：换「5 个产品」——洞口 06、07 空出来（**留洞**），但每个洞里放什么、切角多少、翻边 0.5px 全部不变，机制**不失效**，只掉数量；换「8 道菜」——8 > 7，第 8 道没有槽位，`.op-01..07` 之外没有兜底规则，会落到无样式区。这正好是 `degrades=yes`（`prompts.js:883`）描述的现象，而不是 hard。

**置信度：高。** 这是**只 degrades 不 hard** 的干净标本（详见 ④）。

### S13 棉纸盲压公函 —— 不 hard（判据：都不满足）

**机制**（`mechanisms.mjs:29`）：「光源常驻 135° 一侧，凹槽压深 0.4mm、槽带亮度差 3%、边缘对比度 14%，按下时方位角翻到 315° 并下沉 0.8px——层级由同一光源下的深浅给出，不靠颜色。」

**代码证据**

- `style.css:28`　`--light-azimuth: 135deg;`
- `style.css:132-133`　整套凹凸只有两组 token：
  `--press-1: inset 2px 2px 3px rgba(36, 31, 23, var(--edge-a)), 2px 2px 2px rgba(36, 31, 23, 0.06);`
  `--press-2: 2px 2px 3px rgba(36, 31, 23, 0.08);`
- `style.css:591`　`[data-press] .clause__head { box-shadow: var(--press-1); }` —— 任何 `[data-press]` 元素自动获得凹槽，**与文字内容无关**。
- `index.html:67-99`　7 条 `<section class="clause" data-press>`，标题（事由/依据/检送…）是文案层。（实测 `data-press` 共出现 8 次 = 7 个条款 + 1 处脚本选择器。）

**反事实**：换「8 道菜」——8 个 `[data-press]` 标题各自压出 0.4mm 凹槽，光源仍 135°，**零失效**；换「3 篇文章」——3 条凹槽，**零失效**。这套机制甚至不关心条目数，只关心"这个元素要不要压"。

**置信度：高。** 唯一可议的是 H3：`--edge-a: 0.11` 之类的值（`style.css:125`）是从"纸张形变"工艺推的，但它是**通用光影常量**，不是行业专属字面量；换成餐厅菜单，同一组 token 压出来一样成立。

### S14 零重力发射序 —— **hard**（判据：H1 + H2）

**机制**（`mechanisms.mjs:33`）：「十一个版面块按距质心 24/40/72/120px 分四档、方位角间隔 26° 至 61° 不等，整组沿 48px 半径绕 44% 横位的质心平漂——顺序由半径档位与角度间隔读出。」

**代码证据（一）：位置是逐条写死的字面量**

- `index.html:70`　`<article class="tag tag--foil t120" id="a1107" tabindex="0" data-code="A-1107" style="--i:0;--dx:46.8;--dy:696.2;--w:330;--mh:191;--ux:.067;--uy:.998;--ox:-11;--ord:4">`
- `index.html:97`　`style="--i:3;--dx:224.8;--dy:-606.2;--w:330;--mh:191;…--ord:10"`（共 11 条，`--ord` 取遍 1–11，无重复）
- `style.css:166-171`　`position: absolute; left: 44%; top: 50%;` … `transform: translate(-50%, -50%) translate(calc(var(--dx) * var(--k) * 1px), calc(var(--dy) * var(--k) * 1px)) …`

也就是说：**运行时没有任何一处从 r/θ 计算 dx/dy**。`style.css:7-8` 的注释自己承认「站位数字来自 build/polar-layout.json（质心 677/850、参考椭圆 450×700）」。

**代码证据（二）：那些字面量取决于每条正文的字数（这条决定 H1）**

- `build/polar-layout.py:47-49`：
  ```
  per_line = max(8.0, (w - 28) / 16.0)
  lines = max(3, math.ceil(len(body) / per_line))
  return 24 + 24 + 6 + 25 + 6 + lines * 28.8 + 20
  ```
- `build/polar-layout.py:87-134`　`relax()`：按 `collide()` 逐对分离，每个标贴**沿自身径向**移到「刚好不叠」的位置（`s` 变、`θ` 不变），移动步长取决于该条的 `w`/`h`。
- `build/polar-layout.json:12-13`　`"x": 723.8, "y": 1546.2`；`:23`　`"s": 0.8`（相对档位 `SCALE` 已被 relax 改动）

即：**版式形态 = f(每条正文的字符数, 每条宽高)**。这不是"只由数量决定"——同是 11 条，把字数换一换，`h` 变、`relax` 的分离结果变、11 个坐标全变。

**代码证据（三）：H2 的唯一编号/双射**

- `_specs/S14.md:29`「十一枚标贴各有唯一四位航电编号（如 A-1107），编号顺序就是阅读与 Tab 顺序」
- `index.html:246-256`　站位表 11 行，`<a href="#a1107">` 与 `id="a1107"` 一一对应，`--ord` 1–11 无重复
- `index.html:272`　最近邻列表把三个编号与距离**写死**：`A-1117 主发动机预冷 387px、A-1111 载荷舱机械锁 411px、A-1114 电池组均衡充电 413px`

「唯一四位编号 ↔ 唯一站位 ↔ Tab 顺序」是一个双射，普通内容（8 道菜）没有这种编号体系，做不出"编号即顺序"这条通路。

**反事实**：换「8 道菜」——① `--dx/--dy` 是 11 条的，第 9–11 槽空着（数量问题）；②更致命的是，即使凑够 11 道菜，每条字数与 330/254/310px 的 `--w` 对不上，`min-height:191px` 兜不住，绝对定位的块会互相压（`relax` 是离线算的，页面里没有重排逻辑）；③「最近邻三个」和「X-634 / Y-850」（`index.html:177`）全是字面量，换内容后读数指向不存在的标贴。换「3 篇文章」——极坐标退化成一圈散点，`--ord` 1–3 的 Tab 顺序还在，但"绕一个心"的构图不成立。

**置信度：高。** 三条证据链彼此独立：就算不认 H2 的编号双射，H1 也独立成立（坐标是字面量、且字面量来自正文字数）。**前任审计「纯条数约束被误标」的结论不成立**——它只看了 11 这个数字，没看 `build/polar-layout.py` 的 `estimate_h(len(body))` 与 `relax()`。

### S15 三层硫酸纸 —— **hard**（判据：H2）

**机制**（`mechanisms.mjs:37`）：「平面图占 1 至 8 栏并左出血 40px，图例挂 9 至 12 栏、高度只到图幅 62%；同一图叠三层，错位 0/3/7px，第三层 56% 不透明——版本差异靠错位与透明度读出。」

**代码证据（一）：三层是三个"年份"，不是三个"复制品"**

- `style.css:171-173`：

### S16 斜线速度宣言 —— 不 hard（判据：都不满足）

**机制**（`mechanisms.mjs:41`）：「所有词块左端对齐同一条 12° 斜线，每块再沿斜线递增 24px，块宽只取 4/6/7/9 栏四档，行高压到 0.95 倍、字距 0.02em——斜线给顺序，块宽与行距给层级。」

**代码证据**

- `style.css:55-56`　`--slant: 12deg;` / `--step: 24px;`
- `style.css:221-222`：
  `.slab { position: relative; width: calc(var(--span, 9) * 100% / 12);          /* 4/6/7/9 栏四档 */`
  `  margin-left: calc(var(--slot, 0) * var(--step));  /* 左端沿 12° 斜线递增 24px */`

## ④ `hard` 与 `degrades` 的实证区分

### 两个概念各自在测什么

- **`hard`**：机制**读不读内容本身**。测的是"换题材会不会失效"。警告文案：「机制绑在特定题材上，换普通内容会退化」（`_selection/prompt-copy.js:475`）。
- **`degrades`**：机制**吃不吃固定槽位**。测的是"内容变少会不会留洞"。警告文案：「单元位置是手工排定的，内容少于 N 条会留洞」（`prompt-copy.js:476`）。

两者由**不同的代码路径**分别算出，只是被同一个提示条消费：

- `_selection/prompt-copy.js:471`　`var riskyTopic = !!s.hard;`
- `_selection/prompt-copy.js:472`　`var riskyCount = !!(s.capacity && s.capacity.degrades === "yes");`
- `prompt-copy.js:473-477`　`if (riskyTopic || riskyCount) { … why.join("；") … }` —— 两个都真时，**一条警告里会同时出现两句**。

### 实测的 2×2 分布（脚本读取 `_selection/prompts.js` 全 30 案）

| | `degrades=no` | `degrades=yes` |
|---|---|---|
| **`hard=true`** | **3 案**：S03、S10、S21 | **6 案**：S05、S14、S15、S18、S20、S29 |
| **`hard=false`** | 14 案：S01 S06 S07 S09 S11 S13 S16 S17 S24 S25 S26 S27 S28 S30 | **7 案**：S02 S04 S08 S12 S19 S22 S23 |

（`degrades=yes` 共 13 案 = 6 + 7，与任务给的名单 S02 S04 S05 S08 S12 S14 S15 S18 S19 S20 S22 S23 S29 完全一致，已逐个核对 `prompts.js` 对应行：S02→`:443`、S04→`:530`、S05→`:576`、S08→`:710`、S12→`:883`、S14→`:970`、S15→`:1013`、S18→`:1145`、S19→`:1193`、S20→`:1235`、S22→`:1324`、S23→`:1368`、S29→`:1631`。）

### 所以 S14/S15/S18/S20 同时为真，意味着什么

**四格全都有实例，所以两者不是同一个概念，也互不蕴含。** 这 4 案同处重叠区，是因为它们共享一个**结构原因**：

> **机制一旦按"每一条"手工绑定（位置/面积/行号/编号），就同时获得了 hard 和 degrades。**

逐案对一遍：

| 案 | hard 从哪来（按条绑定） | degrades 从哪来（按条占位） |
|---|---|---|
| S14 | `index.html:70-160` 每条一个 `--dx/--dy`，且由该条字数算出 | 11 个绝对定位槽；`--ord` 1–11 缺一即空 |
| S15 | 3 个年代图层，每层内容不同（`index.html:129/165/182`） | 14 个热区 `x/y/w/h` 绝对坐标（`index.html:139-152`），少一区平面图缺一块 |
| S18 | `--at` 把牌钉到指定行（`style.css:122`），行内容变了就挂错 | 60 行分 3 段 × 20 行（`index.html:97/121/145`），段少了下游 `--at` 全漂 |
| S20 | （**不成立**，见 ②） | 6 张图版 `nth-child` 跨度 2+2+1+3+1+3=12（`style.css:267-272`），少一张即错列 |

**关键点**：S14/S15/S18 的"按条绑定"是**一分钱两半**——同一次手工劳动，既让机制依赖了那一条的**值**（→ hard），又让它依赖那一条的**存在**（→ degrades）。S20 是**唯一一个"只有 degrades 那一半"的例外**：它的图版槽位是手工配平的（degrades），但针笔走线跟内容无关（不 hard）。**所以 S20 正好反证了"重叠是必然的"这个猜测是错的。**

### 是否一定有重叠？**不。** 两个反例都在本仓库

**只 hard 不 degrades（3 个）**，最干净的是 **S21 联锁释放簿**：

- `index.html:234`　`<li class="lockbar" data-lock="1" data-lever="道岔 1" data-pairs="3" data-angle="45" data-excl="9,12,13" …>`
- 14 枚锁闭条各有 `data-excl`（互斥锁号清单）与 `data-angle`（30/45/60°）。**互斥关系是数据值**：第 1 枚排除了 9、12、13，换一套编号这套排他关系就全错 → hard。
- 但它 `degrades=no`（`prompts.js:1277`）：`data-excl` 的引用是**按锁号**而不是按位置，删掉几条不会留下空槽，剩下的条照样连。**互斥图是"值绑定"而非"槽位绑定"**。
- 另两例：**S03**（`index.html:71-99` 的 `--h` 逐条按曝光秒数换算：30s→28px，值绑定；但 `.band` 是流式列表，少一条不留洞）、**S10**（五栏 `6:7:9:8:5` 的比值绑定内容，但列数由 CSS 给，不靠条目补齐）。

**只 degrades 不 hard（7 个，本段就有 2 个）**，最干净的是 **S12**：

- `style.css:263-269` 七个洞口逐槽写死 `grid-column` / `height` / `margin`，少一个就留洞 → degrades=yes（`prompts.js:883`）。
- 但每个洞口填什么完全自由，`style.css:212-214` 的 `clip-path` 只吃 `--cut` 一个变量，跟内容无关 → 不 hard（见 ②）。
- 同段的 **S19** 也是这一类（跨度配平 12 栏，但 `--s` 与菜品名无关）。

### 一句话总结

`hard` 与 `degrades` **正交**（2×2 四格都有实例），但**正相关**：凡是"按条手写值"的实现，往往一次付两笔账。S14/S15/S18 属此类；S20 只有 degrades 那一半，S21 只有 hard 那一半。**因此"同时 hard 和 degrades"既不是冗余标注，也不是必然重叠，而是"逐条绑定"这一种实现方式的典型副作用。**
