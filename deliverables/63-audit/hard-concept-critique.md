## ① 「hard」混了几个意思

「机制绑死在行业数据上」这个短语里，**至少塞了 6 个互不等价的意思**。
它们不是同一个命题的 6 个侧面，而是 6 个可以用不同方法测、且答案会互相打架的命题。

### D1｜机制的**实现**读不读内容数据（可机械核验）

问题：JS/CSS 里有没有一处「从内容里取值，再据此决定版面」的读取动作？

  **S03** `index.html:234-235` 的 `var years = [1957,…]` / `var drift = [0,1.13,…]` 是字面量，

> **这说明什么？**
> 不是「四个 Agent 有人不认真」。四份审计都给了文件行号、都做了逐案取证、都标了置信度，

### 3.2 统计上：`hard` 与 `degrades` **几乎无关**，与「门槛」才有关

```
hard(9) × degrades=yes(13)/30 → 重叠 6，期望 3.90，P(X≥6)=0.0995   ← 不能拒绝独立
hard(9) × 门槛高(7)/30        → 重叠 5，期望 2.10，P(X≥5)=0.0139   ← 显著
hard(9) × 门槛低(11)/30       → 重叠 0，期望 3.30，P(X=0)=0.0065   ← 显著
```

**判读：`hard` 不是 `degrades` 的粗糙版，它是 `threshold` 的粗糙版。**
这直接决定 §6 的建议：**该被合并的是 `hard` 与 `threshold`，不是 `hard` 与 `degrades`。**

### 3.3 该不该合并成一个多维标注？

**不该合并成一个三档标，但该合并成一个「带两个可测槽位 + 一条可编辑文案」的对象。**
理由：
1. 三档（够/勉强/不行）会把「我凑够 N 条就能用」与「我永远用不了」压成同一档——
   这两件事的处置方式完全相反（前者补内容，后者换方案）。
2. 但**两个平行布尔值也不行**：现状就是两个布尔值，结果是 6 案拿到两句都成立的话、3 案拿到一句错话、
   14 案拿到一句「都行」而其中 19/21 其实会因条数断言而撒谎（§1 D5）。
3. 真正的正交维度是 4 个（D1/D2/D4/D5），其中 **D1 已被 D2 蕴含、D3 不可核验、D6 已有字段**——
   去掉这三者，**只剩两个可测槽位：`pinned`（D4，已有实测）＋ `requires`（D2，需人写但可指证据行）**，
   外加一个可选的 `asserts`（D5，机械可数）。

1. **它是「意图声明」，不是「实测」**，而且**已经被证伪过**。
   并行审计 `deliverables/63-audit/hard-S21-S30.md:433-444` 逐案列出 4 处「规格声称由数据生成、代码里是手工摆放」：
   S24（`--depth` 手填 `[1,1,2,2,3,3,4,4,4,4]`）、S23（`--r` 与 `grid-row` 两份常量人肉对表）、
   S28（`blk--sN`/`blk--cN` 逐块手写类名）、S22（`attr(data-verse)` 手打第二份字符串，不读正文）。
   ⇒ **S24 的字段 11 原话「分叉结构由标本数据生成」，代码里查不到生成逻辑。** 拿它当权威会把 `hard` 判高。
2. **它把「内容不可移植」与「几何不可移植」混在一起**。S01 的原话是「栏宽比与 11° 角度绑定报头文字的实际长度，换一个品牌必须重排栏宽」——
   这是排版随文案长度回流的问题，任何报纸版式都有，与「行业数据」无关。
3. **覆盖率不完备且分布是批次造成的**（§5.1），不能反过来用「没有该句」推断「不 hard」。

### 5.5 核实结论

> **「如果作者自己说『换品牌就得重写』，那才是 hard 的权威来源」——这个判断成立，但要加一个限定：**
> **字段 11 是 `hard` 唯一有资格的上游，可它只覆盖 21/30，且其中至少 4 条已被代码证伪。**
>
> 因此：
> - **`HARD_IDS` 与字段 11 是两条互不相关的来源**（Jaccard 0.25）——`HARD_IDS` 必然漂移，事实上已经漂了（§2 有 4 案不成立）。
> - **若要用字段 11 重建名单，得到的是另一份 9 案：`S14 S15 S18 S19 S20 S22 S24 S29 S30`（取 B/C 类 + A 类里经代码复核成立的），
>   而不是现在的 `S03 S05 S10 S14 S15 S18 S20 S21 S29`**。两份只重叠 4 个（S14 S15 S18 S20）。
> - **两份都不该直接采信**：必须「字段 11 提供候选 → 代码复核 `data-*`/坐标/双射是否真被读 → 才落标」。

### 6.2 建议：废除 `hard`，把 `capacity` 扩成一个「可移植性」对象，UI 只出一句话

**字段设计（`build-prompts.mjs` 的 `HUMAN`/`CAPACITY` 合并为一张表，写进 `prompts.js`）**

```js
portability: {
  // 槽位 1：几何（实测，来自 60-minitems 口径，可一行命令复验）
  pinned: true | false,          // true = 单元位置写死（绝对定位/写死 grid 坐标/手绘 SVG 坐标）
  minItems: 8,                   // 设计规模，不是「至少要」
  evidence: "style.css:246-253", // pinned=true 时必须给，能指回写死的那几行

  // 槽位 2：字段（人写，但必须带证据行；无则 null）
  requires: null | {
    what: "每条一个可换算成条高的数值（曝光秒数/强度 1–9）+ 一张与之一一对应的读数表",
    ifMissing: "条高变成随机数，读数表无处对应",
    evidence: "index.html:71-99,113-120"
  },

  // 槽位 3：文案（可机械数，两个现有标注都没管）
  assertsCount: 3                // 正文里断言设计条数的次数；>0 时提示「改内容要同步改文案」
}
```

**取值与覆盖面**

| 字段 | 取值 | 谁提供 | 可复验 |
|---|---|---|---|
| `pinned` | `true`/`false` | 实测（现 `degrades`） | ✅ 一行 `grep` 到坐标 |
| `minItems` | 整数 | 实测（现 `minItems`） | ✅ 数 DOM |
| `requires` | `null` 或 `{what, ifMissing, evidence}` | 人工，**但必须给 `evidence`** | ⚠️ 半可验（能验「代码里有没有读这个字段」，不能验「语义还在不在」） |
| `assertsCount` | 整数 | 实测（正则可数） | ✅ |

这正好把 §1 的六个维度收敛成三个可落地的：**D4→`pinned`、D2→`requires`、D5→`assertsCount`；
D1 由 `requires.evidence` 是否读得到来复核；D3 由 `requires.ifMissing` 这句话承载（明确写成判断，不再伪装成事实）；
D6 交还给已有的 `threshold`。**

**UI 文案模板（一句话，最多两个从句，按槽位拼接）**

```
pinned && requires : ⚠ 版式按 {minItems} 条手工排定，少了会留空位；而且 {requires.what} 必须有——没有的话 {ifMissing}。
requires only      : ⚠ 这案的记忆点靠 {requires.what} 撑住；{ifMissing}。
pinned only        : ⚠ 内容少于 {minItems} 条会留空位（单元位置是手工排定的）。
neither            : 粘给 ChatGPT / Claude / v0 都行，约 {n} 字。
```
