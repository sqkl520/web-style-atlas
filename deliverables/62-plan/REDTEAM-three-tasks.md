## 1. 我第一件要说的事：你没列到的最大问题

### 1.1 复制出去的提示词，13/30 条自相矛盾（`prompt-copy.js:147` vs `L154`）

同一个「结构约束」块里，相邻两条给出**方向相反**的命令：

```
prompt-copy.js:146  "   不凑整、不留空位、不留占位符、编号连续不跳号。"
prompt-copy.js:147  "2. 数量不够时按实际数量收敛，**不要拉高或重复填满**。"
prompt-copy.js:154  "所以请**先把数量凑到 " + count + " 个再排版**；确实凑不够时…"
```

第 2 条说「**不要**凑」，第 3 条说「**先凑到 N 个**」。这不是措辞问题，是**两条互斥指令**。

实测命中 13 案（我自己跑的判定：同时含「不要拉高或重复填满」与「先把数量凑到 N 个」）：

```
S02 S04 S05 S08 S12 S14 S15 S19 S20 S22 S23 S29 S30   → 13/30
```

**而且这 13 案恰好就是 `degrades=yes` 的那 13 案。**也就是说：**给最需要精确指令的那批方案，发了最矛盾的指令。**

错成什么样：模型面对两条冲突指令时，通常服从**后出现的那条**（这里就是"先凑到 N 个"）。于是它会**编造内容填满**——正是第 1 条「不留占位符」和第 2 条「不要拉高或重复填满」明令禁止的。用户拿到一个「看起来排满了、但一半是编的」页面，而且不知道哪一半是编的。

这比你在 A 里要修的「两个字段打架」严重得多：
- A 的问题是**两个低注意力位置各说各话**，用户可能根本没读；
- 这个问题是**用户唯一真正带走的那段文本内部打架**，用户一定会读（他要粘给 AI），且 AI 一定按错的执行。

### 1.3 提示词把「你的实际情况」写死成方案的实际情况（`prompt-copy.js:145`）

```
prompt-copy.js:96   var count = o.count || s.minItems;
```

## 2. 逐项攻击

### 任务 A：修 ⚠️ 标记口径 —— **不做（按你的做法）**

#### (a) 方向反了吗？**没有反，但打偏了。**

你的判断「两处都是低注意力位置」是对的，我量了：

| 位置 | 实测 | 结论 |
|---|---|---|
| 卡片 meta 行 | `.cap-warn` 宽 155px、高 23px、字号 12px，与「家族名 105px + 4 个色块 89px + 错误码 64px」同排，`gap 6px 14px`，`max-width 706px` | 扫视可及，但**没有层级**——它和错误码长得一样重 |
| 详情面板顶部 | `.prompt-cta` 首个子节点，`top=120px`，1440×900 下 **在视口内**；字号 12px、`opacity .7` | 位置是对的（e11 那次上移有效），但**内容错了**（见 1.2） |

我实测了"用户能不能读到"：
- 卡片：翻 30 行，13 行有黄框 `cap-warn`、17 行有灰字 `cap-ok`。**两档都写了**，所以每行都有一条"内容量"信息——这意味着它不是"警告"，是**每行都有的常规 metadata**。警告一旦每行都有，就不再是警告。
- 详情：`cap` 与 `detail hint` **在同一屏上互相矛盾**。实测：

```
S02 卡片:⚠ 内容少于 16 条会留空位     详情:粘给 ChatGPT / Claude / v0 都行   ← 卡片警告、详情不警告
S03 卡片:条目可增减（设计时 8 条）      详情:⚠ 这案机制绑死在行业数据上        ← 卡片说没事、详情说别用
S10 卡片:条目可增减（设计时 12 条）     详情:⚠ 这案机制绑死在行业数据上
S18 卡片:条目可增减（设计时 20 条）     详情:⚠ 这案机制绑死在行业数据上
S21 卡片:条目可增减（设计时 14 条）     详情:⚠ 这案机制绑死在行业数据上
S29 卡片:⚠ 内容少于 23 条会留空位      详情:⚠ 这案机制绑死在行业数据上
```

**这才是真正的"打架"：不是两个字段的数字不一致，而是同一个案子的同一个屏幕上，一句话说"可增减"，另一句说"别用"。** 用户如果先看卡片后看详情（正常路径），会经历一次认知反转；先看详情后看卡片（不可能，卡片在前）则不会。所以这个矛盾是**单向可见**的——一半用户撞上，一半不撞。

#### 这件事真的解决用户问题吗？

**不。** 它解决的是"我们有两个字段、数字对不上"这个**内部一致性问题**。用户的处境是：他要决定"我只有 3 个产品，这个方案能不能用"。

- 你统一口径之后，用户拿到的仍然是"⚠ 内容少于 16 条会留空位"——**这句话对"我只有 3 个产品"这个问题没有回答**。它回答的是"少于 16 条会怎样"，没说"3 条行不行"、"行的话难看多少"。
- 更值钱的做法（你自己提出来的方向，我同意）：**不要警告，让提示词适配内容量**。现在 `d.degrades` 已经进了 `prompt-copy.js:152`，已经在教 AI「数量不够就把空位删掉、整块重排」。**这条指令本身已经解决了 80% 的问题**——剩下 20% 是它在 13 案里被 1.1 的矛盾指令覆盖了。

**所以正确的修法不是「统一口径」，是「删掉卡片上的容量标记 + 修掉 L147/L154 的矛盾」。** 卡片上那句 155px 宽、12px 字、每行都有的标记，删掉之后：
- 信息不丢（提示词里有）；
- 矛盾消失（只剩一处）；
- 卡片更干净（`meta` 从 4 项降到 3 项）。

#### 做了会引入什么新问题？

若按 P1-2 的做法（"改口径为 `degrades`，13 案有警告、17 案无"）：
1. **警告数从 13 增到 13（不变），但含义变了**。现在 `cap-ok` 的 17 行会**完全失去容量信息**（因为你说"17 案无警告"）。而 `cap-ok` 里包含 S07（46 条）——用户最需要知道"46 条我撑不住"的恰恰是这案。删掉 `cap-ok` 等于把"设计规模 46"这个有用数字一起删了。
2. **`hard` 那 4 个（S03 S10 S18 S21）会变成"完全无警告"**，而它们恰恰是"机制绑死行业数据"的 4 个——**这是真实存在的风险，且比"留空位"更严重**（留空位是难看，机制绑死是**用不了**）。你统一到 `degrades` 之后，这 4 个从"有警告但警告不准"变成"没有警告"——**从误报升级成漏报**。

这是典型的"修一个指标、坏一个语义"。

#### 更小的做法？**有。**
- 一行改动：`prompt-copy.js:147` 的「不要拉高或重复填满」改成条件句（只在 `!d.degrades` 时说），或直接删除 L147（L154 已经表达了正确意思）。
- 一行改动：`prompt-copy.js:366` 的「不适合」改成「适用场景」末尾那句。
- 卡片：`app.js:238` 的 `meta.push(capacityHTML(r))` 直接删掉。

三处加起来 < 10 行，比"统一口径"（需要决定以哪个字段为准、需要改 `build-prompts.mjs` 重新生成、需要重新验证 30 案）便宜一个数量级，且修的是**真问题**。

#### 现在不做会怎样？**后果不严重。** 
卡片和详情继续各说各话，用户继续可能撞上认知反转。但**用户不会因此损失什么**——最坏情况是他不用这个方案。相比之下 §1.1 的矛盾指令会让用户**拿到一个编造的页面**，那是实损。

```js
// probe.js:237
```

**这就是自己判卷的具体形态：写探针的人和写实现的人是同一个（或同一批），他们共享同一套"我以为 DOM 长这样"的假设。** 换 session 不改变这一点——换 session 只换了上下文，没换**假设**。

而且这条反证更强：**S07 的实现里出现了 `.verso` / `.folios` / `.folio` 这些类名，而交给实现者的 `prompts/S07.txt` 里 `.verso`、`.catalog`、`.folio` 命中 0 次**（我 grep 过）。也就是说实现者**猜中了原型的类名**。这不是"不知道答案"，这是**同一个模型对同一段 DNA 生成了同名结构**——它当然会生成同名结构，因为它读的是同一份 style.css 抽出来的 DNA。

> 换 session 能让它"不知道原型路径"，但**不能让它"不知道答案"**。答案在提示词里（机制句、配色、字体、数量），而那正是它要复现的东西。

#### 验证 3 条之后呢？

- **1 条失败，改什么？** 不知道。这次验证测的是"提示词能否产出该风格"，但失败可能来自：提示词缺陷 / 实现者能力 / 探针 bug / 素材缺失。实测 `S07` 的 prompt 要求 `46 个条目`，实现产出了 `.entry: 92`（46 × 2，因为镜像双面）。**这算失败还是成功？** 验证逻辑里没有定义。
- **3 条全过，能推出 30 条都对吗？** **不能。** 3 条是从 30 条里挑的（S07 密集目录 / S30 hard 边界 / S23 写死坐标），是**最难的 3 条**。最难的对，不代表中间的都对——反过来也不成立。抽样逻辑只在"随机抽样"时有效，这里是**目的性抽样**（挑最难的），推不出总体。
- **成本**：这次已经跑了 **45 分钟**（18:11 → 18:56），产出了 1 个 JSON、12 张截图、0 个结论。**而 §1.1 那个 13/30 的矛盾，一个 node 脚本 3 秒就能列全。**

#### 更硬的做法？**有，而且不需要"实现者"。**

不要验证"提示词能否产出风格"（这个断言不可判定，你也承认 CDP 验不了气质）。改验证**可判定的**：
1. 提示词内部无矛盾（脚本可判，见 §1.1）；
2. 提示词里每个数字/色值/字体，与 `data.js` 实测值一致（脚本可判）；
3. 提示词引用的每个字段名，在详情面板里真实存在（脚本可判，见 §1.2）。

这三条都是**静态、可复算、零成本**的，而且**已经找出了 3 个真缺陷**。相比之下，"跑一个人时 × 3 条 × 45 分钟"换来的是一个测不准的 JSON。

## 4. 我找到的其它问题（带证据）

### 4.1 向导的"为什么是它"有 63.1% 是假的

`wizard.js:134` `var TIGHT = 0.75;` 定义"对上了"的阈值。`reasonsFor(v, wantMatch)` 只筛 `d <= TIGHT` 的维度，然后拼「（对上你要的「X」）」。

**问题是 `stretch()`（L56）把全库 min/max 线性映射到 0..2，所以"距离小"不等于"符合用户的答案"。**

实测：遍历全部 162 个答案组合，检查推荐卡里"对上你要的「基本不用图」/「一屏说清」"的断言：

```
断言总数: 203
事实上错误: 128
错误率: 63.1%
```

例子（用户答"基本不用图"，推荐卡说"6 张真实图片（对上你要的「基本不用图」）"）：
```
S07  6 张真实图片（对上你要的「基本不用图」）
S17  5 张真实图片（对上你要的「基本不用图」）
S12  6 张真实图片（对上你要的「基本不用图」）
```

用户说"基本不用图"，系统推荐了 6 张图的方案，并**告诉他这符合他的要求**。这不是排序偏好问题，是**界面在说谎**。

同一段还有：用户答「一屏说清」时，`S07` 被推荐（`46 个条目`、`510 字`），理由是「认知门槛低 + 彩度 29% 对上」，**没有一条对上"一屏说清"**。

### 4.2 向导会把闸门 FAIL>0 的方案推荐给你，且从不提"FAIL"

`wizard.js` 全文不含 `gate` / `FAIL` 字样。实测 162 个组合：

```
推荐 top-3 里含 FAIL>0 方案的组合: 46 / 162 = 28.4%
被推荐的 FAIL 方案: S07(29 次) S13(7) S08(7) S21(7)
```

`data.js` 里 `S07.gate.fail=1`（`mono`）、`S08.fail=2`、`S13.fail=4`、`S21.fail=1`。**选型台的卡片用红字标了 FAIL，向导却把这些方案当作推荐给出且只字不提。**

用户如果从向导进来（首屏就有向导入口，`index.html:42`），他会**完全不知道**这个仓库自己判定这 4 个案有缺陷。

### 4.3 空状态说"三个模板不在索引里"，但同时给了模板卡

见 §B。实测同一屏：`#e-why` 说"三个大众模板也不在索引里"（`index.html:161`），`#tpl-strip` 里渲染了 M02 卡片。

### 4.4 移动端：rail 内部滚动，用户看不到自己在哪

实测 390×844：

```
.mast 高 489px（占 58% 首屏）
.rail 高 338px，内部 scrollHeight 1406px → 隐藏 1070px
第一行 top=989（1.17 屏）
.rail-lead 在 ≤620px 时 display:none（style.css:413）
```

`rail-lead` 是唯一解释"组间是并且、组内是或者"的那句话（`index.html:73`），**移动端被隐藏了**。也就是说：手机上 11 组筛选叠在一个 338px 高的滚动盒里，用户不知道这些组之间是什么关系，也看不到"怎么用"（在 1723px 处，被滚动盒裁掉）。

### 4.5 提示词里的字体可能根本不存在于用户机器

`prompts/S07.txt`：「标题用 Libre Franklin，正文用 Newsreader」。这两个是自托管字体（`prototypes/_fonts/`）。用户粘给 AI 生成单文件 HTML 后，**字体不会被带上**。提示词没有说"这些字体需要自备或换成本地等价字体"。实测 `S07` impl 的 `h1` 用的是 `"Libre Franklin", serif`，`winner.likelyReal: true`——**因为验证环境里恰好有 `_fonts/`**。用户环境里没有。这是"验证环境 ≠ 用户环境"的典型。

**修 `prompt-copy.js` 的结构约束段（L145–155）+ 删掉 `:366` 的"不适合"引用 + 删掉卡片上的 `capacityHTML`。**

4. **它让 A 变成不必要**。卡片上那句容量标记一旦删掉，A 要修的"两处打架"就只剩一处，问题自然消失。
