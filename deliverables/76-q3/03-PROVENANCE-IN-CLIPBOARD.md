# Q3 第三项：出处进剪贴板

> 2026-11-11　已上线并真浏览器验证

## 一、做了什么

选型台详情面板里，复制按钮旁边多了一个**「复制并附出处」**。

点它会复制同一份提示词，末尾多一段：

```
────────────────────
下面这段是给出处的，不是给 AI 看的。核对完可以删掉再粘：

本案 S17-revenue-stamp-stub 里的实测位置（5 个数值）：
  16px      直接      S17-revenue-stamp-stub 第 104 行
  6px       直接      S17-revenue-stamp-stub 第 92 行
  24px      直接      S17-revenue-stamp-stub 第 18 行
  88px      直接      S17-revenue-stamp-stub 第 53 行
  2mm       直接      S17-revenue-stamp-stub 第 20 行
```

实测（真 Chrome，截获剪贴板）：S17 复制出 **2406 字**，含 5 处行号。

## 二、四个设计决定，每个都有理由

### 1. 默认不附，做成并列按钮

提示词是给 AI 读的施工说明。把 40 行「第 N 行写着 24px」贴在末尾，
AI 会开始解释这些行号而不是照着做 —— 输出质量反而下降。
**出处是给人核对的，不是给 AI 看的。**

做成并列按钮而不是复选框：复选框在 560px 面板里要额外一行，
而且"勾了才生效"的控件在快速复制动作里容易被忽略 ——
用户点了主按钮就走了，永远不知道还有出处可看。

### 2. 主按钮在左，附出处按钮在右

按钮顺序本身就是优先级声明。视觉上只用**虚线边框**区分：
不换颜色轴（那会变成两个同等重要的动作），虚线语义是"同一族但可选的那个"。

### 3. 每个数值都标四态

```
直接     CSS 里写着这个数
换算     由几何声明换算，不是直接写的
资源     载体是位图/字体，不在 CSS
未定位   我没找到 —— 不一定是缺陷，但值得你自己看一眼
```

不区分这四种，用户会以为"没标 = 没问题"，而恰恰相反。

### 4. 附录开头明说「不是给 AI 看的，核对完可以删」

这句话是这一项的全部价值所在。它把「实测抽取」这个声明变成了**可验证的**：
用户拿到行号，打开 `style.css` 第 104 行，看到 `font-size: 16px`，核对完成。
不需要相信我们，自己去核。

## 三、数据链路

```
style.css / index.html
      ↓  build-provenance.mjs（逐字符状态机 + 141 个数值定位）
dna-provenance.json（116 KB，含每个数值的最多 6 条候选行，给人排查用）
      ↓  裁剪（每值只留选中那一行，key 缩写，text 截 60 字）
provenance.js（16.5 KB，浏览器可读，window.PROVENANCE）
      ↓  prompt-copy.js 的 buildProvenanceAppendix()
剪贴板里的附录
```

为什么要裁剪成两份：`dna-provenance.json` 是**排查用**的（我想知道一个数为什么
定位到那一行，得看全部候选）；`provenance.js` 是**展示用**的（用户只需要最终答案）。
116 KB 的 JSON 不该进浏览器。

## 四、过程中修的一个数据质量 bug

第一次验证时发现 S17 的 `6px` 定位到第 53 行，而那行是：

```css
h1 { font-size: clamp(46px, 6vw, 88px); line-height: 1.04; }
```

`6` 在 `6vw` 里，`px` 在 `46px`/`88px` 里 —— **分开看都命中，合起来是假阳性**。

根因：单位判据只问「这一行里有 px 吗」，没问「这个数字旁边的单位是 px 吗」。
改成要求**数值与单位紧邻**（`6px` 而不是「6 和 px 各自在同一行」）之后，
`6px` 正确指向第 92 行的 `gap: 6px 34px;`。

这是 `build-provenance.mjs` 里第五个同类修正（前四个：`\bpx\b` 词边界、
数据源错用 dna-clean.json、`.5px` 无前导零、SVG 的 stroke-width 无单位）。
**每一个都是"字符串判据无法表达 CSS 语义"的同一个病。**

## 五、回归防线

`probe-ui.mjs` 新增第 11 条断言 `provenance-appendix-copied`，
用**截获剪贴板**的方式验证（把 `writeText` 打桩，拿到真实要写的内容再断言）。

这比"点一下按钮看它变没变色"可靠 —— 后者只能证明 click 生效了，
前者证明**内容真的对**。

配了两条变异用例，都验证会红：

| 变异 | 守的是什么 |
|---|---|
| 把附录从复制内容里丢掉 | 按钮在、能点、但复制出去没有出处 —— 界面上看不出任何异常 |
| 不加载 provenance.js | `window.PROVENANCE` 未定义时的静默降级 |

probe-ui 现在 **11 PASS / 0 FAIL**，变异自检 12/8（有断言带多条变异）。
