## ① 路线 A：把 30 条提示词当用户读一遍

方法：给 `prompt-copy.js` 一个最小 DOM 桩（不装浏览器），走**与浏览器完全同一条 `buildPrompt()` 路径**把 30 条 dump 成文件，逐条读。先证明样板行恒定（30 案逐字节相同的行有 25 行），只精读每案不同的 12 行，避免把重复内容读成"没发现问题"。

脚本：`r2/dump2.mjs`、`r2/routeA3.mjs`、`r2/a4.mjs`、`r2/c3.mjs`；产物：`r2/prompts2/S01..S30.txt`。

### A-1【硬伤】S03：标题链没有中文，却配了一条"不准回退"的禁令

原文（`r2/prompts2/S03.txt` 第 8–9 行）：

```
2. 字体：标题按这个顺序取第一个可用的：IBM Plex Mono → Cascadia Mono → Consolas（前一个缺字就换下一个，不要自己另选）。正文同理，按序取：IBM Plex Sans → Noto Sans SC → Source Han Sans SC。编号/价格等数字用等宽 IBM Plex Mono、tabular-nums 右对齐。
   不要用 Playfair Display、Inter、Roboto，也不要跳过上面这条链直接回退成系统默认无衬线。
```

`IBM Plex Mono` / `Cascadia Mono` / `Consolas` 三个都是纯拉丁等宽体，**没有一个有中文字形**。标题是中文时，这行指令的实际含义是"必须回退"，而下一条同段又写"不要跳过上面这条链直接回退"。AI 无论怎么做都违反其中一条。

`prompt-copy.js:103` 本来写了判断：

```js
var hasCJKInStack = CJK_RE.test(fStack.join(" ") + " " + bStack.join(" ") + " " + fTitle + " " + fBody);
```

问题在于它把**标题链和正文链拼在一起**判断——S03 的正文链里有 `Noto Sans SC`，于是 `hasCJKInStack=true`，走了严格分支。可是这条禁令约束的是"标题回退"，标题链里根本没有中文族。**判据的粒度错了：应该分标题/正文两条链各判一次。**

### A-2【硬伤】S04：同一个 bug 的镜像版本，正文侧

原文（`r2/prompts2/S04.txt` 第 8–9 行）：

```
2. 字体：标题按这个顺序取第一个可用的：LXGW WenKai → KaiTi → STKaiti（前一个缺字就换下一个，不要自己另选）。正文同理，按序取：Redaction 20 → Georgia → Nimbus Roman。编号/价格等数字用等宽 Martian Mono、tabular-nums 右对齐。
   不要用 Playfair Display、Inter、Roboto，也不要跳过上面这条链直接回退成系统默认无衬线。
```

`Redaction 20` / `Georgia` / `Nimbus Roman` 都是拉丁衬线体，中文正文必然回退。标题侧有 `LXGW WenKai` 让 `hasCJKInStack` 为真，于是又走了严格分支。

### A-3【数据被渲染层截断】S04 的中文兜底在数据里有，提示词里没有

这是我本轮找到的**最隐蔽的一条**：数据层是对的，渲染层把它切掉了。

`prompts.js` 里 S04 的真实数据：

```json
"bodyStack": ["Redaction 20", "Georgia", "Nimbus Roman", "LXGW WenKai"]
```

而 `prompt-copy.js:96` 是：

```js
fontLine += "正文同理，按序取：" + bStack.slice(0, 3).join(" → ") + "。";
```

`slice(0, 3)` 把**第 4 位的 `LXGW WenKai`（整条链里唯一的中文族）切掉了**。上一轮修复专门为了"补全中文兜底链"才加了 `displayStack`/`bodyStack` 字段（`clean-dna.mjs:164-183` 的注释写得很清楚："只输出 firstFamily 会丢掉中文兜底"），结果渲染层用 3 个上限又把它丢了回去。

我扫了全部 30 案：**只有 S04 的正文链属于"数据有中文族、提示词丢了"**（其他长栈的前 3 位里都恰好含中文族）。

如果只改一个字符——把 `slice(0, 3)` 改成 `slice(0, 4)`——S04 就从"必然回退"变成"有中文兜底"。**这与 A-2 是同一案的两面**，改一处能同时消掉 A-2。

### A-4【口径打架】S25：说了"数字用等宽"，但没给等宽字体

原文（`r2/prompts2/S25.txt` 第 8 行）：

```
2. 字体：标题按这个顺序取第一个可用的：Besley → Noto Serif SC → Georgia（前一个缺字就换下一个，不要自己另选）。正文同理，按序取：Noto Serif SC → Songti SC → Georgia。
```

对比其余 29 案，都有一句 `编号/价格等数字用等宽 xxx、tabular-nums 右对齐。`。S25 的数据是 `dna.fonts.mono = ""`，而 `prompt-copy.js:100` 是 `if (mono) fontLine += ...`——**空值就整句省略**。

后果不是错，是**不一致**：S25 是"手工装订刊物目录，两专色叠第三色"，编号/价格正是它的核心元素（页面上有 `spot-a`/`spot-b` 双色套印的价目表），却没有等宽体约束，AI 会用正文字体排数字，tabular 对齐就没了。

### A-5【结构约束两条口径并存，但已被 degrades 分化救回来】

我一开始怀疑这是执行者没修干净的遗留：

```
1. 我实际有 20 个条目，就排 20 个：
   不凑整、不留空位、不留占位符、编号连续不跳号。
2. 这个版式的单元位置是手工排定的（不是自动流），撑不住太少的内容。请先用你真实的 条目数去排；如果确实不足 20 个…
```

第 1 条说"就排 20 个"，第 2 条说"按你真实的数量"。**但第 2 条现在是分岔的**：`degrades=yes` 的 13 案拿到"不足就整块重排"，`degrades=no` 的 17 案拿到"条目增减只让页面变短"。两个分岔都把"按真实数量"落在同一个方向上（不编造、不留空槽），不再是原来那种"不要拉高"+"先凑够"的互相抵消。

**判定：这项通过。** 30/30 都存在两句，但语义不再互斥。我逐条核对了 `capacity.degrades` 与 `dna.degrades` 两个字段：30/30 完全一致，没有一案打架。

### A-6【小瑕疵，30/30】ASCII 单引号混进中文句子

`4. 阴影：无阴影。不许用柔和外投影制造'浮起卡片'。`——30 条全部用直引号 `'` 而不是中文引号 `「」`。同一份提示词里其他地方（如 `「餐厅」`）用的是中文引号。不影响 AI 理解，但同一段文本里两套引号不统一。

### A-7【新引入，20:00 那次改动带来的】S09：「全站只用一款字体」+ 同句指定第二款，且漏掉真正在用的 Syne

`prompt-copy.js` 在 **20:00:10** 被改过一次（sha256 从 `09C26C81` → `1B0C3D0E`），新增了一个 `sameFace` 分支（`:90-92`）：

```js
var sameFace = fStack.length === 1 && bStack.length === 1 && fStack[0] === bStack[0];
if (sameFace) {
  fontLine += "全站只用一款字体：" + fStack[0] + "（标题、正文、标签都用它；这一案刻意不引入第二款）。";
```

S09 是唯一命中这个分支的案子（`displayStack = bodyStack = ["LXGW Marker Gothic"]`）。生成的提示词（`r2/prompts2/S09.txt` 第 8 行）：

```
2. 字体：全站只用一款字体：LXGW Marker Gothic（标题、正文、标签都用它；这一案刻意不引入第二款）。编号/价格等数字用等宽 JetBrains Mono、tabular-nums 右对齐，...
```

**同一句话里先说"只用一款、刻意不引入第二款"，紧接着又指定了第二款（JetBrains Mono）。** 这是本轮新造出来的自相矛盾——`sameFace` 的判据只看 `displayStack`/`bodyStack`，**没把 `mono` 算进"第几款字体"**。

更实质的问题：**S09 原型真正用了三款字体**，提示词只说了两款：

```css
/* prototypes/S09-batik-price-board/style.css */
--f-cn:    "LXGW Marker Gothic", serif;    ← 中文，:58 body
--f-latin: "Syne", serif;                  ← 拉丁，:203
--f-mono:  "JetBrains Mono", monospace;    ← 数字，:76
```

`Syne`（拉丁标题体）**在提示词里完全消失了**。`clean-dna` 的 `stackFromVars` 按语义优先级匹配变量名，`--f-cn` 先命中（含 `cn`），于是 `displayStack` 只拿到中文那一支，`--f-latin` 从未被读。**"全站只用一款字体"这个断言是错的**：原型有三款，提示词说了两款，还宣称只该有一款。

判定：这是一条**比 S03/S04 更硬的自相矛盾**——S03/S04 是"禁令与字体能力冲突"（AI 努力一下能兼顾），S09 是"同一句话内部直接打架"（先说只用一款，下一句给第二款），而且把一个真实存在的字体（Syne）从提示词里抹掉了。

## ⑥ 如果只能改一件事

**改 `prompt-copy.js` 空状态的最后一个 else 分岔，让"只有近似"的 9 个词不再被说成"都给不了你"。**

理由，按重要性排：

1. **它说谎，而且是对最需要帮助的人说谎。** 用户在搜索框打了"书店"、看到 0 行、读到"这套图集和模板层都给不了你"——而实际上 `sceneIndex["书店"].near = ["S19","S22","S25"]`，三个方案就在屏幕上方的列表里，点一下芯片就能看到。这是本轮所有问题里唯一一个**主动误导用户放弃**的。

2. **它和本轮要修的是同一类错误，只是方向相反。** 原来的 bug 是"模板层明明有 M02，却对搜「餐厅」的人完全隐身"；这次的 bug 是"近似方案明明有 3 个，却对搜「书店」的人说没有"。执行者修好了前者，把后者留在了原地——而两者的判据在同一个函数、相隔 20 行。

3. **修法已经在文件里了，是漏改不是不会改。** 第一个分岔（`:831-838`）已经会写"点左侧「X」芯片能筛出来"并点名具体方案号。把同样的处理套到"近似>0 但 exact/adjacent 都为 0"这一档即可，判据现成：`(P.sceneIndex[term] || {}).near`。

4. **不修的代价随时间放大。** 23 个词命中这个判据（占 44 个行业词的一半），其中 9 个会真的输出假结论，覆盖的正是"个体户最常做什么站"那一类——书店、婚礼、健身、宠物、诊所、会计。这些人打开页面第一眼就会被打发走。

我**没有**改任何仓库文件。这是一条需要 lead 派执行者去修的独立 bug，修法建议（一行判据 + 沿用第一分岔的句式）已写在上面的第 3 点里。

排在第二不是因为它更轻，而是因为**它只影响 1 个案（S09）**，而第一件影响 9 个词 × 每个词的全部访客。但它的性质更糟——它是**在验证期间新引入的**：

```js
if (mono) fontLine += "编号/价格等数字用等宽 " + mono + "、tabular-nums 右对齐。";
```

`sameFace` 的判据没把 `mono` 算进"第几款"，于是同一句里先说"刻意不引入第二款"、下句就给 `JetBrains Mono`。同时 `--f-latin: "Syne"` 因为 `--f-cn` 抢先匹配而从未进入 `displayStack`，**S09 真实存在的第三款字体在提示词里消失了**。

修法两条任选：
1. **判据加上 `mono`**：`sameFace` 只在 `!mono` 时成立；且断言句改成"标题与正文同一款字体"（不要断言"全站只有一款"）。
2. **让 `stackFromVars` 不要只取一支**：`--f-cn` 与 `--f-latin` 是两个正交的族（中文/拉丁），应当合成一条链而不是后者覆盖前者。

**这条本身也说明一件事**：执行者在验收到一半还在改代码，而改动没有经过独立复跑。我的建议是**冻结本轮改动**，把上面两条修完再重跑一次全量（脚本已备好，见文末）。
