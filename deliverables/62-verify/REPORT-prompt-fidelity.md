## ① 方法说明

### 1.1 我如何确保没看原型

这是本次验证唯一可信的前提，做法如下，可复核：

1. **只运行提示词生成器，只取字符串。** 全部输入来自一条 node 命令：加载 `prototypes/_selection/data.js`、`prompts.js`、`prompt-copy.js`，对每个 id 调用 `buildStylePrompt(id)`，把返回值写进 `prompts/S07.txt` 等三个文件。除了这三个 `_selection` 脚本（选题数据 + 提示词模板），我没有读取 `prototypes/` 下的任何其它文件。
2. **从未打开目标原型的 HTML/CSS。** 我没有 `read`、没有 `cat`、没有 `grep`、也没有 `glob` 过 `prototypes/S07-*`、`prototypes/S30-*`、`prototypes/S23-*` 目录里的任何文件；也没有用浏览器访问过它们（本地服务只挂载了 `deliverables/62-verify/impl` 一个目录，URL 只有 `/S07.html`、`/S30.html`、`/S23.html`）。
3. **没有意外看到。** 生成器的输出只有提示词正文（1309 / 1431 / 1436 字符），不含原型标记；报告里的每条判定都能回溯到「提示词某一行 + 我写的 HTML 的实测值」，中间没有第三方参照。
4. **时序上不可能偷看后改稿。** 三份 `impl/*.html` 的第一版是在 `prompts/*.txt` 落盘之后一次性写成的；之后的编辑全部由实测反馈驱动（记录在文末「实现迭代记录」），没有一次是因为「记得原型长什么样」。

> 声明：我确实加载了 `prototypes/_selection/data.js` 与 `prompts.js` **用于产出提示词**。这两个是共享的选题/模板数据，不是 S07/S30/S23 原型页面的实现代码。除此之外没有任何原型代码进入过我的上下文。

### 1.2 测量手段

- CDP：`tools/taste-skill/skills/taste-skill/scripts/lib/cdp.mjs`，`Browser.launch()` → `newPage()` → `goto()` → `eval()`。本地静态服务端口 9573–9583（9570+ 段）。
- 所有数据来自**真机 computed style / 布局盒 / 平台字体**，不是读我自己的 CSS 推断：
  - 颜色：遍历全部元素（S07 534 个 / S30 188 个 / S23 264 个）的 `color`、`background-color`、四边 `border-*-color`、`outline-color`、`text-decoration-color`、`background-image`，把 `rgb()/rgba()` 归一成 hex，按 alpha 单独记。
  - 字体：`getComputedStyle().fontFamily` + **CDP `CSS.getPlatformFontsForNode`**（返回真正画字形的平台字体与字形数）+ `document.fonts` 面状态。后者是关键：它区分「CSS 声明了什么」和「谁真的画了字」。
  - 圆角/阴影/线宽：逐元素 `border-*-radius`、`box-shadow`（区分 inset/外投影）、`border-*-width`（**跳过 `border-style:none` 的元素**，否则浏览器会把计算宽度报成 medium=3px，产生假阳性）。同时用 800×600 空白页单独验证 0.5px / 1.5px 能否落地。
  - 图片：`document.images` 的 `getBoundingClientRect` + `naturalWidth/Height` + `width/height` 属性，确认不是 1px 图、不是纯色块、不是 CSS 假图。
  - 条目数：结构选择器计数 + 编号字符串抽取，并对编号序列做唯一性检查。

### 1.3 三档判定口径

- ✅ 提示词说清了，我照做，实测命中。
- ⚠️ 提示词有歧义/区间/缺数据，我必须做选择，已注明选择与理由。
- ❌ 提示词无法执行或自相矛盾（含「浏览器做不到」）。

## ⑤ 提示词自身的缺陷（按严重度）

### P0 — 无法执行 / 自相矛盾（必须改，否则下一轮还是做不出来）

**P0-1｜指定拉丁字体 + 中文文案 = 指定字体永远不落地（三份全中，S07/S30 致命）**

提示词一边规定「标题用 Libre Franklin / Anton」「正文用 Newsreader / Zhuque Fangsong」，一边要求「照这个调性写文案和标题」——也就是写中文。
实测（CDP `CSS.getPlatformFontsForNode`，看的是**真正画字形的平台字体**）：

| 案 | 声明字体 | h1 实际画字 | 正文实际画字 |
|---|---|---|---|
| S07 | Libre Franklin / Newsreader | **SimSun**（21 字形） | **SimSun**（18 字形） |
| S30 | Anton / Zhuque Fangsong | **Noto Sans SC**（4 字形） | **FangSong**（28）+ Noto Sans SC（1） |
| S23 | Noto Serif SC | **Noto Serif SC**（web，16） | **Noto Serif SC**（web，13） |

只有 S23 命中，因为它是唯一指定 CJK 家族的。S30 更糟：它自己写着「不要回退成系统默认无衬线」，而 Anton 无中文字形 → 浏览器必然回退到 **Noto Sans SC**，**这条禁令被它自己的字体选择强制违反**。
修法：每个拉丁字体后面必须补一个 CJK 兜底（如 `Anton, "Noto Sans SC"`），或对中文文案显式声明「标题的中文字形用 X」。

**P0-2｜「线宽只用这几级」与「签名动作」的线宽三份全部互斥**

| 案 | 允许档位 | 签名动作要求 | 冲突 |
|---|---|---|---|
| S07 | 1px、2px | 栏线 **0.5px** | 0.5px 不在档位内 |
| S30 | 1px、3px、6px、8px | **1.5px** 白带 | 1.5px 不在档位内 |
| S23 | 1px、6px | 斜痕 **2px** | 2px 不在档位内 |

而且 0.5px / 1.5px **浏览器根本无法用 border 画出**：空白页单测 `border-top:0.5px` → 计算 **1px**、`border-top:1.5px` → 计算 **1px**、`column-rule:0.5px` → **1px**。只有 `height:0.5px` / `height:1.5px` 的元素（背景色）才能真出 1.5px。
也就是说 S07 的「栏线 0.5px」在任何实现里都会变成 1px；写 0.5px 的人以为自己做到了，实测是 1px。**「逐条执行，不得改」+ 自相矛盾 = 执行者只能二选一违规。**
修法：把签名动作里的线宽并入档位表（S07 加 0.5px 并说明用 `height`/`scaleY` 实现；S30 加 1.5px；S23 加 2px），或把签名动作改成档位内的值。

**P0-3｜S30 的几何签名在一张正常宽度的页面上无解**

「沿 −32° 对切成两半，斜切带高 96px」。在 1440px 宽的版面上，一条 −32° 的直线横向走完需要 **1440×tan32° ≈ 900px 的垂直落差**，不可能塞进 96px。
我按「96px = 楔形的垂直高度、−32° = 白带/撕口的走向」实现，实测：带高 96px ✅、白带旋转矩阵 `matrix(0.848,-0.530,0.530,0.848)` = **−32°** ✅，但楔形可见斜边只有 **arctan(96/1440) ≈ 3.8°**。
两个数字无法同时成立。必须改写其中一个（例如「斜切带厚 96px（垂直于切线的厚度）」并给出切线角度，或「−32°」改成「≈4°」）。

**P0-4｜S30 指定了一个不存在的字体**

`Zhuque Fangsong`（朱雀仿宋）：
- `https://fonts.googleapis.com/css2?family=Zhuque+Fangsong&display=swap` → **HTTP 400**（Google Fonts 无此家族）
- `https://cdn.jsdelivr.net/npm/@fontsource/zhuque-fangsong/index.css` → **404**

提示词写「不得换字体」，但该字体无公开 webfont 源。执行者只能落到系统 `FangSong`（实测确实如此）。这是「无法执行」而非「我偷懒」。

### P2 — 轻微

- **S07**：要求「编号/**价格**等数字用等宽…右对齐」，但该案是修复所目录，没有价格概念 → 无价格可排（我用了尺寸 `265 × 190 mm` 充当数字位）。
- **S23**：只写「Noto Serif SC」不给字重，我取 600，实测平台字体报 `ExtraLight`，字重没按设计落地（我要么漏写 `font-weight` 的可用面，要么该家族可变字重解析异常）——这条是我实现侧的偏差，但它暴露了提示词「不给字重」的信息缺口。
- **S23**：CJK 字体代价未提示——实测声明 **422 个字体面**、`fonts.ready` **16.7s**，首屏有可感闪烁。
- **S07**：`column-rule` 的 0.5px 与「正面 5 栏」在同一元素上，改档位时容易连栏数一起改错。

## ⑥ 总判定：这份提示词能不能产出该风格

| 案 | 结构/配色/几何 | 字体 | 结论 |
|---|---|---|---|
| **S07** | 全部命中（4 色、0 圆角、0 阴影、46 条连续、7 图、5/7 栏、镜像 11%、防退化 8/8） | ❌ 标题/正文实测是 SimSun，不是 Libre Franklin / Newsreader | **版式能，字体不能。** 若「字体」算硬约束（提示词自己说「不得换字体」），则**不能完整产出该风格**；若只看版面语言，能。 |
| **S30** | 5 项命中但签名动作有 2 处不可执行（−32°+96px 无解、1.5px 越档） | ❌ Anton 不画中文（回退 Noto Sans SC，违反自己的禁令）；Zhuque Fangsong 不存在 | **不能。** 三处 P0（几何矛盾、越档、字体不存在）+ 一处自打嘴巴的禁令，执行者无论如何都会违反至少一条。 |
| **S23** | 全部命中（7 色、0 圆角、0 阴影、9 开口 3/2/2/1/1、层数 2–4、10 图、96px 索引条、1px 层线、防退化 8/8） | ✅ Noto Serif SC 真的画了中文 | **能。** 三份里唯一自洽的一份；唯一硬缺陷是 2px 斜痕越出「1px/6px」档位（可用背景实现绕过，但规则上仍算违规）。 |

**一句话总判定：** 三份提示词的「配色 / 圆角 / 阴影 / 条目数 / 图片位 / 防退化」这六类约束是**可执行且可验证**的（本次 100% 命中）；坏掉的是**字体**（3 份里 2 份的指定字体根本无法渲染中文，1 份指定了不存在的字体）和**签名动作里的线宽/几何**（3 份全部与「线宽档位」互斥，1 份几何无解）。下一轮优先修 P0-1（CJK 兜底）、P0-2（线宽档位并入签名动作）、P0-3/P0-4（S30 几何与字体）。
