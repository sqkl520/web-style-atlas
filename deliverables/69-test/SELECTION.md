# 选案说明（在写任何 PROMPT.md / JUDGE.md 之前完成）

本轮任务：验证「线上 `buildStylePrompt(id)` 产出的提示词，喂给一个只看得到提示词的实现者，能不能得到那个风格」。

## 0. 先复现「线上提示词」这一步

`prototypes/_selection/prompt-copy.js` 的 `buildStylePrompt` 挂在 `window` 上，依赖
`window.STYLE_PROMPTS`（prompts.js）与 `window.SCHEMES`（data.js）。用 Node `vm` 起一个最小
DOM 沙箱按 **data.js → prompts.js → prompt-copy.js** 的顺序加载，再逐案调
`window.buildStylePrompt(id)`，落盘到 `_staging/prompt-Sxx.txt`。
脚本：`_tools/build-prompts.mjs`。30/30 全部产出，长度 1,639–1,998 字。

**复核任务书给的 S19 数字**：`prompt-S19.txt` = 1,945 字（任务书说 1,945 字 ✓），39 行，
字体链 `Noto Serif SC → Georgia` ✓，7 个 hex ✓，无段落结构（全文只有 39 行，没有「二～七」章节）✓。
四项全对。任务书关于「线上这份 = 1,945 字、无段落」的说法成立。

## 1. 选案的三条硬前提

1. **信息隔离可行性**：我只能靠自律（本会话 delegation depth = 0，无法派子 Agent）。
   所以必须优先选**在 `prompt-copy.js` 注释里零出现**的案 —— 那个文件是本任务唯一必须读的
   源文件（要跑 buildStylePrompt），而它的注释里塞了大量逐案原型事实（`style.css:132` 的类名、
   空抽屉在第 4 与第 16 个、某案 h1 实际是哪个字体……）。读它 = 被动泄题。
   实测每案在注释里的出现量（字符数）：

   | 零出现（12 案） | 少量 | 大量 |
   |---|---|---|
   | S05 S11 S13 S14 S16 S17 S20 S21 S25 S26 S27 S28 | S03 S08 S22 … | S06(3122) S19(3128) S30(2417) S23(1532) S12(1462) S18(1355) |

   → **S19（任务书举例的那个）与 S18/S06 被排除**：它们的原型细节已经躺在生成器的注释里，
   我无法诚实声明「我只看过提示词」。这一条本身就是本轮的一个结论：**生成器注释是提示词
   Agent 的泄题源**（详见 REPORT 第 4 节）。

2. **难度必须真的分层**，不能是三个同质案。我用「提示词里可机械验证的声称密度」给 30 案打分
   （`_tools/score.mjs`：hex 数、线宽级数、机制句里的数字+单位数、结构约束里的数字+单位数），
   再人工读前几名确认。

3. **三案要落在不同的「可验证性结构」上**：绝对量（能直接量像素）／可数结构（能数个数）／
   相对量与气质（只能判「像不像」）。

## 2. 最终三案

| 角色 | 案 | 为什么是它 |
|---|---|---|
| **A 机械约束密集（好验）** | **S20** 白图纸上针笔单线走位 | 三个「绝对量」都可直接量：画布 1:1、边长 = 视口高 − 96px、安全区 24px、坐标格 8px 间距。4 个 hex、4 级线宽、圆角 0、无阴影 —— 机械判据能占到 13 项，是 30 案里最「可证伪」的一类。**并且它自带一处硬矛盾**（见下），正好用来区分「实现者漏了」和「提示词自相矛盾」。 |
| **B 结构约束强（可数）** | **S21** 值班台上的联锁释放簿 | 结构全是可数的：10 栏里 1–4 与 7–10 给两张表、5–6 栏留给 **14 枚 24×96px** 横条、条间 **1px** 缝、右端 **30/45/60°** 三档斜切。数量、尺寸、分栏、角度四件事都能逐条机械判定，且互不重叠。 |
| **C 气质型（难验）** | **S28** 唱片封套裁开重拼，暗紫配黑 | 它的硬约束几乎全是**相对量**（错位 4–14px、出血 24px、栏距 0），没有「必须在某个绝对位置」的东西；识别度主要靠 `tone=奢华暗黑/高定` 与一整段**只说不许什么**的 risk。4 个 hex 里两个近黑（#0B0D12 / #07080C），"都用上了"这件事机械可判、肉眼不可判 —— 正好把机械判据与人判项切开。 |

排除说明（为什么不是别的）：
- **S13** 分数高但 shadow = 「inset 与外投影混用」，判据 6「外投影=0」直接不适用，会白丢一类判据。
- **S29/S18** 机制句数字最多，但 S29 与 S18 在注释里有原型细节，隔离不可信。
- **S06/S19** 泄题最重（3122/3128 字），必须排除，哪怕 S19 是任务书点名的对照案。
- **S12/S23** 有「刻意留空」分支，判据会牵进「空位算不算缺失」的争论，不适合首轮。

## 3. 三案各自的一处「预判矛盾」（写在这里，避免事后诸葛）

- **S20**：机制句说走线「0.35px 按 0.6/1.2/2.4px 三级分档」，而硬约束第 5 条说线宽「0.35px、0.5px、1px、3px」。
  两处给的线宽集合**交集只有 0.35px**。这是判据必须分开记的原因（见 JUDGE-S20 的 C9）。
- **S21**：机制句说「14 枚 **24×96px** 横条」——24 宽 × 96 高是**竖条**，不是横条；而且 24px 宽的条上做
  **60° 斜切**需要 ~41px 的横向跨度，几何上放不下。
- **S28**：risk 段说「配色锁死**三个** HEX」，而配色行给了**四个**。

这三处都不是我事后编的，是从提示词原文直接读出来的，且都在写 index.html 之前记录在本文件里。

## 4. 三案共同的、我先验过的环境事实（不是设计事实）

本机 Chrome（HeadlessChrome/156）里，用 `CSS.getPlatformFontsForNode` 逐族实测**装了**的只有：
`Georgia`、`Times New Roman`、`SimSun`、`Noto Sans SC`、`Consolas`、`Microsoft YaHei`、`KaiTi`。
**没装**的包括三案点名的全部字体：`Space Grotesk`、`Martian Mono`、`Antonio`、`WenJin Mincho`、
`Songti SC`、`STSong`、`Instrument Serif`、`Noto Serif SC`、`JetBrains Mono`、`Glow Sans SC`。
（复算：`_tools/font-probe4.mjs`）

这条事实决定了字体判据怎么写，也提前暴露了一个全库级缺陷：**30 案点名的字体在本机几乎全部不可用，
而提示词从未说过「要不要用 Google Fonts 加载它们」**。这一点在 GRADE 前必须登记（见各 JUDGE 的 F1/F2）。
