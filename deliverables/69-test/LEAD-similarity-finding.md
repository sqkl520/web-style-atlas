# Lead 新发现：端到端产物的视觉相似度只有 0.49，根因是提示词缺两类规格

- 测量时刻：2026-10-29 03:40 (Asia/Shanghai)
- 方法：对 3 个端到端产物（S20/S21/S28）与其原型，用 CDP 提取「视觉指纹」（字符数加权的字号分布 / 元素面积加权的色板分布 / 字体分布），算余弦相似度

## 结果：平均视觉相似度 0.490

| 案 | 综合 | 色板 | **字号** | 字体 |
|---|---|---|---|---|
| S20 | **0.391** | 0.479 | **0.030** | 0.664 |
| S21 | **0.583** | 0.958 | **0.001** | 0.791 |
| S28 | **0.497** | **0.000** | 0.543 | 0.949 |
| **平均** | **0.490** | | | |

对比：同一批产物的**机械判据通过率是 91.5%**。

**机械判据 91.5%，视觉相似度 49%。** 这个落差就是端到端验证的真实图景。

---

## 根因 1（P0）：提示词从不给字号规格

### 实测

```
S20 提示词：提到「字号 / font-size」= false
            全文 px 值只有 96 / 24 / 0.2 / 8 / 0.35 / 2.4 / 0.5 / 1 / 3px
            —— 全是布局尺寸（画布边长、安全区、坐标格）与线宽，没有一个字号

S28 提示词：提到「字号 / font-size」= false
            全文 px 值 64 / 14 / 24 / 2 / 8 / 1px —— 同样没有字号
```

### 后果：字号层级完全丢失

| 案 | 原型字号（字符数占比） | 实现字号（字符数占比） |
|---|---|---|
| **S20** | **13–72px**：13(55.2%) 16(34.7%) 17(8.8%) **34(0.8%) 72(0.1%)** | **8–19px**：12(48.5%) 10(35.1%) 13(5.5%) 11(5.3%) 19(3.1%) 8(2.1%) |
| **S21** | **12–86px**：16(93.3%) 17(3%) **86(标题)** | **9–26px**：12(40.8%) 9(35.6%) 10(8.8%) |
| **S28** | **13–92px**：13(44.3%) 16(43.1%) 15(8.1%) **92(标题)** | **9–44px**：12(30.3%) 9(23%) 13(22%) 10(14.7%) |

**三案的最大字号：原型 72/86/92px → 实现 19/26/44px。**

大标题是版式的「表情」。原型的标题是 72–92px（占首屏显眼位置），实现者猜成了 19–44px。这不是「差一点」，是**从"宏大标题"变成"普通网页"**。

而且实现的字号集合（8/9/10/11/12/13）明显是**浏览器默认值 + 常规做法**（0.75rem/0.875rem 之类），说明实现者**没有任何依据，只能用通用套路**。

### 为什么这特别严重

提示词在别的方面极其精确：
- 「线宽只用 0.4px、0.8px」——精确到 0.1px
- 「抽屉面板高 24px，抽出位移 24px」——精确到 1px
- 「画布 1:1，边长 = 视口高 − 96px」——精确到 1px

**唯独字号一个字都没提。** 这给人一种"提示词很精密"的错觉，但精密的都是"骨架尺寸"，不是"排版层级"。

## 根因 2（P1）：色板给了值，没给面积配比

### S28 实测

```
原型： #0B0D12 67.3%  |  #AF74BE 31.6%  |  #D8D4C6 1.1%
实现： #0B0D12 69.1%  |  #07080C 30.9%  |  #AF74BE 0%  |  #D8D4C6 0%
```

提示词原文：
> 「配色只用这几个值：`#AF74BE`（plum）、`#D8D4C6`（paper）、`#0B0D12`（ink）、`#07080C`（ink2）。不新增更多彩色。」

**值全对，但用错了比例。** 原型里 `#AF74BE`（梅子紫）占 31.6% 是第二主色，实现里 **0%**；实现用 `#07080C`（ink2，接近黑）占了 30.9%，而原型里 ink2 只占 0.9%。

**结果：一个紫色调的设计变成了纯黑设计。** 而「梅子紫」很可能是这个风格的识别核心（它叫 `plum`）。

### 为什么提示词会漏掉这个

`build-prompts.mjs` 只抽**色值**，不抽**面积占比**。而 `style.css` 里是有面积信息的（哪个色用在背景、哪个用在小面积强调）。

**提示词给了"调色盘"，没给"配方"。** 相当于给人一盒颜料和四个颜色名，但不说哪个是主色。

## 这两个发现对 A 项的判决

### 机械判据 91.5% 是真的，但它测的是「有没有违反禁令」

24 条判据里绝大多数是**否定式**（不准有圆角、不准有外投影、不准用 Inter、不准有渐变）+ **枚举式**（14 枚条、10 栏、6 个图片位）。

这些都对。**但它们全部测"不该有什么"，几乎不测"该有多强"。**

- 「标题字体是 Noto Serif SC」→ PASS（字体对了）
- 「标题是 72px 还是 19px」→ **没有这条判据**

### 所以 A 项的准确结论应该是

**提示词能让 AI 避开 30 种已知的 AI 味，但不能让 AI 做出该案的视觉强度。**

用一句话概括：
> 提示词是一份**很详细的禁令清单 + 一份不完整的规格书**。
> AI 照着它做，能保证「不像 AI 生成的通用网页」，但保证不了「像这个案」。

### 补规格的做法（下一轮）

要给 `build-prompts.mjs` 加两类抽取：

1. **字号层级**：从 CSS 抽实际使用的 `font-size` 集合 + 每个字号对应的元素角色（h1 / h2 / 正文 / 小字）+ 字符数占比。写成：
   > 「字号只用这几级：72px（大标题，占 0.1% 字符）、34px（区块标题）、16px（正文，占 34.7%）、13px（小字，占 55.2%）。不要自己加中间档。」

2. **色板面积配比**：从 CSS 抽每个色的使用面积占比，写成：
   > 「`#AF74BE` 是第二主色，占画面约 30%（不是点缀色）；`#0B0D12` 是底色占 67%；`#D8D4C6` 只用于少数高光（1%）。」

这两条都不难抽（`getComputedStyle` 循环 + 面积累加，我这一轮的脚本就是这么做的），但它们**决定了产物"像不像"**。

## 一个诚实的边界

这是我自己的测量，不是端到端验证 Agent 的。它有两个已知局限：
1. **余弦相似度对「占比分布」敏感，对「绝对值」不敏感**——S21 色板 0.958 很高，但那是因为两案都只有一种底色占绝大部分，不说明"看起来像"。
2. **字号用字符数加权**，若实现者写的内容比原型少（S20 实现 487 字符 vs 原型 5473 字符），分布仍可比，但"内容量"差异没被捕捉。

要更准的「像不像」，需要人看截图对比（红队和端到端 Agent 都强调了这一点）。
