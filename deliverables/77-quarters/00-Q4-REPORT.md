# Q4：让它能被持续维护

> 2026-11-11　季度体检脚本已跑通一轮（22 步全过）
> 计划原文：「季度全流程可在一台干净的机器上从零复现」

## 一、做了什么

`prototypes/_build/quarter.mjs` —— 一条命令跑完整个季度流程。

```bash
node prototypes/_build/quarter.mjs              # dry-run（默认）
node prototypes/_build/quarter.mjs --write      # 真的重新生成产物
node prototypes/_build/quarter.mjs --render     # 连三档渲染一起跑
node prototypes/_build/quarter.mjs --report     # 只出报告
```

实测一轮（`--write`）：**22 步全部通过**，含 6 个生成步骤、11 道静态闸门、
4 组自测、1 个真浏览器探针（176 秒）。报告落盘到 `deliverables/77-quarters/<日期>.md`。

## 二、三个设计决定

### 1. 默认 dry-run，写盘必须显式

这个脚本会重写 `data.js` / `prompts.js` / `provenance.js`。
如果默认就写，**任何人随手跑一下都会改工作区** —— 而"随手跑一下看看"
恰恰是季度体检最可能被怎么用的方式。

dry-run 时不跑生成步骤，但也**不静默略过**：报告里逐条列出"跳过（dry-run）"
以及它会写哪些文件。静默略过会让报告看起来"全过"，而产物可能是旧的。

### 2. 渲染单独开关

渲染 35 案 × 3 档 = 105 次 Chrome 加载，实测十几分钟。
它是季度体检的必要一步（截图会过期），但不该让"我只想看看闸门状态"的人等这么久。

### 3. 依赖顺序写在脚本里，且注释写清为什么

```
1. extract-specs      deliverables/04|05|06-*.md → _specs/*.md
2. [render]           _specs + html/css → .inspect/report.json + 截图
3. extract-dna        _specs + css → dna-raw.json
4. clean-dna          dna-raw.json → dna-clean.json
5. collect-schemes    _specs + report → data.js
6. build-prompts      dna-clean + data.js → prompts.js
7. build-provenance   prompts.js + css → dna-provenance.json + provenance.js
8-18. 十一项检查 + 四组自测
19. probe-ui（真浏览器）
```

两个容易搞反的地方，都是本仓库实际踩过的：

- **collect-schemes 必须在 build-prompts 之前**：后者读 `data.js`（`build-prompts.mjs:40`）。
  反过来跑会得到一份基于旧数据的提示词。
- **build-provenance 必须在 build-prompts 之后**：它读 `prompts.js` 取机制句
  （不是读 `dna-clean.json` —— 那条路只有 34 个数值，因为机制句的补丁是在
  build-prompts 里打的）。

## 三、跑第一轮就抓出四个问题

这一节是本轮最有价值的部分 —— **季度脚本第一次运行就暴露了四处此前没人发现的东西**。

### ① `check-distribution` 的 B6 夹具过期（假红变假绿）

B6 原本写死「加 5 个暖米纸色 → 占比 65.7% > 60% → 必须红」。
那是 30 案时的算术。Q2 扩到 35 案后，加 5 个只有 23/40 = 57.5%，**正确地不红** ——
于是自测报「✗ 该红没红」。

根因不是断言坏了，是**夹具把会随季度变的案数写死了**。
改成从当前数据现算「需要注入几个才能越过 60%」（现在是 8 个）。

### ② `check-scenes` 存在循环论证（恒真式）

这条最严重。原 `searchHaystack(r, sceneIndex)` 同时干两件事：
1. 复刻 app.js 的搜索索引（**含"把 direct 词拼进去"这一层**）
2. 被用来判「direct 命中能不能在该案正文里搜到」

而 2 用的是 1 的产物 ⇒ **direct 词被 1 拼进去之后，2 永远成立**。
断言变成恒真。

证据：变异测试 B4（造一个「紫砂壶→S01」但正文里没有的词）本该红，实测**绿**。

修法：拆成 `bodyText()`（只含该案自己的文字）与 `searchHaystack()`
（bodyText + 同义词展开）。判据 2 只用 bodyText。

修完之后立刻抓出 **3 条被恒真式掩盖的真 FAIL**：潮牌 / 修鞋理发 / 小吃店 ——
正是 Q2 我以为修好了的那三个词。**当时它们从来没被真正验证过。**

### ③ 同义词表可能变成豁免表（新增 S4 断言）

修好 ② 之后，同义词表已经不可能自证了。但风险本身还在：
只要有人往表里塞一个"看起来像同义、实际放宽了语义"的词，S1 就会绿而产品没变好。

所以加了 `scenes-synonym-unbacked`（FAIL）：
**表里每一项都必须真的能在它声称直连的案的正文里找到**。

它当场抓到「小吃店 → S09」：S09 的正文写「独立餐饮」，没有"小吃"。
这条**应该红**，因为它暴露的是真实的产品问题，而不是表写错了。

### ④ `_specs` 是产物，不是源

我一开始去改 `prototypes/_specs/S12.md` 和 `S09.md` 加「潮牌」「小吃店」。
跑完季度脚本，改动**被覆盖了** —— 因为 `extract-specs.mjs` 从
`deliverables/04|05|06-schemes-*.md` 重新切分。

正确的修复位置是上游。改完之后 22 步全过。

这个事实值得记住：**`prototypes/_specs/` 下的每一份都是产物**，
手改会静默消失。季度脚本的价值之一就是让这件事变得可见。

## 四、修掉的一个"假 0"

`quarter.mjs` 的报告第一版显示：

```
少货少图  0 案（地板 2）
提示词    0 份，行业词 0 个
```

但实际是 5 案 / 35 份 / 44 个。

根因：`load()` 返回的是**沙箱的 window 对象**，而 `data.js` 挂 `window.SCHEMES`、
`prompts.js` 挂 `window.STYLE_PROMPTS` —— 两边顶层名不同。
第一版写成 `const P = load(...)` 然后 `P.schemes`，永远 undefined。

**这个 bug 之所以没被当场发现，是因为 0 是一个合法值** ——
报告看起来只是"这项没有"，而不是"读取失败"。
这正是本仓库反复在治的那个病：读不到数据 → 打出一个好看的 0。

修法：`load(p, key)` 显式取顶层名，取不到就 `throw`，
让 catch 记进 `d.error`，报告里出现「数据读取失败」而不是一排 0。

## 五、从零复现验收

写了 `deliverables/77-quarters/_check-reproducibility.mjs`，检查五件事：

| 检查 | 结果 |
|---|---|
| 11 个关键产物是否 tracked（clone 拿得到） | ✓ |
| 有没有**唯一**硬编码路径 | ✓（4 处路径字面量全部有 env/候选列表兜底，逐个核实过） |
| 外部依赖 | ✓ 零 npm 依赖，所有 import 都是 `node:` 内置或相对路径 |
| 需要的外部程序 | ✓ 只需要 Chrome（python 只被 `make-textures.py` 用到，不在季度流程里） |
| quarter.mjs 的每一步都指向真实文件 | ✓ |

**关于硬编码路径这条判据本身**：第一版只 grep 路径字面量，报了 4 处"问题"。
逐个核实全是**跨平台候选列表**（`[env.GIT_BIN, 'git', 'D:/Git/...', 'C:/Program Files/Git/...']`），
在 Linux/CI 上前面的候选就命中了。把它们报成"不可复现"是假阳性。
判据收紧到「只有一个路径字面量，且前后 6 行没有 env/PATH 回退」才报。

## 六、Q4 还没做的两件（都需要你定）

计划里的 Q4 有四项，我做了两项：

### ✗ 第一次完整增删演练（归档流程）

计划原文：「按 R3 只增不删，但演练『若某案表现差，归档流程是什么』」。

**这条我没有自己决定怎么做**，因为它涉及产品承诺：
一个案子被归档之后，之前复制过它的人手上那份提示词还算不算数？
站点上要不要留一个"已归档"的页面？

计划自己在 §5.2 写过归档的触发条件应该是数据（连续两个季度被复制次数排末位 5），
而**现在没有任何使用数据**。所以在 Q4 做归档演练只有形式没有依据。

如果你要现在做，我建议的最小版本是：
写一份 `ARCHIVE.md` 定义「归档 = 从选型台隐藏 + 原型目录保留 + 提示词 URL 永久 301」，
并在 `_entries.mjs` 里加一个 `archived: []` 数组（现在是空）。

### ✗ 轻量使用信号

计划原文：「这是唯一能知道『哪个案是废的』的方式。但这条与『数据不出本机』
的自我描述冲突，需你单独批准。」

**这条明确需要你批准**，我没有动。

它解决的是一个真问题：Q4 的归档决策、Q2 的分布目标，现在全部靠推测，
没有一个"哪个案真的被复制了"的数据。而代价是站点上第一次出现第三方请求。
