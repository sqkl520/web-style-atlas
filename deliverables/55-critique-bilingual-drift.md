# 55 · 双语漂移审计（第 2 轮锐评）

> 审计人：55 号（双语漂移审计员）。只读审计；产出仅 55-*。
> 问题：**中英双语 README 是实质还是装饰**——两份是不是同一个文档，还是两份各自漂移的文档；以及更狠的一刀：**README 双语了，产品呢**。

## §0 方法

**审计对象**：`README.md` 与 `README-EN.md`。初读基线 = `e15a6ee`（30,393 B / 432 行；34,488 B / 435 行），**定稿基线 = `73bdecb`（31,038 B / 435 LF；35,248 B / 438 LF）**——审计期间 Lead 重写过一次"阶段 4"，详见 §1.1 注 1。

**审计问题**（三层，一层比一层狠）：

1. **镜像完整性**：`契约` 与 `deliverables/README-REWRITE-NOTES` 都写过"逐节对译"。量它有没有被破坏——标题集合、顺序、篇幅比、数字同值、❌ 条目同集。
2. **可点性**：锚点在对方语言里能不能跳、EN 引用的路径是不是中文命名空间、双语互链对不对。
3. **诚实性**：README 双语了，产品没有。**EN 读者 clone 之后能消费的文件与字节占比是多少**，README-EN 有没有在第一屏告诉他。

**手法（全部只读，未运行 `_build/` 下任何脚本，未 commit）**：

| 步 | 做了什么 |
| --- | --- |
| A | Node 脚本逐行抽两份文件的**全部标题**（含 `##`/`###` 与代码块内的 `#` 排除）、slug 化后按序对齐 → §1 对照表 |
| B | Node 脚本抽每节的**篇幅字节数**与**全部数字 token**（带上下文），按节对撞 → §2 |
| C | 两份文件的全部 `](...)` 链接与锚点，逐条解析回本文件标题 slug；跨文件链接查存在性 → §1 附"锚点与链接" |
| D | ❌/⚠️ 条目集合逐条对齐（含"本文自称 N 条"与实际条数）→ §2 |
| E | 全库 **2,034 个 tracked 文件**（`git ls-tree -r -l HEAD`，177.5 MB）按语言密度分四桶，媒体/字体单列 → §4 给可消费比例的**文件数与字节占比** |
| F | EN 句级抽 10 句判翻译腔（`——` 残留、`【】` 残留、四字结构、成语直译、破折号密度）→ §3 |

**基线与判据**：

- 判"漂移"只认**可指到行号的差**：一份有一份无、同节数字不同值、同集条目不同集。措辞自然差异不算。
- 判"篇幅比 >2×"用节内字节数（不含标题行），因为翻译天然让 EN 字节数偏大——**阈值定在 EN/CN > 1.6 或 < 0.55** 才列为可疑，>2 列为破坏。
- **一致的错不算漂移但算诚实性问题**：两份文件同写一个过期数字，双语对齐了，读者照样被骗——本报告单列这类（见 §2 末"双语一致地错"）。
- 数字复算用 `git ls-files` / 直接读文件；不跑 `verify-prototype.mjs`（`_build/` 禁运，agent 在改案 css）。

**产出**：本文件 + `deliverables/55-scratch/`（脚本与原始输出）。

## §3 翻译腔与语言质量

### 3.1 语言卫生（区分管住：`## 中文` 摘要节**不算** EN 正文，实测见 `55-scratch/hygiene2.md`）

| 特征 | EN **正文**（L1–L420） | CN 全文 | 判定 |
| --- | --- | --- | --- |
| 全角标点 `，。：；（）、／` | **0** | 大量 | ✓ 干净 |
| 汉字 | **4**（L1 导航行"简体中文"，属双语惯例） | — | ✓ |
| 直角引号「」 | 0 | 16 | ✓ |
| 全角方头括号 `【】` | 2（L144 一处，且是 §1.3-1 的假标记） | 2 | ⚠️ |
| **`——`（中文双 em）** | **39** | 38 | **✗ 严重** |
| **`—`（英文正规 em）** | **11** | 3 | **✗ 密度反了** |

**这一条最能说明"双语是实质还是装饰"**：EN 正文的标点几乎全洗掉了，**唯独 `——` 一个没洗**。EN 正文破折号里 **39/50 = 78% 用的是中文双 em**，正规英文 em 只有 11 处；按密度算是 **8.0 次/千词**，而 CN 原文是 6.76 次/千字——**EN 比中文还爱用中文破折号**。184 个正文行里有 **35 行（19%）** 带 `——`。这不是漏检，是把"补刀句式"连标点一起搬过去了。

`——` 在英文排版里是**可识别的非母语指纹**（英文用 `—`，两侧不空格，或改逗号/冒号/括号）。任何英文母语编辑一眼就能看出这份文件是从中文过来的。
