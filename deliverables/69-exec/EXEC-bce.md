`index.html`：`<section class="tpl-strip" id="tpl-strip" hidden>` → `<details class="tpl-strip" id="tpl-strip" hidden open>`，加 `<summary class="tpl-strip-sum" id="tpl-strip-sum">`。`index.html` 的 `sync()` 把 `#tpl-strip` 加进 `folds` 数组（窄档收起 / 宽档展开）。

**第一版只折内容（= 审计的做法），实测差了 28px：**

**所以多做的 3 处：**

1. `style.css` 新增 `.tpl-strip:not([open])`：收起时 `padding:0; border:0; border-top:2px solid var(--rule-2); background:transparent; margin:10px 0 14px`。留 2px 而不留 0：本文件所有分节线都是 2px，且 lint 的 `hairline` 只匹配 0.5px 与 1px —— 写 1px 会同时破"合群"和"lint 全绿"两件事。
2. `prompt-copy.js` 新增 `drawStripSummary()`：summary 上的字必须报**真实张数**，`现成模板 N 张 · M0x（不计入方案数）`。这个数从 `hit.exact + hit.adjacent` 现算 —— 写死"1 张"会在「设计工作室」那种 exact+adjacent 双命中时少报一张，而 summary 恰恰是**收起态下用户唯一读得到的字**，它报错数就等于折叠在说谎。实测「设计工作室」：`现成模板 2 张 · M01 / M03`，DOM 里确实 2 张卡（`cardIds: ["M01","M03"]`）。

### 3.3 一个必须记下来的测量陷阱：收起 ≠ rect 消失

`<details>` 收起后：

```
.tpl-open 的 getBoundingClientRect().height  = 33px      ← 说谎
::details-content 的 content-visibility      = hidden    ← 真相
elementFromPoint(链接中心)                    = IMG       ← 真相
```

也就是说，**任何只看 `getBoundingClientRect` 的检查都会以为"收起后链接还在 33px 高、还能点"**。我在 `paint-truth.mjs` 里用 hit-test 复核了全部三种状态：

| 状态 | `content-visibility` | 链接中心点打中谁 | 结论 |
|---|---|---|---|
| 收起（390） | `hidden` | `IMG`（底下的卡片） | 链接真的没画出来 ✓ |
| 展开（390，点了 summary） | `visible` | `A`（就是那个链接） | 真的可点 ✓ |
| 展开（1440，默认） | `visible` | `A` | 真的可点 ✓ |

**顺带一个真实的坑**：`paint-truth.mjs` 第一版在"收起"状态下点了一下链接坐标，结果页面跳到了 `#S06` —— 因为那个坐标上躺着的是一张**卡片**，点卡片会开详情。这不是 bug，是"折叠区不该吞点击"的正确行为；但它提醒我：**收起态下那块区域属于下面那张卡，不属于模板带**。

### 3.4 B（方案 4）：`#empty-tpl` 句子里的模板名就地成链接
