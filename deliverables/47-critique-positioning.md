## §1 一句话定位测试

### 原句（我逼自己写的、不许躲的那句）

> **外人 clone 这个仓库，拿走的是 30 个各自不能独立运行的 HTML 原型，外加它们必需的 29.75 MiB 共享字体库、50.85 MiB 渲染截图、69.45 MiB 素材原件，外加 57 份从没被链接的内部审计文档，外加一套 13/18 个脚本硬编码了作者机 `D:/Web/style` 的门禁工具链。**

### 判定：**不通过。失败点有三处，不是修辞问题，是仓库结构问题**

> **附一条我自己必须交代的**：这句里的"13/18 个脚本硬编码 `D:/Web/style`"在 **04:47 之后只有一半成立**——那两个施工 agent 提交了 `fe4c2c2`，把 13 处硬编码清零了。**这不是我写错，是这个仓库在我写这句话的二十分钟里自己改了口径**（详见 E7）。原句一字不改地留着，因为它的失效过程正是本份审讯的结论。

1. **"外加"出现 3 次**（等价于用户设定的"两个以上以及"红线）。一句话里必须并列 3 个不相干的东西才能说清"拿走的是什么"，这就是定位失败。
2. **第一个名词短语自己就崩了**：README.md:16 的门面句是"30 个方案各配一个**能直接打开**的 HTML 原型"，但 `HEAD:prototypes/S14-zero-g-launch-sequence/index.html:9-11` 用 3 个 `<link rel="stylesheet" href="../_fonts/css/*.css">` 引外部字体，S01 3 条、S22 3 条、S28 3 条、S30 3 条 —— **案不是可交付的最小单元**，最小单元是"整个 `prototypes/` 目录"。README.md:239-240 自己承认（"每个 `prototypes/<方案目录>/` 是**自包含**的……要让它独立跑起来，需**一并带上 `prototypes/_fonts/`**"——**同一行里"自包含"和"需一并带上 29.75 MiB 邻居"并列出现**）。所以"拿走 30 个案"这句在物理上不成立。
3. **最重的那一项恰恰是没人能拿走的**：读者真正用得上的代码（30 案 html/css/js + 3 模板 + 选型台 html/js/css/data）实测 **80 个文件 / 2.047 MiB**，占全仓 **177.13 MiB（`0e28503`）/ 177.16 MiB（`fe4c2c2`）的 1.16%**。剩下 98.84% 里，截图+素材 **140.83 MiB（79.5%）**，内部文档+契约+工具链+规格 **108 文件 / 4.23 MiB（提交后 109 / 4.26）**，`_fonts` 29.75 MiB。

**一句话结论**：这个仓库卖的是 1.16% 的东西，占体积的是 79.5% 的东西，占叙事的是 109 个内部文件。定位失败不是"没说清"，是**三个互相抢读者的身份同时住在同一个目录树里**。

### E1 —「图集」的主体比它自己以为的小一号
README.md:16 说"30 个方案各配一个能直接打开的 HTML 原型"。实测 30 个案里 30 个 html 合计 **0.85 MiB**、30 个 css 合计 **0.68 MiB**。所谓"案"作为**可打开的东西**只有 1.53 MiB；剩下 175.6 MiB 是让它能打开、能好看、能被证明打开过的附属物。**谁为谁服务**：案名义上是主角，体积上是被服务方（截图、素材、字体都围着它转），但读者带不走"主角+配角"这个组合——他只能全带走。

### E2 — 案不是自包含单元，README.md:239-240 在同一行里自相矛盾
`HEAD:prototypes/S14-zero-g-launch-sequence/index.html:9,10,11` 三行 `<link rel="stylesheet" href="../_fonts/css/{oswald,noto-serif-sc,space-mono}__*.css">`。抽查 S01/S22/S28/S30 每案同样 3 条。案目录里 `@font-face` 计数 = **0**（字体声明全在共享层）。**后果**：README.md 阶段 4 标题写"只想取用某一个原型"，实际取用单位是"1 个案 + 29.75 MiB 的整个 `_fonts/`"——**最小可运行体积是 30 MiB 起，不是 32 KB**（S14 index.html = 32,652 B，live HTTP 200 实测同值）。**谁为谁服务**：`_fonts/` 服务的是造它的人的排版执念，代价由读者的磁盘承担。

### E3 — 41 个文件、17.08 MiB 是纯死库存，页面一次都没引用

## §3 主线判定：名字与实质的落差

仓库名 `web-style-atlas`、README.md:5 的 `# 网站设计风格图集`、README-EN.md 的 `# Web Style Atlas`——名字承诺的是**图集**：一本供人翻、供人取用的图样集。先把话说公道：**图集大，不冤**。截图 50.85 MiB（272 张 jpg）是选型台的画面本体（E5），素材 69.45 MiB 是案例排版的血肉，`_fonts` 29.75 MiB 是画面成立的前提。这三项加起来 150.05 MiB / 全仓 84.7%，它们是"集"的合法组成，我不拿体积告它。

**真正与名字对撞的是另外三处错位。**

**错位一：主角不是那 30 个案，是那 30 个案的质检过程。**
一个"图集"的正文是图，脚注最多一行出处。这个仓库的 README 有 **45/432 行（10.4%）** 逐行出现施工词（`_build`/`_CONTRACT`/闸门/判据/口径/豁免/复算/FAIL/`_specs`/Jekyll/box-shadow/mono…），其中 6 节 137 行（31.7%）在做向后自证（E11）。仓库里给"造"这件事配的常驻文件是 **109 个 / 4.26 MiB**（`0e28503`：108 / 4.23）：`deliverables/` 57 份 + `_specs/` 31 份 + `_build/` 20 个 + `_CONTRACT.md`。而"图"这一侧，读者能带走的代码只有 **80 文件 / 2.047 MiB = 1.16%**。**图集里正文与后记的字节比是 1 : 2。**

**错位二：门禁与契约不是给读者看的，但它们的发布方式说明作者也没把它们当内部件。**
356 行、31,520 B 的 `_CONTRACT.md` 里写着"新 22 个适用"（第 1 行）、"渲染命令（唯一，不许换）"（§3）、"违反即返工"（§6）、"完成判据（缺一不算完）"（§7）、"量错了对象：本项目最高发的 **Lead** 级错误"（§9.19）。**这是一份施工队的内部交底，用了工单语言，且直接躺在 `prototypes/` 根目录**——紧挨着读者要打开的 `_selection/`。**图集需要门禁吗？需要。** 但需要门禁的动机不是"图要干净"，是**"30 个案两两不重"这个卖点必须自证**（`03-uniqueness-matrix.md` 用五元组保证两两不同，`29` 号文又自证了 43.3% 共用同一张首屏模板）。**门禁服务的是这个仓库的差异化叙事**。所以它本质上是内部件——可它现在同时是 `prototypes/` 的根级公开文件（live HTTP 200 / 31,520 B），读者第一眼就会撞上。

**错位三：对外发布的举证，作者自己能复核、读者不能。**
README.md:359 立了誓："**这里没有一条断言是估的**"。我实测下来这句话**在数字上是成立的**（272 张、26 案 FAIL=0 / 8 条，逐案复算通过——E6，这点必须记好）。但它的举证链是断的：`deliverables/` 57 份里 **55 份在 README 正文里零引用**；已发布的 29 号文（41,954 B）自称"16 组成对图 + 4 张全批墙图"，而这些图在 live 上**双双 404**、在 git 里**跟踪数 0**（`_crit*/` 被 `.gitignore:52` 排除，磁盘上 `deliverables/_crit*` 目录**连一个都不存在**）。`.gitignore` 还留着 `internship-portal/`（:65,77,78）与 `new_api_internship_project_plan.md`（:73 注释写着"详见方案 §3 F-16"）——**上一轮 commit `99e2cad` 刚为"误入的 internship-portal 描述"道过歉，它的残留规则还在公网上**（live 200 / 3,016 B）。
