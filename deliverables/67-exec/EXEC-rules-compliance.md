### 1.1 现状核实（先核实，再动手）

## 2. 问题 2：`--s-h1` 是死变量

### 2.1 现状核实

**（a）`--s-h1` 是否真的零引用？—— 是。**

```
=== --s-h1 refs (prototypes/_selection) ===
style.css:42:  --s-h1: clamp(34px, 5.2vw, 74px);      ← 唯一定义
```
全目录 grep（`style.css` / `app.js` / `index.html` / `wizard.css` / `wizard.js` / `prompts.js` / `data.js` / `prompt-copy.js`）只有定义那一处，零处 `var(--s-h1)`。`prompts.js` 里的 `--fs-h1` 是**另一个东西**（给 30 个原型用的变量，不是选型台的），不构成引用。

**（b）`.mast h1` 是否真的用 `clamp(30px, 4vw, 56px)`？—— 是。**

```css
.mast h1 {
  font-family: var(--ui);
  font-size: clamp(30px, 4vw, 56px);   /* ← 改前 */
  ...
}
```

且 `@media (max-width: 1180px)` 那段里的注释明确写着「保持 clamp(34px, 5.2vw, 74px)，768px 档得 39.9px / 5.2vw」—— 注释描述的是一个**从未生效**的值。改动前实测 768 档 h1 = **30.72px / 4.00vw**，注释里写的 39.9px / 5.2vw 一次都没出现过。

这与上一轮的 `--s-15` 是同一类 bug 的两个方向：那次是变量没定义（浏览器按 16px 兜底），这次是变量定义了却没人读（字面值顶替它）。**共同点是注释与计算值从不对账。**

### 2.2 改法取舍

**就地改 L129 那一行，不追加新规则。** 规划 Agent 的这个要求是对的，我照做了，并复核了原因：

`.mast h1` 在 `style.css` 里被三条规则命中：
- L127 `.mast h1 { font-size: clamp(30px,4vw,56px) }`（基础，1958 行区间之前）
- L809/L836 `@media (max-width:1180px) .mast h1 { max-width: 20ch }`（只改 max-width，不动字号）
- L836 `@media (max-width:620px) .mast h1 { font-size: max(26px, 6.6vw) }`

如果在文件末尾追加 `.mast h1 { font-size: var(--s-h1) }`，它会排在 620 档那条之后且同特异度 → **390 档也会被改成 5.2vw**，破坏"390 档 h1 不变"的目标。就地改基础规则，620 档的 `max(26px,6.6vw)` 仍然靠"更靠后 + 同特异度"赢。

（顺带：这也解释了为什么 390 档 h1 是 26px 而不是 5.2vw —— 6.6vw × 390 = 25.74 < 26，`max()` 取 26。）

### 2.3 改后验证

`.mast h1` 现在是 `font-size: var(--s-h1);`，即 `clamp(34px, 5.2vw, 74px)`。**我复测了规划 Agent 那张表，结论方向一致，但有两行数字不同**：

### 3.2 改法取舍

**直接删掉 `⚠ ` 前缀，靠 `.cap-warn` 已有的颜色/边框表意。**

理由（不是"删了就行"，是"删了之后表意仍然完整"）：

1. **`.cap-warn` 已经有三重视觉信号**：底色 `#fdf6e3`（暖黄）、描边 `#b8860b`（赭黄）、文字色 `#7a5a00`（深赭）。`.cap-ok` 是"无底 + 灰字"。两者在同一行里并排出现，是**同一元素的两种视觉状态**，对比度足够区分。
2. **emoji 的字形不受控**：Windows / Android / iOS 三套字体画出来的 `⚠` 大小、颜色、基线都不同（`U+26A0` 在 Windows 上是彩色 emoji，在部分 Android 上是单色）。用一个字形不可控的符号做状态标记，本来就不如背景色稳。
3. **文案本身已经说清了**：「内容少于 16 条会留空位」是完整的一句话，不需要符号提示"这是警告"。`title` 属性还给了完整解释。
4. **仓库口径一致**：`taste-skill` 的 emoji 规则原文是 `Remove. Use words or real imagery.` —— 它给的修法就是"改用文字"，不是"换个字符"或"加 `taste-skill-ignore`"。

## 8. 我可能弄坏的地方

按"最可能 / 后果最重"排序。

### 8.1 1180 档首屏余量只剩 63px（最需要盯的一处）

`--s-h1` 生效后 1180 档 h1 从 47.2 涨到 61.4，`.mast` 在 ≤1180 是单列、h1 折 **2 行**，页头一次涨 **+30.0px**（不是规划 Agent 估的 +15.0）。该档首卡底 837.0 / 视口 900，**余量 63px**。

现在仍是 1 张完整卡，但这是全五档里最薄的余量。任何一次后续改动（换字体导致折行变 3 行、`.mast-claim` 多一行、facts 多一项）都可能把它打到 0 张。**建议下一轮把 1180×900 也纳入首屏卡数的回归检查**，不要只看 1440/768/390。

### 8.2 980×900 档仍是 0 张完整卡（改前就是 0，没变差，但也没修好）

980 档不是本轮目标档，改前 0 张、改后 0 张。但 h1 涨了会让它离达标更远一点（首卡 top 441.3 → 466.2，卡底 936.5 / 视口 900 ⇒ 差 36.5px）。如果哪天有人要"980 档也得有 1 张卡"，`--s-h1` 会让这件事比改前更难 —— 需要额外的 980 档规则。

### 8.3 `.cap` 13px 让详情面板与列表页整体变长

`.cap` 从 12px 到 13px，盒高 23.44 → 25.05（+1.61），30 个卡各一处：
- 390 档 `docH` 11481 → 11598（**+117**）
- 768 档 15003 → 15051（**+48**）
- 1440 档 8792 → 8792（**Δ0**，卡高由截图列撑起，absorb 掉了）

390 档首屏仍有 51px 余量，但**整页长了 117px**。如果后续某个任务以"390 档总屏数 ≤N"为指标，这 117px 会被算进去。我没有为它加窄档补偿（实测补偿只值 1px 的布局差，不值得多一条只在窄档生效的覆盖规则）—— 如果 lead 认为总高比"少一条特例规则"更重要，可以在 620 档加 `.cap{padding:1px 5px}`，实测 `docH` 11598 → 11483。

本轮期间另一个 Agent 在改同一个 `style.css`：缩略图 176 → 160、`.row` 内距 8 → 6、`.row-meta` gap `3px 10px` → `2px 8px`、`.mast` 再加收 2px。文件从 65,792 → 72,671 字节。

### 8.6 `prompt-copy.js` / `wizard.js` 里还有 3 处会渲染的 emoji（未修）

`prompt-copy.js:952` 的 `⚠`、`prompt-copy.js:774` 的 `✓`、`wizard.js:204` 的 `⚠` —— 打开详情面板或向导结果页时会渲染。inspect 的默认动线（停在列表页）走不到，所以 `emoji` FAIL 现在不报。**两个文件都在我的写作用域之外**，我原样留着并在此列出。

顺带：`✓`（U+2713）落在 probe 的 `\u{2700}-\u{27BF}` 区间内，是这四条 emoji 规则里最容易漏的一个 —— 它不是 emoji，是"对勾"，但检测区间包括它。修法不应是"换个勾的字符"，而是同样用已有样式表意（`.is-copied` 已经有反色底 `background:var(--ink); color:var(--card)` 表示"已复制"）。

### 8.7 我没有核实的事

- **没在 Firefox / Safari 跑过**。`--s-h1` 的 `clamp()` 与 `var()` 组合在两者都支持（`clamp` Safari 13.1+），理论上无差异；但 1180 档的折行数依赖字体度量，那两个引擎的 Noto Sans SC 度量可能与 Chrome 不同，余量 63px 未必够。所有数字都是 Chromium。
- **没测 dsf=2 的亚像素差异**。本轮全部 dsf=1。dsf=2 下 51.12px / 63px 的余量通常更稳（取整误差更小），但没有实测支撑这句话。
- **没验证 `--s-h1` 在两个上限处的行为**（1440 卡在 74px、390 卡在 26px）之外的中段档位，比如 1100 / 900 / 700。只测了 5 档。
