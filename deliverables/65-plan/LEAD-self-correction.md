## 错误 1：「去 AI 味审查点」= 26,096 字（真实 11,220 字）

**我的错误口径**：从「去 AI 味审查点」出现处起，用
```
/\n\s*(?:\d{1,2}\.\s*)?(?:\*\*)?(?:反\s*AI\s*味风险|适用场景|可落地要点|设计师签名)/
```
找结束位置。这个 lookahead 对 S11–S20 的标题写法（`**9. 反 AI 味风险与规避**`）匹配失败，
于是段落一直「吃」到文件后面的「设计师签名式怪癖」，把字段 9/10/11/12 全算了进去。
S13 因此多算约 1,400 字。

**正确口径**：结束于「反 AI 味风险」标题行
```
/\n[^\n]{0,40}反\s*AI\s*味\s*风险/
```

**正确数字**：总 **11,220 字**，区间 **297–828 字**，逐案：

```
S01=315 S02=362 S03=319 S04=299 S05=303 S06=315 S07=336 S08=311 S09=314 S10=297
S11=401 S12=314 S13=828 S14=363 S15=337 S16=340 S17=325 S18=386 S19=345 S20=370
S21=350 S22=390 S23=320 S24=436 S25=382 S26=416 S27=421 S28=422 S29=436 S30=467
```

**连带作废的说法**：
- ❌「S11–S20 各约 1800 字，S01–S10 各约 300 字，体量差异极不均匀」
  → 真实是 297–828 字的**均匀分布**，只有 S13 一个异类（828 字，因为嵌了「反套路改造三指标」评审清单）
- ❌「直接塞进 900px 面板会爆」
  → 300–800 字/案，比已在面板里的 `layout`（381 字/案）、`landing`（465 字/案）还小，压力小得多
- ⚠️ 「26,096 字蒸发」→ 真实是「11,220 字蒸发」。**结论方向不变（确实是孤儿字段），但严重度被我自己夸大了约 2.3 倍**

## 教训

这个仓库反复出现的模式是「解析了 ≠ 用上了」。我在侦察时犯了同一类错误的镜像：
**测了 ≠ 测对了**。切分口径没验证，就直接拿数字去派单，差点让 6 个 Agent 在错前提上工作。
