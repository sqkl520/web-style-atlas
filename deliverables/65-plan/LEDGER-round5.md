## 已知缺陷与边界（提交前必须记录）

### 1. `check-docs.mjs` 对「方案总数写错」失明（阻断级）

验证 Agent 实测：把「30 个方案」改成 31 / 29 / 40，**全部 0 FAIL**。

两处根因：
- `check-docs.mjs` 有 `if (/模板|template/i.test(line)) continue;` —— 招牌句「30 个方案…外加 3 个模板」同时提两者，**整行被跳过**
- `if (n <= 30)` 让 31/40 被当字节数放行；中文数字「三十」`[\d,]` 完全抓不到

**20 个腐化样本只抓出 5 个**（漏检：总数、degrades 13、并集 14、layout 字数、闸门合计 8 条、删 FAIL 条目、18/30 比例）。

### 2. 英文版 `check-docs` 常驻 1 FAIL（阻断级）

`nums/schemes` 把 `18 schemes use no shadow` / `4 schemes have a mechanism` / `13 schemes lay their units out` 当成「方案总数」。11 项误报，exit 1。

**「三个 check 全 exit 0」只对中文版成立。**

### 3. `audit` 折叠块位置仍在 `risk` 之后（P0，执行 F 未完成）

裁决 Agent 判定应在 `risk` **之前**（audit 是 risk 的前提）。数据层键序已改（14 < 15），UI 未跟上（第 10 位 vs 第 9 位）。

### 4. `AUDIT_CUT_AT` 已成死代码

数据层已修（S13 = 306 字），UI 层那份白名单 `indexOf` 返回 −1，永不生效。

### 5. 390px 档 scrollHeight 25/30 超 3800px

执行 B 实测最差 4668px。它判断：移动端字段本体占 81–84%，是**内容长度而非布局浪费**，继续压缩只能删内容。**建议改验收口径（按视口给不同阈值）。**

### 6. 键盘 Tab 到折叠条需按 114 次

`#detail` 在 DOM 末尾（既有结构，非本轮引入）。修它要动 `index.html` 的 DOM 顺序，超出本轮范围。

### 7. 390px 列表首屏 0 卡片

首个行卡 y=989，视口 844。1440 档正常（394px）。从未达标过，不在本轮任何 Agent 任务里。
