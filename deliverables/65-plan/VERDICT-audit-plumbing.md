## 2. 裁决 1：`audit` 不进 AI 提示词

### 2.1 决定

**`audit` 一个字节都不进 `prompts.js`。** 不是「截断进」，不是「抽取进」，不是「只取跳脱句」。

### 2.2 AI 读 audit 能改善什么、不能改善什么

`audit` 的契约是「**它故意反了哪条 AI 陈辞**」——**回溯性举证**，不是施工图。

| 能改善 | 不能改善 |
|---|---|
| 让 AI 知道「这一案的主视觉为什么不是渐变/卡片」的**理由** | 不知道**怎么做**——正面动作占 69.4%（7,127/10,539 字），但**只有 2/27 条「跳脱句」含数值**，零可执行参数 |
| 提供极少数提示词没有的物理量（实测净新增 **5 个**） | 不知道**边界**——77 处 `C-x.y` 指向 `deliverables/02-anti-ai-rules.md`，**AI 手上没有那份文件**。「反 C-2.11」= 「反一个你看不到的条款」 |
| 在 S13 一案提供可测量的验收阈值 | **不能改善任何可执行指令**——不含 CSS/尺寸/数量。真正的施工参数在 `dna`（palette/radius/shadow/lineWidths/h1Size/minPics）里，**已全在提示词中** |

**一句话**：`audit` 是给**人**做选型判断的证据，提示词是给**AI**的施工图。把证据塞进施工图，AI 只会把它读成又一段「不要做 X」。

### 2.3 重叠度实测（全部我亲自复算）

#### (a) 与 `risk`：**0/30 案、0/165 句**

用「句级最长公共子串 ≥12 字」判：`有重合句的案 0/30，重合句数 0/165（0.0%）`。
**这推翻了「audit 与 risk 是同一件事」的猜测。它们确实不重复**——但不重复只说明是两件事，不说明第二件值得说。

#### (b) 与「视觉硬约束」（第 1–5 条）：**48.2% 的条目同话题**

按 ①②③/（1）（2）/第一第二 切成 **110 条**：
```
涉及圆角/阴影/配色/字体任一: 53 条 (48.2%)
  圆角 24.5% ｜阴影 24.5% ｜配色 24.5% ｜字体 0.9%
```
逐案对照（S28，05:30 复测）：
```
提示词 3. 圆角：全站一律 0，卡片、按钮、图片、标签全部方角。
提示词 4. 阴影：只用 drop-shadow（硬边厚度，无模糊投影）。不许用柔和外投影制造'浮起卡片'。
audit  ：它故意反的是 C-2 第 11 条（24px 圆角加柔和投影的浮起卡片）→ 全站直角…
```
**AI 已从第 3、4 条知道「圆角 0、无阴影」。`audit` 再说一遍，唯一新增是「为什么」——AI 不需要理由，它需要参数。**

#### (c) 与「防退化 8 条」：**30/30 案至少撞 1 条**
```
圆角卡片+柔和投影 26/30 ｜ emoji/iconfont 17/30 ｜ 三条等宽feature 15/30
居中大标题+双CTA 14/30 ｜ 玻璃拟态 8/30 ｜ 紫蓝渐变 1/30 ｜ 暗底发光 2/30 ｜ 轮播/视差 0/30
合计 83/240 (34.6%)；与至少 1 条重合的案 30/30
```
「防退化 8 条」仅 **191 字**，覆盖了 `audit` 反复申辩的绝大部分对象。

#### (d) 与 `reuse`（硬前提）：内容不重复，**功能重叠**

`reuse` 21/30 案有值（1,227 字，均值 58），讲「这个版式撑不撑得住你的内容」；`audit` 讲「它反了什么」。**但功能上都在说「这个方案不是通用模板」——`audit` 是第三遍说同一件事**（plain → 机制句 → 跳脱句）。

### 2.4 为什么「截断进」和「抽取进」都不成立

实测 5 种切法（`_v4_extract.mjs`、`_v3_prompt.mjs`、`_v10_tiao.mjs`）：

| 方案 | 字数 min/p50/max | 合计 | 投影 max | 超 1920 | 致命缺陷 |
|---|---|---|---|---|---|
| 全文 | 276/327/780 | 10,539 | 2,593 | **30/30** | +24%，最长案 +35% |
| 按 `risk` 的 220 字口径 | — | — | 2,166 | 29/30 | **30/30 全被截**（最短 276 > 220），丢 3,939 字；220 必切在句子中间 |
| 截 120 字 | — | — | 2,066 | 21/30 | 对 327 字的中位数**丢掉 63%**，必然切断「跳脱之处」 |
| 去元叙述（R2） | 172/233/676 | 7,240 | — | 28/30 | 只省 31% 仍超；需一套正则剥「它故意反 C-x.y——」，是**第二份会漂移的副本** |
| **只取「跳脱之处」句** | 0/20/36（27/30 非空） | 581 | **1,927** | **6/30** | **唯一接近可用的，但不成立** |

**「只取跳脱句」为什么不成立：**

27 条跳脱句里，**13/27 是「不是 X」的否定式**（96 字 / 16.5%）：
```
S05 不是卡片浮起来的   S13 不是元素被抬起   S27 不是浮起来的   S28 不是浮起来的卡片
S30 不是浮起来的       S08 不是算出来的模糊  S29 不是卡片集     S22 不是"模糊"
```
**这些否定对象（浮起/模糊/卡片）全部已在「防退化 8 条」第 ②⑥ 条禁死。且只有 2/27 含数值——零可执行参数。**

再与**提示词已有的机制句**做 2-gram Jaccard：
```
Jaccard: min 0.000  p50 0.014  max 0.151  mean 0.022
J>=0.25 的案: 0/27 ｜ 对照（完全无关的两句中文）J=0.019
```
**这个数字说明「用词不重合」——但语义高度平行。** 人工对照（`_v21_pairs.mjs`）：

| 案 | 提示词已有机制句 | 跳脱之处 |
|---|---|---|
| S01 | 一块实色多边形以 11° 切入 4 栏版心…阅读顺序由角度与越界量决定 | 阅读起点由红色楔形切出来 |
| S16 | 所有词块左端对齐同一条 12° 斜线…斜线给顺序 | 版面主轴是斜的 |
| S26 | 12 栏栏线整体倾 11°…次序由斜角与压叠量给出 | 分区靠版压版，不靠浮起 |
| S30 | 版面沿 −32° 对切成两半，斜切带高 96px… | 贴纸是刮上去的，不是浮起来的 |

**每一行都是「同一设计事实的两种说法」：机制句给参数，跳脱句给观感。Jaccard 低是因为一个用数字一个用比喻——这正是「重复」最容易被误判成「互补」的形态。**

### 2.5 「净新增设计参数 = 0」怎么来的（本裁决最硬的一条）

抽出全部带单位的设计参数（px/°/%/mm/ms/em/栏/级），去重 **97 个**，其中 **53 个（54.6%）提示词里找不到**。看似可观——但逐条打上下文窗口（`_v25_cliche.mjs`）：

```
缺失参数出现次数：陈辞语境 49 ｜设计值语境 5
```

**49/54 的「缺失参数」根本不是参数**：
```
S01 缺 1.3 2.14 2.11 2.15 000000   ← C-1.3 / C-2.14 编号里的数字
S08 缺 2.17 2.11 16 32px 2mm 45°   ← C-2.17 的 "17"、"24px 圆角"里的 24/32px
```

**剩 5 个真参数，4 个在 S13 污染块里**：
```
S13 [2级] [12°] [1.5px] [18%] [6%]   ← 全部落在「反套路改造三指标」验收表内
```
（`12°`/`1.5px`/`18%`/`6%` 已用 index > 307 核实；`2级` 因 `dec()` 压空格未能定位，但与其余 4 个同属「±2 级、偏 12°…≤18%…≤6%」那一句。）

**结论：剥掉 S13 污染后，`audit` 对提示词的净新增可执行设计参数 = 0。**
这条把「要不要加 audit」从「取舍」变成「**没有东西可加**」。

### 2.6 我放弃了什么

- **放弃了「让 AI 理解为什么」**。若将来做多轮对话生成，`audit` 会重新有价值。当前单轮复制形态下，理由对 AI 是纯 token 成本。
- **放弃了 S13 那 473 字里的 11 个真实阈值**（135°、0.4mm、120ms、0.8px、14%、3% 等）——全库唯一的可测量验收标准。**但它们是验收判据，不是生成指令**（「按下时光源方位角反转量 ≥ 90°」是验收，不是施工）。正确归属是 `landing` 或独立的 `acceptance` 字段。
- **放弃了「加 40 字跳脱句提升质感」这个诱人小改动**。投影 max 1,927（6/30 超线），便宜；但它是同一件事的**第三次表述**，13/27 否定式，2/27 含数值。

### 3.2 差异 1：位置必须在 `risk` 之前（为什么我坚持这条）

现状 audit 在 idx 9、risk 在 idx 8。**后果是**：risk 在现状 617–668px 首字段 + 前面 7 个字段之后，位置约 **1,900px**；audit 在它后面约 **2,150px**。用户要滚 2.4 屏才看到。

**但更重要的是语义**：`audit`（凭什么说它反了 AI）是 `risk`（所以最容易做错成什么样）的**前提**。先举证、后警告是论证；反过来是「先警告再解释」。

**改动**：把 `app.js` 里 audit 那一行从 `field('反 AI 味风险与规避', r.risk)` 之后挪到之前。零成本（高度不变，只是顺序）。

**我放弃了什么**：放弃了「相邻便于对照」这个直觉（相邻仍然成立，只是前后反过来）。代价：读者先看 292 字举证，再看 192 字禁令，**认知顺序变成「论据→结论」，比「结论→论据」慢半拍**。但这一案的结论（「最容易做成什么样」）如果不带论据，读者无从判断它是不是套话——所以论据优先是对的。

### 3.3 差异 2：S13 的切断应该在数据层，不是 UI 层

**现状**：`app.js` 里有一张硬编码表
```js
var AUDIT_CUT_AT = { S13: '反套路改造三指标' };
```
**问题（三条，都是结构性的）：**

1. **`data.js` 里的 `audit` 仍然是 780 字、仍含污染**（我已核实 `s13.audit.includes('反套路改造三指标') === true`）。**任何读 `data.js` 的下游（未来的导出、API、第二个 UI）都会拿到污染。** UI 层的修补只保护了这一个消费者。
2. **它是一张「按案号硬编码」的表**。下次若 S17 也混进小节，这张表不会知道。数据层的切断是**按标记**（`indexOf('反套路改造三指标')`），对 30 案普遍成立——全库只有 1 例，所以两者当前等价；但**「按标记」会在新增污染时自动生效，「按案号」不会**。
3. **它把「数据对不对」的判断放进了「怎么显示」的文件里。** 这正是本仓库反复出现的病根（`FIELDS` 是手抄清单、`--check` 只查 7 个字段、`copy` 是中间量却没人标注）。

**改动**：把切断移到 `collect-schemes.mjs` 的 `audit:` 赋值处。
```js
audit: (() => {
  const v = spec && spec.fields['去 AI 味审查点'] ? dec(spec.fields['去 AI 味审查点']) : '';
  // S13 的无编号加粗小节「反套路改造三指标」被并进了字段 8。
  // 全库仅此 1 例（_v8_s13cut.mjs 扫 33 键 × 30 案 = 1 次命中）。
  // 只切 audit，不碰 layout —— S14/S15/S16/S17/S20 的「断点具体行为」子块
  // 仍并进 layout，那是既有行为，改它会撞「27 案字节不变」的红线。
  const i = v.indexOf('反套路改造三指标');
  return i > 0 ? v.slice(0, i).trim() : v;
})(),
```
**验收：**
- `data.js` 的 `audit`：30/30，合计 **10,065 字**（10,539 − 474）
- `data.js` 的 S13.audit = **306 字**，不含 `反套路改造三指标` / `V-11` / `R-40` / `打勾`
- 其余 29 案**逐字节不变**（sha256，方法同 `_bytes-proof3.mjs`）
- `data.js` 的 `layout` 合计**仍 13,046 字**（一个字都不许变）
- UI 侧删除 `AUDIT_CUT_AT` 表（切断已在数据层完成）

**我放弃了什么**：放弃了「UI 层切断更安全」这个直觉——它的好处是不动数据、不重跑生成器。但代价是「数据层永久带污染」，而这个污染会随 `data.js` 扩散到每一个未来消费者。**数据层的债必须在数据层还。**

### 3.4 我放弃了什么（裁决 2 整体）

## 4. 裁决 3：`family` 的 34 字截断 —— 真凶不是 34（已按此修好）

### 4.2 34 是替罪羊（对审计 Agent 与 Lead 的直接纠正）

审计 Agent §6.7 说 `slice(0,34)` 切掉 **4,891 字、30/30 全中**；Lead 复核改口 **5,254 字**，「口径差在是否含句号前家族名」。

**两个数字都不对，因为它们把两把刀算成了一把。** `app.js:235` 那一行有**三个**操作：

```js
esc((r.family || '').split('。')[0].split('：').pop().slice(0, 34))
```

我逐刀归因（`_v1_family.mjs`，基于当前 data.js）：
```
family 全长合计      : 5911
split('。')[0] 后    : 665    ← 这一刀丢 5,246 字，命中 30/30
split('：').pop() 后  : 665    ← 这一刀 0 损失（30 案第一句都不含全角冒号）
slice(0, 34) 后      : 657    ← 这一刀只丢 8 字，命中 1/30（S13，第一句 42 字被切到 34）
```

**结论：**
- `slice(0,34)` 只丢 **8 字**、只影响 **1 案**
- 真凶是 `.split('。')[0]`，丢 **5,246 字**、影响 **30/30**
- 审计的 4,891 与 Lead 的 5,254 都是**两刀之和再减一点**的混合口径

**为什么这个区别重要**：`slice(0,34)` 是**长度**问题（放宽到 N 字即可）；`split('。')` 是**语义**问题（别丢句子）。**按「34 改 80」去修，会花掉 80 字位置却仍丢掉整个「参考对象」清单和「偷的机制」句——修了 8 字的洞，留下 5,246 字的洞。** 已落地的实现正确地选了大刀。

- 220 口径确实截掉 30/30、丢 3,939 字
- **但真正的理由是「220 这个数字对 audit 没有意义」**——它中位数 327 字，220 大约切在**第 2 条论据的中间**
- **正确的截断粒度是「条目」不是「字数」**：它的结构是「①②③」的完整论据单元。要截就整条丢（我实测的 R2 去元叙述 = 保留整条），要么不截。**「截 N 字」这个工具本身选错了。**

### 7.6 补充：一个所有人都没说的事 —— `audit` 的元叙述占 14.5%

```
「它故意反 C-x.y 与 C-z.w」这类元叙述前缀合计约 1,533 字（占 10,539 的 14.5%）
「反 X」前缀 3,142 字 ｜「而是/跳脱」正面动作 7,127 字（正面占 69.4%）
```
**对裁决 2 有用**：折叠态 summary 可直接从这 14.5% 抽，不必新写文案。（当前实现用的是「（4 条）」，更简洁，我认可。）

### 7.7 警告：判决 3 的实现在 mobile 上付了 5.9%，这个代价没有被测过

已落地的 `.row-family { flex: 1 1 100%; line-clamp: 2 }` 在桌面**零成本**（75px 余量吃掉），但 **mobile 30 卡总高 +914px（+5.9%）**，28/30 案行高上升，单案最大 +48px。**如果这个改动没有在 390px 档回归过，那是一个未验证的退化。**

## 8. 不该做什么

| # | 不要做 | 理由（我实测的） |
|---|---|---|
| 1 | **不要把 `audit` 全文或任何截断版塞进提示词** | 净新增可执行设计参数 = 0（剥 S13 污染后）；全文让 30/30 案破 1,920 上限，最长案 +35% |
| 2 | **不要用「截 N 字」处理 `audit`** | 它是「①②③」的完整论据单元，任何字数截断都切在句子中间。220 字会切在第 2 条论据中间并丢 3,939 字 |
| 3 | **不要为了修 `family` 调大 `slice(0, 34)` 的数字** | 34 只丢 8 字/1 案。真凶是 `.split('。')[0]`，丢 5,246 字/30 案。改数字 = 修错地方 |
| 4 | **不要在 `collect-schemes.mjs` 里「认无编号加粗小节」** | 会连带改 S14/S15/S16/S17/S20 五案 `layout`（−2,426 字），撞碎 EXEC 的「27 案字节不变」验收线 |
| 5 | **不要把 `scenesNo` 加进搜索 hay 却不加行卡反标** | `app.js:133-145` 记录过：会制造与事实相反的结论。这个位置已被改错过一次 |
| 6 | **不要给 `primary`/`buttonText`/`scenesNo` 新建详情字段** | `primary` 独立展示 = 同一 HEX 相邻两次；`buttonText` 要付 25.9px 且必然折行；`scenesNo` = 同一段话出现两次 |
| 7 | **不要满足于「S13 已在 UI 层切干净」** | `data.js` 里它仍是 780 字含污染。任何未来的导出/API/第二个消费者都会拿到污染。**UI 层修补只保护了一个消费者** |
| 8 | **不要再往面板前面加东西** | 首屏刚修到 2 个字段。`.prompt-fill` 那两个输入框已经推深了 153px。**面板上半部分现在是满的** |
| 9 | **不要删 `FIELDS` 里的 `机制` 却不留说明** | 它确实是永远匹配不上的死名字（读 0 次、md 里 0 次作为标题）。但删掉就抹掉了「机制句走 `extract-dna.mjs` + `mechanisms.mjs` 另一条路」这个唯一路标。**改成 `机制（走 mechanisms.mjs，勿在此赋值）`** |
| 10 | **不要动 `risk` 的 220 字截断去「对齐」`audit`** | `risk` 8/30 被截、丢 315 字；`audit` 30/30 被截、丢 3,939 字。**两者体量不同档，共用阈值本身就错**。且 risk 的 220 工作正常 |
| 11 | **不要给 S13 的 473 字验收表找个字段直接塞** | 它是**验收判据**（「按下时光源方位角反转量 ≥ 90°」），不是施工参数（「压印深度 0.4mm」）。属于 landing 重写素材或独立的 `acceptance` 字段。塞进任何现有字段都是污染转移 |
| 12 | **不要相信「零消费 = 该删」的推论** | 三个字段都零消费，但都不该删。**零消费是 UI 的问题，不是数据的罪。** 它们是「一次切分动作的三个产物」，删任一个都让另两个失去可重建性 |
| 13 | **不要让输入框保持默认展开** | `.prompt-fill` 高 191.1px，把字段区推下 153px。**「不填也能复制」的东西不该默认占位。** |
