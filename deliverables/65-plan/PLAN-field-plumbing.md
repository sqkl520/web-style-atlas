## 0. 一句话结论

三个目标里，**B（死字段）最该做的不是「加字段」而是「改结构」**：

1. `去 AI 味审查点`（键名 `audit`）确实是孤儿，但真实体量是 **10,539 字**（不是 26,096，也不是 11,220），
   每案 276–780 字，**比已经在面板里的 `layout`（435 字/案）和 `landing`（465 字/案）还小**。
   「塞进去会爆」这个前提不成立；真正的问题不是它太长，而是**它在外面的每一秒都是零**。
2. `机制` 是**真孤儿但走对了路**——它不该接通，接通会造出第二份 20/30 残缺数据。
3. `primary` / `buttonText` / `scenesNo` 三个死字段里，**只有 `scenesNo` 值得单独接**，
   另外两个是「数据冗余」而非「信息丢失」，接成独立字段等于给用户看两遍同一个色。
4. 面板可发现性的瓶颈**不在字段数量，而在字段之前那 1,014px**：
   用户打开详情，第一个字段出现在 786–1,198px（**0.87–1.33 屏**），
   也就是说**第一屏一个字段都没有**。这一条比「加不加 audit」重要一个量级。

### 1.4 事实 4：`layout` 3 案为空 —— **现象成立，根因已定位，且已被并发修掉**

**现象**（我 04:00 实测）：`layout` 27/30，缺 S12、S15、S19。

**根因**（我独立定位，与并发 Agent 的结论一致）：`collect-schemes.mjs` 的 A 惯例正则
`^(\d{1,2})(-附)?[.．]?\s*NAME：` 里，**分隔符 `.` 是可选的**。于是 S12 字段 5 正文的
**第一句**被当成了字段标题：

```
S12.md:26   8 栏，基线 6px（对齐街机像素栅格），栏间距 0。不对称方式：七个洞口按 3 / 2 / 1 / 1 …
            ^^^^^ 被读成「字段 8，名字 = '栏，基线 6px（…），栏间距 0。不对称方式'」
```

它紧贴在 `**5. 布局与网格**`（S12.md:25）之后，于是字段 5 的段落被切到长度 0，
正文反而挂到一个**谁也不读的幽灵键**上。

**我扫了全库 30 案确认这不是孤例而是恰好 3 例**（复算脚本见 §1.9 `_phantom.cjs`）：

```
S12  extra=["栏，基线 6px，栏间距 0。不对称方式"]  missing=["机制","布局与网格"]
S15  extra=["栏，基线 8px，栏间距 20px。不对称方式"]  missing=["机制","布局与网格"]
S19  extra=["栏，基线 8px，抽屉面板高 24px。不对称方式"] missing=["机制","布局与网格"]
其余 27 案 extra=[] 
```

判据：**正文第一句以数字开头**才会被 `^\d{1,2}` 咬住。S15/S19 是「12 栏」（两位数）、S12 是「8 栏」（一位数），
所以「把 `\d{1,2}` 收成 `\d`」治不了，只能收掉「分隔符可选」这个口子。并发 Agent 的修法
（`(-附|[.．])` 改必需）我复核后认为**方向正确**：`-附` 那一路的 key 剥括号后是空串，
加白名单反而会把 10 案的 `1-附` 起点挡掉、让机制句被字段 1 吞回去（那是 L143 记录过的老 bug）。

**当前状态**：`layout` 已 30/30、13,046 字，三案长度 549 / 640 / 420。**已修，无需再动。**

## 3. 每个死字段的判决

### 3.1 `audit`（去 AI 味审查点，10,539 字）→ **接通，但只以「折叠块 + 一句话摘要」形态**

**理由（三条，都是实测的）**：

1. **它是这仓库唯一「作者自证反 AI」的文本**：30/30 含 `C-x.y` 条款编号，86 处引用；
   与 `risk` 的 4-gram 重合率 0–4%，**不是重复**。
2. **它不大**：276–780 字/案，比已在面板的 `layout`（435）、`landing`（465）都小。
   「会爆」是伪问题——**真问题是它现在等于 0**。
3. **但它不能平铺**。我实测了三种形态（S01/S13/S24/S30，900px 视口）：

| 形态 | 面板增量 | 需滚 |
|---|---|---|
| A 全文平铺 | **+257 ~ +594px**（S13 最贵） | 3.0–3.9 屏 |
| B `<details>` 收起（summary 一行） | **+51px（30 案恒定）** | 2.8–3.3 屏 |
| C 摘要 120 字 + 收起 | +51px | 同 B |

**推荐形态 B+**：`<details>` 收起，summary 里放**「跳脱之处」那 11–38 字**（27/30 有），
展开后是全文。用户看到的（折叠态）：

```
▸ 去 AI 味审查点   它故意反了 3 条 AI 陈词 · 跳脱之处：阅读起点由红色楔形切出来，用户第一眼看的是被压住的那 3 行   [292 字]
```

**用户看到什么（展开态）**：完整 292 字，含 `①它故意反 C-1.3 与 C-2.14——主体不是居中大标题加三张等宽卡…`。

**放哪里**：紧接 `反 AI 味风险与规避`（`app.js:453`）**之后**。理由：两者是同一件事的两面
（risk 前瞻 / audit 回溯），相邻便于对照；且它落在字段区下半部分，不会把 `layout`/`landing`
这两个高价值字段进一步推深。

**不进提示词**（见 §5.2）。

### 3.2 `机制` → **不接通。它是真孤儿，但走的是正确的另一条路**

**复算证据**：

| 检查 | 结果 |
|---|---|
| `key` 恰好 `=== "机制"` 的出现次数（30 份 md） | **0** |
| `1-附（去掉名字之后的机制）` 出现 | **10 次**（S01–S10） |
| `3-附（反套路改造三指标）` 出现 | **2 次**（S03、S08） |
| `-附` 剥括号后 key 为空串的 | **12 处**（= 10 + 2，与并发 Agent 记录一致） |
| `extract-dna.mjs:101` 的抓取正则 | `/1-附（去掉名字之后的机制）[：:]\s*([^\n]+)/` → **绕开 collect 直接抓 md** |
| `dna-clean.json` 有 `mechanism` 的 | **10/30** |
| `mechanisms.mjs` 补的 | **20/30**（S11–S30） |
| 两者是否互补无空洞 | 是（10 + 20 = 30，无交集） |
| `prompts.js` 最终有机制句的 | **30/30** |

**判决理由**：机制句的**唯一消费者是提示词**，而它已经 30/30 到位。
如果在 `collect-schemes.mjs` 里也读一遍 `fields['机制']`，会得到一份 **10/30 的残缺副本**
（S11–S30 全空，因为它们的 md 里根本没有 `1-附` 这一行）。下一个读 `data.js` 的人会以为
S11–S30 没有机制句，然后去 md 里「补」，而 `mechanisms.mjs` 已经补过 —— **这正是本仓库
记录在案的「两份副本静默分叉」**（`build-prompts.mjs:225-237` 删 `TEMPLATE` 的理由）。

**该做的事**：把 `机制` 从 `FIELDS` 里**删掉**（或改名为 `机制（走 mechanisms.mjs，勿在此赋值）`），
让清单与实现一致。**这是 A0 任务的一部分，不新增任何数据。**

**接通后用户看到什么**：**什么都不会变**——因为 `prompts.js` 的机制句早就在提示词第 8 行
（`这个风格的签名动作：…`）里，用户复制提示词时已经带走了。

### 3.3 `primary`（主色，30/30 · 210 字）→ **不接通为独立字段；并进「当前有效配色」那一行**

**决定性实测**：

| 检查 | 结果 |
|---|---|
| `primary === palette[1]` | **30/30** |
| `primary === palette[0]` | 0/30（`palette[0]` 恒为 `bg`，30/30） |
| `primary ∈ palette` | 30/30 |
| `palette` 长度分布 | 3 色 × 5 案、4 色 × 25 案 |

**判决理由**：`palette[1]` 就是 `primary`。它已经在 `app.js:440` 的
`field('当前有效配色', palette.join('　') + '（底色 …）')` 里**逐个打印出来了**，
只是没有标「哪个是主色」。**接成独立字段 = 让用户在两个相邻的位置看到同一个 HEX 两次。**

**该做的事**（零新增像素）：把那一行从

```
当前有效配色   #EFE7D7　#C8322B　#1A1A1A　#F2E9D8　（底色 #EFE7D7）
```

改成

```
当前有效配色   #EFE7D7　#C8322B（主色）　#1A1A1A　#F2E9D8　（底色 #EFE7D7）
```

**用户看到什么**：配色行里主色多了个「（主色）」标签。**高度不变（76px，不变）**。

### 3.4 `buttonText`（按钮字色，17/30 · 119 字）→ **部分接通：并进配色行，并先在数据层补到 30/30**

**决定性实测**：

| 检查 | 结果 |
|---|---|
| `buttonText` 在 `palette` 里 | **0/17**（全部是 palette 之外的新色） |

（`主色作按钮底时用白字 = 6.51:1`）。对一个要照着做站的人来说，这决定了按钮会不会不可读。
**但它是 0.5 行文字，不该占一整段。**

**这是本轮最需要判断的一个，也是我唯一建议「改行为」而不是「改展示」的。**

**现状实测**：

| 检查 | 结果 |

② **零风险改动**：维持 `scenesNo` 不进 hay，改为**新增一组「不适合什么」的筛选芯片**

**用户看到什么**（方案 ①）：搜「政务」→ 7 行，每行带 `⚠ 写着「不适合」` 黄标，点开详情
能在「适用场景」段末读到原文「…不适合政务类项目」。

**⚠️ 不确定**：方案 ① 会改变搜索结果集，属于行为变更，**必须配 CDP 回归**（跑全 44 个索引词 × 30 行）。
我建议 A4 任务设**独立的验收门**，不达标就回滚到方案 ②。

## 5. 风险与回滚

### 5.1 会破坏闸门的改动：**没有——但有前提**

**实测**：`verify-prototype.mjs` 只读三个路径（L37 `readFileSync(html)`、L38 `readFileSync(css)`、
L111 `readFileSync(report.json)`），**全文 0 次引用 `_selection` / `_build` / `_prompts` / `SCHEMES` / `data.js` / `prompts.js`**。

所以 A1–A5 全部只动 `_selection/` 与 `_build/` 的产物，**闸门结果不可能变**。
A6 的第 3 条验收（26/4/30 不变）应当**必然通过**；**若不通过，说明有人动了 `prototypes/Sxx/` 下的文件——
那是越界，立即停止并上报。**

### 5.2 提示词变长会不会反而降质：**会，所以我不建议加 audit 全文**

实测（`buildStylePrompt()` 在 vm 里跑真数据）：

| 方案 | 提示词长度 min–max | avg |
|---|---|---|
| **现状** | **1,617–1,905** | **1,778** |
| +`audit` 全文 | 1,930–2,573 | 2,149（**+21%**，最长案 +35%） |
| +`audit` 截 120 字 | 1,757–2,045 | 1,918 |
| +`audit` 截 200 字 | 1,837–2,125 | 1,998 |

**三条判据支持「不加」**：

1. **`risk` 已经在做同一件事，且已经有 220 字上限**（`prompt-copy.js:295`）。
   再加一个 220 字的「禁令块」，提示词里会有**两段语义相邻的长禁令**，互相稀释注意力。
   这是本仓库已经踩过的坑：`prompt-copy.js:241-252` 记录过「不要拉高」+「先凑够」两句方向相反的
   指令让 AI 二选一的实测事故。**同类风险不该再引入一次。**
2. **`audit` 的内容对 AI 是噪声**：86 处 `C-2.11` / `C-1.6` 这类编号，指向的是
   `deliverables/02-anti-ai-rules.md` 那份文件——**AI 手上没有它**。
   对 AI 说「反 C-2.11」不如说「不要 24px 圆角配柔和投影」（后者 `risk` 已经说了）。
3. **`audit` 的价值对象是人**：它是「选型时判断这案的反 AI 是真是假」的证据，
   属于**选型证据**，不属于**施工图**。提示词是施工图。

**若 Lead 仍要加**：只加「跳脱之处」那一句（11–38 字，27/30 有），
它才是「什么让这案不普通」的可执行描述，且**不含 C- 编号**。代价 +40 字，长度落到 1,657–1,945。

### 5.3 其他风险与回滚点

| 风险 | 触发信号 | 回滚动作 |
