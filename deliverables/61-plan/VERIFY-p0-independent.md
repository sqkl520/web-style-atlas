### A-1（最离谱）同一个提示词里，两套互斥的线宽指令 —— 22/30 案

硬约束第 5 条说"线宽只用这几级"，机制句却给出另一套线宽数值。**同一个 AI 同时读到这两句，只能二选一，必错一个。**

以 S19 为例（这是本轮声称要修的那一案）：

```
5. 线宽只用这几级：1px、3px，不要自创第三级。
这个风格的签名动作：20 块面板分 5 行，……线宽只 0.4 与 0.8px——层级由下移量与线宽差给出。
```

第 5 条允许 {1, 3}，机制句要求 {0.4, 0.8}，**交集为空**。而机制句那句还带着"层级由线宽差给出"——也就是说，照第 5 条做，这个案子的风格签名直接失效；照机制句做，就违反了"不得自创第三级"。

全 30 案里机制句提到线宽、且与第 5 条不交的：**S07、S09、S12、S17、S18、S19、S20、S29、S30 共 9 案**（`routeA-a1.mjs` 输出）。范围更宽的"机制句任何 px 值越出第 5 条"是 22/30。

**根因（这条执行者完全没查）**：`clean-dna.mjs:331 lineWidthVerdict()` 只抽 `border*` 和 `outline`，**从不抽 SVG 的 `stroke-width`**。

```
const re = /(?:border(?:-(?:top|right|bottom|left))?(?:-width)?|outline(?:-width)?)\s*:\s*([^;}]+)/g;
```

实测：**24/30 案的 `style.css` / `index.html` 里有 `stroke-width`，其中 21 案的 `stroke-width` 值落在第 5 条声明的档位之外**（`linewidths-gap.json`）。S19 的 `stroke-width: 0.4` 与 `0.8` 就明明白白写在 `style.css:297-298`：

```css
.e4 { fill: none; stroke: #7C7460; stroke-width: 0.4; vector-effect: non-scaling-stroke; }
.e8 { fill: none; stroke: #7C7460; stroke-width: 0.8; vector-effect: non-scaling-stroke; }
```

也就是说：**第 5 条这个"硬约束"本身是抽取不全的产物，却被写成"不得自创第三级"的强制条款。**

## ⑤ 我找到的、执行者漏掉的问题

按严重度排序。全部可复算，脚本在 `deliverables/99-scratch/iv/`。

### 漏项 1（最重要）`lineWidths` 从抽 SVG 的 `stroke-width`，导致"线宽硬约束"本身是错的

`clean-dna.mjs:331` 的 `lineWidthVerdict()` 正则只覆盖 `border*` / `outline*`。实测 **24/30 案有 `stroke-width`，21/30 案的 `stroke-width` 落在第 5 条"线宽只用这几级"的档位之外**。于是同一条提示词里，第 5 条与机制句给出**交集为空的两套线宽**（S19 是 {1,3} vs {0.4,0.8}）。

这是"P0-1 圆角/线宽可执行"这一项修复留下的**未覆盖面**：修复只保证了"不出现「未声明」"这个字面目标，没有保证"这条约束是真的"。执行者的 `verify-p0.mjs:90` 只检查 `wl.indexOf("未声明") >= 0`——**只要不是"未声明"就算过**，所以这个 bug 对它的闸门完全隐形。

### 漏项 2 `minPics` 补丁与输出要求自相矛盾（30/30 全中）

第 4 条"要放 6 张**真实**图片……不许用 1px 占位或纯色块顶替" vs 输出要求"图片用 `images/` 下的**占位路径**"。同一份提示词，30/30 案都有这两句。这个补丁是 04:26 加的（我开工后 14 分钟），加进去的时候没有回看输出要求那一段。

### 漏项 3 提示词禁止占位符，而它要求照抄的条目里含占位单元

S19 说"20 个条目、不留占位符"，DOM 里 20 个抽屉有 2 个是 `dw--void`（原作写着"这个抽屉是空的……位置照留"）。S02（1 空梯位）、S04（1 空贴位）、S06（3 空白卡）同型。**"数对了数量"掩盖了"数的是含占位的数量"。**

### 漏项 4 S18 的数量口径错位（20 vs 60）

提示词说"我实际有 20 个条目"，DOM 是 `3 × 20 = 60` 行 `span.ln`。机制句"每 20 行压一条折痕"在 60 行上会得到 3 条折痕。`minItems` 在这里数的是"每段行数"，被当成"条目总数"塞进句式。

### 漏项 5 `_prompts/` 未入库，声称 8 只兑现了一半

`git ls-files prototypes/_prompts` = **0 行**，`git status` 显示 `?? prototypes/_prompts/`（未跟踪，且 `.gitignore` 未忽略它）。路径确实不再硬编码、脚本确实能从零复算——**但"入库"没做到**。这正是 `.gitignore` 的历史教训（该仓库记录过一次 2833 文件误提交事故、以及 `tools/` 因未入库被清理进程蒸发且无法恢复）。现在 `_prompts/` 是**唯一能复算 `prompts.js` 的东西，却不在版本控制里**。

### 漏项 6（流程）执行者在验证进行中改动产物

`prompt-copy.js` / `prompts.js` 的 mtime 是 04:26，我在 04:12 已 dump 过一轮。**一个"独立验证"如果在被测对象持续变动时进行，任何结论都可能指向一个已经不存在的版本。** 我已重跑全部检查，但这条要记下来：提交前应该冻结产物。

> 另有一处**不是**他们的问题但值得记：`prompt-copy.js` 在缺 `window.SCHEMES` 时会静默省略整句调性（`prompt-copy.js:121-123`）。代码注释说这是刻意为之（"宁可不说"），我认同这个取舍，但它意味着**声称 5 的 30/30 有一个隐藏前提**：`data.js` 必须先于 `prompt-copy.js` 加载。当前 `index.html` 顺序是 `data.js → prompts.js → prompt-copy.js → app.js`，成立。

## ⑥ 如果只能改一件事

**改 `lineWidthVerdict()`，让它把 SVG 的 `stroke-width` 一起抽进 `lineWidths`。**

理由：

1. 它是唯一一个**同时污染 21/30 案**、且**会让 AI 做出错误页面**的数据缺陷。第 5 条写着"不要自创第三级"，而它给出的档位与本案真实线宽（0.4/0.8px 蚀刻细线、0.2/0.35px 走线）交集为空——AI 只能违背其中一条，两条都通向"这个风格没被复现"。
2. 它是**当前唯一没被任何闸门覆盖**的一类：`verify-p0.mjs` 对线宽只查"未声明"，所以这个 bug 在"全过"的报告里完全隐形。修它必须同时补闸门（判据应从"不出现未声明"升级为"机制句里出现的线宽必须 ⊆ 第 5 条档位"）。
3. 成本低：`lineWidthVerdict()` 加一条 `stroke-width` 正则（CSS 声明 + SVG 属性两种写法），重跑生成器即可——我已验证生成链可逐字节复现，改动可安全重算。

次优选择是漏项 2（minPics 与"占位路径"的矛盾），那条改一句话就行，但它只影响"图放几张"，不影响风格能不能被复现。
