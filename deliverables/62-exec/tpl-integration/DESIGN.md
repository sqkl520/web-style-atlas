# 模板层接进行业反查 —— 设计方案与被否掉的方案

> 执行记录（2026-10-26）。只改 `prototypes/_selection/` 下的文件。

## 1 数据结构：三个候选，选第三个

| 方案 | 做法 | 为什么不行 / 行 |
| --- | --- | --- |
| A | 在 `prompts.js` 里加顶层 `templates` 数组 | **不行**。`prompts.js` 第 1 行写着「自动生成，勿手改。生成器：prototypes/_prompts/build-prompts.mjs」，生成器每次**整文件覆写**。加进去的字段下一次跑生成器就静默消失 —— 这正是本仓库反复踩的「改了又被覆盖」。而生成器不在本轮可改范围（只改 `_selection/`），没法让它带这个字段。 |
| B | 写进 `app.js` | **不行**。`app.js` 第 1–4 行明确写着「这一层不做任何判断，也不写死任何方案信息 —— 页面上出现的每个数字都来自磁盘」。把行业口径写进这里，等于自己违反文件契约；以后谁按注释去信 `app.js`，就会被骗。 |
| C | 写进 `prompt-copy.js`，暴露 `window.benchTemplateHits(term)` | **选它**。这是手写文件（不被生成器覆写），且它已经承载「你是做什么的」这层行业 UI（`mountSceneChips`），模板口径与芯片同源，放一起读得通。app.js 只做渲染，不判断"哪个模板适合哪个行业"。 |

模板数据形状（每项）：`id / title / short / href / scenes / colors / desc`。
`scenes` 是 **README 正文原文词**，逐词抄，不做同义扩张；索引词与 README 词的差异走一张显式 `ALIAS` 表（每条都写理由）。

## 2 独立渲染通道

`#tpl-strip`（列表上方，有行时）与 `#empty-tpl`（空状态里，0 行时）是**两个独立容器**：
- 不进 `#ledger`（那是 30 个案的行卡，每行都有 `.inspect/report.json` 与三档截图）；
- 不进 `state.sceneIds`（那是 `S\d{2}` 白名单 —— 实测 `benchSetSceneIds(["M02"])` → 0/30 行、`["M02","S06","S19"]` → 2/30 行，模板被静默吞掉）；
- 不进 `#count`（模板不是方案，计进去就是假数字）。
