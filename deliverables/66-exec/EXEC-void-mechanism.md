## 0. 一句话结论

`prompt-copy.js` 的结构约束第 2 条原本对 30 案说同一句
「不凑整、**不留空位、不留占位符、编号连续不跳号**」，而其中 **7 案的签名机制就是「空位」本身**
（不是 3 案——任务书列了 S19/S02/S06，穷尽排查后实际是 7 案）。现在改成按案分化：

其余 23 案只去掉「不留空位 / 编号连续不跳号」两个词，**保住**「不凑整、不留占位符」与
`degrades=yes` 的「不要留空槽 / 整块重排」。

这 5 案是检测器必须**挡住**的假阳性来源；如果判错，它们会拿到一句"有些位置是刻意留空的"，
AI 就会自己去编空位。

| **S07** 铅灰油墨目录 | `ol.toc start="19"`、`div.missing`（1953 年缺期清单）、`aria-disabled` 的「翻到第 119 页」 | `start="19"` **不是跳号**：正面 18 条 + 背面从 19 起续号，本来就是一份连续目录。`div.missing` 是"缺号档案的**清单**"，清单本身条目排得满满的。`aria-disabled` 是禁用态链接，不是空位 |

### 排查结论

- **受影响 7 案**：S19、S02、S06（任务书点名）+ S01、S12、S23、S29（穷尽排查新增 **4 案**）。
- **7 案里 `degrades=yes` 的有 3 个**：S19、S02（+ S23 也是 yes）。这 3 案最危险——
  它们同时收到「不要留空槽（第 3 条 yes 分支）」与「不要补满（新第 2 条）」，
  所以第 3 条必须加括号限定，否则同一份提示词里两句话正面对着干（见 §2.3）。
- **旧第 2 条的杀伤面比任务书估计的更大**：不只 S19 的编号会被重排，
  S12 的「未开」洞口、S23 的第 9 处未铲开、S29 的糊掉行、S01 的三行空白，
  全都会被「不留空位」这四个字判成瑕疵而抹掉。

## 2. 四个候选的取舍

### 2.1 甲：删掉「不留空位、不留占位符、编号连续不跳号」整句

- **好处**：改动最小，一句话解决 7 案。
- **为什么不选**：`degrades=yes` 的 13 案**同时**失去「不要留空槽」这条唯一能阻止 AI 留洞的约束。
  这是上一轮（`deliverables/66-exec/EXEC-minitems-semantics.md`）刚修好的东西：
  第 3 条 yes 分支的全部意义就是"不够 N 个就整块重排、不要留空槽"，
  而「不留空位」是它在第 2 条里的配套。删掉之后，13 案会真的留出一堆空槽。
- **放弃的**：省事。

### 2.2 乙：保留第 2 条，加一句「除非机制句说这里该留空位」

- **好处**：不引入分支，30 案同一句话。
- **为什么不选**：**AI 判断不了**，而且实测数据支持这个判断——
  7 案的 `dna.mechanism` 里**一次都没提"空位"**：
  - S19 机制句 =「20 块面板分 5 行……层级由下移量与线宽差给出」（空抽屉写在 `audit`）；
  - S02 机制句 =「同一张位图以一条 2px 中轴做 180° 相位取样……」（空缺写在 `audit`）；
  - S06 机制句 =「卡片沿 3° 斜轨排布……顺序由速度差与斜角给出」（空白卡写在 `quirk`）。

  也就是说：按"机制句里有没有说"去判，AI 对 7 案会 **100% 判成"没有"**，等于没加。
- **放弃的**：一句话的统一性。

### 2.3 丙（**选这个**）：只对有空位机制的案换第 2 条措辞

```js
// hasVoid = 该案命中 5 个短语之一
hasVoid
  ? "2. 用你自己的真实数量排：有几个排几个，不凑整、不留占位符。" +
    "但这个版式有几处位置是刻意留空的（缺号、空抽屉、空白卡），那是叙事证据：" +
    "不要补满、不要删掉、编号不要重排。"
  : "2. 用你自己的真实数量排：有几个排几个，不凑整、不留占位符。"
```

同时**必须**给第 3 条加括号限定（这是任务书没提、但不加就会新造一个矛盾的地方）：

```js
d.degrades
  ? "3. …确实不足 N 个时，把空出来的位置删掉、整块重排，不要留空槽，也不要编造内容去填。" +
    (hasVoid ? "（上面说的刻意留空除外）" : "")
  : "3. 这个版式是自动流排版……你按自己的数量排就好。" +
    (hasVoid ? "（上面说的刻意留空照旧留着）" : "")
```

**为什么不加这个括号就会坏**：S19/S02/S23 三案同时是"有空位"与 `degrades=yes`。
第 2 条刚说「不要补满、不要删掉」，第 3 条紧接着说「把空出来的位置删掉、整块重排」——
AI 又要在两条相反指令里二选一。这个仓库反复记录的病（"两句方向相反，选哪边都错"）
会在修第 2 条的同时从第 3 条复发。括号把豁免范围**精确限定在被点名的留空**，
其余位置「不要留空槽」照样成立。

### 2.4 丁（想到但没选）：把「空位机制」做成 `data.js` 的正式字段

- **好处**：最干净。检测不再是关键词，而是数据（`capacity.voidMechanism: "S19×2,K-04;K-16"` 之类）。
- **为什么不选**：`data.js` 由 `collect-schemes.mjs` 生成，加字段要动生成器 + 重新生成 30 案
  + 更新 `prompts.js`，**越出本轮写作用域**（只允许 `prompt-copy.js` + README 6 个数字），
  而且并发有别的 Agent 在读 `data.js`。这条是**将来该走的路**，本轮只留记录，见 §5。

### 2.5 检测器的可靠性（丙方案最容易出错的地方）

判据只用 5 个**短语**，不用 `空` / `缺` 这种单字，也不用 `disabled` / `--empty` 这类通用属性：

| 短语 | 命中案 | 出处的原文 |
|---|---|---|
| `故意留空` | S02 S12 S23 | S02 `audit`「第 5 级故意留空并写明空缺原因」；S12 `layout`「只占 1 栏并故意留空」；S23 `layout`「只占 2 栏且故意留空不填内容」 |
| `空抽屉` | S19 | `audit`「刻意留 2 个空抽屉……位置照留」+ `index.html:72/102` |
| `空白卡` | S06 | `quirk`「固定留 3 张空白卡片」+ `index.html:140/145/150` |
| `空白行` | S29 | `quirk`「多出一条 1px 空白行」+ `index.html:324` |
| `永久留` | S01 | `quirk`「第一栏顶部永久留 3 行空白」+ `index.html:44` |

**并集 = 7 案，与 §1 人工逐个读原型得出的清单完全一致，零误判、零漏判。**

反证（为什么不能放宽）——`void-detect.mjs` §C 的实测：

```
「空」会命中 30/30 案
「缺」会命中 22/30 案
「disabled」会命中 1/30 案
```

单字 `空` 命中 30/30 等于没有判据；`缺` 命中 22/30，会把 S07/S10/S18/S24/S30 全部误判进来。

**一条自我修正记录**：初版我加了第 6 个词 `刻意留空`，跑 `void-detect.mjs` 发现它命中 **0 案**——
S19 的原话是「刻意留 **2 个空抽屉**」，中间有空格，四字串不存在。留着它就是一个永远为假的分支
（正是本仓库记在案的「参数收下但不用」病）。已删除，并在 `prompt-copy.js` 注释里写明
"加词之前先跑 void-detect 看命中数，别凭手感加"。

## 6. 我可能弄坏的地方

1. **`app.js` 有一块不是我改的改动混在同一条 diff 里，而且是并发写者写的。**
   我在 18:0x 做基线快照时 `app.js` 尚未修改；等我在 18:12 之后写文件时，
   `prototypes/_selection/app.js` 在 **18:21:45** 被另一个 Agent 改过（+350 行，
   内容是"芯片 × 搜索框：同一根轴只允许一个主人"、`state.qParked`、`parkQuery()`）。
   **我全程没有写过 `app.js`**（写作用域也不允许），但 `git diff --stat` 现在会把它算进去。
   我做了三项检查确认它与我无关、也没被我的改动影响：
   - 我的 diff 只落在 `prompt-copy.js`（`--numstat` 356/20）与 README（各 2/2）；
   - `prompt-copy.js` 里确实**也**多了一段调用 `window.benchSetSceneIdsParkingQuery`
     与注释提到 `state.qParked` 的内容 —— **那不是我写的**，是同一次并发写；
   - 关键验证：把 `buildPrompt` 的函数体（`function buildPrompt` 到 `function showManual`）
     单独切出来搜 `benchSetSceneIdsParkingQuery` / `qParked` / `benchClearSceneIdsKeepQuery`，
     **3 个全部 `no`** —— 并发改动落在 `buildPrompt` 之外，所以我的长度对比与措辞断言
     **没有被污染**（`buildPrompt@150` 在 BASE 与当前版本相同，`showManual` 从 504 变 669，
     多出来的 165 行就是并发那段）。
   - 结论：**提交时若看到 `app.js` 在 diff 里，那是另一位 Agent 的工作，不要算进本轮交付。**
     我给 lead 的摘要里也点名了这件事。

2. **7 案的追加句是"一个模板"，不是"每案定制"。**
   文案写的是「（缺号、空抽屉、空白卡）」，但 S01 是留白、S23 是未铲开的剥落、S29 是糊掉的行——
   这三个例子在括号里没有精确对应。我选择了统一模板（省字数、少一处分支、AI 不需要逐案理解），
   代价是 S01/S23/S29 的括号举例略有出入。**这是刻意的取舍**：它们共享的是同一条指令
   （"那是叙事证据，不要补满"），举例只是帮 AI 认出形状，不是契约。若要更准，应走 §2.4 的
   数据字段路线，把每个案的留空位置写进数据。

3. **检测器是关键词，不是结构解析。** 它依赖 `data.js` 的**文字**。
   如果将来有人重写 S19 的 `audit` 而不带「空抽屉」三个字，检测会静默失效、判定退回 `false`，
   提示词又会开始教 AI 删空抽屉。这不是"可能"，是这个方案的固有脆点。
   缓解：`prompt-copy.js` 注释里写清了复算脚本路径（`_out/void-detect.mjs`）；
   但**没有**任何自动测试会在 `data.js` 改动后提醒你重跑它。真正的修法是 §2.4。

4. **`degrades=no` 的留空案（S01/S06/S29）我给了「照旧留着」的括号，但这句在语义上是冗余的。**
   `no` 分支本来就说"删条目只是变短、不留空位"，没有"把空位删掉"的指令可豁免。
   我仍然加了，理由是：第 2 条刚说"有几处刻意留空"，若第 3 条一个字不提，AI 可能把
   "自动流"理解成"什么都自动重排、包括那几处空位"。**代价是 14 个字符**，
   收益是不给 AI 留一个"自动流会自己处理"的误读空间。这是我判断的净收益，但它确实是
   可以争议的一处：如果 lead 认为 `no` 分支不该加，删掉 `sn` 那 14 字即可，不影响任何断言。
