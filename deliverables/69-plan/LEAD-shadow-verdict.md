# 裁决：S19 的「外阴影」到底几处，以及它的性质

- 测量时刻：2026-10-29 03:05 (Asia/Shanghai)
- 冲突双方：我（第一版扫描说 **0 处**）、红队（说 **1 处**）

## 结论：两个都不对，是 **20 处**，而且性质特殊

### 我的漏洞
第一版 `LEAD-reconcile30.mjs` 只扫 `getComputedStyle(el).boxShadow`，**没有扫伪元素**。
S19 的这 20 处全在 `span.dw__in::after` 上。

### 实测（三档视口，含伪元素 + filter + backdrop-filter）

```
=== S19 1440x900 / 768x1024 / 390x844（三档完全相同）===
box-shadow 总数: 60（inset 40）
外投影（非 inset）: 20   ← 全部是 span.dw__in::after
  值: rgba(255, 255, 255, 0.55) 0px 0px 0px 1px
filter: drop-shadow: 0
backdrop-filter: 0
```

### 这 20 处的性质：不是「浮起投影」，是**用 box-shadow 画的 1px 描边**

`0px 0px 0px 1px` 的含义：
- 偏移 X = 0、偏移 Y = 0 → **不投射到任何方向**
- 模糊 = 0 → 没有柔和过渡
- 扩散 = 1px → 在元素边缘外扩 1px

视觉上它等价于 `border: 1px solid rgba(255,255,255,.55)`，只是用了 box-shadow 实现（大概是为了不占布局宽度，或者能盖在 padding 上）。

**它绝对不会产生「卡片浮起」的观感。** 也就是说：

- 从「规则的字面」（阴影只允许 inset）看：**违反**，20 处。
- 从「规则的目的」（禁止用影子造假浮起）看：**不违反**，因为它不投射。

### 这解释了闸门为什么没报

`rules.mjs` 里 `probe.mjs` 的 `surfaces` 统计口径（我读过）：
```js
if (s.shadowStatic ...) // 判据是 boxShadow !== 'none' 且不含 inset?
```
S19 闸门报告里 `shadow` 这条**从未 FAIL**（26/30 达标，S19 在达标名单里）。说明闸门的判据要么排除了 `0 0 0 1px` 这种无偏移的，要么只统计特定元素（卡片/按钮），不统计任意 span 的伪元素。

**这是一个真实的规则口径问题**：我、红队、闸门三方对「什么是外投影」各有一套判据，得出 0 / 1 / 0 三个不同答案。

## 三方判据对比

| 判据 | 覆盖范围 | S19 结果 | 问题 |
|---|---|---|---|
| **我的第一版** | 元素 `getComputedStyle().boxShadow` | 0 | 漏伪元素 |
| **红队** | 未明说（可能查了特定元素或去重） | 1 | 数字对不上（实际 20 处同值） |
| **闸门 probe.mjs** | 特定元素（卡片/按钮），只判 `withShadow` | 0 | 不覆盖伪元素，但这是**有意的**（防退化规则针对的是卡片浮起） |
| **我的第二版（含伪元素）** | 全部元素 + 伪元素 + filter | **20** | 把「用 box-shadow 画的描边」也算成外投影，**过严** |

## 我的裁决

**这一处不该算违规，但提示词该改。**

理由：
1. **性质上不是浮起** —— `0 0 0 1px` 无偏移无模糊，视觉是一条描边。规则的目的是「禁止用影子造假浮起」，不适用于此。
2. **但提示词的表述过严** —— 它说「阴影：只用 inset（凹槽，无外投影）」，而原型自己有 20 处 `box-shadow` 非 inset。AI 如果严格照提示词做，会改用 `border` 或者干脆不要这条描边，产物就和原型不一样了。
3. **最干净的修法**：提示词改成「**有偏移量的外投影一处都不要；用 `box-shadow: 0 0 0 Npx` 画的描边不算阴影**」。这样既保住禁令的目的，又不会让 AI 误删原型里真实存在的描边。

## 对 A 项的意义（重要）

这件事直接证明了红队 A5 的判断：**「提示词自洽性」这类检查，判据口径的严谨度决定了一切。**

我第一次跑出「阴影 30/30 完全一致」，是因为漏了伪元素。
红队跑出「29/30」，数字也对不上。
如果把这做成 30/30 门禁（红队建议的第一件事），**必须先把这个判据的覆盖面钉死**，否则门禁本身会说谎。

📌 **这是本轮最重要的方法论教训**：
> 任何「声称值 vs 实际值」的对账，必须明确覆盖：
> 1. 元素的 `color/background/border-*/outline` 
> 2. **SVG 的 `fill` / `stroke`**
> 3. **伪元素 `::before` / `::after`**
> 4. `backgroundImage` 里的渐变色标
> 5. `filter: drop-shadow` / `backdrop-filter`
> 6. 并且要区分「有偏移的投影」与「`0 0 0 Npx` 描边」
>
> 我第一版漏了 2、3、5，代价是：色值假阳性 3 个、阴影假阴性 20 个。
