## 一、判据：哪些维度「该有」

判断标准不是「我觉得重要」，而是：**原型里存在这个维度吗？**

```
原型 CSS 的 font-size 档数：min 1 / max 12 / 均值 6.9
原型 CSS 的 hex 数：       min 4 / max 14 / 均值 8.1
```

原型平均用 **6.9 档字号**、**8.1 个颜色**。所以字号层级和色板都是**真实存在的设计维度**。

## 三、这个表的含义

### 3.1 提示词「精确」的部分是「骨架」，不是「排版」

**30/30 全覆盖的四项**：色板值、圆角、阴影、线宽。
这四项都是**「元素属性」**——好抽（正则扫 CSS 就能拿），也好写（`#E4DECD`、`0px`、`inset`、`0.8px`）。

**缺失的是「关系」与「层级」**：
- 字号层级（6.9 档 → 提示词 1/30 案）
- 字重（完全 0）
- 行高（5/30）
- 色板配比（8/30）
- 图片宽高比（2/30）

这五项的共性：**它们不是某个元素的属性，而是「多个值之间的关系」**。
- 字号层级 = 6.9 个字号之间的比例关系
- 色板配比 = 8.1 个颜色之间的面积关系
- 行高 = 与字号的关系
- 图片比 = 宽与高的关系

**「属性」好抽，「关系」难抽。** 而设计的识别度恰恰在关系里。

### 3.2 这解释了视觉相似度 0.49

我实测的 3 个端到端产物：

| 案 | 综合相似度 | 字号相似度 | 声明 vs 实际最大字号 |
|---|---|---|---|
| S20 | 0.391 | **0.030** | 原型 72px → 实现 19px |
| S21 | 0.583 | **0.001** | 原型 86px → 实现 26px |
| S28 | 0.497 | 0.543 | 原型 92px → 实现 44px |

**机械判据 91.5%，视觉相似度 49%。**

因为机械判据覆盖的正是「30/30 全覆盖的那四项 + 否定式禁令」，而它**测不到字号层级**——提示词里根本没有字号，AI 只能猜，猜出来是浏览器默认值（8/9/10/11/12/13px）。

### 3.3 「可验」不等于「完备」

可验证性审计算出 **M 类 646 条机械可验约束**，这个数字是对的。但它测的是「已经写出来的东西里，有多少能机械验」。

**字号层级 0 条可验，因为提示词里压根没写。**

所以：
```
M 类 646 条 = 「写出来的部分里有 646 条可机械验」
≠「提示词的规格是完备的」
```

一个更好的指标应该是：**「原型实际使用的设计维度里，有多少被提示词覆盖」**。按上表算：15 个维度里 4 个全覆盖、1 个近乎覆盖、1 个完全缺失、其余 9 个部分缺失。

## 四、为什么这个发现比清 FAIL 重要

### 清 FAIL 的收益
S07/S13/S21 的 `mono` + S13 的 `empty-screens` → 达标案数从 26 提到 29 或 30。
**这是「展品质量」，影响的是选型台的「26 / 30」这个数字。**

### 补维度的收益
字号层级、字重、行高、色板配比、图片比 —— 影响的是**用户复制提示词后能不能做出「像那么回事」的东西**。
**这是「产品核心功能的可用性」。**

用户来这个仓库，是为了「拿到一个能用的提示词去生成自己的网站」。如果生成出来的东西字号层级全错（72px → 19px），那这个功能就是半成品。

**而「26 / 30」这个数字与他无关**——他是来拿提示词的，不是来审展品的。

## 七、一个诚实的边界

1. **「维度是否该有」是我的判断，不是客观标准。** 我用的判据是「原型 CSS 里存在这个维度」，但存在 ≠ 该写进提示词。比如「锐度/圆角例外」只在 4 案有，可能确实不需要普遍化。
2. **正则检测关键词会漏。** 比如「字号」可能用别的说法（「文字大小」「标题级别」）。我检查了 `字号|font-size|文字大[小]|标题\d+px` 四个模式，但可能仍有漏。
3. **视觉相似度 0.49 这个数字我已在 `LEAD-similarity-finding.md` 里标注了局限**（余弦相似度对占比敏感、对绝对值不敏感）。
4. **最重要的一条**：这三个端到端产物是**一个 Agent 照提示词手写的**，不是真 LLM 生成的。红队已经指出「子 Agent 会忠实执行禁令，真 LLM 会走训练分布高频路径」——所以**真 LLM 的产出可能更差**（更容易忽略没写明的规格），也可能更好（训练数据里有大量网页版式经验）。这个方向无法用当前手段验证。
