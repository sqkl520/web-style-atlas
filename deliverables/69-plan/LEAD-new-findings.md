# Lead 侦察：A 项之外新发现的两个全库级缺陷

- 测量时刻：2026-10-29 02:50 (Asia/Shanghai)
- HEAD：`9d842c7`

---

## 缺陷 1（P0）：30 条提示词，**0 条**提到字体怎么加载

### 事实

```
$ 扫 30 条 dump 的提示词，检测 /Google\s*Fonts|@import|fonts\.googleapis|自行加载|加载字体/
→ 提到字体加载的: 0 / 未提: 30
```

提示词只说了「用哪个字体」，**从来没说「怎么让这个字体真的出现在页面上」**。

S20 的字体段原文（典型形态）：
> `2. 字体：标题按这个顺序取第一个可用的：Space Grotesk → Noto Sans SC（前一个缺字就换下一个，不要自己另选）。正文同理，按序取：Noto Sans SC → Space Grotesk。编号/价格等数字用等宽 Martian Mono、tabular-nums 右对齐。`
> `不要用 Playfair Display、Inter、Roboto。也不要跳过上面这两条链直接回退成系统默认无衬线。`

### 为什么这是 P0

1. **这些字体都不是系统字体。** 端到端验证 Agent 实测本机（HeadlessChrome 156）装了的是：`Georgia`、`Times New Roman`、`SimSun`、`Noto Sans SC`、`Consolas`、`Microsoft YaHei`、`KaiTi`。
   三案点名的 `Space Grotesk`、`Martian Mono`、`Antonio`、`WenJin Mincho`、`Instrument Serif`、`JetBrains Mono`、`Glow Sans SC` **全部未安装**。

2. **`font-family: "Space Grotesk", ...` 在没加载字体的环境里会静默回退**，而且提示词还专门禁止了回退（「不要跳过上面这两条链直接回退成系统默认无衬线」）——**但它没给实现者任何「如何不回退」的手段。**

3. **原型自己是有加载机制的**：30 个原型都通过 `prototypes/_fonts/` 自托管字体（`.gitignore` 里 `prototypes/*/build/` 是字体源文件）。但提示词是给**用户自己的项目**用的，那里没有 `_fonts/`。

4. **提示词要求单文件 HTML、不引外部依赖**：
   > `输出要求：只给一个完整单文件 HTML（以 <!DOCTYPE html> 开头，CSS 内联在 <style> 里），不引 React/Vue/Tailwind/Bootstrap，不拆文件、不构建。`
   
   而 Google Fonts 的 `<link>` 或 `@import` 是**外部依赖**。所以「单文件 + 非系统字体」这两条要求**互相冲突**：
   - 要么允许外部字体链接（破坏「单文件、不引外部依赖」）
   - 要么字体必然回退（破坏「不要回退成系统无衬线」）

### 影响
用户复制提示词给 AI → AI 生成单文件 HTML → 里面写 `font-family: "Space Grotesk"` → 用户打开页面 → **看到的是系统默认字体** → 「这个风格跟我看到的不一样」。

**这是「提示词产不出该风格」最直接、最确定的一个原因**，比色板截断更致命（颜色不对还能看，字体不对整个风格就没了）。

### 待裁决
三个选项：
- (a) 提示词里加一句「用 Google Fonts 的 `<link>` 加载这几个字体」（放宽「不引外部依赖」）
- (b) 提示词里加 fallback 链，承认「装不上就用最接近的系统字体」
- (c) 改用系统字体（但 30 个原型的风格很多依赖特定字体，改了就不是那个风格了）

## 缺陷 2（P1）：色板三层截断，且生成器不在仓库里

### 事实

| 层 | 每案色值数 | 上限来自 |
|---|---|---|
| `prototypes/Sxx/style.css` 实际声明 | 最多 **10+** | 作者自由写 |
| `collect-schemes.mjs` → `data.js` 的 `palette[]` | **3–4** | `collect-schemes.mjs:486` `if (pal.length >= 4) break;` |
| `build-prompts.mjs` → `prompts.js` 的 `dna.palette` | **4–7** | 该脚本自行放到 7 |
| 提示词正文「配色只用这几个值」 | **5–8** | 同上 |

**`data.js`（上限 4）与 `prompts.js`（上限 7）是两套不同的提取逻辑，两者都不等于真实值。**

### 后果（我实测的 30/30 对账）
```
「页面用了但提示词没说」：25 / 30 案
S24: 7 个未声称色（#E6EDF2 #3C5F48 #2A1B50 #1B1136 #3A276E #4A3390 #6E8B7A）
S08: 6 个
S15: 6 个
```
AI 只能对到 5–8 色，其余（可能承担关键视觉作用的）完全没被告知。

### 更麻烦的一层
生成 `prompts.js` 的脚本 `deliverables/99-scratch/build-prompts.mjs`（12KB）**被 `.gitignore` 的 `deliverables/*-scratch/` 排除，不在仓库里**。

它第 230 行的注释写着：
> `" *   dna.palette 由最多 5 色放宽到最多 7 色，主强调色排在最前（S19/S24 的主色曾被截掉）；"`

**「放宽到 7 色」是一次性的、本机做的、克隆者拿不到的修改。** 下一个人 clone 仓库后只有 `data.js`（上限 4），无法重新生成 `prompts.js`。

这与第 8 轮 `tools/` 不入库是同一类病：**关键生成逻辑不在版本控制里。**

📌 `.gitignore` 那条规则的注释原文是「审查 agent 的**草稿**目录…不进 git」——`build-prompts.mjs` 是**生成器**不是草稿，被同一条规则顺带排除了。

## 缺陷 3（P2）：提示词里有 3 处自相矛盾（端到端 Agent 从原文读出来的）

| 案 | 矛盾 |
|---|---|
| **S19** | 「线宽只用这几级：`0.4px、0.8px、1px、3px`，**不要自创第三级**」——列了 4 级，却说「不要第三级」，且原型实际只用 1px/3px 两级 |
| **S20** | 机制句说走线「`0.35px` 按 `0.6/1.2/2.4px` 三级分档」，硬约束第 5 条说线宽「`0.35px、0.5px、1px、3px`」——两处线宽集合**交集只有 0.35px** |
| **S21** | 机制句说「14 枚 **24×96px** 横条」——24 宽 × 96 高是**竖条**不是横条；且 24px 宽的条上做 **60° 斜切**需要约 41px 横向跨度，几何上放不下 |
| **S28** | risk 段说「配色锁死**三个** HEX」，配色行给了**四个** |

这些是 AI 拿到提示词后会**卡住或二选一**的地方。任选一边都可能是错的。

---

## 附：这些发现对 A 项的意义

用户要求「验证提示词真的能产出该风格」。但我在做侦察时就发现**三个确定性的、不需要生成就能证明的缺陷**：

1. 字体加载从未说明 → 产物必然丢风格（最致命）
2. 色板被截到 5–8 个 → 产物必然不完全（25/30 案）
3. 至少 4 案有自相矛盾约束 → 产物会卡住

**所以 A 项端到端验证即使跑出「3 案全过」，也不能说明「提示词能用」**——它只能说明「这 3 案的提示词没踩上面这些坑」。反过来说，如果端到端 FAIL 了，上面这三条是最可能的归因。

这三条应该**先修**，再谈端到端覆盖率。否则就是在验证一份已知有缺陷的提示词。
