| 判据 | 提示词声称 | 原型实际 | 一致？ |
|---|---|---|---|
| 标题字体链 | `Noto Serif SC → Georgia` | `"Noto Serif SC", Georgia, serif` | ✓ |

## 四、30/30 全量对账

### 色值
```
提示词声称 156 个，页面实际命中 150 个（96.2%）
「声称但页面没用」：6 案（S09 #8A4B24 / S10 #6E7076 / S17 #DFD6BF / S18 #278F43 / S22 #6B6558 / S28 #07080C）
「页面用了但提示词没说」：25 / 30 案
```

⚠️ **我第一版扫描有漏洞，修正后数字变了。** 第一版只查 `color/backgroundColor/border*/outline`，漏了 **SVG `stroke`** 和 **伪元素 `::before`/`::after`**。修正后：

| 案 | 第一版 | 修正后 | 真相 |
|---|---|---|---|
| S09 `#8A4B24` | 缺 | **确实缺** | 死变量：`--rust: #8A4B24` 被 `var()` 引用 **0 次** |
| S10 `#6E7076` | 缺 | **75 处**（SVG stroke） | ✗ 我的误报 |
| S17 `#DFD6BF` | 缺 | **确实缺** | 真问题（`--tone-hover` 引用 1 次但渲染不到） |
| S18 `#278F43` | 缺 | **确实缺** | 真问题（`--phos-deep` 引用 1 次但渲染不到） |
| S22 `#6B6558` | 缺 | **2 处**（伪元素） | ✗ 我的误报 |
| S28 `#07080C` | 缺 | **15 处**（伪元素） | ✗ 我的误报 |

**真实问题是 3 案（S09 / S17 / S18），不是 6 案。**

**方法论教训（必须写进 A 项的验证协议）**：
> 扫「页面实际用了哪些色」时，只扫 `getComputedStyle(el)` 的 `color/background/border` 会漏掉三类：
> 1. **SVG 的 `fill` / `stroke`**（S10 有 75 处是这个）
> 2. **伪元素 `::before` / `::after`**（S22、S28 全靠这个）
> 3. 渐变里的色标（`backgroundImage` 里的 `rgb()`）
>
> 漏掉这两类会让「假阴性」与「假阳性」同时出现 —— 我第一次就同时错了 3 个（3 假阳性 + 0 假阴性）。
> **任何「提示词声称值 vs 实际渲染值」的对账脚本，必须覆盖这 5 类属性 + 伪元素。**

## 五、「页面用了但提示词没说」25/30 案 —— 这是 A 项最大的发现

### 根因链（我已追到底）

色值经过 **三层**，每一层都在丢：

| 层 | 产出 | 每案色值数 | 上限来自 |
|---|---|---|---|
| `prototypes/Sxx/style.css` | 实际声明 | **最多 10+** | 作者自由写 |
| `collect-schemes.mjs` → `data.js` 的 `palette[]` | 选型台 UI 用 | **3–4 个**（25 案 4 个、5 案 3 个） | `collect-schemes.mjs:486` **`if (pal.length >= 4) break;`** |
| `build-prompts.mjs` → `prompts.js` 的 `dna.palette` | 提示词用 | **4–7 个**（10 案 4 / 3 案 5 / 7 案 6 / 10 案 7） | 该脚本把上限放到 7，注释写着「不再 slice(0,5)」 |
| 提示词正文「配色只用这几个值：…」 | 给 AI | **5–8 个** | 同上 |

**`data.js` 与 `prompts.js` 是两套不同的提取逻辑**（一个上限 4、一个上限 7），而两者都不等于 CSS 里的真实数量。

举例（我实测）：
```
S24: CSS 用了但提示词没说 → #E6EDF2, #3C5F48, #2A1B50, #1B1136, #3A276E, #4A3390, #6E8B7A（7 个）
S08: #FFF4D6, #8D4C16, #663710, #49270B, #351D09, #1B0F04（6 个）
S15: #E7EBE9, #C8CECC, #F0E4D8, #4C5257, #DDE2E0, #C3C9C7（6 个）
```

**后果**：AI 拿到这份色板，最多只能对到原型色板的 5–8 色，其余（包括可能承担关键视觉作用的）完全没被告知。**所以「提示词能不能产出该风格」这个问题，在数据层就已经注定是「不完全能」。**

这不是端到端验证才能发现的问题 —— 它现在就能看出来，而且是确定性的（不需要生成、不需要人判）。

### 更麻烦的一层：生成 `prompts.js` 的脚本不在仓库里

```
$ node -e "..."   # 查 prompts.js 的生成者
→ deliverables/99-scratch/build-prompts.mjs（12.0KB）
```

而 `.gitignore` 里有 `deliverables/*-scratch/` —— **这个脚本不入库**。

它自己第 230 行的注释写着：
> `" *   dna.palette 由最多 5 色放宽到最多 7 色，主强调色排在最前（S19/S24 的主色曾被截掉）；"`

也就是说：**「放宽到 7 色」这个修复是一次性的、在本机做的、克隆者拿不到的修改。** 下一个人 clone 仓库后，如果只有 `data.js`（上限 4）而没有 `build-prompts.mjs`，他无法重新生成 `prompts.js`，也就无法知道 5–8 个色是怎么来的。

这与第 8 轮发现的 `tools/` 不入库是同一类问题：**关键生成逻辑不在版本控制里。**

📌 注：`.gitignore` 里那条规则的注释原文是「审查 agent 的草稿目录（放在 deliverables/ 下以免被临时目录 sweeper 扫掉；不进 git）」——它本来是给**草稿**用的，`build-prompts.mjs` 是**生成器**，被同一条规则顺带排除了。
