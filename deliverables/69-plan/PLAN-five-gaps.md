### 1.9 D：静态 lint 的 `shadow` 是**正则回溯误伤**，不是设计意图问题

这是本轮第二个新发现。`lint.mjs`（`tools/` 下）对 S13 报 `shadow ×11` + `emoji ×5`，运行期却一条不报。根因不是「注释没清」，是**正则本身有 bug**：

```powershell
node deliverables/69-plan/_p16b_regex.mjs   # 逐条断言 lint.mjs 的 shadow 正则
node deliverables/69-plan/_p34_backtrack.mjs # 证明是回溯导致的
```

```js
/box-shadow\s*:\s*(?!none|0 0 #0000|var\(--tw)|.../
```

| 输入 | 判定 |
|---|---|
| `box-shadow:none;`（无空格） | ✅ pass |
| `box-shadow: none;`（1 空格） | ❌ **FAIL** ← 命中 `"box-shadow:"` |
| `box-shadow: 0 0 #0000;` | ❌ **FAIL** |
| `filter: drop-shadow(...)`（契约 §9.3 明写不算 shadow） | ❌ **FAIL** |
| 注释里的 `shadow` 二字 | ❌ **FAIL** |

**机制**：`\s*` 先吃掉空格 → 环视 `(?!none)` 看到 `none`，失败 → 正则**回溯**成「只吃冒号不吃空格」→ 环视看到 `" none"`（以空格开头，不以 `n` 开头）→ 通过。

**S13 的 11 条 shadow 命中，逐条定性如下**（用状态机逐字符判定「该位置是否在块注释内」，见 `_p16_lintlines.mjs`）：

| 类别 | 条数 | 行号 | 说明 |
|---|---|---|---|
| 在 CSS 块注释内的文字 | **5** | 148 149 164 449 611 | 注释不渲染，且第 449 行的 `⚠️` 就写在注释里 |
| `filter: drop-shadow(...)` | **2** | 165 166 | `_CONTRACT.md` §9.3 明写「drop-shadow 不算 shadow」 |
| `box-shadow: none`（显式声明无阴影） | **4** | 276 426 454 484 | 回溯 bug 把它判成「有阴影」 |
| 真正的静止态外投影 | **0** | — | — |

**5 条 emoji 命中全部在 CSS 块注释里的 `⚠️`**（已逐字符确认在注释内），而运行时 `probe.mjs` 只扫渲染文本 —— 所以运行期报 0。

**结论：`shadow`/`button-fx` 的「17 处」是 static lint 的假阳性，运行期从来没有过。** README 那句「真的未清」是**误读工具输出**。

### 2.5 防作弊：三路相似度 + 校准过的阈值

**风险**：写页面的 Agent 偷看原型 CSS = 抄答案不是验证。

我设计了「泄漏探测器」并在**真实样本**上校准（`_p18_leak.mjs`）：

|---|---|---|---|---|
| 自比（原型 vs 自己） | 1.000 | 1.000 | 1.000 | 上限 |
