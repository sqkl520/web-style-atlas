### 更重要的一件事：A 项的方法论结论

红队用二项分布算清了样本量：

> **3 案全过的 95% 下界只有 36.8%。** 要证明 ≥90% 需 **29 次全部通过**，≥95% 需 **59 次**。

而端到端单案成本是「半天级」（生成 + 实现 + 量测）。所以：

**「验 3/30 就宣称提示词可用」在统计上不成立。** 更有效的路径是：

## E. 移动端 19.4 屏 —— 数字是分母错，但暴露了我上一轮的一个真实错误

### 19.4 的来源

390×844 实测 **13.701 屏**。19.4 精确命中三个场景：
- 今日 360×640：`12424/640 = 19.413` ✓
- 改动前 390×892：`17327/892 = 19.425` ✓
- **历史记录「30 行合计 16,387 ÷ 844」= 19.416** ✓ ← 最可能

`app.js:522` 里留着上一轮自己的账：「30 行总高 15,472 → 16,387（+5.9%）」。
**19.4 = 卡高之和 ÷ 视口高，漏了 chrome、没减视口。**

### 我上一轮的错误：只验了 1 个断点就宣称「移动端达标」

我实测了 8 个断点：

| 视口 | 首屏完整卡 | 余量 | 备注 |
|---|---|---|---|
| **360×640** | **0** | **−174.8** | 安卓小屏，露出 57.6% |
| **375×667** | **0** | −147.8 | iPhone SE/8 |
| **375×812** | **0** | **−2.8** | iPhone X/12mini，露出 **99.3%** |
| 390×844 | 1 | +52.2 | 上一轮唯一验过的 |
| 414×896 | 1 | +151.7 | |
| 768×1024 | 1 | +74.8 | |
| **1024×900** | **0** | **−53.2** | iPad 横屏 |
| 1440×900 | 1 | +192.6 | |

**8 个断点里 3 个是 0 张卡，而上一轮我只测了 390 和 1440。**
但要区分：375×812 露出 99.3% 是「指标不达标但体验无感」，360×640 露出 57.6% 才是真问题。

### 「长」不是主要问题

页面 **96.0% 是 30 张卡**（11,101.8px），chrome 三块合计仅 **400.4px = 0.474 屏 = 3.5%**。全删也只省 0.47 屏。

真问题是**短路径机制齐备但接线断了**：
1. 点「咖啡店」芯片后，**1369px 筛选面板不收起** → 首屏 0 张卡，首卡在 3.48 屏
2. **搜索「咖啡店」→ 0 行**。这是那颗实心芯片的名字。要输入「咖啡」才有 1 行（整串子串匹配）
3. 无粘性、无进度、无记忆；S12 与 S27 相距 **6.63 屏**

### 两个被实测证伪的方案

- **分组折叠**：按结构类型 = 22 组 / 14 个单例组 / 最大组 2；按美学家族 = 30 组全单例。**粒度退化**
- **CSS 虚拟滚动**（`content-visibility`）：页面反而**变长 0.884 屏**，且不减少 DOM
