## 5. 设计决定：三个输入框改成了两个（这条要明确记录）

任务书写「加三个输入框」，但同一段里列的对应关系只有两条：

- 「你经营什么」→ `o.biz` + `o.what`
- 「访客要做的动作」→ `o.action`

第三条 `o.mood` **在 `buildPrompt` 里从未被读过**（全文 grep：`mood` 命中 0 次）。
气质走的是 `window.SCHEMES` 的 `tone`（`prompt-copy.js:181-188` 那段读 `o.tone` 的代码）。

所以三个输入框里必然有一个是死的 —— 而那正是本轮要修的病：
`o.biz` / `o.what` / `o.action` 三个参数"存在但没人传"，`o.mood` 连读都没读，都是同一类：
**界面上/签名上有的东西，背后没有消费者。**

我的裁决：做两个真的，不做三个里有一个假的。
如果 reviewer 认为必须有第三个，那它应该先有消费者（比如把 `o.mood` 接进气质行、覆盖 tone），
那是一处**行为改动**，不是加个输入框就能安全完成的。

## 6. 关键实现说明（为什么这么写）

### 6.1 空槽用 `＿＿＿＿`（全角下划线），不用 `【】` 或 `___`

`【请填写】` 这类方括号会被 AI 当成"必须保留的占位符"照抄进正文 —— 实测过，AI 会输出「我经营【请填写】」。
半角下划线 `___` 在 13px 字号下几乎看不见。全角下划线两档都清晰，且读起来就是一根待填的横线。

### 6.2 框定句的长度是算出来的，不是写出来的

已填状态要求「长度 = 现状 + 用户输入长度 ±10」。

推导（设 `L` = 框定句长度）：

```
旧开头  2 句 + 2 换行                     = 42 + 2 = 44
新开头  4+biz+1 + 8+act+1 + L + 3 换行    = 15 + len(biz) + len(act) + L
净增量  = 15 + L − 44 + (len(biz)+len(act))
        = (L − 29) + 用户输入长度
```

要让净增量 = 用户输入长度 + 0，`L` 必须是 29。我取 34（净 +5，落在 ±10 内）。
这个数字不能随手改：第二轮我先写成 9 字（「照着这份施工图做。」），净增量变成 −20，直接把验收打穿。
所以交付物里把它写死在这儿，改的人会看到。

顺带：那 34 字不是填充语。它做一件真事 —— 把"前两句是我的话"和"后面是风格约束"隔开。
没有这句，AI 会把「我经营…」当成风格描述的一部分。

### 6.3 默认值留空，示例只放 placeholder

一旦预填「一家小店」，用户不填就会把假信息复制走 —— 那正是被修的 bug 换了个位置。
placeholder 不参与取值，用户看得见格式，但不会被当成事实。

placeholder 长度是按**并排档最窄**配的（1440 档每框 253px）。第一版 26 字，截图里被截成
「例：看完就想问价，或者直接加微信下…」——半句比没有更糟。现在 11/13 字，两档完整可见。
`shot-opener.mjs` 里有断言用 canvas 量文本宽来守这条。

### 6.4 只填一处时，第一行要点名缺的是哪一个

否则用户看不出提示词里还留着一根横线，也不知道缺的是哪一项：

```
只填 biz：  下面这份是这个风格的施工图。＿＿＿＿ 那处要你自己填（「访客要做的动作」我不知道）：
只填 action：下面这份是这个风格的施工图。＿＿＿＿ 那处要你自己填（「你经营什么」我不知道）：
```

### 6.5 输入清洗：换行压空格、超长截 80 字

粘贴多行会毁掉提示词的行结构（第 3 行本该是 `请把整页做成这个风格：…`）。
80 字上限是因为正文 1.6K 字，开头一味变长会挤掉有信息量的约束段。
这两条都有断言（§3.2 的 6）。

### 6.6 `o.what` 的向后兼容

`window.buildStylePrompt = buildPrompt` 是**对外暴露**的公开接口，老签名是 `{biz, what}`。
仓库里现在没有调用方传它，但"参数收下但不用"正是本轮要修的病。
所以老形状仍然生效：`{biz:"咖啡店", what:"5 个产区的豆子"}` → 「我经营咖啡店，5 个产区的豆子。」
（三条断言在 §3.2 的 7。）

### 6.7 输入框里的 Esc 与 Enter

- `Esc` 只 blur，**stopPropagation**。`app.js` 的全局 Esc 是"收起详情"，用户在填表时按 Esc
  会连详情一起关掉、填的内容全丢。
- `Enter` 直接复制，`preventDefault` + `stopPropagation`。详情里的行卡对 Enter 有 handler，
  不拦的话合成 click 会被它吃掉（`prompt-copy.js` 里按钮那段注释记录过的老坑）。

## 7. 我可能弄坏的地方

诚实列，按我判断的风险从高到低：

1. **面板高度 +152px（1440）/ +222px（390），第一个字段被推下同样距离。**
   65-exec 有另一个 Agent 的 `panel-measure.mjs` 在追「900px 视口里第一眼能到哪」。
   我的块在 `#d-body` 最顶部，直接抬高它下面所有东西。按钮本身没被推走（仍 `top=120`），
   但"第一个字段的 top"这个指标会变差。这是我这轮**唯一确定的副作用**。
   我已经把它从 +253 压到 +152，再压就要牺牲说明句了（那句是"不填会怎样"的唯一告知）。
   **如果 reviewer 认为不可接受，正确的改法是把它做成折叠区、默认收起** —— 但那会让
   "开头可编辑"这件事重新变成需要先点一下才发现，绕回本轮要修的"藏起来就没人知道"。

2. **`style.css` 我动过一次编码，已修好但值得记录。**
   中途我用 PowerShell 5.1 的 `Set-Content` 重写整个文件，结果引入了 UTF-8 BOM 并把 LF 变成 CRLF，
   `git diff` 一度显示 664 增 / 524 删（整文件变更）——看起来像我重写了整个样式表。
   已用字节级操作恢复到原状态：无 BOM、LF。现在 diff 是 +142/−2，干净。
   **教训：这个仓库的所有文本文件都是无 BOM + LF，PowerShell 5.1 的 `Set-Content -Encoding utf8`
   会同时破坏这两点。改这些文件应该只用 `edit` 工具，不要用 shell 重写。**

3. **我和另一个 Agent 同时在改 `style.css`，而且它在我之后又改过一次。**
   - 我第一次 `edit` 时报 "file changed since it was read"（它先改了）。
   - 我恢复编码时用 `Set-Content` 重写整个文件，那一刻**快照的是它当时的版本**。
   - 之后它的行数从 665 变回 593 —— 它又改了一轮，我的块被它保留了下来（因为我追加在文件末尾）。
   - 我重跑 `shot-opener.mjs` 确认 50 项仍全绿，`.cap` / `.cap-warn` / `.cap-ok` / `.row-family`
     四条规则都在，我的 `.prompt-*` 块完整（§3.3 的输出是重跑后的）。

   **风险仍然存在**：两个 Agent 并发写同一个文件，谁后写谁赢。
   如果它在我这次跑完之后又整文件重写，我的块可能消失。
   **请在合并前重跑一次 `node deliverables/65-exec/shot-opener.mjs`，确认仍是 50/0。**
   这是我这轮最不确定的一件事。

4. **`verify-opener.mjs` 的"已填"用的是同一个固定输入。**
   长度断言是数学恒等式（净增量与输入长度无关），所以换输入也成立；
   但"30/30 首行含原文"这条只证明了一个输入。边界输入（全空格、纯标点、超长）
   由断言 6 覆盖，其余组合没测。

5. **剪贴板只验到"页面内能读回"，没验系统剪贴板。**
   无头实例的系统剪贴板被隔离是已知环境属性。系统那一层靠 `99-scratch/verify-headed-clipboard.mjs`，
   我没有重跑它。**如果 reviewer 要"复制按钮真能用"的完整证据，需要跑一次那个有头脚本。**

6. **`＿` 全角下划线在极少数字体下可能显示为豆腐块。**
   页面用 `--cjk: "Noto Sans SC"` 自托管字体，实测两档都正常渲染（截图可见）。
   但如果用户系统里发生字体回退且回退字体缺 U+FF3F，会出现方框。概率低，但我没法测所有环境。

7. **`promptOpener` 是新增的内部函数，`buildPrompt` 的行为对"不传 opts"的调用方变了。**
   仓库内没有别的调用方（grep 确认过），`wizard.js` / `app.js` 都不调 `buildPrompt`。
   但如果有外部脚本读 `window.buildStylePrompt(id)` 并断言首行文本，它会失败 —— 那是预期的行为变更。
