## 0. 先交代一件影响读数的事：本轮面板里有别人的改动

采集过程中抓到：另一个 Agent 同时往 `prompt-copy.js` + `style.css` 里加了「复制提示词」的两个输入框
（`.prompt-cta` / `.prompt-fill` / `.prompt-f-input`）。它让详情面板顶部多出 **≈299px**。

因此**不能**用「改前 contentH − 改后 contentH」来回答验收第 8 条 —— 那个差值里混着别人的 299px。
我的做法是**同页 A/B**（`audit-isolate.mjs`）：同一个详情面板里，先把我的三处改动从 DOM 上撤掉量一次，
再装回去量一次。两次之间面板其他部分完全没动，差值才是我的净成本。

> 这也是本节存在的理由：如果我直接报 `S01 3274 → 3573 = +299px`，验收第 8 条会被判 FAIL，
> 而那个 FAIL 是假的 —— 归因错了对象。原始数据两种都留着（`audit-before.json` / `audit-after.json`），
> 想复核的人可以自己相减，再看这一节为什么不那样减。

## 4. 任务 4：`family` 截断——实测结论与决定

### 先查清：详情面板里已经是全文

`renderDetail` 里本来就有 `field('美学家族与参考', r.family)`。
**CDP 实测：详情面板的该字段与 `data.js` 逐字相同，30/30。**
所以「丢失」只发生在**行卡**上，严重度按任务要求下调。

### 原来那三刀切掉了什么

```js
(r.family || '').split('。')[0].split('：').pop().slice(0, 34)
```

- 30 案 `family` 全长 133–282 字，**合计 5,911 字**；
- 行卡实际只印 **657 字**（不是任务里说的口径，是逐案复算的值）；
- 30/30 全中。

最难看的是 S13：作者写成「Neumorphism 的实物化改造：把它从屏幕上的软挤出…」，
`.split('：').pop()` 把**家族名本身**切掉了，行卡上印的是半句：

```
把它从屏幕上的软挤出拉回日本凸版印刷的盲压（blind emboss
```

—— 连括号都没闭合。这不是「信息少一点」，是印了一句语法错误的话。

### 三轮实测（都是 CDP 真跑，不是推算）

**第一轮**：把 `slice(0,34)` 放宽到 60 / 80 —— **完全无效**。
因为首句最长只有 34 字，放宽是空操作（s60 与 cur 的行高、字宽逐案完全相同）。

**第二轮**：不切句、按字数截 60 / 80 / 首二句：

| 口径 | 1440 行高 | 1440 总高 | 390 行高 | 390 总高 | 平均字数 |
|---|---|---|---|---|---|
| cur（现状） | 276.8 恒定 | 8,304 | 478.7–601.9 | 15,472 | 21.9 |
| 全文截 60 | 276.8 恒定 | 8,304 | 526.8–623.0 | 16,828 | 60.0 |
| 全文截 80 | 276.8 恒定 | 8,304 | 547.8–644.0 | 17,291 | 80.0 |
| 首句+第二句 | 276.8 恒定 | 8,304 | 568.9–686.1 | 18,618 | 134.2 |

**关键结论：1440 档全部 0/30 行高上涨** —— 桌面行卡的行高由右侧截图列（201.8px）撑起来，
`family` 多几行只是吃掉行内 75px 余量。**代价全部落在 390 档**。

**第三轮**：CSS `-webkit-line-clamp` 1 / 2 / 3 行（不切字，交给浏览器折行）：

| clamp | 1440 总高 | 1440 可见字（30 案合计） | 390 总高 | 390 上涨案 | 390 可见字 | 横向溢出 |
|---|---|---|---|---|---|---|
| 1 行 | 8,305 | 2,066 | 15,709 | 0/30 | 851 | 0 |
| **2 行（采用）** | **8,305** | **3,931** | **16,294** | **28/30（+18~45px）** | **1,634** | **0** |
| 3 行 | 8,305 | 5,379 | 16,879 | 30/30（+19.5px） | 2,463 | 0 |

（可见字数用 `Range.getBoundingClientRect` 逐字测「落在 `.row-family` 可视框内」的字，
不是 `textContent.length` —— 后者会把被 clamp 藏掉的字也算进去。脚本：`audit-family-visible.mjs`。）

**决定：不切字 + CSS 两行 clamp。**

理由：
1. **1440 档零代价**：30/30 行高恒定 276.8px，横向溢出 0，色块/错误码/cap 一个都没被挤掉。
2. 行卡可见字数 657 → **3,931**（1440），信息量 ×6。
3. 390 档的代价是真实的（28 案 +18~45px，30 行总高 +5.3%），但换来的是「家族名 + 一句参考对象」
   能读完（中位 54 字），而不是只剩一个名字（中位 21.9 字）。
4. 不用 3 行：390 档 +19.5px × 30 案 = 总高 +11.8%，而第三行读到的多是「偷的是…」那半句，
   性价比不如两行；两行已经覆盖 30 案里 28 案的家族名全称。
5. 详情面板的全文不动，行卡只是预览 —— 想看完整的仍然在详情里。

同时修掉了 `.split('：')` 那个 bug：现在**不会**再把 S13 的家族名切掉。

### 6.1 并发 Agent 正在改同一批文件（最需要注意）

1. **我的 `style.css` 编辑曾一次覆盖掉它的改动**：第一次 `edit` 报了
   `file changed since it was read`，我重读后才发现文件已被改。现在的 `style.css`
   里两段并存（我的 `.row-family` / `.field-fold` 在 271–304 / 478–521 行，
   它的 `.prompt-cta` 系列在 619 行之后）。**建议合并前 diff 一遍确认没有互相覆盖。**
2. 我为了修 BOM/换行，曾整体重写 `style.css` 与 `app.js`。现在已还原成原状
   （`app.js` 无 BOM、`style.css` 有 BOM、两者都 LF），`git diff --stat` 只剩我自己的 +154 / +146 行。
   但如果那个 Agent 在我重写的那一刻也写了文件，**它的改动可能被我覆盖**。
   时间点在 05:33 前后，请它复核自己的 `.prompt-cta` 那一段还在不在。

### 6.2 验收第 8 条的测量方法是我选的

+45~46px 这个数字来自**同页 A/B**（先在 DOM 上撤掉我的改动，再装回去）。
它不是「改前/改后两个 JSON 相减」那种更直觉的口径 —— 那种口径本轮得 +299px，
但里面 ≈253px 是并发 Agent 的输入框。

我选同页 A/B 是因为它能把我的成本隔离出来，**但这也意味着这个数字不是最终页面的绝对增量**。
想知道用户最终多滚动多少，请看 `audit-after.json` 与 `audit-before.json` 的 contentH 差 ——
**那个差值包含了别人的改动，不该单独记在我或它任何一方账上。**

### 6.3 `steps(4)` 那个坑我只修了一半

`(4)` / `(1)` 会被 `countPoints` 当成编号符。目前靠「取三种数法的最大值」压住了
（S11、S21 的 `steps(n)` 恰好没有把条数顶错）。
但如果将来某一案写成「只有两条，第二条是 `steps(7)`」，最大值会算出 7 条。
真正的修法是给编号符加行首/句首锚点，但那会引入新的误判，本轮没做。

### 6.4 390 档行卡变高了，这是有意的

28/30 案行高 +18~45px（30 行总高 15,472 → 16,294，+5.3%）。
换来的是 `family` 在手机上也读得到一句完整的参考对象。
**如果验收方认为手机档不该变高**，把 `style.css` 里 `.row-family` 的
`-webkit-line-clamp: 2` 改成 `1` 即可完全退回原高度（实测 390 总高 15,709，比改前还低 237px）——
只是可见字数会从 1,634 掉到 851。

### 6.5 S13 的切分是 UI 层的补丁，不是数据修好了

`data.js` 里 S13 的 `audit` **仍然是 780 字**，含那段评审清单。
任何绕过 `app.js` 直接读 `data.js` 的东西（比如将来有人做导出、做提示词、做别的页面）
**依然会拿到脏数据**。这次只保证「用户在选型台里看不到它」。

### 6.6 折叠块用了 `-webkit-line-clamp`

Chromium / Safari / Firefox 现代版本都支持，但它是 `-webkit-` 前缀属性。
本仓库的验证全部在 Chrome 上跑，**没验过 Firefox 的真实渲染**。
如果 `-webkit-line-clamp` 不生效，`family` 会完整展开（30 行总高会涨到约 20,407px），
不会崩，但手机档列表会明显变长。
