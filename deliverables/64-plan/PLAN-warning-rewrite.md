## ① 4 个案子各自「需要什么数据结构」（带代码/规格证据）

先纠正任务书里的三个假设——它们方向对，但有一处偏得挺远：

| 任务书假设 | 核实结果 |
|---|---|
| S15 要求「同一份内容有 3 个版本」 | **部分成立，但真正卡的是第二个维度**：3 个年份是**空间测绘图**的修订层（不是内容版本），并且每块分区都必须有**实测面积**能与矩形对上 |
| S18 要求「一份连续的流水记录，且每条有唯一编号」 | **基本成立**，但要补一句：编号不是每条都有，而是**挂出/摘回成对共用同一个牌号**，且必须能定位到绝对行号 |
| S21 要求「条目之间有明确的互斥/依赖关系」 | **成立**，且比想的更硬：互斥条数直接决定几何（`angle == 15 × pairs`），条数错则切口角度错 |
| S29 要求「条目有唯一零件号，且能被别处交叉引用」 | **成立且已实测 23≡23≡23 全等**，这是四个案里证据最硬的一个 |

### S15 渔场平面簿 —— 要「同一片地方、几个年份、各带实测面积的分区」

**要手上有什么**：一块**有形状的地方**（一间厂房、一层楼、一片场地），把它切成若干块，每块都要有**实测面积**（平方米），而且这块地方要有**两三个年份的测绘图**——旧图上哪道墙挪过、哪个区变大过，得说得出来。

**证据**：

1. **面积是硬约束，残差 0.00%**。14 个热区的 `<rect width/height>` 与登记表声明的 m² 每一块都精确对得上。按 `index.html:406` 的换算（`1 单位 = 1.25cm`）重算：

   ```
   B-3  288×208 → 9.3600 m²  declared 9.36   残差 0.0000%
   B-1  112×128 → 2.2400 m²  declared 2.24   残差 0.0000%
   ...
   G-1  400×240 → 15.0000 m² declared 15.00  残差 0.0000%
   WORST residual = 0.0000%（14/14）
   内区 12 块合计 46.40 ｜外区 2 块 22.40 ｜总计 68.80
   ```
   三个合计值与页面自述（`index.html:214`「建筑内 12 区 46.40m²，建筑外 2 区 22.40m²，图幅合计 68.80m²」）**完全相等**；14 个矩形**两两不重叠**（0 对相交），即真的拼成一张图。

   → 这不是"随便放几个方块"，是**必须提供面积数据**才能生成的版式。数据来源：`index.html:139-152`（`<a class="hot">` 14 个）、`index.html:283-296`（登记表 14 行）、`:406`（换算）。

2. **年份是"同一张图的修订层"，不是内容版本**。三层的信息各自独立：
   - 1934 层：**14 个热区边界**都在这一层（`index.html:138-153` 的 `g.zones` 只出现在 `trace--1934` 里）
   - 1936 层：只有 `R-3 / R-7 / R-9` 三处修订与擦痕（`index.html:165-180`），**不含热区**
   - 1938 层：12 个测点 + 三条等深线（`index.html:182-196`）

   登记表里"所在层与线型"一列实测分布：仅 1934 = 9 块、1934+1936 = 2 块、仅 1936 = 1 块、仅 1938 = 2 块。
   → 用户要有的**不是"3 个版本的内容"**，而是**同一片空间在两三个时点的测量结果，且每次测量改动了哪一块要能指认**。

3. **删内容会怎样（实测）**：把 14 个热区删到 2 个，`.plate` 的 SVG 高度 **1026px → 1026px 不变**，而登记表仍有 14 行 → **12 行变成孤儿**。这正是"留洞"的机理：图与表的耦合是手工的。

**给用户的一句话**：你得先有同一片地方的几个年份量测，每块都带面积。

### S18 磷光检修台 —— 要「一条按时刻排的流水，挂出和摘回共用同一个牌号」

**要手上有什么**：一份**已经发生过的事的连续记录**——每行带时刻，其中有一类动作是"挂牌"（把某设备标成停用），后面必然跟着"摘牌"；同一次挂牌/摘牌要用**同一个牌号**认出来。

**证据**：

1. **牌号是成对的主键**。4 张牌 412 / 530 / 608 / 857，每张都有 tag 行与摘牌（或待核）行，且行号可精确定位：

   ```
   412  tag@第5行  摘牌@第9行
   530  tag@第10行 摘牌@第39行
   608  tag@第18行 摘牌@第58行
   857  tag@第28行 撤牌@第44行
   ```
   （由 `index.html:97-164` 三段各 20 行、共 60 行逐行解析得出；段首 `aria-label` 声明"行 1 至 20 / 21 至 40 / 41 至 60"）

2. **机制绑绝对行号，这是 hard 的核心**。牌挂在右侧悬挂区，纵向位置由 `--at` 乘行高算出：
   - `style.css:132`：`.hangrail .hang{position:absolute;left:0;top:calc(var(--at,0) * var(--line) + 2px)}`
   - `style.css:17`：`--line:24px`
   - `index.html:172,179,186,201`：`--at:5 / 10 / 18 / 28`

   即 **`--at` 是"第几行"，改一行下游全要手改**——`index.html:197-200` 的注释记录了上一轮把 `--at:34` 改成 `28` 的修法（857 牌真正挂在第 28 行）。

3. **改一行会怎样（实测，这是最有力的一条）**：删掉第 1 行整行后重新对齐，牌与行的对应关系**集体错位一格**：

   | 牌号 | 删除前最近的行 | 删除后最近的行 |
   |---|---|---|
   | 412 | 第 6 行 `回执 412 牌位 泵体下阀` ✓ | 第 6 行 `log 本段走纸 20 行` ✗ |
   | 530 | 第 11 行 `回执 530 牌位 出口阀` ✓ | 第 11 行 `log 字体点阵英文…` ✗ |
   | 608 | 第 19 行 `回执 608 牌位 出口阀` ✓ | 第 19 行 `check pump-3 出口压力` ✗ |
   | 857 | 第 28 行 `tag …牌号 857` ✓ | 第 28 行 `回执 857 写入待核` ✗ |

   → **流水少一行，四张牌全部挂错行**。这不是"变短"，是"指错"。

**给用户的一句话**：你得先有一条按时刻排的流水，挂出和摘回共用同一个牌号。

### S21 联锁释放簿 —— 要「每条说清卡住哪几条，条数要对得上切口」

**要手上有什么**：一组**互相制约的步骤**（谁不先做，谁就动不了），每一步都要说得清"它卡住的是哪几步"。**光有"有依赖"不够，依赖的条数必须数得准**——这个案子的几何是按条数算出来的。

**证据**：

1. **互斥关系是双向图，14/14 完全对称**：
   ```
   lock 1  excl 9,12,13   (3 对)  in-degree 3
   lock 3  excl 9,12,13,14 (4 对) in-degree 4
   ...
   14 枚锁，pairs == excl.split(',').length : 14/14
   反向引用缺失（A 说卡 B、B 没说卡 A）: 0 处
   angle == 15 × pairs                    : 14/14
   ```
   数据源：`index.html:234-247` 的 `data-lock / data-pairs / data-angle / data-excl`。

2. **切口角度不是装饰，是从条数算出来的**，而且公开成表供核对：
   - `index.html:286`：「锁闭条右端的斜切角不按外观决定，只按该枚锁的互斥对数分三档」
   - `index.html:287-321` 角度表：30°↔2 对（4 枚）、45°↔3 对（6 枚）、60°↔4 对（4 枚）
   - `style.css:559-561`：`cut-30/45/60` 三档 `clip-path`，`style.css:558` 注明"水平进深分别是 41.6 / 24.0 / 13.9 像素，与角度表第四列一致"
   - 实测 rail 内 14 枚三种角度的分布 **4 / 6 / 4**，与表完全一致（`lockbar--demo` 那 1 枚在 rail 外，`index.html:365`，不计入）

3. **删一条会怎样（实测）**：删掉 9 号锁后，`1→9 / 2→9 / 3→9 / 5→9` **4 处互斥引用指向不存在的锁**，而 `pairs` 字段仍是原值、`angle==15×pairs` 仍成立 → **数据和几何同时变成谎话**（`excl__list` 里还列着 9 号）。rail 高度 349px → 74px（5 条），但角度表仍写"本时段 14 枚"。

**给用户的一句话**：你得先说清每条卡住哪几条，条数要对得上切口。

### S29 钢丝安全册 —— 要「每条一个零件号，图上和表里各写一次、能互相对上」

**要手上有什么**：一份**可拆解的物件清单**——一台设备能拆成 N 个零件，每个零件有编号，并且这个编号要在**两个地方各出现一次**（爆炸图上、零件表里），点一个能跳到另一个。

**证据**：

1. **23 ≡ 23 ≡ 23 有序全等，0 重复**（本轮重新实测）：
   ```
   g.pt[data-part]        : 23 个，01..23 连续无跳号
   tr[id="part-NN"]       : 23 行，01..23
   a[data-back]           : 23 个，01..23
   parts == rows == backs : true
   unique(parts/rows/backs): 23 / 23 / 23
   缺行: none ｜ 缺图: none
   ```

2. **双向跳转是真读取，不是装饰**：`index.html:548-568`
   - 点图上编号 → `document.getElementById('part-' + no)` 闪该行（`:550-554`）
   - 点表里"看剖面" → `querySelector('.pt[data-part="' + back + '"]')` 回跳加粗（`:561-566`）
   - 文案自述见 `index.html:196`「点图上任何一个编号都会跳到零件表里对应的那一行」、`:201`「图上 07 是机械密封，零件表第 7 行必须是同一件」

3. **删一件会怎样（实测）**：删掉零件 07，图剩 22 个、表仍 23 行，且表里 07 那行的回跳链接**目标消失**（`danglingBack: true`）→ 点"看剖面"跳到空。

4. 附带证据：12 个章节号 `1.1…4.3.2` 四级式样、21 处 `N·m` 数值，均在 `index.html` 内可枚举。

**给用户的一句话**：你得先给每条一个零件号，图上和表里各写一次、能互相对上。

## ② 「数据结构」这个词，非技术用户能懂吗

**不懂。而且比"不懂"更糟：它会把人劝退。**

三条理由，都可核：

1. **仓库里从没对用户用过这个词**。`prototypes/_selection/*.js|html` 全文检索 `数据结构 / 数据形态 / 数据格式` **0 命中**。这个词只活在 Agent 与审计文档之间（`deliverables/62-*`、`63-*`）。用户侧现有的词汇是「条目」「内容」「真实图片」「适用场景」，是生活词。突然蹦出"数据结构"，等于切换了语域。
2. **它指的东西本身不直观**。我们要表达的是"有键、有对应关系"——这件事的直觉载体是**具体的物件**（牌号、零件号、面积、年份），不是抽象层级的"数据结构"。
3. **它暗示"你需要会技术"**。用户此刻的心态是"我要把这个风格用在我的生意上"（任务书原话）。"数据结构"四个字会被读成"这活我干不了"，而真相恰恰相反——**大多数生意手上就有这些数据，只是没意识到那叫数据**。餐馆有菜品和价格（有键）；修车行有工单和车牌（有流水）；五金店有零件号（有编号）。文案的任务是**让他认出自己已经有**，不是告诉他门槛在哪。

### 三个可读替代表述

| 候选词 | 适用场景 | 例句（可直接用） | 代价 |
|---|---|---|---|
| **A.「你手上得先有…」** | **首选**。用于 hard 那半句 | 你手上得先有一条按时刻排的流水，挂出和摘回共用同一个牌号 | 略口语，但对 12px 小字最稳；且"手上"呼应"你的生意" |
| **B.「这案子要的是…」** | 详情面板正文、卡片 tooltip 等**有多行空间**处 | 这案子要的是同一片地方的两三个年份版本，每块面积都是量出来的 | 把重心放在"案子"上，用户是被审视的一方，压力感稍高 |
| **C.「先看素材：…」** | 选型向导（`wizard.html`）、空状态、上手清单 | 先看素材：同一片地方有没有两三个年份的实测面积 | 最像清单项、最适合"勾选式"自检；但**不适合**放在复制按钮旁——它读起来像要用户先去做一件事才能继续 |

**淘汰的表述**（写下来是为了不再被提出来）：
- 「非结构化/结构化内容」——比"数据结构"更技术
- 「特殊数据」——空话，四个案无法各自点名（§4 判据会直接判它不合格）
- 「行业数据」——**正是这次要推翻的错**（替换实验证明换成水果名版式也不崩）
- 「数据形态」「数据模型」——同义词替换，没解决可读性

## ③ 三个文案候选与推荐

**硬约束（先算清，再写）**：
- 只说「你需要有什么」，不说「这案子有什么毛病」

- 一句话说完（句号只出现一次，不用分号堆从句之外的结构）
- 落在 `复制 AI 提示词` 按钮右侧，12px、行高 19.44px、可用宽 517px/1440 与 347px/390（实测）

### 推荐 A，四条理由

1. **主语是用户，不是案子。** 用户此刻的念头是"我要把这风格用在我生意上"，他关心的是"我能不能用"，不是"这案子难不难"。A 的落点是"你手上"，B/C 的落点是"这案子"/"素材"——把用户放到被审视位置，或把他推去做前置作业。
2. **A 是四个案唯一能保持同一句式骨架的。** `你手上得先有 X` 后面接四种完全不同的 X（量测/流水/关系/编号），句式不变、内容各异。C 的 `先看素材：有没有…` 在 S21 上被迫改成"能不能说清"，骨架已经破了；B 则把四个案都说成"这案子要"，读起来像免责声明。
3. **A 最长的一条 47 字，仍在 66 字预算内，且 1440 档单行**（实测：注入 46 字候选后 `spanH=19px`、`lines=1`），比现在少一行——**顺带把按钮右侧的行数从 2 行降到 1 行**。
4. **A 删掉了"具体不适合什么，写在详情「适用场景」段末"这句指路**。这句 21 字是旧文案最贵的部分，而它指的东西用户点开详情就在眼前（`app.js:446` 渲染「适用场景」字段）。删掉它，预算才腾出来给真正有用的信息。**注意**：`prompt-copy.js:459-462` 的注释说这个字段"不存在"——实测**该注释已过期**：`app.js:446` 就在渲染 `field('适用场景', r.scenes)`，且 30/30 案的 `scenes` 都含"不适合"从句、都在段末（见 §6）。

### 落地形态（`prompt-copy.js:471-477` 替换）

```js
var riskyTopic = !!s.hard;
var riskyCount = !!(s.capacity && s.capacity.degrades === "yes");
if (riskyTopic || riskyCount) {
  var why = [];
  if (riskyTopic) why.push(TOPIC_NEEDS[id] || "你手上得先有一份能互相对上的清单");
```

## ⑤ S03 的 `degrades` 核实：**验证 Agent 的结论方向对，理由全错**

### 结论

**`degrades` 应为 `yes`——同意。但"8 条影像带高度写死、少一条会留洞"这个理由不成立。** 真实机理是另一件事，而且更严重：**版面没洞，是轴和数据对不上**。

### 逐条核实

**① "高度写死"——属实，但没造成洞。**

`index.html:71-102` 的 8 条 `<figure class="band" style="--h:28px">` 等，`--h` 值确实写在 HTML 里。但 `.band` 是**普通块流**：`style.css:144-149` `.stream{position:relative}` 不定位子项，`.band` 只有 `margin:0 0 4px`。所以删带子只会变短。

**实测**（1440×900）：

| | 8 条（原始） | 删到 3 条 |
|---|---|---|
| `.axis` 高 | **640px** | **640px（不变）** |
| `.stream` 高 | 335px | 96px |
| `.chrono` 高 | 787px | **787px（不变）** |
| 空档 | 305px | **544px** |

→ **没有"洞"（破版），只有"空"（留白变大）**。按仓库自己的定义（`app.js:212`「单元位置是写死的，内容少了会留洞」），这**不构成 degrades**。验证 Agent 把"空"当成了"洞"。

**而且仓库上一轮的实测结论本来就是这个。** `deliverables/60-minitems-degrade-audit.md:27` 给 S03 判 `no`，理由逐字是：「`index.html:70-102` 8×`figure.band`（`.stream`），每张 `style="--h:28px…84px"` 只是条高；`style.css:145` `.band` 普通块流，`:144` `.stream{position:relative}` 不定位子项」。→ **"`--h` 只是条高、块流不定位子项"这句话，正是本轮删带子实测证实的东西**。验证 Agent 的提议是在推翻一份已被复算过的结论，且没有给出新的测量数据。

**② 真正的缺陷是轴与数据零耦合——这是 hard 的证据，不是 degrades 的证据。**

- 年代轴由 **5 个字面量**画成，与 8 条带子完全无关：`index.html:234-235` `var years = [1957,1962,1967,1972,1977]`
- 而数据到 **1978**：`index.html:101` 最后一条带 `1978-11-30`
- **实测轴停在 1977，数据到 1978-11-30，轴少了 1 年**

这正是 `build-prompts.mjs:90` 撤销 S03 `hard` 的理由原文：「年代轴是 5 个字面量 [1957..1977]，与 8 条带零耦合，且轴停在 1977 而数据到 1978」。**上一轮已据此撤了 hard，本轮不应再用另一个理由把它加回 degrades。**

**③ "`--h` = round(秒数×28/30)"——公式成立，但 `--h` 是**手抄**进 HTML 的，不参与计算。**

8/8 全部吻合：30s→28、45s→42、15s→14、60s→56、20s→19、40s→37、90s→84、25s→23（`round(sec×28/30)` 逐条相等，0 例外）。

但**改秒数不会改高度**（实测）：把第 1 条的 caption 从 `30 s` 改成 `90 s`，`.band` 高度仍为 **28px**（`style --h` 仍是 `28px`），没有跟着变成 84px。

→ 这**恰恰证明它是 hard 型的"手工预炸数据"**（和 S14 的 110 个 CSS 变量、S21 的 175 个 `data-*` 同类），而不是 degrades 型的"位置写死、少了留洞"。

**④ 还有一个 degrades 也覆盖不到的耦合**：8 条带与读数表**逐行一一对应**（日期+秒数 8/8 全等），删一条带 → 表多出一行数据无图。
