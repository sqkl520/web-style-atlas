## §0 方法与判定口径

### 0.1 四种裁定的定义（可复核，不含"我觉得"）

| 裁定 | 判定条件（全部满足才给） | 举证要求 |
| --- | --- | --- |
| **误报** | ①它主张的**缺陷不存在**，或②它主张的缺陷存在但**它的测量方法给了错误结论**（口径错／测量法错／把设计意图当缺陷／把工具缺陷当页面缺陷） | 必须给出**反证实测值**：我自己的数字、或判据原文、或截图文件名 |
| **成立（且已修）** | 缺陷存在，且当前树上已有修复，修复可被实测复现 | 实测修复后数值 + 修复落点（文件:行） |
| **成立** | 缺陷存在、未被修、且**修它的收益大于代价** | 缺陷实测值 + 成本（人时）+ 回归风险 |
| **成立但不必修** | 缺陷存在、我**先确认它成立**，但 (成本 × 回归风险) > (可见收益 × 影响面) | 成立证据 + 明确的代价账 + 若不修的可替代动作 |
| **无法判定** | 缺一项决定性证据，且该项证据在当前环境下**不可获得** | 必须写清"还需要什么证据、为什么现在拿不到" |

**"成立且已修"与"误报"绝不混用。**"它报错了"和"它报对了但事后被修了"是两种相反结论——本轮明确按后者处理的 6 条见 §1 上半区。

### 0.2 我给"修复成本"的计法

- **人时**：只算改动本身 + 必须跟着做的验证（`render-scheme.mjs` 重跑、三档截图复看、`data.js` 重生成）。
  不把"开会讨论要不要修"算进去。
- **回归风险**：按"改动的作用域"分级——`media` 内单条声明 = 低；改可见内容/版式 = 中；
  动已审计案的基础规则或断点骨架 = 高。
- **收益**：分四档——**功能失效**（点了没反应／信息不可达）> **硬性不达标**（WCAG AA 未过、明文契约未闭合）>
  **可复算数字与实际不符**（文档/数据层）> **观感**。

### 0.3 我的实测工具自身被纠正过的两处（写在这里以免读者重复踩）

1. **对比度算底色必须把"元素自身背景"算进去。** 我第一版 `bgOf()` 只走祖先链，量 S25 `button.btn--quiet`
   得到 4.71:1；把元素自身 `backgroundColor` 合进去后是 **4.29:1**——与原报告的 4.29 一致，是我错它对。
2. **CDP `Page.captureScreenshot` 的 `clip` 是文档坐标**，不是视口坐标。第一版裁剪把视口坐标当文档坐标，
   拿到 366×844 的纯黑图；改为 `rect + scrollY` 后全部正常（`_crit9/crop.mjs` 已固化这个写法）。

## §2 判"误报"的逐条展开（7 条纯误报 + 3 条内含被驳回的子断言）

### 2.1 纯误报（7 条）

**AH-17（M02 导航被遮挡）——测量法错：对未渲染的折叠内容做命中测试。**
它在 390 档把 5 个链接的"中心点"交给 `document.elementFromPoint`，拿到 `rect` / `div.hero-band` 就判定被遮挡。
但那 5 个链接在 `<details class="nav-mobile">` 内且 `open=false`：`a.checkVisibility({contentVisibilityAuto:true,opacityProperty:true,visibilityProperty:true})`
返回 **false**，`getComputedStyle(.nav-list).display` = `none`。**它们的盒是 80×59（有坐标、落在视口里），但不渲染**——
于是 `elementFromPoint` 命中的是那个位置**真的在画**的东西（`figure.ph` 占位图内的 `rect`、`div.hero-band`）。
页脚 `ul.foot-list` 的同名链接 `checkVisibility=true`、`selfOnTop=true`，同一档位没事。
截图 `_crit9/shots/M02-nav-390.png` 上只有"菜单 ⌄"一个按钮。
**结论：它报的是"两个根本看不见的链接的坐标被别的元素占用"，不是可用性缺陷。**
它自己在置信度理由里写的"很可能是折叠下拉里的链接"——**猜对了，但那时它没有验证手段**（`checkVisibility({contentVisibilityAuto:true})` 就是那个手段）。

**AH-20（271 vs 281/282）——口径错：把 `_selection/.inspect` 混进 30 案分母。**
`data.js` 引用的截图数（`app.js:45-47` 公式）逐案等于该案 `.inspect` 里的 jpg 数：S01 7/7、S02 8/8、S05 6/6、S09 8/8、S28 10/10、S21 8/8 —— **30 案合计 272 = 272，差 0**。
它数到的 281/282 是 30 案 272 **加上 `prototypes/_selection/.inspect` 的 10 张**（那是选型台自己的截图，不属于 30 案）。
它那句"磁盘上更多，因为每档只引用前 2–3 张"**与事实相反**：30 案是**全量引用**，一张不多一张不少。

**AH-24（根 index.html 的 `system-ui`）——口径用错层。**
禁用字体栈的出处是 `prototypes/_CONTRACT.md` §4，而该文件标题自述"**原型建设契约（新 22 个适用）**"，§2 的输出范围写死为 `prototypes/<Sxx>-<kebab-english-name>/`；
`verify-prototype.mjs` 也只遍历 `prototypes/`。根 `index.html` 是给静态托管用的 0 秒跳转页（35 行、`meta refresh`），
AD 不落在任何规则层。它自己写的"文档从未规定根跳转页也要守 30 案的禁用字体规则，可能是我把口径用错了层"——**这次它猜错了**。

**AH-25（forced-colors 两条被压）——结论错：渲染后果不存在。**
我用 CDP 媒体特征仿真把 `forced-colors` 打开（`matchMedia` 从 false → true），
`.plate__meta` / `.plate__credit` 的 computed color 从 `rgb(36,31,23)` → **`rgb(255,255,255)`**。
也就是说**强制高对比下这两个标签确实变成了 CanvasText**。
被压掉的只是 CSS 里的那两条声明文本（静态级联确实可证），**渲染结果没有差异**——它作为"缺陷"不成立，
作为"死声明"成立但收益为 0。它自己写的"影响可能为零"——**猜对了**。

**AH-26（S08 溢出 155–322px）——把未裁剪的几何量当可见缺陷，而"是否被裁掉"正是判据。**
它自己在条目里写明"未测量：被溢出部分是否被 `overflow:hidden` 的祖先裁掉"。我补测这一项：
390 档 71 个、768 档 60 个越界元素，**逐个** `paintedBeyondViewport = 0`（可见右边界 = 视口右缘，没有一像素画到视口外），
全部被 `div.stage-wrap` 裁掉，`scrollTo(999999)` 后 `scrollX = 0`。截图里印版在舞台右缘被干净切断。
**"155px 越界"在渲染上不存在。**

**AH-27（S14/S26/S06/S23/S30 越界）——同 AH-26，且它自己已写"多数应属意图"。**
5 个组合合计 65 个越界元素，`paintedBeyondViewport` 全为 0、`scrollX` 全为 0。

它把启发式（"越界量远大于可见范围是这类 bug 的典型形态"）当成了证据。
**它给的两条建议里"不需要改"是对的**；另一条（契约里补装饰性越界上限）我保留为流程建议。

**AH-28（近乎空白屏 → 闸门漏洞）——它猜对了规则口径，但"该判没判"不成立。**
规则原文：`inspect.mjs:140` `const empty = frameChecks.filter(f => f.filled < 0.2)`，`:152` `if (w >= 1100 && empty.length >= 2 && !allow.includes('empty-screens'))`。

**闸门没有覆盖漏洞，是它把"阈值只在 1440 档跑"这个前提当成了"该案该判而没判"。**
