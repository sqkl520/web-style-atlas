# Lead 补充验证：`--s-15` 对向导结果页的影响

> 背景：A11y Agent 在报告里明确说：「`--s-15` 连带改了 `wizard.css:68` 的 `.wz-card p`（16→15px，行数不变、无横向溢出，已量已截图）。但向导结果页我没点完五道题，所以『整体观感没变』这句**我没有证据**，只测了那一条 CSS 规则的效果。」

**这一处它诚实地标了「无证据」，我来补上。**

## 验证方法

用仓库自带零依赖 CDP，真实浏览器 1440×900 与 390×844 两档：
1. 打开 `prototypes/_selection/wizard.html`
2. **一次性回答全部五题**（每题点中间档）
3. 等结果渲染完成后，量结果区的结构与字号

> 踩过一个坑：向导是**五题同屏**（不是逐题切换），我第一版探针假设了「选完一题下一题出现」，结果每次都点中问题 1、永远点不动，`resultVisible: false`。看到截图才明白。**这是探针的错，不是页面的错。**

## 结果：两档都正常

| 指标 | 1440×900 | 390×844 |
|---|---|---|
| 五题全部答完 | ✓ 5/5 | ✓ 5/5 |
| 结果区可见 | ✓ `resultVisible: true` | ✓ `resultVisible: true` |
| 推荐卡数 | **3** | **3** |
| 明确排除数 | **3** | **3** |
| 结果区 `<p>` 数 | 27 | 27 |
| 出现的字号 | 13 / 14 / 15 / 24px | 13 / 14 / 15 / 24px |
| **`15px` 是否出现** | ✓（`--s-15` 生效） | ✓ |
| **横向溢出的 `<p>`** | **0** | **0** |
| 页面横向溢出 | 无 | 无 |
| 文档高 | 4,910px | 5,208px |
| 首个推荐 | S26 几何对撞栏 | S26 几何对撞栏 |

## 结论

**A11y Agent 那个「无证据」的判断，实测是安全的。**

`--s-15` 从「未定义（浏览器按 16px 兜底）」改成「15px」，连带影响 `wizard.css:68` 的 `.wz-card p`：
- 字号确实 16px → 15px
- 但 **27 个 `<p>` 无一个横向溢出**
- 页面无横向滚动
- 结果区结构完整（3 推荐 + 3 排除）

**唯一未覆盖的**：我没做「改前/改后」的像素级对比（那需要重建 `--s-15` 未定义的现场）。所以「观感完全没变」这句话仍不能断言，能断言的是「改后不溢出、结构完整、字号符合设计意图 15px」。

## 顺带：向导本身的一处观察

五题同屏、每题 2–3 个选项、全部选完才出结果——这个交互是**没有「下一步」按钮**的（`wizard.html:83-86` 只有「重来」和「复制链接」）。选项点完自动跳到结果区。

所以用户如果只答了前两题，页面不会提示「还差三题」——它只是在原地不动。这是另一个可发现性问题，但不在本轮范围（本轮 A11y 任务只覆盖 5 条已定位缺陷）。
