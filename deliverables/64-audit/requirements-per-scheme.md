## 1. S15 渔场平面簿

### 1.1 一句话要求（可直接贴 UI）

> **同一张图得有两三个年份的版本，各分区带面积**

### 1.2 具体要求

1. **条目数：14 个分区**（设计规模，不是下限）。`index.html:139-152` 是 14 个 `<a class="hot">`，每枚一枚绝对坐标 `<rect class="edge">`；`index.html:283-296` 是 14 行 `<tr id="z-XX">`。两处一一对应（我按 `data-code` / `id` 配对，14↔14，无孤儿、无重复编号）。
2. **每个分区要有 4 个属性**：① 唯一编号（`B-3` / `N-1` / `G-1` 这种"字母-数字"式）；② 空间位置（x/y）；③ 尺寸（w×h）；④ **登记面积（m²）**。
3. **面积必须和画出来的方块对得上**。我按 `w×h/6400 = 声明 m²` 独立重算 14 条，**14/14 残差 0.0000%**，且 14 个矩形的 `x/y/w/h` **全部是 8 的整数倍**（14/14），14 个矩形两两**不重叠**（0 处）。这是一条真的恒等式，不是凑的。
4. **同一张图要有 3 个时间版本，且是"同一张图"的三个版本，不是三张不同的图**：`index.html:129`（1934 原始平面）/ `:165`（1936 网具区修订）/ `:182`（1938 水深补测）。三层共用同一个 `viewBox="0 0 896 1024"`，且 `#p-frame`、`#p-wall` 两张底图符号**各被复用 3 次**（我数了：3 次 / 3 次）——这是"同一张纸叠三次"在代码里的物证。
5. **条目与版本之间是"归属"关系，不是"互斥"**：`index.html:436` 的 `layerOf` 把每个分区编号的**首字母**映射到年份（`B/N/W/R/D/M → 1934`，`S/G → 1938`）。也就是说一个分区属于哪一层，是由它自己的编号决定的，用户得知道"这一区是哪一年测的"。

### 1.3 反例

- 「我只有 3 个产品」——凑不到 14 个区，更凑不到"同一个东西的 1934/1936/1938"。
- 「我的分区没有面积」——`legend__note`（`index.html:214`）与页脚（`:406`）都写着 `46.40m² + 22.40m² = 68.80m²`，这是页面上印出来的数；没有面积，这行字就是编的。
- 「我只有一版内容，没有修订史」——这是最致命的，见 1.5。
- 「我的东西是并列的 8 个卖点」——并列关系没有"年份"这个维度，三层无从落。

### 1.4 代码证据

| 要求 | 证据 |
|---|---|
| 三层是**绝对叠放**的，不是三个 section | `style.css:169` `.trace { position: absolute; inset: 0; opacity: var(--op,1) }` |
| 三层必须有**不同的错位量** | `style.css:170` `transform: translate(var(--off), var(--off))`；`:171-173` `--off: 0px / 3px / 7px` |
| 三层的内容**必须不同**，否则叠起来看不出差别 | `index.html:129-163`（14 个热区 + 港池）/ `:165-180`（只剩 3 处修订 R-3/R-7/R-9 + 4 块擦痕）/ `:182-196`（12 个测点 + 3 条等深线） |
| 三层是**同一支铅笔**（同一张图的三个版本） | `style.css:176` `mix-blend-mode: multiply`；`:197` 所有 `use` 共用 `stroke: currentColor` |
| 只有 1934 / 1938 两组能切 | `style.css:174-175` 只有 `[data-year="1938"]` 两条规则，没有 1936 |
| 分区面积被印在页面上 | `index.html:214`、`:406`、`:283-296` 每行一个 `<code>N.NNm²</code>` |

### 1.5 特别核实：到底要"3 个年代"还是"14 个面积对得上"？

**答：要"3 个年代"，面积是配套的一致性约束，不是主要求。** 三条理由：

1. **面积是硬编码的，没有一行代码读它。** 我把 S15 的 `<script>` 整段抽出来查：`width` / `height` / `rect` / `area` / `m²` / `6400` **全部零命中**。JS 只碰 `reg`、`fault`、`stack.dataset.year`、`--trace36`、`is-lit`、`is-cued`。所以 14 个矩形的尺寸和表格里的 m² 是**两处手写、彼此校验**，不是一个"数据驱动"的机制。换内容时它不会崩——只是 "面积按舱室真实面积等比"（`index.html:214`）这句话变成空话。
2. **三层是结构性的，缺了就塌。** `.trace` 是 `position:absolute; inset:0`（`style.css:169`），高度由相对定位的第 1 层撑（`:171` `position: relative`）。第 2、3 层如果是空的，**不报错、不塌**，但也不显示任何东西——三层退化为"一层 + 两片空白"。
3. **更糟的是切换会露馅**：`style.css:174-175` 只写了 `[data-year="1938"]`——点"第 3 层"，第 1 层淡到 `--op: 0.3`、第 3 层升到 `1`。如果第 3 层没有真内容，**用户点一下就看到主图淡掉、画面近乎空白**。这是"版式崩"的一种，只是崩在交互之后。

**所以两个审计各对一半，但都说偏了**：
- "要 14 个面积对得上"——数字对（我复核 14/14、0.0000%），但这是**作者期转写忠实度**，不是用户必须具备的东西。
- "要 3 个年代"——对，且是真正的结构要求；但**只对了一半**：代码里"第 2 层"连热区都没有（`layerOf` 无 1936），点它直接 `return`（`index.html:463-467`）只闪一下错误态。也就是说这案子实际只需要**两个**可读版本 + 一个"缺页"占位。规格要求三档（`_specs/S15.md:29`「固定三层」），实现只跑通两档。

### 1.6 用户不满足会怎样

**不是版式崩，是"点一下画面就淡没了"。**
- 只有 1 个版本：第 2、3 层是空 div。点年份按钮 → `style.css:175` 把第 1 层压到 30%，空层升到 100% → 整张平面图淡成一片浅灰，页面上只剩图例和比例尺。
- 有 14 个分区但没有面积：`index.html:214`「建筑内 12 区 46.40m²，建筑外 2 区 22.40m²，图幅合计 68.80m²」变成三个编出来的数；`index.html:300` 那句"空状态挂在 M-1 上，它是唯一只被登记、没被测绘过的区"也失去依据（因为"测绘过"的定义就是"有面积"）。
- 有 3 个版本但版本之间不是"同一张图"：`mix-blend-mode: multiply`（`style.css:176`）会把三套不同坐标系叠成一片无法辨认的线团——这个我看代码能确定，三层的 `viewBox` 必须一致。

## 2. S18 磷光检修台

### 2.1 一句话要求（可直接贴 UI）

> **得有一条按先后排好、能数到第几行的长记录**

### 2.2 具体要求

1. **条目数：60 行**（设计规模，`prompts.js:1139` 记 `minItems: 20` 是"折页一段"的量）。`index.html:97-116` / `:121-140` / `:145-164` 三段各 20 行，共 60 个 `<span class="ln">`（我数了：20/20/20，`class="fold"` 折页线 3 条）。
2. **每一行要有：① 时刻（精确到秒，`14:06:30` 这种）；② 一个动作词（`tag` / `摘牌` / `回执` / `check` / `log`）；③ 一个对象（`pump-3` / `出口阀` / 牌号 `412`）。** 时刻必须**严格递增**——我逐行比对 60 行的时间串，**0 处逆序**。
3. **行必须是"可按下标寻址"的**：某一张牌（回执牌 412 / 530 / 608 / 857）要能找到它"挂在第几行"。
4. **条目之间是"先后 + 因果"关系，不是并列**：`tag 412`（第 5 行）→ `回执 412`（第 6 行）→ `摘牌 412`（第 9 行）。同一张牌有"挂上 / 回执 / 摘下"三段生命周期，且摘牌必须晚于挂牌。
5. **必须有一个真冲突**：两张牌（530 与 608）抢同一个牌位（出口阀），才生得出 `TAG-409`（`index.html:278`、`:285-287`）。没有冲突，整套错误态是空的。

### 2.3 反例

- 「我一共只有 5 条更新，还是按重要性排的」——`--at` 按行号定位全部失配；20 行一折的折页线只剩 0–1 条（`style.css:185`）。
- 「我的记录没有时刻，顺序无所谓」——60 行里每行都以时刻开头，`index.html:220` 的折页索引表还按"每段第一行的回执时间"取 `14:02:11 / 14:22:07 / 14:40:11`。没有时刻，这张表和 60 行全部作废。
- 「我的条目是并列的（服务项目 / 团队成员）」——`tag → 回执 → 摘牌` 这个三段生命周期不存在，挂牌的"未摘 / 已摘"两种状态也就没有意义。
- 「我不会同时有两条记录抢同一个位置」——`TAG-409` 强制要求这种冲突（`index.html:279`「两张牌挂在同一个阀上，等于没人能说清该由谁签字复位」），没有它，页尾整段是空转。

### 2.5 特别核实：是"`--at` 行号定位"还是"连续流水记录"？

**答：两个都要，但它们是同一件事的两层——`--at` 是那条流水被"按下标寻址"的方式，流水本身才是数据要求。**

- `--at` 确实是机制：`top: calc(at × 24px + 2px)`，把"第几行"直接换成像素。改一行日志，这条 `--at` 就得跟着改。
- 但"四张牌挂在特定行"只是**这条流水的一个用法**。真正的门槛是：**你得有一条够长（60 行 / 20 行一折）、严格有序、每行带时刻、且条目之间有"挂上→摘→再挂"生命周期的记录。** 8 个并列的产品卖点给不出这个——不是牌挂错了，是根本没有"第 5 行"这回事。
- 顺带纠正一处**审计自己说已修好、其实还没修好的事**：`style.css:122-131` 的注释说 off-by-2 已修（旧式 `at×line + line + 2` → 新式 `at×line + 2px`）。按现行公式重算：行 n 的顶 = (n−1)×24，牌顶 = `at×24+2`，解得 **所在行 = at + 1.083**。也就是说 `--at:5` 现在落在**第 6 行**，不是第 5 行。**从偏 2 行变成偏 1 行**，`--at` 与行号仍差一个。要真正对齐，公式该是 `(at − 1) × var(--line) + 2px`。
  - 置信度说明：这条是**纯算术**（`style.css:17` + `:132`），我没有浏览器实测（见 §4）。但两行代码都在，任何人都能复算。
  - 这一条正好说明问题：`--at` 这种"手写行号"的写法本身极脆，审计三轮都在争它偏了几行，而**无论偏 0 行还是偏 2 行，用户需要的数据都没变**。

### 2.6 用户不满足会怎样

**不是崩，是"纸变成便条"，外加牌挂到别人旁边。**
- 只有 10 行：三段 `<pre>` 各 20 行的结构撑不住，`index.html:168` 那句"三段共 60 行，其中回执行 9 条，挂牌 4 条、摘牌 5 条"直接是假数（我按语义数：真正的 `tag` 行 4 条、`摘牌` 行 7 条、`回执` 行 7 条——连原型自己的统计都和正文对不上）。折页线从 3 条掉到 0 条，`style.css:185` 的折痕纹理没有落点。
- 顺序一改（插入/删除一行）：`--at:5/10/18/28` 全部失配，四张回执牌会飘到不相关的行旁边（`style.css:132` 只认数字，不认内容）。**页面不会报错**，牌还挂着、还在摆（`style.css:149`），只是挂错了阀门。
- 没有"同一牌位两张牌"的冲突：`TAG-409` 那段（`index.html:278-297`）没有对象，`data-retry` 按钮点下去只会改一句文案（`index.html:456-461`）。
- 没有时刻：`index.html:220` 的折页索引表、「摘牌靠回执行留痕」（`index.html:263`）全部失去依据。

## 3. S21 联锁释放簿

### 3.1 一句话要求（可直接贴 UI）

> **得有「要了这个就不能要那个」的成对清单**

（**不用"互斥"这个词**。理由：`_specs/S21.md:15` 用的是"两根杆之间存在物理互斥关系"，`index.html:268` 用闭塞器的 `LINE CLOSED / TRAIN COMING FROM` 两个状态举例——那台机器上写的就是"一个时刻只给一个"。对非技术用户，"互斥"是行话；"要了这个就不能要那个"是他自己会说的话。）

### 3.2 具体要求

1. **条目数：14 条**（设计规模，`prompts.js:1271` 记 `minItems: 14`），编号 1–14 连续、不重复（我核过：14 个 `data-lock`，零重复）。
2. **每个条目要有：① 唯一编号；② 一个"叫什么"（道岔 1 / 信号 A）；③ 一张"和谁不能同时存在"的名单；④ 名单的长度。** `index.html:234-247` 每条都写着 `data-lock` / `data-lever` / `data-pairs` / `data-excl`。
3. **这份名单必须是"双向的、封闭的"**：A 说和 B 冲突，B 也必须说和 A 冲突；不许指向不存在的编号。我独立重算：**42 条有向关系，21 对，全对称，0 条悬挂，0 条单向**。
4. **每个人的"冲突数"要不一样**（这是最容易漏的一条）：现行数据里冲突数是 `2/3/4` 三档，分布 **2 对 4 枚、3 对 6 枚、4 对 4 枚**。这个分布不是随意的——它**必须**长得像 `index.html:299-320` 那张角度表（30 度→4 枚 / 45 度→6 枚 / 60 度→4 枚，我逐行核过，与 `.cut-30/45/60` 在锁条上的实际出现数 **4/6/4 完全一致**）。
5. **条目之间还要有"谁在谁之前"**：`index.html:78` 的「前序锁」列是 锁1←锁2←…←锁14 的一条严格链（我逐行核过 14/14）。

### 3.3 反例

- 「我的 8 个功能是并列的，互不相干」——`data-excl` 只能全空或全填同一组。
- 「我的条目冲突数都一样」——三档角度塌成一档：`style.css:559-561` 只有 `.cut-30 / .cut-45 / .cut-60` 三个 `clip-path`，全填 45 度就只有一种切口，"按互斥对数分三档"（`index.html:286`）当场变成假话。**这是本方案最具体的一条退化。**
- 「我只有 3 个服务套餐」——凑不到 14 条，`style.css:520` 的 `gap:1px` 扣接缝隙只有两三条，横向路径撑不满（`style.css:492` 占第 5–6 栏）。
- 「我的关系是"包含"不是"互斥"（大类含小类）」——包含关系可以 A⊂B⊂C 传递，互斥不能传递；`style.css:590` 的 `box-shadow` 高亮会点亮一串不该被点亮的条。

### 3.5 特别核实：这个"互斥"用户懂不懂，怎么说？

- 规格自己的说法是"物理互斥"（`_specs/S21.md:15`），页面上的说法是"哪两根杆不能同时扳动"（`index.html:48`）、"同一时刻只能给出一个"（`index.html:268`）。**页面已经在用大白话了，只有审计报告还在用"互斥图"。**
- 给 UI 的说法建议就用 3.1 那句。若要更短：**「得有『二选一』的清单」**（11 字），但会丢掉"可能同时和 3、4 条冲突"这层意思——而这层意思正是三档角度的来源，所以我还是选 3.1 那版。
- 额外核实：`data-pairs` 这个属性**没有任何代码读**（JS 查 `data-pairs` 零命中），它和 `data-excl` 的度数只是"两份手写数据恰好相等（14/14）"。角度也是——`data-angle` 只被用来写文案（`index.html:454`），**没有一行代码把 `pairs` 换算成 `angle`**。所以"角度由冲突数决定"目前是**声明**，不是**计算**。这点会影响 UI 文案的口气：写"有多少条冲突，切口就有多陡"是在承诺一个页面没做的事，建议写"每条得有几个对手"。

### 3.6 用户不满足会怎样

**版式不崩、条数还能加减（这是四案里唯一 `degrades:"no"` 的，`prompts.js:1271`），塌的是语义，而且塌得很难看。**
- 没有冲突名单：`data-excl` 为空 → `light()`（`index.html:443-457`）先 `clear()` 点亮 0 条，再把提示写成 **「第 1 枚锁闭条（道岔 1）与 0 枚锁互斥： 号。切口 45 度…」**——一句话里出现"0 枚"和空编号，**用户会以为页面坏了**。这是本组四案里唯一会当场产出**语病**的退化。
- 冲突数全一样：三档角度塌成一档，`index.html:286`「全站共用这一张表」与 `index.html:348`「数出几条，就能拿尺子量出切口该有多陡」全部失效——因为再没有"陡"和"缓"的差别可量。
- 只有 3 条：`style.css:516-527` 的竖向扣接带只有 3 格，`style.css:499` 的 `position:sticky; bottom:48px` 让这么短的路径几乎不动，"读一列等于走一遍推理"（`_specs/S21.md:13`）无从谈起。
- 有"包含"没有"互斥"：高亮会点亮整条链，用户看不出"到底卡在哪一根"。

## 4. S29 钢丝安全册

### 4.1 一句话要求（可直接贴 UI）

> **得有一台能拆成二十几个编号零件的实物**

### 4.2 具体要求

1. **条目数：23 件，编号 `01`–`23` 连续、不重复、不许跳号**（`index.html:88`「零件号两位，从 01 到 23…不许跳号，缺件时保留空号」）。我核过：`data-part` 23 个、`id="part-NN"` 23 个、`data-back` 23 个，三列**有序全等**（不只是集合相等，顺序也一致），零重复。
2. **每件要有：① 唯一编号；② 名称；③ 材料；④ 一个能写进表格的数值（扭矩 N·m / 间隙 mm / 压量 mm / 对中 mm）。** `index.html:244` 表头就是这五列。实测 23 行里 **21 行有数值，2 行是「—」**（02 泵体蜗壳、13 轴承箱）——所以"每件都带数"这条要求，原型自己也没做到 100%。
3. **图和表必须能双向跳**：图上点编号 → 跳到表里那一行并闪一下；表里点"看剖面" → 图上那一件加粗。`index.html:87`「两套编号必须双向能跳」，`:272` 再说一遍。
4. **23 件必须是同一台设备的分解**（不是 23 个并列产品）：`index.html:209-231` 是 23 条手绘 `<path class="pc">`，沿同一条轴心线 `M48,300H912`（`index.html:207`）排开，左边吸入侧、右边电机侧。这是**装配几何**，不是列表。
5. **编号还要和章节编号共存**：`4.2.1` 式样四段以内（`index.html:87`），且"图上 `07` 是机械密封，零件表第 7 行必须是同一件"（`index.html:201`）。

### 4.3 反例

- 「我只有 3 个 SKU」——23 件凑不出，`style.css:188` `.spec--parts tbody th{width:9.5em}` 那列宽度也没意义了。
- 「我的产品没有编号」——`getElementById('part-' + no)` 拿不到东西，点图上的编号**什么都不会发生**（见 4.6）。
- 「我的说明书是纯文字，没有可拆解的结构」——爆炸图 23 条路径画不出来，`index.html:196`「一台离心泵拆成 23 个零件」这句是页面主视觉的全部理由。
- 「我有 23 个功能，但它们是并列的」——`index.html:207` 那条轴心线要求它们沿一个轴排开、有"左是进口右是出口"的方向；并列功能没有轴向。
- 「我的编号是 1、2、3 不是 01、02、03」——表里 `01` 是两位等宽（`style.css:53` `font-variant-numeric:tabular-nums`），`4.2.10` 与 `4.2.1` 要上下对齐（`_specs/S29.md:19`），一位数会错位。

### 4.4 代码证据

| 要求 | 证据 |

| 23 件在表里，ID 是编号 | `index.html:247-269` 23 个 `<tr id="part-01"> … <tr id="part-23">` |

### 4.5 特别核实：这个"三列严格双射"在代码里是怎么实现的？

**不是靠"列表顺序凑巧一致"，是靠三处编号字面相等 + 两次按键查表。**

1. 图上每个零件组带 `data-part="NN"`（`index.html:209-231`）；
2. 表里每行 `<tr id="part-NN">`（`index.html:247-269`）；
3. 每行末尾 `<a … data-back="NN">看剖面</a>`（同段），把跳回去的目标也写死在行里；
4. JS 两个方向都是**拼字符串 + 按键取**，不是 `nth-child`：
   - 图 → 表：`getElementById('part-' + no)`（`:550`）
   - 表 → 图：`querySelector('.pt[data-part="' + data-back + '"]')`（`:561`）

所以"双射"的实现方式是：**三个数组（`data-part` / `id=part-NN` / `data-back`）必须逐项相等**。这不是渲染时算出来的对应，是**数据必须自己长成对应**——这正是 hard 的含义：它要求用户手上那份清单**本来就有唯一编号**，页面只是把这个编号当主键用了两次。

我独立重算的结果：三列各 23、有序全等、0 重复、0 悬挂（`data-back` 的 23 个目标都能在图里找到对应的 `.pt`）。

**一个必须点出的短板**：这套双射**没有防错**。`flash()` 第一句就是 `if (!row) return;`（`:551`）——编号对不上时它**静默返回**，用户点了没反应、也没有任何提示。

### 4.6 用户不满足会怎样

**不崩、不报错，是"点了没反应"——这是四种退化里最难排查的一种。**
- 编号有跳号（比如没有 12）：图上第 12 件仍是 `data-part="12"`，但表里 `part-12` 不存在 → `getElementById` 返回 `null` → `flash()` 在 `:551` 直接 `return`。**页面上没有任何反馈**，用户只会觉得"这个图点不动"。
- 编号重复（两个 `07`）：`getElementById('part-07')` 只返回第一个，第二件永远跳不到同一行；`querySelector('.pt[data-part="07"]')` 同理。**两个零件会指向同一行参数**，这在安全手册里是事故级的错（`index.html:201`「对不上说明这一版的图与表不是同一次印刷」）。
- 零件数不足 23：`style.css:215-221` 的逐件描画只给了 `:nth-of-type(8)` 到 `:nth-of-type(24)` 共 17 个 `--i` 值（我核了，17 条），少件时那条动画时间轴空转；`index.html:196`「23 个零件」与 `:240`「零件表 · 23 件」两处印死的数字要改。
- 只有并列条目、没有装配关系：23 条 `<path>` 画不出来，"沿轴心展开、吸入侧在左、电机侧在右"（`index.html:233`）就没有依据，主视觉退化成 23 个带编号的方框——**版式还在，但它不再是"一台泵"，而是一张清单**。

## 6. 最容易被误解的一案：S15

**为什么是 S15，而不是机制最绕的 S21：**

1. **它有一个"漂亮得可以当证据、却不是要求"的数**：14 个矩形 `w×h/6400 = 声明 m²`，残差 0.0000%。任何审计拿到这个都会想写进报告——第一份审计确实写了，还给它配了个**不存在的引用**（说依据是 `_specs/S15.md:26` 的「1 单位 = 1.25cm」；`S15.md:26` 讲的是 12 栏与 40px 出血，全文件没有"1.25cm"三个字）。第二份审计抓到了假引用，却没顺势问"那真正的 hard 在哪"，而是换了个论据（三层不同内容）——**换对了，但没解释为什么面积不是**。
2. **真实要求恰好不可数值验证**："同一张图有三个年份的版本"没有残差可算。它就藏在 `_specs/S15.md:52` 一句大白话里（「任何没有『多版本信息』的项目套上去，三层就变成无意义的装饰」），和 `style.css:169-176` 六行 CSS 里。
3. **对用户来说，最像"风格"的部分（三层透叠、错位 0/3/7px）恰恰是最难满足的部分**：用户看到的是"复古描图纸好好看"，看到不的是"你得先有三个年份"。
4. **还有一层自我矛盾会误导判断**：规格写"固定三层"（`S15.md:29`），代码只跑通两层（`style.css:174-175` 只有 1938 分支；`index.html:463-467` 点 1936 直接 `return` 只闪错误态；`layerOf` 里没有 1936）。**第三层在实现里是个"缺页"演示，不是内容层。** 所以严格说它要的是"2 个可读版本 + 1 个可空版本"，而文案上写"3 个年份"会许一个页面没兑现的愿。

**次席：S21。** 它机制最干净（0 悬挂、42 条全对称），但"互斥"这个词对非技术用户是纯粹的行话，且 `data-pairs` / `data-angle` 都不被代码读、角度也不是算出来的——**文案若说"冲突越多切口越陡"就是在承诺一个页面没做的事**。
