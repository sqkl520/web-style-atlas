## 结论：这是真缺陷

**关键发现：16px 的 `chars≥60` 节点数量 = 0。**

`.row-def`（一句话定义，`var(--s-16)`）和 `.field dd`（`var(--s-16)`）确实写的是 16px，但：
- `.row-def` 太短（每张卡一句话，约 20–30 字），**进不了 `chars>=60` 的筛选**
- `.field dd` 在**默认收起的折叠块**里，不可见

而页面上**真正最长的文字**是 `span.row-family` 的家族借鉴描述（152–219 字/案），它是 **13px**。

## 这是「两个正确决策叠加」的产物

**决策 A（上一轮执行 C）**：把 `.row-family` 从 `slice(0,34)` 改成显示全文。

理由（我当时认同并写入 commit `1753f94`）：
> S15 显示「北欧渔业档案（1930 年代挪威）」，而作者真正写的是「参考三个真实对象…偷的机制是…我们拿的是透叠层数与擦痕，不是泛黄纸感」。**行卡上丢了作者最有价值的判断。**

这个修复本身是对的——可见字数从 657 涨到 5,911。

**决策 B（更早，`87a0235` 前后）**：`.row-family` 的字号是 `var(--s-13)`（13px）。

当时它是元数据小字，13px 合理——因为它只显示 34 个字符（首句）。**改成显示全文后，它变成了页面上的主体文字，13px 就不合理了。**

## 判定

| 项 | 判定 |
|---|---|
| `body-size` FAIL 本身 | **真缺陷**（页面上最长的连续文字用 13px 呈现） |
| 是不是 lint 误报 | **不是**。这是动态闸门，判据就是「字符数最多的字号」，产品确实如此 |
| 该不该加 `allow` | **不该**。加了就是"让检查闭嘴"，而这里真的有一个可读性问题：**用 13px 排 152–219 字的连续中文段落** |

## 修法（交给执行 Agent 验证）

最小改动：把 `.row-family` 的 `font-size` 从 `var(--s-13)` 提到 `var(--s-15)` 或 `var(--s-16)`。

但要先算代价：
- `.row-family` 是 `line-clamp: 2`（行卡里最多 2 行），字号变大 → 每行字少 → **可见字数下降**
- 行卡高度可能变化 → 影响 390 首屏「1 张完整卡」这个刚做出来的指标

**替代修法**：把 `.row-family` 恢复成短版本（首句 + `…`），另加一个可展开的「完整家族说明」在详情面板里。这样：
- 行卡保持 13px（元数据地位正确）
- 长文本回到它该在的地方（详情面板，16px）
- `body-size` 的 7,025 字符主要来源消失

但**代价是撤销上一轮"显示全文"的修复**，而那个修复的理由（"行卡上丢了作者最有价值的判断"）依然成立。

**这是一个真实的取舍，不是 bug。** 我倾向：先试「提字号到 15px + 保持 line-clamp:2」，实测首屏指标，若不退化就采用；若退化，则降回 14px 试。

**执行 Agent 若选择 `allow`，必须有比上面更强的论证。**
