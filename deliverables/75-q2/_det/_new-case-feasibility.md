# N31–N35 可行性：这条渲染链能建新案，但「图」是硬约束

> 2026-11-10　实测记录

## 一、渲染链可用（已实测）

`node prototypes/_build/render-scheme.mjs S17-revenue-stamp-stub` 退出码 0，
FAIL=0、WARN=3、9 张截图俱在。W1 的两处修复在位：
`vendor/inspect.mjs:57` 的 `launch()` 在 `:64` 删图之前；`vendor/cdp.mjs:64` 超时 60000。
**新建一个方案 → 三档视口出 report.json，这条链今天是通的。**

## 二、但「图从哪来」是硬约束

`_CONTRACT.md §10`（2026-10-18 实测，非配置问题）：

> 能检索的图源在本环境**全部不可用**：Wikimedia / archive.org / openverse / DuckDuckGo
> 全部 ECONNRESET 或 ETIMEDOUT；loc.gov / picryl / pexels / pixabay 是 403 拦截页。
> 仍然可用的只有：**images-api.nasa.gov**（题材偏航天、地球观测、地面设施）、
> 以及 unsplash/pexels/pixabay 的**直链**（无 API key 无法发现地址）。

契约给的替代路径：`assign-assets.mjs` 从工作区**已有语料**（209 条真实照片）交叉分配，
不足的用 NASA 补；纹理用 `make-textures.py` 的 **14 个确定性生成器**。

### 2.1 实测现状

| 项 | 实测 |
|---|---|
| 全库位图 | **364 张** |
| 其中生成纹理（CREDITS 标"生成物/纹理/程序化"） | **45 张** |
| 其中照片/其他 | **307 张** |
| 确定性纹理生成器 | **14 个**（grain / scanlines / grid / halftone / streak / blotch / fiber / flake / crease / band / misreg / rule / groove / vignette） |
| 逐张署名覆盖率 | **312/364 = 85.7%**；5 案有缺口（S02 2、S04 25、S15 6、S16 1、S21 18） |

### 2.2 结论：新案必须偏「少图 / 无照片」

如果 N31–N35 里有哪一案的目标是「多图」「图片是主角」，它**建不出来**：

- 不能抓新照片（图源不可用）；
- 只能从 209 条已有语料里交叉分配，而那批照片**已经带着原始署名与"原本为哪个案抓取"的记录**，
  再用就等于第 N 次复用，且 S04/S21 自己还有 43 张没署名的缺口没补（R1 的债）；
- 14 个纹理生成器做不出"店面照片"，只能做纸纹、网纹、扫描线这一层。

**这恰好与缺口合流**：`check-distribution.mjs` 实测全库 `minPics` 最小是 **4**，
没有任何一案是「店主只有两三张图」能用的。那个缺口本来就要靠「少图」来补，
而少图正好是这条链**唯一**能新建的类型。

**所以 N31–N35 的选题应当全部落在「minPics ≤ 2」与「无照片、纯排版/纯纹理」这一侧。**
这不是妥协，是让最缺的缺口与最可行的技术路径重合。

## 三、选题约束的三层（按硬度排序）

| 层 | 约束 | 来源 | 违反的后果 |
|---|---|---|---|
| 硬 | 不得有远程 URL | 契约 §5 | 闸门 FAIL |
| 硬 | 不得用禁用字体栈（Inter/Roboto/Arial/system-ui 等） | 契约 §4 | 闸门 FAIL |
| 硬 | 正文 ≥15px、标题 ≤2 行、无横向溢出、无静止态 box-shadow、有错误码、有 reduced-motion 降级 | 契约 §6 | 闸门 FAIL |
| 硬 | **图片来源只能是已有语料 / NASA / 14 个纹理生成器** | 契约 §10 | 建不出来 |
| 软 | 同一结构标签最多 3 次（现有最高 2 次） | 契约 §F | `check-distribution` FAIL |
| 软 | 同一美学家族互斥 | 契约 §F.1 | 人判 |
| 软 | 与最接近的那一案要有结构差异 | 计划 §5.1 第 8 条 | 人判 |
| 软 | 7 种调性每种 ≥3 案（现最低 3 案，已压线） | 契约 §F.4 | `check-distribution` FAIL |

**「调性每种 ≥3」已压线**：`奢华暗黑 / 高定` 正好 3 案。新增 5 案若都不落在这一调性，
它仍是 3（不红）；但若将来有案被归档，会立刻跌破。这一条要记着。

## 四、五个缺口的可建性逐个判

| 缺口 | 需要几图 | 靠什么素材 | 可建？ |
|---|---|---|---|
| 中间明度带（现 1 案，Lab 口径 0） | 少 | 纯排版 + 纹理（纸纹/网纹） | **可建** |
| 亮底紫（现 0 案） | 少 | 纯排版 + 纹理 | **可建**（颜色是 CSS 的事） |
| 很安静（现 2 案，要 5） | 少 | 纯排版 | **可建**（安静的案子天然少图） |
| 少货少图 minPics ≤2（现 0 案） | **≤2** | 2 张纹理或 1 照片 + 1 纹理 | **可建，且这是最该建的** |
| 结构标签不新增撞车对（现 8 对） | — | — | 需选未撞车的标签；22 个标签里 14 个还有余量 |

## 五、给选题的具体建议

按「缺口 × 可建性」交集，五个案子的画像应当是：

1. **一两案纯排版、零照片**（minPics = 0–1）——补 `low-photo` 缺口的正解。
   纯排版 + 纹理在 30 案里几乎不存在（307/364 是照片），这本身就是差异化。
2. **至少一案落在中间明度**（CIELAB L\* 31–81），且不能再是亮黄那种 HSL 误判。
3. **一案亮底紫**（色相 260–320、明度 ≥60）。
4. **三案「很安静」**（调色板最高饱和 ≤25）——这三案天然少图，与第 1 条重叠是好事。
5. 结构标签从**有余量的 14 个**里选，且每案要说清「它解决哪个现存案解决不了的处境」。

> 未验证的部分：以上都是**约束层**的判断。具体五案的机制、字体、布局怎么写，
> 属于设计工作，不在本文件的证据范围里。
