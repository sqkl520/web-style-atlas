# 负对照 B（S98）：删掉全部尺寸数值后，模型做不出任何东西

> 2026-11-13　主线程
> 这是区分「数值承重」还是「文字承重」的唯一实验。结果很明确。

---

## 一、结论

**删掉全部尺寸数值后，模型在两小时、29,320 行输出、44,788 thinking token 之后，
一个文件都没写。**

对比：S31 用同样的流程、同样的模型、几乎同样的任务书（只多了数值），
**约 30 分钟写出 399 行页面**，六个可测值精确命中。

## 二、实验设计

### 2.1 怎么造的 S98

从 S31 的产品提示词出发，只改数值相关的内容：

| 项 | S31（有数值） | S98（无数值） |
|---|---|---|
| 机制句 | 主刻度每 60px、长 34px、3px 宽，次刻度每 12px、长 12px、2px 宽 | 主刻度的间隔宽、刻线长而粗，次刻度的间隔窄、刻线短而细，主次两级按固定倍数递进 |
| 线宽 | 1px | 只用一级，全站同粗细 |
| 字号 | 正文 16px；最大标题 6.5 倍（约 104px） | 正文是常规阅读字号；最大标题压到正文的好几倍 |
| 条目数 | 6 个条目 | 一组条目 |
| 图片数 | 至少 1 个图片位置 | 要有不同的图片位置 |
| 风险段 | 含 60px / 12px / 3px / 1px | 改成「主刻度的间隔、次刻度的间隔、主刻度的线宽」 |

**刻意保留的两项：配色 hex、字体名。**

理由：它们是**设计身份**，不是尺寸参数。而且保留配色能做内部对照 ——
如果产物仍精确用上那 5 个色，说明「照着值做」这条通道本来是通的；
那么如果结构做不出来，差异就只能来自「数值 vs 文字」。
全删就分不清是「删太多让它无从下手」还是「文字不承重」。

自检：改写后全文**无任何 `px`、无任何「N 倍」**，配色行完整保留。
40 行 / 5090 字节（S31 是 40 行 / 5025 字节）。

### 2.2 怎么跑的

真隔离沙箱（NTFS Deny ACE + 独立账户），超时设 120 分钟。
与 S31 完全相同的 runner、相同的模型参数、相同的元指令。

## 三、结果

```
总行数        29,320
thinking 峰值 44,788 token
工具调用      5 次
文本块        2 个（都是空的）
工具错误      1 次（第一次 Read 试图读目录而非文件）
产物          **无**
耗时          约 2 小时（跑到超时）
```

5 次工具调用分别是：

```
Glob  **/*
Glob  *
Read  C:\tmp\bb-home\.claude\projects\C--tmp-bb-S98\memory\MEMORY.md   ← 不存在
Read  C:\tmp\bb\S98\task.txt                                            ← 成功
Read  C:\tmp\bb\S98\_run.ps1                                            ← 成功
```

它读了任务书、看了 runner 脚本、查了记忆目录，**然后开始思考，再也没有动手**。

### 3.1 排除的替代解释

- **不是 API 故障**：我一度以为 stream 里有 205 处 `API Error 524`，
  逐条核查后发现那些 `524` 全部来自 UUID 和 token 计数（`estimated_tokens:524`），
  真实的 API 错误数 = 0。
- **不是隔离失败**：它成功读了 `task.txt`，说明工具链正常。
- **不是任务书损坏**：`task.txt` 5090 字节、40 行，格式与 S31 同构。

### 3.2 thinking 在单调增长，不是死循环

采样最近 400 行的 thinking token：15850 → 16432 → 17105，单调递增。
它在**持续推进思考**，只是永远不收敛到「动手写」。

## 四、这个结果意味着什么

### 4.1 「承重的是数值」成立

S31（有数值）→ 30 分钟出 399 行，六值精确命中。
S98（无数值）→ 2 小时零产物。

**差别只有数值。** 配色、字体、调性、机制句的文字描述、防退化八条、验收三问、
输出要求 —— 全部保留。

所以：

> **文字的机制描述本身不足以让模型产出这个结构。让它动手的是数值。**

### 4.2 但要注意一个替代解释（不能忽略）

「零产物」也可能意味着**模型陷入了分析瘫痪**，而不是「它不知道怎么做」。
44,788 token 的思考、5 次工具调用 —— 它在反复权衡，但始终没有开始。

这两者的区别很重要：
- 如果是「不知道怎么做」→ 数值是**信息**，没它就没法做
- 如果是「分析瘫痪」→ 数值是**收敛锚点**，没它就无法结束思考

**我无法从外部区分这两者。** 但它们对产品的含义相同：
**没有数值，用户拿到的是一份 AI 用不动的提示词。**

### 4.3 对 S31 结论的最终定位

三轮实验合起来：

| 实验 | 做法 | 结果 | 说明什么 |
|---|---|---|---|
| S31 | 有数值 | 399 行，六值精确 | 数值通道可用 |
| S99 | 不存在的风格 + 精确数值 | 459 行，9 值精确 | 数值通道与风格无关，给什么都行 |
| **S98** | **有文字、无数值** | **零产物** | **没有数值就做不出东西** |

合起来是一句话：

> **这份提示词之所以有效，靠的是数值，不是文字描述。**
> 数值通道很可靠（S31 + S99 共 11 次验证），
> 但它是「施工图」意义上的可靠，不是「风格描述」意义上的可靠。

这正好符合你定的北极星：**测复刻保真度**。
施工图给全了，模型能照着做对；施工图不给数字，模型做不出来。
这对产品是**好消息**——产品本来就是给施工图的。

### 4.4 但产品有一个真实的脆弱点

如果哪天需要给用户一个「只说风格、不给数字」的简短版本，
**这一轮实验说明那样做不行**。用户拿到会卡住。
