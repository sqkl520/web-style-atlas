# S34 七档：等盲测数据来裁决

## 要回答的问题

S34 的「七档缩进」少排到 5 条，这个案还算不算成立？

## 两边的证据

**说「可流」（`degrades=no`，现况）**

- `style.css:99` 用的是 `.drift-block:last-child`，不是 `nth-child(7)` —— 作者本来就按"最后一块"写。
- 七个 `margin-left` 只是七个绝对值，排 5 条就用 `.d1`–`.d5`，页面只会变短。
- `nth-child(1..7)` 只出现在 `@media (max-width:767px)`（`:223-224`）与
  `prefers-reduced-motion`（`:235-241`），都只改 `margin-bottom`。

**说「必需」（`_specs/S34.md:33`）**

> 「七档左缩进…这是本页唯一的记忆点」

如果七档是记忆点，那少到五档就失去了这个案的全部识别度。

## 一条被忽略的证据：原型自己这个前提就很弱

审计 Agent 实测 7 块缩进 vs 汉字数的相关性：**Spearman ρ = −0.36**
（方向对但很弱）。三块明显错位——

- `d7` 缩进只有 1%，却只有 64 字（应该最"轻"）
- `d4` 缩进 2%，却有 114 字

也就是说 `reuse` 里写的「七档缩进与文字重量的绑定」，
**在原型自己身上只兑现了 36%**。这条硬前提本身就不成立。

## 盲测能回答什么、不能回答什么

这次跑的是**当前版本**的提示词（含新加的动效段），`have:5`。
判据 `judgeItems` 会报「应排 5 条，实得 N 条」。

- **N=5** → 模型照提示词排了 5 条，说明"可流"是站得住的做法；
  但如果产物读起来明显是"七档缩水的残骸"，那说明产品意图（七档是记忆点）更重要。
- **N=7** → 模型又一次抗命保住机制（和第一轮一样），
  说明这条硬前提对模型来说比"排 5 条"更强。
- **N=其它** → 需要看它怎么处理缩进。

**不能回答的**：这条 `reuse` 在原型里的 36% 兑现率是不是本身就该修。
那是另一个问题，与 5 还是 7 无关。

# 裁决数据到了（2026-11-21）

## 结果：两轮都排 7 条，两轮都完整实现了七档

| | 第一轮（旧提示词，无动效段） | 第二轮（新提示词，2859 字） |
|---|---|---|
| `<article>` 条数 | **7** | **7** |
| 七档缩进 | 完整 | **完整，值与原型逐字相同** |
| 怪癖（末块窄 12px） | 未做 | ✓ `:nth-child(7){padding-right:12px}` |

第二轮的缩进值（`deliverables/78-northstar/_blindtest/S34-r2/index.html`）：

```css
.entry:nth-child(1) { --indent: 0%;    }
.entry:nth-child(2) { --indent: 3%;    }
.entry:nth-child(3) { --indent: 5.5%;  }
.entry:nth-child(4) { --indent: 2%;    }
.entry:nth-child(5) { --indent: 7%;    }
.entry:nth-child(6) { --indent: 4%;    }
.entry:nth-child(7) { --indent: 1%; padding-right: 12px; }
```

对照原型 `style.css:102-108` 的 `.d1..d7`：`0 / 3% / 5.5% / 2% / 7% / 4% / 1%`。
**七个值全部一致，顺序也一致。**

## 这说明什么

提示词里有两句互斥的话：

```
2. 你手上有 5 条内容，就排 5 条：不凑整、不留占位符。
6. 这个版式的硬前提（作者原话）：「七档缩进与文字重量的绑定——
   没有一个"每块重量不同"的叙事，七档缩进就成了随机的错位。」
```

**模型两次都选择服从第 6 条、违反第 2 条。** 而且它不是随便排了 7 条，
是精确复刻了七档的值 —— 说明它把 `reuse` 当成了这个案的定义性约束，
把「排 5 条」当成了可协商的建议。

## 裁决：`degrades` 应改为 `yes`

理由不是"模型这么做了所以它对"，而是三条独立的证据指向同一结论：

1. **模型的可复现行为**：两轮、两个不同提示词版本、都是 7 条。
   这不是随机波动。
2. **`_specs/S34.md:33` 的产品意图**：「七档左缩进…这是本页唯一的记忆点」。
3. **`reuse` 是提示词里的硬前提段**，用的措辞是「最难被复用到别处之处」——
   它描述的是**这个案之所以是这个案**，不是"最好这样"。

而支持 `no` 的那条证据（CSS 用 `:last-child`）**只证明了 DOM 可流，
没证明设计意图可流**。作者用 `:last-child` 可能只是写 CSS 的习惯，
不代表他接受五档的版本。

## 改法

`prototypes/_prompts/minitems-parsed.json` 里 S34 的 `degrades` 从 `no` 改 `yes`，
然后提示词第 3 条会从

> 「这个版式是自动流排版，删条目只会让页面变短…你按自己的数量排就好」

变成

> 「但这个版式的位置是按 7 个数出来的…确实不足 7 个时，把空出来的位置整块重排」

后者与「七档是记忆点」一致。

## 但还有一条独立的债，与这个裁决无关

审计 Agent 实测：原型自己的七档缩进 vs 汉字数 **Spearman ρ = −0.36**，
三块明显错位（`d7` 缩进 1% 却只有 64 字，`d4` 缩进 2% 却有 114 字）。

也就是说 `reuse` 声称的「七档缩进**与文字重量**的绑定」，
**在原型自己身上只兑现了 36%**。这一条不管 `degrades` 改成什么都需要单独修 ——
否则提示词会把一个原型自己都没做到的要求交给 AI。
