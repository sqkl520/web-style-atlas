# S31–S35 的提示词是坏的（主线程复核）

> 2026-11-12　抽样 Agent 发现，主线程独立复核确认

## 结论

**S31–S35 这 5 个案的 `plain` 字段是空字符串**，导致产品实际输出的提示词里出现
`请把整页做成这个风格：。` —— 一句没有宾语的病句。

这是我在 Q2 建这 5 个新案时留下的缺陷，而且**全库闸门没有一个发现它**。

## 一、证据

`prompts.js` 里逐案检查：

```
$ node -e "…P.filter(s=>!s.plain).map(s=>s.id)…"
S31 plain= ""  ← 空
S32 plain= ""  ← 空
S33 plain= ""  ← 空
S34 plain= ""  ← 空
S35 plain= ""  ← 空
--- 全部 plain 非空的案数: 30 / 35
```

## 二、根因：手写表只有 30 案

`prototypes/_prompts/build-prompts.mjs` 里有一个手工维护的 `HUMAN` 表：

```js
$ grep -n 'S31:' prototypes/_prompts/build-prompts.mjs   → 无输出
$ grep -cE '^\s+S[0-9]{2}: \{ plain' prototypes/_prompts/build-prompts.mjs
30
```

表里只有 S01–S30。S31–S35 从来没被加进去。

而取值的兜底（`build-prompts.mjs:246`）：

```js
const h = HUMAN[d.id] || { plain: "", scenes: [], minItems: 3, minPics: 3 };
```

**缺数据时默认成空字符串，不报错、不警告。** 然后 `:309` 原样写进产物：

```js
plain: h.plain,     // → ""
```

## 三、为什么闸门没发现

这正是本仓库记录在案的老病：**闸门读不到数据 → 不报错 → 打印一个漂亮的结果**。

- `check-prompts.mjs` 查的是「提示词 ↔ CSS」的数字一致性，`plain` 不参与
- `check-docs.mjs` 查的是文档里的数字，不查数据字段完整性
- `check-twolines.mjs` 查 R1/R6/R7/R8，`plain` 不在其中
- `quarter.mjs` 的 15 步全过 —— 因为它跑的就是上面这些

**没有一个闸门问过「`plain` 是不是非空」。** 而它是一个用户**看得见**的字段
（选型台卡片上的「人话版」描述，`build-prompts.mjs:12` 写着「让用户三秒判断这适不适合我」）。

## 四、对北极星审计的影响

### 4.1 好消息：我的盲测没受影响

我在 `blind-run.mjs` 里拼提示词用的是 `dna.mechanism` + `tone`，**没用 `plain`**。
所以 S31 那次成功的盲测（704s、414 行、六项约束全中）是有效的。

### 4.2 坏消息：产品实际给的提示词是坏的

用户点「复制 AI 提示词」时拿到的是 `prompt-copy.js` 的 `buildPrompt()`，
它第 597 行写的是：

```js
"请把整页做成这个风格：" + s.plain + "。",
```

`s.plain` 为空时，输出就是 `请把整页做成这个风格：。`。
**5/35 = 14.3% 的用户会拿到这句病句。**

### 4.3 对抽样方案的影响

抽样 Agent 的结论是对的：S31–S35 在修复之前**不能进盲测**，
否则量到的是「提示词缺陷」而不是「风格难度」。

这也让我先前给抽样 Agent 的那条约束（「S31–S35 是 Q2 新建这一风险类的全部成员」）
失去意义 —— 这一风险类当前是空集。

## 五、修法

两件事，必须都做：

1. **补数据**：给 `HUMAN` 表加 S31–S35 五项（`plain`/`scenes`/`minItems`/`minPics`）。
   `plain` 要 ≤20 字、不含 px/HEX/角度、能让人三秒判断（`build-prompts.mjs:118` 的判据）。
2. **加闸门**：一条断言「35 案的 `plain` 全部非空且 ≤20 字，且不含数字单位」。
   **必须做变异测试** —— 把某一案的 `plain` 改成 `""`，确认闸门会响。
   否则下一个人加新案时还会重蹈覆辙。

第 2 条比第 1 条重要。第 1 条只修这 5 案；第 2 条防住第 6 案。

## 六、这一条值得单独记的原因

它说明 **Q2 建新案这件事本身没有走完流程**：
建了 5 个案、过了分布闸门、过了契约闸门、过了季度体检，
但漏了一个用户直接看得见的字段。

而且我上一轮写 `01-ROUND-SUMMARY.md` 时，还专门夸过 S31–S35 填补了分布缺口
（中亮度 1→3、亮紫 0→1、很安静 3→5、少图 1→4）。**分布是补上了，提示词是空的。**
