## §0 结论先行

**结论稳，但不是「10/10」这个数字稳。** 现有重复数据（不新跑，全部取自磁盘与 git 历史）给出三层结果：

### 0.1 一号结论：达标项的**判定结果**完全稳定，但**产物本身**差异极大

找到 5 个案子各有 ≥2 份独立产物（§1.1）。达标项逐案比较：

```
案   份数  配色      线宽      字号比                      图片
S04   2   4/4=4/4  3/3=3/3  4.24 = 4.24              12/9 vs 10/9 ✅均达标
S08   3   6/6 全同 4/4 全同  4.88 = 4.88 = 4.88        7/4 三份全同
S13   2   4/4=4/4  5/7=5/7  3.73 = 3.73              6/4 vs 5/4 ✅均达标
S15   2   4/4=4/4  6/6=6/6  5.75 vs 5.80（差 0.9%）    18/18 全同
S29   2   6/6=6/6  7/7=7/7  4.69 = 4.69              7/6 vs 6/6 ✅均达标
S31   2   5/5=5/5  1/1=1/1  6.5 = 6.5                3/1 vs 0/1 ❌ 这一项不一致
```

**判定结果 6 案 × 4 项 = 24 个格子：23 个两次一致，1 个不一致（S31 图片数）。**

字号比是最硬的一项：**6 案 13 份产物，比值两两之间的最大差是 0.9%**（S15 的 5.75 / 5.80），
其余 4 案完全相同到小数点后两位。配色与线宽在 13 份产物里**没有一次**出现「一份全中、另一份缺」的情况。

### 0.2 二号结论：但「产物稳定」这件事是假的 —— 同提示词能做出**不同生意**

这是本轮最重要的发现，也是任务的预判（「S31 两次差异很大本身就是重要发现」）应验之处：

| 案 | 第一次的生意 | 第二次的生意 | 正文 8-gram 重合 |
|---|---|---|---|
| **S04** | 野电流 · 菜市场二楼的独立展览空间 | **贴满印社 · 一面墙的印品** | **0.042** |
| **S13** | 棉纸公函 · 盲压装帧条例 | **蝉翼石室 · 拓本档案馆** | **0.004** |
| **S29** | 液压缸大修规程册 · HY-114 | **漏点对章节 · 密封件与备件行** | **0.000** |

三案的**页面标题、店名、内容全部换掉**。字节数差 0.9%（S04: 32542→32829）、
diff 670~1856 行、正文几乎没有一句共用。

对照：S08 三次的标题**一字不差**（`琥珀暗房 AMBER DARKROOM — 六块手冲板`），
8-gram 重合 0.91~0.97。S15 两次也是同一家店（`一介 · 旧房改造小组`），重合 0.878。

**所以复现性不是一个数，而是两个层次：**
- **数值层**（配色、线宽、字号比）：高度稳定，跨 13 份产物零翻转
- **内容层**（做什么生意、店名、文案）：**不稳定，同一个提示词能从「菜市场展览」跳到「印社」**

而「10/10」这个结论只在数值层成立，它**从来不是**对内容层的断言。
报告 §一 自己也写了这个口径（`06-BLIND-RESULT.md:74`：「这张表证明『数值被遵守得很稳』，
不证明『风格被传达』」）—— 本次审计的重复数据给这句话补上了定量证据。

### 0.3 三号结论：十案产物的**完整性全部成立**，无截断

12 份产物逐一检查（§4）：`</html>`、`</body>`、`</style>` 全部闭合，
CSS 花括号收支为 0 且最小深度不为负，`<div>` 开闭数全等，无 `TODO`/`省略`/`lorem`。

**更强的证据**：每份产物的文件 mtime 与它自己 stream 里**最后一次写入的时间戳精确吻合到秒**：

```
S15  mtime 07:29:39  ←  stream last write 23:29:39.652Z
S29  mtime 05:57:46  ←  stream last write 21:57:37.878Z
S35  mtime 05:33:01  ←  stream last write 21:33:01.164Z
S99  mtime 06:14:37  ←  stream last write 22:14:37.167Z
```

「超时边缘救回来」不等于「未完成」—— 它们是**完整写完**之后才超时的。
（唯一例外见 §4.3：S04 的 stream 里根本没有 Write 调用，产物来源存疑。）

### 0.4 四号结论：报告里有 4 个数字与磁盘不符，且**方向都对本轮有利**

| 项 | 报告写的 | 磁盘实测 | 性质 |
|---|---|---|---|
| S13 字节 | 25730 | **31256** | 报告用的是旧版本 |
| S15 字节 | 44814 | **47030** | 同上 |
| S29 字节 | 59861 | **41371** | 同上 |
| 线宽全中 | **9/10** | **8/10** | 报告多算一项 |

前三个是因为 `_staged/` 里留着上一版产物（`-oldverify`），报告表格抄的是旧值。
第四个是 `S18` 缺 4px 在正文里被点出来了（`06-BLIND-RESULT.md:91`），
但汇总行数写成了 9/10（`06-BLIND-RESULT.md:67`）—— 10 案里 S13、S18 各缺一档，应为 8/10。

**这三份「旧版本」不是废文件，它们恰好是本轮唯一的重复样本**（§1.1）。

### 1.2 S31：两次产物（任务指定）

**先纠正任务描述里的一处串位**：

| 文件 | 行 / 字节 | 说明 |
|---|---|---|
| `_probe/_sandbox-S31-out.html` | 399 / 22064 | 与 `C:\tmp\bb\S31\index.html` **md5 相同**，是真跑出来的那份 |
| `_probe/_feasibility-S31-out.html` | 414 / 10722 | 任务里写的是第一份，实际是第二份 |

任务给的行数/字节数把两个文件写反了；按 md5 核对，`_sandbox-S31-out.html` ≡ `C:\tmp\bb\S31\index.html`。

**两份的提示词并不相同。** 这是关键前提：

```
$ diff _feasibility-prompt-S31.txt blind/S31/task.txt
- 26 行 / 2338 字节，写于 2026-11-12 03:27，开头是「你是一个前端开发者…」
+ 39 行 / 5025 字节，写于 2026-11-12 06:00，开头是「下面这份是这个风格的施工图…」
```

后者多了 8 条防退化要求、验收三问、`images/` 占位约定、以及**「版式里至少要 1 个不同的图片位置」**。
前者则明写「不用任何 CDN、不用任何图片文件」。

**所以 S31 的两份不是「同一提示词的两次采样」**，而是「短版提示词 vs 长版提示词」各一次。
这反而让对比更有信息量：**长版多了「至少 1 个图片位」这条要求，产物就有了 3 个 `<img>`；
短版明令不用图片，产物就是 0 个。**

逐项对比：

| 项 | sandbox（长版提示词） | feasibility（短版提示词） | 一致？ |
|---|---|---|---|
| 行数 / 字节 | 399 / 22064 | 414 / 10722 | 差 2 倍 |
| 五个色值 | 5/5 全中 | 5/5 全中 | ✅ |
| 字号比 | 6.5（`clamp(46px,10.4vw,104px)`） | 6.5（`font-size:104px`） | ✅ 计算值相同（实现写法不同） |
| 线宽 1px | 1/1 | 1/1 | ✅ |
| 圆角 / 阴影 | `border-radius:0` / `box-shadow:none` | 同 | ✅ |
| `--scale-major` 等 6 个机制变量 | **全部显式声明**：`--scale-major:60px; --tick-major-len:34px; --tick-major-w:3px; --scale-minor:12px; --tick-minor-len:12px; --tick-minor-w:2px` | **一个都没有**，改写成 `.tick.major{width:3px;height:34px}` / `.tick.minor{width:2px;height:12px}` | ❌ 机制承载方式不同 |
| 图片数 | 3（3/1 ✓） | 0（0/1 ✗） | ❌ 提示词差异导致 |
| 网格轨道 | 12 | 3 | 不同实现 |
| 外链字体 | 3 处 googleapis/gstatic | 0 处 | 短版明令禁 CDN |
| 正文可见字符 | 937 | 931 | 几乎相同 |

**判定：S31 两份的「达标项」在 4 项里 3 项一致，机制值全部落地（只是写法不同：
一份用 CSS 变量声明，一份直接写进选择器），图片项不一致可完整归因于提示词差异。**

「机制值写法不同但数值都对」这件事本身有价值：它说明**判据抓的是数值而不是写法**，
换一种写实现仍然能量到同一批数 —— 这正是 `_batch-compare.mjs` 想要的性质。

### 2.2 串行 vs 并行的真实约束

`_blindbox-batch.ps1:4-9` 写明了为什么不能并行：

> Deny ACE 是按**账户**生效的（`icacls <repo> /deny ClaudeBlindBox`），
> 不是按进程。几个沙箱运行重叠时，任何一个撤 Deny 都会静默解隔离其余的。

实测确认当时的并发情况：**最大同时运行 5 个**（17:48 时刻），
但那是**主线程自己跑的多批**（S04/S08/S22/S13/S32 重叠），不是 batch 脚本并行
—— 这解释了为什么会出现「撤 Deny 互相干扰」的隐患。

### 2.3 三个重跑方案

**方案 A：串行重跑 10 案 × 1 次 = 35 小时，$95**
- 最保真，但要一整个工作日半
- 不能缩短：实测最长 S29 4.91h，固定超时必须 ≥ 6h 才能不截断

**方案 B（推荐）：重跑 3 案 × 2 次 = 约 15 小时，$30**
选案理由见 §5。

**方案 C（最快）：降 effort + 缩超时 = 约 4 小时，但代价最大**

| 手段 | 实测依据 | 代价 |
|---|---|---|
| `CLAUDE_CODE_EFFORT_LEVEL` medium → low | 当前已是 medium（`_make-runner.ps1:24`） | 未测过 low；medium 已经出现 S04/S31 的「大量 thinking 不落笔」 |
| 超时 2400s → 1200s | **会截断 8/10 案**（仅 S35/S97/S32/S22 能在 1200s 内完成） | 大部分案拿不到产物 |
| 换更小模型 | 未测 | 换了模型就不是「同模型重跑」，复现性结论失效 |

**关键警告**：降 effort 会破坏复现性的**前提**。复现性问的是「同条件跑两次一不一样」，
改 effort 就变成「不同条件跑两次」，测的是敏感性而不是复现性。
**而且实测 stream 里 init 事件的 `effort` 字段是 `undefined`** —— 说明这个参数
未必真的传到了模型侧，改它可能只改元数据。要验这一点得先跑一次对照，又是一笔成本。

**性价比判断**：方案 C 省 11 小时但结论不可用（条件变了）；方案 B 的 3 案 × 2 次
已经足以把「23/24 一致」的观测升级成「同提示词 3 次采样」的统计。**建议 B。**

## §3 建议的复现性判据

### 3.1 先回答任务里的问题：「6/8 一次、8/8 一次」算稳还是不稳

**按现行判据（达标项数），算不稳 —— 但现行判据本身有三个缺陷，直接比数会误判。**

缺陷一：**分母会变。** 若两次产物结构不同（如 S31 一份 12 轨道一份 3 轨道），
可判项数就不同，「6/8 vs 8/8」可能只是因为第二次多了两项可测。

缺陷二：**只判「够不够」，不判「多不多」。** `_batch-compare.mjs:91` 只算 `missHex`，
从不检查产物**新增**了提示词没给的色。而提示词明写「不新增更多彩色」。实测这个缺口是真的：

```
S15-oldverify.html   declared=4  used=10   EXTRA=6 [#8B9298 #A9B0AD #B9BFBC #C8CECB #CFD5D2 #D5DAD7]
S15-sandbox.html     declared=4  used=4    EXTRA=0
```

S15 两份在现行判据下**都是 4/4 全中**，但一份偷偷加了 6 个色阶。
「配色全中」这个结论对前一份是**假绿**（同 `MEMORY.md` 记的 W5 三条假绿同源）。
其余 13 份产物全部 EXTRA=0，所以本轮结论没有被污染，**但判据有洞**。

缺陷三：**达标项是二值的，丢掉了「差多少」。** S13 缺 9px/14.5px 两次都一样，
说明这是「案子根本没有需要该档位的元素」，不是「这次没做好」——
二值判定把这两种情况压成同一个 ✗。

### 3.2 建议的判据：三层，各有阈值

**第 0 层（前置）：可判性检查** —— 不算分，先确认两次可比

```
□ 两次的 task.txt md5 相同                    ← 本次 S31 就是在这里失败的

任一条不满足 → **不进入复现性判定**，先修条件。S31 就属于这一类（提示词不同）。

**第 1 层（数值层，必须稳）：**

**第 2 层（内容层，允许不稳，但要记录）：**

内容层不该判「稳不稳」，而该**定量报告漂移**，因为它本来就不稳（§0.2）。

| 指标 | 采集方式 | 参考区间（本轮实测） | 含义 |

**第 3 层（完整性层，一票否决）：** 见 §4，任一项不过则该份产物作废、不进任何统计。

### 3.3 关于「字节数」

**明确建议：不要用字节数做任何判据。**

实测同一案件不同产物的字节数：10722 / 22064 / 25730 / 31256 / 32542 / 32829 / 39807 / 40074 /
41371 / 44814 / 47030 / 59861。同案之内即可差 2~5 倍。
字节数受外链字体、注释密度、缩进风格影响，与「做得好不好」无关。
报告里出现的字节数（`06-BLIND-RESULT.md:58-63`）只应作为**溯源标识**，
且本次实测已发现其中 3 个与磁盘不符（§0.4）。

### 4.4 S04 与 S31：产物来源存疑（本轮唯一的真问题）

### 4.5 stream 文件本身的损坏（新发现）

```

S18   12003935   4917622        ?
