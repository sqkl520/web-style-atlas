## §0 结论先行：**B（负对照失败）**

**S99 做出了一个和 S31 同量级完整、同量级自洽的页面。** 它 459 行 / 23,204 字节，
比 S31 产物的 399 行 / 22,064 字节**更大**；它把 S99 机制句的**全部 9 个可测值**都实现了
（132px 尺寸链栏宽、1×9px 端点短线、12px 断口、18px 逐级内移、6px 延长线、93px 标题、
15px 正文、24px 行高、5/5 配色），并且做出了机制的**语义**而不只是字面：
7 块的行数读数互不相同、总读数 36 = 七块读数之和、其中 **4 块读数精确等于该块实测高 ÷ 24px**
（另 3 块差 1–3，是真缺陷，见 §3.3）。

**所以「模型照着提示词的数值精确命中」这件事，本身不能证明提示词承载了那个风格。**
S99 的提示词同样是精确数值，模型同样精确命中。区分 A 与 B 的那条证据线，在 S31 那次实验里不存在。

**但这不等于 S31 的结论作废 —— 它把 S31 能主张的东西换成了一个更弱、但更站得住的版本。**
详见 §5。

（盲测版 21 行 / 2,580 字节 vs 产品版 40 行 / 5,025 字节）。负对照的全部价值在于
「除了风格本身，别的都一样」，所以格式必须由同一个函数产出。

实测同构度（`_probe/_compare-S99.mjs` 之外的逐行比对）：

| 行数 | 40 | 40 |

### 1.3 S99 的机制句（写进 task.txt 原文）

> 整页的骨架是一条贴在左侧 132px 空白里的尺寸链：每块内容的上下沿各横向引出一条 6px 延长线，
> 两条延长线之间是一条 1px 尺寸线，尺寸线两端各一枚 1×9px 的端点短线，正中留 12px 断口、
> 断口里竖排这一块的行数（正文 24px 一行）；总尺寸记在最外侧，分段尺寸按 18px 逐级内移——
> 读序是先读最外侧的总行数、再逐级读分段、最后才读块里的字。

**这不是「换了个皮肤的 S31」。** S31 的刻度是「横向尺规、上下两排、60/12px 间距」——
间距是**空间**的单位；S99 的尺寸链是「左侧纵向、三级内移、量的是**行数**」——
读数是**内容**的函数（换一套内容，数字全变，链的位置不动）。这正是 S99 的 `reuse` 字段写的那句。

**但必须如实说：这个区别对模型不是障碍。** 见 §3。

这一节必须写，因为它同时是「本仓库的老病」的第五个实例：**闸门量的不是它声称量的东西**。

| 次 | 现象 | 根因 | 证据 |

| 1 | 报 `NO_HTML_FOUND`，agent 却还在跑，stream 后来涨到 2.7 MB | v1 用「`stream.jsonl` 300 秒不增长 ⇒ 判定失败」 | 23:45–23:50 stream 冻在 13,016 B；agent 之后继续产出 43,892 thinking tokens |

### 3.2 几何层（`_probe/_s99-geometry.mjs`，浏览器实测，1440×900）

这一层比文本层强，因为它排除了「变量写对了但没接上」：

```
.wrap padding-left = 132px；首块相对 .wrap 的左边距 = 132px
三级链的实际左缘 x：总尺寸 170px / 分段 188px / 块链 206px
  → 总↔分段 = 18px，分段↔块链 = 18px          （机制句：18px 逐级内移）

h1 = 93px（Karla）/ body = 15px，行高 24px（Newsreader）→ 比 = 6.20
圆角集合 = {0px}；box-shadow 非 none 的元素 = 0
```

**9/9 可测值在浏览器里实测命中**，三级内移的 18px 也真的出现在几何里（不是只写在 CSS）。

### 3.3 语义层（`_probe/_s99-readings.mjs`）—— 这里是唯一不足的地方

机制句要求「断口里竖排这一块的行数，读数 = 该块实际占的行数」。逐块对账：

| 块 | 读数牌 | 实测高 | 高÷24 | 一致 |
|---|---|---|---|---|
| 01 收件条 | 02 | 48px | 2 | ✓ |
| 02 报头 | 06 | 144px | 6 | ✓ |
| 03 能力表 | 07 | 168px | 7 | ✓ |
| 04 工位 | 09 | 216px | 9 | ✓ |
| 05 步骤 | **05** | 192px | **8** | ✗ |
| 06 图片 | **04** | 120px | **5** | ✗ |
| 07 页脚 | **03** | 96px | **4** | ✗ |

- 读数与实测高一致：**4 / 7**
- 七块读数互不相同：**7 / 7** ✓（机制句与风险段都要求这点）
- 总读数 == 七块读数之和：36 == 36 ✓

后三块的 `--rows` 是 8 / 5 / 4，读数却写 05 / 04 / 03 —— 差 3、1、1。
这是**真的缺陷**，不是我的度量误差（`--rows` 与读数牌在同一个 `section` 里，直接可核）：
`_S99-out.html:63` `.b5{--rows:8}.b6{--rows:5}.b7{--rows:4}`，读数在 `:408 / :430 / :446`。

**但它是「几乎对了」的缺陷。** 4/7 精确 + 3/7 差个位数 + 7/7 互不相同 + 总和自洽 ——
这已经远超「通用漂亮页面」会给出的东西。这恰恰是 B 判定的核心证据：

> 一个**不存在的**风格，模型不但做出了它的全部 9 个可测值，还做出了它的**语义**
> （读数随块高变化），只在三块上执行得不够彻底。

### 4.2 一个必须一并报告的发现：S31 自己也违反了它自己的硬约束

对两边用同一套判据时看到的（`_s99-vs-s31.mjs` / `_s31-mechanism.mjs`）：

- S31 的 prompt 第 5 条写「线宽只用这几级：**1px**」，而 S31 的产物用了 **1px 与 3px**
  （`_sandbox-S31-out.html:124` `.claim{border-left:var(--tick-major-w) solid …}`，`--tick-major-w:3px`）。
  3px 是机制句里的**刻度宽**，模型把它挪用成了分隔线。
- S99 的 prompt 第 5 条写「1px、2px」，产物用了 **1px / 2px / 6px**
  （`_S99-out.html:133` `border-left:6px solid var(--accent)`）。

**两边各有一条越界，性质相同：把机制句里的某个数值挪用到别处。**
所以在「硬约束遵守度」这一项上，S31 与 S99 **同样程度地不完美** —— 这又是一条
「S31 的命中不特殊」的证据。

同时必须说清：**S31 的机制实现是真的**（`_s31-mechanism.mjs` 实测）：
4 条刻度带、每条 1440×34px 贯穿全宽、`background-size: 60px 34px, 12px 12px`、
纹理 SVG 里 `width=[60,3,12,2] height=[34,34,12,12]`、上下两排 / 两条基线两处尺规齐备。
它不是「只写了几个数字」。

## §5 对 S31 结论的影响：**下调**

### 5.1 下调什么

原来 S31 那次要主张的是：

> 给一份提示词，模型能复刻出与原型一致的结果 —— 六个可测值全部精确命中。

**这个主张现在不能单独成立**，因为 S99 证明：**给出任何一组精确数值，同一个模型都会精确命中它们**。
「命中」是提示词格式（「视觉硬约束第 N 条」+ 可测数字）的函数，不是「这个风格被传达过去了」的函数。

S99 的六个值同样精确命中：
`132px`（栏宽）、`1×9px`（端点）、`12px`（断口）、`18px`（内移）、`93px`（标题）、`6.2`（字号比）。
和 S31 的 `60/34/3px`、`12/12/2px`、`6.5`、`104px` 是同一级别的命中。

### 5.2 上调什么（这轮实验真正得到了什么）

**下调的只是「命中 ⇒ 风格被传达」这条推理，不是「提示词有效」这个结论。**

这轮负对照反而给了 S31 三件更硬的东西：

1. **S99 的命中证明「数值可传递」是稳的。** 换一个 5 色全新配色、两个全新字体、
   一套全新几何，模型依然 9/9 精确命中。这说明产品的**数值通道**是可靠的 ——
   这正是产品存在的理由（业主的北极星是「测复刻保真度」）。
2. **S99 命中的是「语义」而不只是「字面」。** 这是本轮最强的发现：
   机制句要求读数 = 块的行数，S99 的产物让读数**随块高变化**（总读数 36 = 七块读数
   2+6+7+9+5+4+3 之和；而这七块按 `--rows` 应当是 2+6+7+9+8+5+4 = 41 ——
   总和自洽，逐块有 3 处差。见 §3.3）。一个「通用漂亮页面」不会
   自发长出一个自洽的尺寸链语义。**但这既抬高了 S31，也抬高了「模型确实在按机制句做」这件事。**
3. **S31 的结构独特性仍然成立，S99 没有推翻它。** S31 的 12 等分方阵 + 贴左边缘长出、
   S99 的 132px 标注通道 + 三级内移，是两个不同的骨架；两者都做出来了 ——
   说明模型能执行**给定的**骨架，但这一幕**没有**测「模型会不会自己想出这个骨架」。

### 5.3 这个对照暴露的真正缺口（下一轮该测的）

S99 证明的不是「S31 假」，而是：**S31 那一次实验的对照组选错了。**

要区分 A/B，正确的问题是「**同一个模型，拿到一份不带数值的风格描述，会不会做出同样的东西**」，
而不是「拿到一份不存在的风格的数值，会不会做出来」。前者测的是「数值是不是承重墙」，
后者测的是「数值能不能被遵守」。本轮测的是后者，答案是「能，而且很稳」。

具体建议（不在本任务范围内，记录给下一轮）：
- **负对照 A（已做，本报告）**：不存在的风格 + 精确数值 → 模型 9/9 命中。**结论：数值可传递。**
- **负对照 B（未做，建议做）**：把 S31 提示词里的**全部数值删掉**（`60/34/3`、`12/12/2`、`6.5`、`104px`），
  只留机制句的文字描述 → 若仍能做出 12 等分 + 刻度带，才说明「文字描述本身」承载了风格；
  若做不出来，说明**承重的是数值，不是风格描述** —— 那时 S31 的结论要再下调一次。
- **正对照（未做）**：把 S99 的 10 行风格正文换成一份**通用漂亮页面**的描述（无机制句、无数值），
  看模型会不会也做出 459 行 —— 这一步才能定量「通用漂亮页面」的基线高度。

### 6.3 一个诚实的边界

**本轮的 served model 不是 `claude-opus-5[1M]`，而是 `deepseek-ai/deepseek-v4.1-flash`**
（`init.model` 与唯一一个 `assistant.message.model` 不一致，与 S31 那次同病，见

可能正是弱模型的执行深度不足。

这一条不改变 §0 的判定：负对照要问的是「给定这份格式，能不能做出像样的页面」，
而**格式是产品的、模型是路由给的**；两者里任何一个成立，S31 的「命中」就都不构成风格证据。
