# 65 · 选型台决策路径 · 第二类：35 张卡上挂着同一个常量警告

日期：2026-11-05
范围：`prototypes/_selection/`（选型台）
命题：店主要靠**方案卡**做决定。卡片上放的东西，要么帮他区分，要么就是噪声。

---

## 0. 缺陷

实测 35 个案，`gate.warnIds` 里 `no-footage` 的命中数是 **35 / 35 —— 100%**。

也就是说，每一张卡片页脚上都印着同一串东西，其中包含 `WARN：no-footage`。

它是一条**零信息量的警告**：

- 对**区分**：35 张卡全一样，它不能帮店主在这张和那张之间做任何选择。
- 对**判断质量**：它在暗示"这 35 个方案都有同一个问题"。而这个问题在本仓库里是**分级的**——`deliverables/12-tool-rule-audit-30-FULL.md` 对每个案的 `no-footage` 逐条判过：

  | 结论 | 含义 | 计数 |
  |---|---|---|
  | `earned` | 该案机制本身不需要视频/动态影像，缺影像是有理由的 | 5 |
  | `indefensible` | 规格里没写任何影像安排，也没有机制上的理由——是真缺口 | 2 |
  | 其它/未覆盖 | 该文件只覆盖了 9 个案 | 2 |

  **"有理由"和"没理由"在卡片上长得一模一样。** 店主看到 `WARN：no-footage`，无法分辨某个案是「它的世界本来就没有视频」还是「作者漏了」。

---

## 1. 为什么是这类问题

卡片页脚的完整形态（`app.js:591-597`）：

```
桌面 3 屏 · 真实图 6 · 横向溢出 0 · WARN：palette-cream font-count no-footage side-scroll
```

四个 WARN 里，`no-footage` 是全库常量。剩下三个才是真能区分的（`palette-cream` 7 案、`font-count` 32 案、`side-scroll` 1 案）。

**`font-count` 32/35 也接近常量**——它几乎同样不携带区分信息，只是没到 100% 那么显眼。

这构成一个结构性问题：页脚这一行**看起来像在提供决策依据**（"这个方案有这些警告，那个没有"），实际上它的主体是一个所有人共有的常量，外加一个 32/35 的近常量。真正的区分信息被埋在噪声里。

## 3. 还有一个更隐蔽的层

这些 id 是**英文短横线标识**（`palette-cream` / `font-count` / `no-footage` / `side-scroll`），页面上没有任何地方解释它们是什么意思。

一个店主看到 `WARN：palette-cream font-count`，可能的理解包括：
- "这个方案的配色有点问题"
- "这个方案没做好"
- "这是个技术参数，跟我没关系"

三种理解里，只有第三种是"正确"的（这些是设计质检的自动规则，多数是风格取向而非缺陷）——而它恰好是最容易让他**忽略全部警告**的那一种。

而真的需要他注意的 `FAIL 3`（S31–S35 五个案，失败项是 `mono` / `hairline` / `few-pictures`）用的是**同一个视觉层级**：都是页脚上的一个小标签。

---

## 4. 和第一类的关系

第一类（报告 64）是「数字旧了」。这一条不是数字错——每个数字都是现算的、真实的。

它是**判据层次的错**：卡片页脚被设计成一个"如实汇报闸门结果"的地方，汇报得很诚实，但**没有按"这条信息能不能改变店主的选择"排序或过滤**。

诚实不等于有用。35 张卡都印着 `no-footage`，诚实且无用。

---

## 5. 可能的处置（待定，等 agent 结果）

1. **过滤常量警告**：出现率 ≥ 90% 的 warn id 不在卡片上显示（但仍在详情面板里保留）。同时保留一条汇总说明「35 个方案都有一条共同的 no-footage，原因见 X」。
2. **区分 earned / indefensible**：把 `12-tool-rule-audit` 已经做过的逐案判定接进数据，`earned` 的不显示、`indefensible` 的显红。这是最准确的做法，但要新增数据字段。
3. **换文案层级**：把 `FAIL N` 从页脚小标签提升为卡片主区的显眼位置，WARN 折进详情。理由是 FAIL 才是"别选它"的信号。

我倾向 **3 + 1**：FAIL 提到能被看见的位置（真正影响决策），WARN 只在详情里出现，卡片上只留一句「N 条常规检查提示，详见详情」。理由：卡片是"选"的地方，详情是"查"的地方，现在两边的信息分工是反的。
