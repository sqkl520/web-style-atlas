## 4. 未修：筛选层的结构性缺陷

### 4.1 色带组与明暗组是同一根轴

实测每颗色带只对应一种明暗（唯「中间明度带」对应两种）。明暗 × 色带 **24 种组合里 15 种为 0（62.5%）**：

| 组合 | 角标承诺 | 实测 |
|---|---|---|
| 亮底 + 冷暗带 | 5 | **0** |
| 暗底 + 暖浅色带 | **18** | **0** |
| 中间调 + 任意 7 条带 | 2 | **0** |

删掉色带这一组可消掉 62% 的结构性归零。

### 4.2 归零组合的规模

| 层级 | 归零数 / 总数 |
|---|---|
| 四根用户轴两两组合 | **36 / 99 = 36.4%** |
| 三组组合 | **176 / 243 = 72.4%** |
| 四组全选 | **195 / 216 = 90.3%** |
| 选任一场景芯片后，其余 9 组点下去 | **821 / 1452 = 57%** |

高频具体组合：`餐厅 + 暗底` → 0（各自单独是 2 和 10）、`咖啡店 + 暗底` → 0、`三五屏 + 很安静` → 0。

（本轮的分面计数让这些 0 在**点下去之前**就看得到，但组合本身仍然存在。归零是数据分布问题，不是界面问题。）

### 4.3 空状态在纯轴归零时说反话

亮底+冷暗带这类"一个字没搜、一颗行业芯片没点"的归零，`#e-why` 仍输出：

> 行业词搜不到，是这 35 个案缺这条数据，**不是你条件加多了**。

而这次**确实就是他条件加多了**。同屏紧接着 `#e-next` 又说「是右侧几组筛选取「并且」取窄了」——两句互相否定。

### 4.4 第一组是单选，但引导语说组内是「或者」

`index.html:171` 明写「组内多选是『或者』」，而 `prompt-copy.js:2143` 每次点击先把所有场景芯片置 false，再点亮当前那颗——实测点「咖啡店」再点「书店」，只留 3 行而非并集 5 行。全页没有一处说明这一组是单选。

### 4.5 场景芯片没有角标数，且结果行不标直连/近似

16 颗实心芯片合计 17 行直连 + 26 行近似（**近似占 60%**）；8/16 颗实心的近似数多于直连数；**5/16 颗实心芯片按方案号排序时第一行是近似行**。结果行里 `直连|近似` 命中 0/4。

44 个词的并集只覆盖 34/35，**S10 没有任何芯片可达**。

### 4.6 排序有 5 个选项，1 个是空操作

「未建的在前」与「方案号」**逐项完全相同**（35/35 全部 `built:true`，比较函数恒返回 0）。5 个里只有「认知门槛」是店主能用的。

### 4.7 标签不可解码

- 「底色属于哪条带」8 个值，全站无定义。`中性中带 / 中间明度带 / 中性浅带` 三种说法非专业人无法区分。
- 「结构类型 F 型 / R 型」全站无解释（只有 README 有），详情面板不含该字段；16/19 对半分，收敛力≈0。
- 「要装多少内容」按字数算而非屏数：`一屏说清` 实测桌面 **3–11 屏、中位 5.5**，S16 = **11 屏**却标"一屏说清"。行卡脚注自己印着"桌面 11 屏"。
- 「要安静还是要扎眼」按调色板最高饱和度算：19 个"就要扎眼"里 **13 个是米白/奶白底**。
- 「建成状态」只有一颗芯片（35/35 全已建），点了行数不变——死控件。
