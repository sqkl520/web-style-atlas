## 2. 两条真发现

### 2.1 底色赋值那句是有效的（上一轮改动的直接证据）

四个案的底色全部正确铺在 `background` 上：

| 案 | 提示词指定底色 | 生成结果 |
|---|---|---|
| S01 | `#EFE7D7` 米黄报纸底 | ✓ 铺在 `html` + `body` |
| S13 | `#F4E3BE` 暖米色 | ✓ |
| S19 | `#E4DECD` 米纸 | ✓ |
| S34 | `#2C3034` 深灰 | ✓ |

S34 尤其能说明问题：`#2C3034` 在 `dna.palette` 里是**第一个**。
如果没有「页面底色用 X」那句，模型很可能把列表第一个色当强调色用 ——
而实际它把 `--paper: #2C3034` 铺满了 `html` 和 `body`。

**这是那次改动的直接验证，不是推理。**

### 2.2 「相邻两级」是模糊表述 —— 已改并复测

S19 第一轮生成里有：

```css
background: repeating-linear-gradient(0deg, var(--paper) 0, var(--paper) 3px,
                                      var(--deep) 3px, var(--deep) 3.4px);
```

提示词规则：「允许渐变时只用**相邻两级**之间的过渡」。

从**意图**上这是对的（S19 是铜版蚀刻，3px 条纹模拟刻线）；从**字面**上
「相邻两级」没有定义 —— `dna.palette` 是一串平铺的「#hex（角色名）」，
没有级这个概念，模型无从判断哪两个算相邻。

**改法**（`prompt-copy.js` 第 ① 条）：

> 需要做渐变或纹理时只用**同一色系里明度接近的两档**，跨度不超过一档
> （比如底色与它稍深的一档之间），不要从深色直接过渡到浅色。

**复测结果**：S19 重跑后 ⑤ 禁项**无违反**。这是盲测驱动改进的完整闭环 ——
发现 → 改提示词 → 重测 → 确认消失。

## 3. 精确值 vs 比例值：这一轮最值得记的结论

提示词里的要求分两类，模型的遵守情况**完全不同**：

**精确值（全部命中）**
- hex 色值 → 4/4、4/4、9/9、6/6，一个不差
- 标题/正文像素 → 96=96、56=56、72=72、108=108，误差 0
- 线宽级数 → 全部在允许级内，零越界
- 字体族名 → 全部命中

**模糊表述（会走样）**
- 「相邻两级」→ 模型自己理解成"任意两色做条纹"
- 「条目设计规模」→ 模型按实际内容量放（见 §5）

这给了一个可操作的方向：**凡是能写成精确值的要求，就写成精确值**。
提示词现在已经这么做了（hex、px、线宽都是精确的），而那些仍然是
模糊表述的地方，就是复刻走样的地方。

## 4. 判据改过三次，前两次都是错的

这一节比结论重要。

### 第一次：字体判据不展开 CSS 变量

只查 `font-family:` 后面的字面值。S13 写成 `font-family: var(--serif-title)`，
于是 4 个字体全判成"没出现"。

**这是判据的盲区，不是模型的错。** 修法：建 `--var: value` 表后递归展开。
修完 S13 字体从 **0/4 → 4/4**。

### 第二次：字号判据漏了 clamp()

只抓 `font-size: Npx` 字面值。S19 写的是
`font-size: clamp(48px, 7.4vw, 72px)` —— 72px 正是提示词要的数，
却被判成「实测 2.09×」。**把完全正确的实现说成失败的。**

### 第三次：用 max/min 比值，而提示词说的不是比值

改成比值后报「实测 9×，要 6.4×」。但提示词说的是
「正文约 17px；最大标题 6.4 倍（约 108px）」，**两个绝对值都精确命中**。
模型把标签压到 12px，于是 max/min 被拉大了 —— 用比值判，
等于用"最小值"冒充"正文"。

**最终版**：直接查两个绝对值（标题取全页最大 font-size，正文取 `body`/`:root` 的
font-size，缺失时取 ≥14px 声明里的众数），各自允许 ±4px。
四个案全部命中。

### 第四次：正文取值用了众数而不是 body 规则

取「≥14px 声明里的众数」当正文。S19 的众数是 22px（它有很多 18–22px 的小标题），
于是报「正文 22px vs 要 16px ✗」—— 而它的 `body{font-size:16px}` 就在那儿，
**完全正确**。判据先信了一个间接信号，把直接信号扔了。

### 第五次：线宽按字符串比而不是按数值比

CSS 允许 `.8px` 和 `0.8px` 两种写法。字符串比对把同一个值判成越界 ——
S19 因此报「越界 .8px .4px」，而提示词写的正是 `0.4px`。

**教训**：这一轮判据错了五次，每一次都是把**正确的东西说成错的**。
这类错比漏判危险得多——漏判只是没发现，误判会让人去改本来没问题的东西。
所以判据报"失败"时的第一反应必须是怀疑判据，而不是怀疑被测对象。

## 5. 已知没解决的

### 5.1 结构条目数：判据分不清"设计规模"与"实际放置数"

S19 报 5/20。它提示词里的「20」是**索引卡的设计规模**，而生成的页面放 5 张卡
（测试输入是"手上有 5 条内容"）—— 这**可能完全正确**。

报告 66 早就指出过这个区别（`minItems` 是设计规模不是"至少要这么多"），
所以这一项只能报数不下结论。

### 5.2 样本只覆盖 4/35

选择上偏"有特色"的案（有空位机制 / 零图案 / 依赖 JS）。剩下 31 案没跑。
其中最值得单跑的是 `hard=true` 的四个（S15 S18 S21 S29）——
它们验证的是另一个问题：agent 自己会不会写 JS 让机制成立。

## 6. 工程要点

完整步骤在 `69-acp-blindtest.md`。三个会再踩的坑：

1. **`session/new` 的 `cwd` 必须存在**，否则报
   `working-directory: directory does not exist` —— 而这个错误在 result 里不在 error 里。
2. **agent 不一定把 HTML 写进文件** —— S01/S13/S34 吐在消息里，S19 真写盘（调了 `edit`）。
   两种都要接住。
3. **agent 会先 `glob` 探路，有时探完就卡住。** 在 cwd 放一条 README
   说明"这是空目录、不用探索"能显著降低卡死率。
   这条 README 不透露任何设计信息，而且更接近真实场景（店主粘提示词时也是空对话）。
