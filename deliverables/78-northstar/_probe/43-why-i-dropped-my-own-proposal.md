# 我自己否掉了自己的方案：四次历史事故，没有一次是「字段为空」

> 2026-11-15　主线程
> 派出去的五专家 Agent 还没回来，但这一条不需要等他们——它是可实测的。
> 结论：**「加一条 dna 字段非空断言」不该做。** 我原来那个方向是错的。

---

## 一、判据

如果一条新断言值得加，它至少应当能拦住这个仓库**真实发生过**的事故中的一次。
下面把四次有记录的事故逐个对照。

这个仓库的闸门史（`check-prompts.mjs` 与 `prompt-copy.js` 的注释记录）：

| # | 事故 | 当时的形态 | 「字段非空」能拦住吗 |
|---|---|---|---|
| 1 | **plain 为空**（S31–S35 建案漏进 HUMAN 表） | `plain: ""` | ✅ **能** |
| 2 | **minPics falsy-0**（S34 真实值是 0，被 `\|\|` 吞掉改成 3） | `minPics: 0` → 写成 3 | ❌ **不能**：0 不是空，`String(0).trim()` 非空 |
| 3 | **palette 截断到 7 色**（S17 缺 `#D6C9AC`） | 值非空，只是少了 2 个 | ❌ **不能**：数组非空 |
| 4 | **h1Size 抽到 30/30 但渲染进提示词 0/30** | 值一直都在 | ❌ **不能**：30/30 非空 |

**四次里只有一次是「值为空」，而那一次已经有 D1 断言在守了。**

### 1.1 实测复核（不是从注释里抄的）

```bash
# 事故 4：h1Size 从来没有空过
$ node -e "…统计 prompts.js 里 h1Size 非空数…"
h1Size 非空: 35/35

# 事故 1：plain 现在是 35/35（当年那个事故已被 D1 修好并守住）
$ node -e "…统计 plain 非空数…"
plain 非空: 35/35
plain 空的案: （无）

# 事故 2 的形态：0 是合法值，String(0).trim() === "0"，非空
$ node -e "…统计 minitems-parsed.json 里 minPics 为 0 的案…"
minPics 为 0 的案: 1 S34

# 事故 3 的形态：palette 长度分布，非空但少
$ node -e "…统计 dna-clean.json 的 palette 长度…"
palette 色数分布: {"4":10,"5":4,"6":8,"7":6,"8":2,"9":5}
```

事故 2 的 `0` 尤其说明问题：`minPics: 0` 是**一个合法的、有意义的、非空的值**。
它在 `build-prompts.mjs` 里被 `||` 吃掉的，正是因为 JavaScript 把 `0` 当成 falsy。
**「非空」和「真值」是两件不同的事，而真实事故恰恰发生在后者。**

---

## 二、这条新断言实际能拦住什么

只有一类：**将来 clean-dna 某次改动让某个字段变成 `""` 或 `undefined`**。

这是一类**从未发生过**的假想事故。而这个仓库已经有一层保护在守它了：
`check-prompts.mjs` 末尾的 `KEY_FIELDS` 陈旧度检查会拿 `dna-clean.json` 与 `prompts.js`
逐项比对，两边不一致就 FAIL。它漏的只是「两边同时变空」——而这种情形要求
`clean-dna.mjs` 和 `build-prompts.mjs` **同时**向同一个字段写空，那不是「静默变空」，
那是有人故意要删掉这个字段。

### 2.1 更麻烦的是：新断言无法证明自己不是恒真

我实测过，假设的断言会响：

```
清空 S13.bodySizeWhy → 断言检出 1 处（应=1）
```

但这次「响」有欺骗性。因为 `bodySize` 为空是 `clean-dna.mjs:1093` 的**合法降级**：

```js
return { text: "", why: "该案没有显式的正文字号规则（浏览器默认 16px，不写进提示词以免编造）" };
```

所以变异测试的绿是假的：它证明「我能检出空串」，却同时会把「不编造」这个**正确行为**
判成缺陷。**变异通过 ≠ 断言正确**——这是这个仓库归纳的第五类缺陷的又一个实例。

---

## 三、那真正的缺陷是什么

不是「字段可能为空」，是**判据分不清三种状态**：

| 状态 | 表现 | 该怎么做 |
|---|---|---|
| 抽取成功 | 有值 | 写进提示词 |
| 抽取失败 | `""` | 报错 |
| 设计上无此值 | `""` + 理由 | 放行 |

区分它们的信息**已经存在**——`dna-clean.json` 里的四个 `*Why` 字段。但：

1. `build-prompts.mjs:364-397` 手工枚举字段时没带上它们（有意为之，注释说「不进提示词，只留档供人复核」）；
2. **而「供人复核」从来没有被任何东西执行过**——四个 Why 在 23 个字段里是零读取者的 8 个之一。

所以真正该做的不是「加断言判空」，是**让那层已经写好的依据第一次被人或机器读到**。
详见 `42-why-fields-dropped.md`。

---

## 四、我的结论

**不做**「dna 字段非空」这条断言。理由三条，任何一条单独成立就够：

1. 四次真实事故里，它只能拦住一次，而那一次已经被 D1 守住了。
2. 它拦不住这个仓库真实事故的主要形态——「值对但对象错／值在但没接上」（事故 3、4）。
3. 它会让「合法空」这个正确行为变成红灯，而变异测试无法发现这个错误。

**该做的**（按优先级）：

1. 修 `_staged` 证据副本可能被覆盖的缺陷（`06-BLIND-RESULT.md` §1.2 记录，未修）。
   它威胁的是**已经入库的全部盲测证据**，比一个假想事故严重得多。
2. 处理「内容层完全不稳」（`20-reproducibility.md`）：同一提示词两次产出文案完全不同。
   这直接影响产品体验，而数值层已经很稳。
3. 让四个 `*Why` 第一次被读到（人或机器），否则「供人复核」是一句空话。

---

## 五、这条自查教会我的

我一开始的推理是：「字段空 → 闸门不报 → 加断言」。三步都对，但**第一步就选错了对象**：
我拿一个自己构造的输入（手工改生成物）当成了真实失效形态。

这个仓库的教训里有专门的一条：

> **量错了对象（元层级）** —— 在分析产品的近似物，而不是产品本身。

我手工改 `prompts.js` 就是那个近似物。真实失效路径是 extract→clean→build 这条链，
而那条链上的真实事故形态，是与空值无关的另外三种。

**下次的顺序应该是：先去 git log 和现有注释里把「真实发生过什么」列出来，
再去设计判据——而不是先想一个判据，再去找它能拦住什么。**
