> 2026-11-14　分析 Agent

> 纪律：不改任何文件（本轮只在 `_probe/_ci-scratch/` 下建了 3 个一次性度量脚本 + 6~10 份产物副本，见 §6）。

## §0 结论先行

**是真问题，但问题的位置和任务书假设的不一样。**

三条结论，按重要性排序：

### 0.1 内容不稳是真的，但它不是「随机性」，是「提示词没给内容」

我生成了 S04 / S13 / S29 的**真实提示词**（不填输入框，即店主什么都不填时拿到的那份），
逐字读完，结论是：

**提示词里没有任何一条指令规定「做什么生意」。**

```
第一行：下面这份是这个风格的施工图。开头两行要你自己填（我不知道你做什么生意）：
第二行：我经营＿＿＿＿。
第三行：页面需要让访客＿＿＿＿。
```

`prompt-copy.js:126`（都没填的分支）把这两行留成**全角下划线空槽**，
这是 2026-10-27 明确修过的行为 —— 改之前是「我经营一家小店，有一些内容和图片要放上去」，
30/30 份提示词首行完全相同，系统替用户编了一门他没做过的生意（`prompt-copy.js:50-68`）。

**所以「菜市场展览」和「印社」不是同一个指令的两次随机执行，
而是同一个空白槽的两次独立填充。** 这是**设计如此**，不是随机性。

### 0.2 但「设计如此」不能免责 —— 有一条信号被系统自己丢掉了

关键实测：**`scenes` 字段 35/35 全有值，却从来没有进过提示词。**

```
$ grep -n "scenes" prototypes/_selection/prompt-copy.js
31, 1430, 1471           ← 全是注释
1998, 2007, 2016, 2101, 2115, 2128, 2261, 2327, 2344  ← 全是模板层 TEMPLATES，不是 35 案
$ grep -c "scenes" 生成的提示词        →  0（35 案逐个核过）
```

`data.js` 里 S04 的 `scenesYes` 是「文化机构的展览导览页与艺术家个人项目页、独立音乐节或戏剧节的排期页、
面向年轻人的街头品牌互动页」，`scenesNo` 是「需要严肃可信感的金融机构官网、需要清晰表格的医疗与政务系统页面」。
**这是一份写好了、测过的「这门风格适合做什么生意」的清单，产品拿在手上，但没有写进那份要给 AI 的提示词。**

后果是具体的：AI 拿到空槽后只能从 `plain`（「手贴满的展览墙，色块互相压边」）里**倒推**生意。
`plain` 描述的是**版式**，不是**行业** —— 「展览墙」这个词同时可以读成画廊、印社、贴纸墙、公告栏。
两次运行各挑了一个，都说得通，这就是 0.042 重合度的来源。

### 0.3 结构是否稳定：**数值层稳、版式骨架不稳**，任务书的两个层面要拆成三个

任务书要求分「层面一：结构是否稳定」和「层面二：文案差异是否在预期内」。
实测下来「结构」这个词必须再拆一层 —— 否则会得出相反结论：

| 层 | 指标 | S04 | S13 | S29 | 判定 |
|---|---|---|---|---|---|
| **数值层** | 配色 / 线宽 / 字号比 / 机制值 | 全同 | 全同 | 全同 | **稳定** |
| **版式骨架层** | 页高 / 内容区左缘 / 楼宽 / 区块数 | 差 3.8% / 0 / 0% / -2 | **差 15.8% / -186px / +22% / -3** | **差 -37.8% / +19px / -15% / -18** | **不稳** |
| **内容层** | 店名 / 文案 / 编号体系 | 8-gram 0.048 | 0.003 | 0.000 | **不稳** |

对照组（S08 三份、S15 两份 —— 这两案的两次产物**店名一字不差**）：

| 对照 | 页高 | 左缘 | 楼宽 | 区块数 | 8-gram |
|---|---|---|---|---|---|
| S08-a / S08-b | 6339 → 6698（+5.7%） | 160 → 160（0） | 1120 → 1120（0%） | 27 → 28（+1） | 0.912 |
| S15-a / S15-b | 7982 → 8160（+2.2%） | 0 → 0（0） | 1440 → 1440（0%） | 27 → 27（0） | 0.873 |

**这就是判据的分界线**：内容稳定时，页高只差 2~6%、左缘差 0、楼宽差 0%、区块数差 0~1。
S13 差 186px 左缘 + 22% 楼宽、S29 差 37.8% 页高 + 18 个区块 —— 这不是采样抖动，是**换了一个版式**。

实测输出（`_ci-frame.mjs`，1440×900，见 §2.2）：

```
S13-a  pageH 4347   contentLeft 186   contentWidth 1180   seg 14
S13-b  pageH 5032   contentLeft   0   contentWidth 1440   seg 11
S29-a  pageH 13704  contentLeft 101   contentWidth 1440   seg 38
S29-b  pageH  8519  contentLeft 120   contentWidth 1224   seg 20
```

**S13-a 有 186px 的左缘装订带（它的版式骨架是「div.wrap 包住一切」），S13-b 完全没有这一层。**
同一份提示词，一次做出了带装订边的公函，一次做出了全幅的档案馆 —— 这两份不是同一个版式的两次实现。

**所以对「复刻风格」这个目标：数值层成功，版式骨架层失败。** 任务书假设的
「如果两次产物的版式结构相同、只是文案不同，那对复刻风格这个目标是成功的」——
**前提不成立，S13 与 S29 的版式结构并不相同。**

### 0.4 要不要打折（与传参 bug 的关系）：**不打折，而且这个发现比之前更硬**

任务书的推论是「如果两次运行都只收到 `Read`，那两次都是模型自己发挥，文案不同是必然的」。
**这条推论的前提本身是错的**，但结论不受影响。详见 §4，一句话：

> 传参 bug 吃掉的是**运行器元指令**（`$msg`），不是产品提示词。
> 产品提示词走的是 `task.txt` → `Read` 工具这条通道，**逐字节完整送达**。
> 所以「模型没收到任务书」这个说法不成立，而「内容层不稳」这个结论不需要打折。

## §1 提示词对文案的约束强度（逐条）

`buildPrompt()`（`prototypes/_selection/prompt-copy.js:275`）里，**涉及文案内容的指令一共只有 5 类**，
全部列在下面。判据是「读这份文字的人能否据此写出一句确定的文案」。

### 1.1 硬约束：**「必须这样写」的，只有 1 条，而且是格式不是内容**

| # | 出处 | 原文 | 约束力度 |
|---|---|---|---|
| 1 | `:597` | 「照这个调性写文案和标题，每一句都像这个案子的人自己说的。」 | **调性约束，非内容约束**。7 个 tone 值（`混乱活力 / 街头`、`学术档案 / 严肃出版`、`机能冷峻 / 工业`…），S04=tone「混乱活力/街头」、S13=「学术档案/严肃出版」、S29=「机能冷峻/工业」。它规定**怎么说**，不规定**说什么**。 |

**就这一条。** 35 案逐个核过，**没有任何一份提示词要求标题或站名必须包含某个词**：

```
$ 「标题必须包含 / 标题必须写 / 必须叫 / 站名必须 / 店名必须」→ 35 案命中 0
```

### 1.2 软约束：**「你自己决定」的，2 条**

| # | 出处 | 原文 | 实际效果 |
|---|---|---|---|
| 2 | `:779` / `:782` | 「用你自己的真实数量排：有几个排几个，不凑整、不留占位符。」 | **明确把内容量交给模型**。这一句是 2026-10-27 第五次修的结果，改之前是「我实际有 46 个条目，就排 46 个」—— 系统替用户宣称有 46 个产品（`:700-710`）。修法是把它改成「版式规模」而非「你的内容量」。 |
| 3 | `:595` | 「请把整页做成这个风格：`{plain}`。」 | `plain` 是**版式描述**（S04=「手贴满的展览墙，色块互相压边」），不是行业。模型要从版式倒推行业。 |

### 1.3 空槽：**「你自己填」的，2 行，而且是提示词的第一、二行**

| # | 出处 | 原文 |
|---|---|---|
| 4 | `:122` | `我经营` + `{biz}`，空则 `我经营＿＿＿＿。` |
| 5 | `:123` | `页面需要让访客` + `{act}`，空则 `页面需要让访客＿＿＿＿。` |

`:126`：`if (!biz && !act) return [FRAME_EMPTY, l1, l2];`
`FRAME_EMPTY` = 「下面这份是这个风格的施工图。开头两行要你自己填（我不知道你做什么生意）：」

**这两行是提示词里唯一指名「做什么生意」的地方，而它在默认路径下是空的。**

### 1.4 有一条内容约束藏在 `risk` 里 —— 但它只覆盖 6/35 案

`dna.risk` 字段 35/35 有值，进提示词时截到 220 字（`:945-953`）。
逐案扫「必须挂真实 / 真实列名 / 真人 / 具名」这类**内容级**指令，只有 6 案命中：

```
S02 必须挂真实|真实编号
S03 必须挂真实
S04 必须挂真实|真实的|作者     ← 本案
S07 真实的
S09 必须挂真实|真实的
S29 真实列名                    ← 本案
```

S04 的原文（进提示词的那一段）：
> ③ 每个纸块必须挂真实的展期、作者与作品编号，混沌里要有可核查的事实。

**这是一条「内容必须带事实」的约束，不是「内容必须是某个行业」的约束。**
实测两个版本都遵守了它（§3.2），所以它起作用，只是它管不到「菜市场 vs 印社」这个层级。

### 1.5 小结：提示词对内容的约束强度 = **弱**

```
「必须这样写」的内容指令：  0 条
「必须包含某个词」：        0 条（35 案）
「你自己决定」：            2 条（数量、版式风格）
「你自己填」：              2 行（在提示词最前面，默认空）
「内容必须带真实事实」：    6/35 案，且只约束真实度不约束行业
```

**结论：提示词在内容层是「留白」的。两次产出不同生意，是这份提示词的必然结果，不是模型的失误。**

而是**页面几何**：页高、内容区左缘、版心最大宽度、视觉区块数。

脚本 `_ci-scratch/_ci-frame.mjs`，1440×900，量 `p/li/td/h1..h3/section/article/main` 的

- **S04 的版式骨架稳**（Δ 页高 3.8%、左缘 0、楼宽 0%、区块 2）。它和对照组 S08/S15 一个量级。
  → S04 的「菜市场 vs 印社」是**内容层**差异，版式没坏。

**这条差异比内容差异更接近「产品坏在哪」。** 因为它意味着：**同一份提示词，一次做出了「装订册」，一次做出了「目录册」。**

补一条 S29 的机制证据（说明第二版不是把机制丢了，是换了一套承载方式）：

```
S29-b  .punch（width:72px）+ .thread（width:1.2px）+ .bleed{margin-right:-96px} + .chapno{left:-48px;width:48px}
```

两版都把 72/3/18/1.2/48/96 实现了。**机制在，但装订带的承载结构不同**（a 是 `.bind` 包一切 + 绝对定位 rail，
b 是 `position:fixed` 的 `.wire` 装饰层）。这就是为什么 `measure()` 的 `gridSel` 在两版选了不同元素：

```
S29-a  gridSel = div.bind   tracks 2
S29-b  gridSel = ol.reg     tracks 12
```

### 2.4 8-gram 这个指标要打个折扣（顺带的方法论问题）

用 S08/S15 做标定：

```
pair            8gram-jaccard   A 正文长   B 正文长   title
S08-a/S08-b      0.9124          2888      3095     完全一致
S15-a/S15-b      0.8731          3312      3412     完全一致

S29-a/S29-b      0.0000          4808      4219     「大修工坊」vs「密封件与备件行」
```

（我复算的数与原报告略有出入：S04 我算 0.0482 / 报告 0.042，S13 我算 0.0029 / 报告 0.004，
差异来自标点清洗口径。结论方向完全一致。）

**指标特性**：8-gram 是**逐字**指标，0.9 vs 0.05 的落差极大，方向判断可靠。
但它把「同一行业的两种写法」（S29 的液压缸 vs 液压缸）和「两个行业的两种写法」都压到 0 ——
**它测的是「逐字复用」，不是「语义是否同类」**。所以 §2.1 那条「S29 其实没换行业」被它掩盖了。

用词频交叉验证可以看出来（`_ci-scratch` 逐词计数）：

**S29 是「同一门生意的两种组织方式」，S13 是「确实换了一门生意」，S04 是「同一个行业的两个细分类」**
（展览空间 vs 手贴印社，都属于「版画/纸品视觉」这一族）。
8-gram 把三者都报成「几乎无关」，这是它的已知局限，不是新缺陷。

## §3 文案差异是否在预期内

任务书给了正确的框架：如果两次产出**都避开了 risk、都符合 scenes**，那文案不同是**正常且期望的**。
逐案验。

### 3.1 `scenes` 这一条：**无法验证** —— 它根本没进提示词

这是本轮最重要的发现，已经在 §0.2 说过，这里给实测：

```
$ node -e "…对 35 案逐个检查提示词里是否出现该案 scenesYes 的关键词…"
提示词里出现该案 scenesYes 关键词的案数： 1 / 35
   S22  手作    ← 唯一命中，且是巧合（tone 里就有"温暖手作 / 人味"）
```

**所以任务书问「如果 S04 的场景是『展览』，那『菜市场二楼』和『贴满印社』是不是都合理」——
这个问题本身无法用「符合 scenes」来回答，因为 AI 从来没见过 scenes。**

`data.js` 里 S04 的 `scenesYes` 确实写了「文化机构的展览导览页与艺术家个人项目页、
独立音乐节或戏剧节的排期页、面向年轻人的街头品牌互动页」——
「菜市场二楼的独立展览空间」在第一条里，「贴满印社」不在任何一条里（印社不属于「文化机构的展览导览」）。
**但 AI 不知道这份清单存在。**

### 3.2 `risk` 这一条：**三案两版都守住了**

risk 是提示词里唯一一份「写给会犯错的执行者」的具体处方（`:945-953`）。逐条实测：

**S04**：`risk` ②「橙色与绿色各自压到 34% 与 26%，深棕黑保证 26%，画面不许出现第五种实色」
```
S04-a 实色：#2F7D4F #96550F #14100C #F0E2C8   (4 个，无第五色)
S04-b 实色：#2F7D4F #96550F #14100C #F0E2C8   (4 个，无第五色)
S04-b 正文里出现 26% 与 34% 两个面积值；S04-a 无面积数字但实色数同样受控
```
`risk` ③「每个纸块必须挂真实的展期、作者与作品编号」
```
S04-a  S04-xx 编号 34 处、展期 24 处、含「作者」「展期」字样  → 遵守
S04-b  3 位编号 50 处、展期 19 处、人名（何嘉树·三色丝网）→ 遵守
```
**两版都遵守，只是编号体系不同（S04-01…11 vs 001…009）。**

**S13**：`risk` ①「同色系双阴影 → 一律单向硬光源」②「全文不允许圆角胶囊」③「立体感必须能用『亮度差 3% + 压深 0.4mm』解释」
```
S13-a  border-radius 声明 1 处，非零 0 处；3% / 0.4mm / 14% 全部出现
S13-b  border-radius 声明 1 处，非零 0 处；3% / 0.4mm / 14% 全部出现
（双阴影检查：两版的 box-shadow 全是单向/inset，无一同色系对称双阴影）
```
**两版都遵守。**

**S29**：`risk` ①「黄 #644F02 面积上限 22%，45° 斜纹只在警示框内」②「斜纹固定 45°、纹宽 8px、间隙 8px」③「规格表必须写出真实列名与单位」
```
S29-a  repeating-linear-gradient 2 处、45deg 3 处、8px 间隙；扭矩/间隙/N·m/mm/油品/HL-46 全部出现
S29-b  repeating-linear-gradient 2 处、45deg 1 处、8px/8% 出现；扭矩/间隙/N·m/mm/油品/HM-46 全部出现
```
**两版都遵守。**

### 3.3 所以「是否在预期内」的答案是分裂的

| 判据 | 结论 |
|---|---|
| 都避开 risk？ | **是，三案两版全守住** |
| 都符合 scenes？ | **无法判定 —— scenes 从未进提示词** |
| 都遵守「内容必须带真实事实」？ | **是（S04 两版都挂展期/作者/编号，S29 两版都写真实列名与单位）** |
| 内容不同是不是设计如此？ | **是 —— 提示词在这两行留了空槽，且明说「我不知道你做什么生意」** |

**结论：文案不同本身在预期内。但「版式骨架不同」（§2.3）不在预期内** ——
因为版式骨架是提示词**明确约束**的部分（配色/字体/圆角/线宽/字号比/机制句/结构约束 1–5 条），
而它在 S13 / S29 上没守住。

**这两件事必须分开：**

```
内容层不同  → 提示词没规定，属设计如此，不是缺陷
版式层不同  → 提示词规定了，属未执行，是缺陷
```

任务书把两者合成一个问题问「内容不稳是不是问题」，实测答案是：
**内容不稳不是问题，和它同源的那个「版式骨架不稳」才是问题。**

## §4 与传参 bug 的关系：要不要打折

**结论：不打折。而且任务书里那条推论的前提是错的。**

### 4.1 任务书的推论

> 已知盲测因传参 bug 作废（模型只收到一个词）。但内容不稳这个发现可能不受影响 ——
> 因为如果两次运行都只收到 "Read"，那两次都是模型自己发挥，文案不同是必然的。
> **核实这个推论**：那两个版本的产物，是不是都在传参 bug 下生成的？如果是，那「内容不稳」这个结论本身也要打折。

### 4.2 实测：传参 bug 吃掉的是元指令，不是产品提示词

`29-prompt-truncation-bug.md` 的记载是对的 —— `Start-Process -ArgumentList` 传数组时
不给含空格的元素加引号，`-p` 只吃掉第一个词 `Read`。**这一步我复核过，是真的。**

**但被吃掉的是 `$msg`（运行器元指令），不是提示词。** 两者是两样东西：

```
$msg（_runner-template-literal.ps1:21）：
  "Read task.txt in this directory, then write the finished page to out.html..."

task.txt（产品提示词）= buildStylePrompt(id) 的输出，38–39 行
```

`_blindbox-batch.ps1:34-40` 把 `blind/<id>/task.txt` 拷进沙箱：
```powershell
$src = Join-Path $blindDir "$id\task.txt"
Copy-Item $src (Join-Path $taskDir 'task.txt') -Force
```

**我独立核实了这个等式**（不引用别人的结论，自己生成再逐字节比）：

```
$ node -e "…prompts.js + data.js + prompt-copy.js → buildStylePrompt(id)…"
S04  task.txt 1827 B  buildPrompt 1827 B  identical? true
S13  task.txt 1936 B  buildPrompt 1936 B  identical? true
S29  task.txt 2117 B  buildPrompt 2117 B  identical? true
```

模型虽然只从 `-p` 收到 `Read`，但 `Read` 是个**工具名**，它接下来 `Glob *` → `Read task.txt`，
拿到的就是这份逐字节相同的提示词全文。`Read` 返回 38 行不触发 2000 行上限。

**所以「模型没收到任务书」这个说法不成立。** 正确的说法是
「产品提示词完整送达，但走的是 tool_result 通道而不是 user turn」。

（这一条 `27-rerun-critique.md:410-475` 已经自己更正过，`_staged/README.md` 也写了。
我独立复算了其中的关键等式，结论相同。）

### 4.3 这对「内容不稳」这个结论意味着什么

**不影响，因为内容不稳的成因是「提示词里那两个空槽」，不是「没收到提示词」。**

如果模型真的只收到 `Read`（完全没读到 task.txt），那它连
「手贴满的展览墙，色块互相压边」「#2F7D4F #96550F #14100C #F0E2C8」「4.2 倍 / 72px」
都不会知道 —— 而实测这些值**两版全中**（§2.2），且**逐 byte 可核**。
**一个没读到提示词的模型不可能命中这些数。** 这本身就是「提示词到了」的因果证明。

### 4.4 但要打折的是另外两条（必须一起说）

| 结论 | 打折？ | 理由 |
|---|---|---|
| **A 类：产物内容 vs 提示词内容**（配色/字号比/机制值/risk 遵守） | **不打折** | 提示词完整送达，逐字节可核 |
| **D 类：内容层不稳**（本报告的结论） | **不打折** | 成因是提示词的留空设计，与送达通道无关 |
| **B 类：耗时 / 卡不卡 / 零产物** | **打折** | 元指令走的是绕道（`_run.ps1`），时序不同 |
| **S04 / S31 的产物溯源** | **打 `UNVERIFIED-PROVENANCE`** | `20-reproducibility.md` §4.4：S04 的 stream 有 81079 事件但 **0 次 Write / 0 次 Edit**，result 是 `API Error: Connection lost mid-response`，而磁盘上有 32829 字节完整产物 |

**S04 这条对本报告的影响：** S04-a 和 S04-b 的**产物内容**（配色、字号比、结构）可信，
但「S04-a 来自哪一次成功的生成过程」无法溯源。§2.3 那条「S04 版式骨架稳」的结论
依赖两份产物都在，这一条**成立**（两份文件都在，都完整），只是不能反推「模型第二次做 S04 也会这么稳」。

**C 类（模型能力）** 也打折，但与本报告无关。

### 4.5 一句话

> 传参 bug 是真的，但它伤的是「模型怎么收到任务」而不是「模型收到了什么」。
> 内容不稳的成因在提示词文本里，读得到、抄得下、改得动 —— **这个结论比原来更硬，不是更软。**

## §5 如果要修，怎么修

**先明确修什么。** 依据 §3.3：**内容不同不是缺陷，版式骨架不稳才是缺陷。** 所以修法分两条线，
优先级不同，**不要用修版式的办法去修内容**。

### 5.1 第一条线（P0）：内容层 —— 不要修「文案不同」，要修「scenes 没进提示词」

**不建议**给提示词加「必须写某个行业」。那会退回到 2026-10-27 修掉的病
（系统替用户编生意），而且会杀死这产品最大的价值 —— 让店主的店出现在这个风格里。

**建议做的是：把 `scenes` 作为「参考范围」写进提示词，而不是作为「要求」。**

具体位置：`prompt-copy.js:117-133` 的 `promptOpener()`，在 `FRAME_EMPTY` 之后加一行。

```
现在（都没填）：
  下面这份是这个风格的施工图。开头两行要你自己填（我不知道你做什么生意）：
  我经营＿＿＿＿。
  页面需要让访客＿＿＿＿。

改成：
  下面这份是这个风格的施工图。开头两行要你自己填（我不知道你做什么生意）：
  我经营＿＿＿＿。
  页面需要让访客＿＿＿＿。
  这个版式最常配的几类内容（仅供参考，你可以换）：{scenesYes 的前 3 项}
```

**为什么是「仅供参考」而不是「必须」**：`data.js` 的 `scenesNo` 23/35 案明确写了「不适合」什么，
说明这份清单是**范围**不是**规定**。写成硬约束会让 S15/S18/S21/S29 这 4 个 `hard` 案
（机制绑死特定题材）做出用户其实不做的生意 —— 那正是 README L105 警告的「退化」。

**成本**：`prompt-copy.js` 一处改动，约 3 行。**收益**：把「菜市场 vs 印社」的散布从
「无约束」收窄到「4 个相邻类目」。**它不会让两次产出相同** —— 那是 AI 生成的固有属性，
也不是产品该承诺的东西。它会让两次产出**都在合理范围内**。

**验证方法**（可执行，约 5 分钟）：改完后生成 S04 提示词，确认 `scenesYes` 前 3 项出现、
`scenesNo` 一个字都不出现（否则等于告诉 AI「不要做什么」，违反本仓库的负向指令纪律，
`prompt-copy.js:844-864`）。

### 5.2 第二条线（P0）：版式骨架 —— 这是真正的缺陷，要加闸门

**现状：没有任何闸门量「生成的产物有没有照提示词做出结构」。**

实测：`measure()` 只返回 `gridTracks` / `headBodyRatio` / `hexes` / `borderWidths` / `imgVisible`
（`deliverables/74-q7/measure.mjs:555-565`），`minItems` 在 `measure.mjs` 里**命中 0 次**。

```
$ grep -c "minItems" deliverables/74-q7/measure.mjs   →  0
```

**所以提示词里「这个版式设计时排了 23 个条目」「少一个就空一格」这两条约束，
从来没有被任何闸门验证过。** S29 两版把 23 落到 23（a）和 0 个 `<article>`（b），
**闸门全程报绿**。

**建议加一条闸门（C10：unitCount）**：

| 项 | 内容 |
|---|---|
| 量什么 | 产物里「同构重复单元」的数量（`minItems` 的定义就是它，`build-prompts.mjs:90`） |
| 判据 | `实际单元数 >= minItems × 0.8`（不要求精确，因为提示词第 2 条明说「用你自己的真实数量排」） |
| 为什么是 0.8 | `degrades=yes` 的案（13 个）里，用户内容少时提示词允许「整块重排」；0.8 是「重排了但没塌」的下限 |
| 对 S29-b 的判定 | 20 个视觉区块 / 23 = 0.87 → **过**；但 3 个 `<table>` vs a 的 7 个 → 「规格表」这一类退化，建议单列 WARN |
| 怎么取单元 | 不能数 `<article>`（S29-a 是 23 个 `<article>`，S29-b 是 0 个，但两者都有 6–10 个 section）。**按 `gridSel` 选中的版心容器的直接子元素数** |

**这条闸门要防的假绿**（本仓库的老病，`_batch-compare.mjs:40-50` 记过一次）：
拿 35 个**原型**去过判据。如果原型自己就过不了，说明判据错了，不是产物错了。
**先跑这一步再上产物。**

### 5.3 第三条线（P1）：8-gram 指标要标注局限

`20-reproducibility.md` 用 8-gram 判「内容稳不稳」。这个指标：
- **方向可靠**（0.9 vs 0.05 落差极大，不会误判「稳」为「不稳」）
- **会把「同行业两种写法」和「换行业」压到同一个数**（S29 实测 0.000，但两版都是液压缸）

建议在报告里标注口径，或补第二个指标（关键词交集 / 语义向量）。
**成本**：一行注释。**收益**：避免下一次有人拿 0.000 断言「S29 换了一门生意」（这次就发生了）。

### 5.4 不建议做的三件事

| 不建议 | 为什么 |
|---|---|
| **给提示词加「标题必须包含某个词」** | 35 案实测当前命中 0。加了之后，用户拿到的站会带着我们编的词 —— 退回 2026-10-27 的「我经营一家小店」病。 |
| **接受「AI 生成本来就有随机性」然后什么都不做** | 内容不同是随机性，**版式骨架不同不是**。把后者也说成随机性，就是本仓库记录过的「判据看到的东西 ≠ 实际发生的事」。 |
| **重跑全部 13 案来「确认」内容不稳** | 成本 ≈ 35 小时 / $95（`20-reproducibility.md` §2.1 实测）。而现有两版已经足以证明结论 —— 再跑一次只会得到第三门生意。**要跑就跑加完闸门之后的版本。** |
