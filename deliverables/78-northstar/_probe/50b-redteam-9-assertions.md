## 重点三条

### A. `section-missing` —— 它能抓「标题被改字」，抓不到「同名段被复制」

- 切段：`SECTION_RE = /^(视觉硬约束（[^\n]*|结构约束：|防退化（[^\n]*|验收三问（[^\n]*|输出要求：[^\n]*)$/gm`（1271 行）。段名键是 `hits[k][1].split(/[（：]/)[0]`，所以 `视觉硬约束（补充）：` 与 `视觉硬约束（逐条执行…）：` **是同一个键**，`out[key] = slice(...)` 后写覆盖先写（1278 行）。
- 改一个字会怎样（问题里问的）：实测三种都**报 `section-missing`**，不会静默跳过——
  - `验收三问（做完自己检查）：` → `验收三问：` → 35 条 `section-missing`；
  - → ` 验收三问（做完自己检查）：`（行首一个半角空格）→ 35 条 `section-missing`（正则锚 `^`）；
  - `结构约束：` → `结构约束:`（半角冒号）→ 74 条（`section-missing` + 连带 `xref-wrong-target`、`minpics-one-lost-constraint`）。
  - `视觉硬约束（逐条执行；配色与字体照此固定）：` → `视觉硬约束（逐条执行）：` → `FAIL 0`（因为 `[^\n]*` 吃掉了后半句，这是设计允许的）。
- 真正的洞不是「改名」而是「**再写一个同名段**」。两种一行构造实测都 `FAIL 0`：
  1. 伪造 `"验收三问（补充）："` 放在真验收段之后 → `acceptance-count` / `acceptance-range` 全部作用在伪造段上，真段可以随便写错；
  2. 伪造 `"视觉硬约束（补充）："` 列出 `1. 配色 / 2. 字体 / 3. 圆角 / 4. 线宽 / 5. 字号 / 6. 阴影` → `hardGen` 被整段替换，`xref-*` 与 `acceptance-range` 都以假条目为准（实测：真引用错位「见第 4 条」+ 伪段，`FAIL 0`）。
- 修法方向（不在本报告实施）：`splitSections` 遇到重复键时报 `section-duplicate`，而不是覆盖。

### B. `acceptance-count` —— 数的是「行首圈号 + 一个空白」

- 1436 行：`[...antiSec.matchAll(/^([①-⑳㉑-㉟])\s/gm)]`。三个可绕过点，全部实测：
  1. **行首要求**：`⑧ …。⑨ 所有间距…` 写在同一行 → `⑨` 不在行首，不计数，`FAIL 0`（提示词里实际有 9 条，验收仍说 8）；
  2. **空白要求**：`⑨所有间距…`（圈号后无空白）同样不计；换成「九、」这种非圈号编号也完全不计（`FAIL 0`）。反过来，只要圈号后跟全角空格（`⑨　`）**会**被计入并触发 `acceptance-count`（实测 35 条）—— 判据对排版敏感，对语义不敏感；
  3. **首处命中**：`claimed = /上面\s*(\d+)\s*条正面要求/.exec(accept)`。在第 1 问里写「上面 8 条正面要求都在」当诱饵、第 3 问写「上面 3 条」→ 取到 8，`FAIL 0`。
- 另：`acceptance-count` **只在 `claimed` 存在时才判**。防退化整段删成一句散文、同时把验收改成「上面 0 条」→ `0 === 0`，`FAIL 0`（提示词丢了 8 条处方）；如果验收改成「上面那些正面要求」（无数字）→ 不判；只有保留「上面 8 条」时才报。也就是说「删光防退化」这个最严重的形态**默认是绿的**，除非恰好保留了数字。
- 段被清空时的连带后果：`accept` 为空串 → `claimed` 为 null、`acceptance-range` 不扫 → `FAIL 0`。实测「验收三问」只留标题、三个问题全删，闸门 `FAIL 0`。

### C. `xref-wrong-target` —— 从「4 个主题白名单」变成「6 个主题 + 40 字窗口 + 括号限定词」，仍然是关键词判定

- 现状（1367–1410 行）：`ctx = text.slice(idx-40, idx)`；若有「（」则用括号后那段当 `scope`；`scope` 命中已知主题就必须与被引条目一致；`scope` 为空则退回看**括号外** 20 字，且只在括号外主题**唯一**时才判。
- 绕过的三条路（均实测 `FAIL 0`）：
  1. **40 字窗口**：把引用写成「…图形的一致性由统一笔画、统一转角、统一端点处理共同保证，任何位置都不允许例外，也不允许随手缩放或改粗细，具体级数见第 4 条。」→ 窗口内没有任何主题词，不报；
  2. **上下文含两个主题**（`outerTopics.length === 1` 才判）：上下文同时提「线宽」和「字号」→ 不判；
  3. **非阿拉伯数字**：`/见第\s*(\d+)\s*条/` 只认 `\d+`。写成「（线宽见第五条）」→ **整条引用不被扫描**，连 `xref-missing` 都不会报。这一条比「主题没覆盖」严重：它让引用从判据的视野里整个消失。
- 回答「引用上下文讲圆角会不会被查」：6 主题版**会**（`xref-round-corner` 变异已固化，`--selftest` 响）；但「间距」「栏数」「留白」这类仍不在 `TOPIC_WORDS` 里 —— `xref-unknown-topic`（1384 行）只在限定词是 2–5 个纯汉字且不含功能词时兜底，实测「（间距见第 4 条）」会被它抓到，但「（具体间距值见第 4 条）」这种带修饰的写法因 `^\S{2,5}$` 长度限制不匹配而放行（`FAIL 0`）。

## 其余六条的一句话结论

- `typescale-degraded`：`.test` 全文任一处匹配即可，可以用「在别处按同一格式补一句」骗过；但真降级 + 只有降级句时会响，形似保护有效。
- `typescale-detail`：`text.includes` 全文任意位置，把两个子句挪到别的段即过；守的位置不对（应限定在第 6 条那一行内）。
- `have-not-wired`：探针固定 `have:5`，把模板硬编码成 5 或只在 `have===5` 时接线都能过；`o.have` 的真实接线没有被守。
- `have-phantom-number`：只看 `/\d+ 条内容，就排/` 一个句式；换个说法（「典型是 7 条内容」）就隐形。
- `have-pics-conflict-ignored`：只看两个短语在不在，不看在不在同一句、前后有没有反向指令。
- `minpics-one-nonsense`：正则 `不是1 个 img 标签` 与原文 `不是 1 个 img 标签` **差一个空格** —— 这是当前代码里已经失效的判据（见下）。

## 顺带查出的两个「判据本身错」而不是「能绕过」

1. `minpics-one-nonsense` 的空格错位（1246 行 vs 模板 899 行）。现有 `--selftest` 的 `minpics-one-nonsense` 变异之所以响，是因为它把模板换成了 `"不是" + s.minPics + …`（`minPics=1` 时拼出「不是1」无空格），**恰好**与闸门的错误拼写对上 —— 变异测试在这里给了假绿：它证明的是「闸门的错拼能被错拼的模板触发」，不是「真实的病句会被抓」。
2. `typescale-body-mismatch` / `typescale-h1-mismatch` 只与 `dna.bodySize` / `dna.h1SizeAt1440` 复算，不与 `style.css` 对账（`KEY_FIELDS` 里也没有 `bodySize`/`h1SizeAt1440`，1512 行）。实测把 `prompts.js` 里 S01 的 `bodySize` 从 `16px` 改成 `60px`、`h1SizeAt1440` 从 `96` 改成 `400`，各自 `FAIL 0` —— 提示词会说「正文约 60px；最大标题压到正文的 1.6 倍（约 96px）」/「正文约 16px；25 倍（约 400px）」，而 `style.css` 里 `--fs-body: 16px`、`--fs-h1` 展开是 `96px`。这条不属于任务书列的 9 条，但它是「数据侧一行改动即可让字号条说谎」的现成通道（T-11/T-12 只守「文本里有三个数」，不守「这三个数与 CSS 一致」）。

## 按严重度排序：最该先修的 3 条

1. **`minpics-one-nonsense` 的空格错位（1246 行）** —— 这不是「可能被绕过」，是**现在就没在守**。`/不是1 个 img 标签/` 与病句原文 `不是 1 个 img 标签` 差一个空格；而 `--selftest` 因为变异构造恰好也用了无空格拼写而显示「✓」，属于本仓库反复在治的那类假绿。修法：正则改成 `/不是\s*1\s*个\s*img\s*标签|同一张图重复用不算/`，并把变异改用真实病句原文（带空格）当锚点。
2. **`section-missing` 的「同名段覆盖」（1278 行 `out[key] =`）** —— 它是其他五段的守护者，一旦出现第二个同名前缀标题，`acceptance-*`、`xref-*`、`hardGen` 全部作用在伪造段上，真段写错完全看不见（实测两条构造 `FAIL 0`）。修法：切段时检测重复键并报 `section-duplicate`；段键改为「标题原文」而不是「括号/冒号前的短名」，或要求段标题在全文**唯一**。
3. **`acceptance-count` 的「首处命中 + 行首圈号」（1436/1438 行）** —— 诱饵句、合并行、非圈号编号三种写法都能让「验收说的条数」与「实际条数」脱钩（均 `FAIL 0`）；更严重的是 `claimed` 缺失时整条不判，导致「防退化被删光」这个最坏形态默认绿。修法：只取验收第 3 问那一行（`^3\.`）里的数字；圈号计数改为「任何位置出现且不重复」；`claimed` 缺失时报 `acceptance-claim-missing` 而不是放行。

次优先：`have-not-wired`（探针单值 5，硬编码即过）、`xref-wrong-target`（中文数字引用整条逃逸 + 40 字窗口）、`have-pics-conflict-ignored`（只查短语在不在）。`typescale-*` 三条属于「位置不敏感」的中等问题，`typescale-body-mismatch` 与 CSS 不对账这条建议单列一条新规则。
