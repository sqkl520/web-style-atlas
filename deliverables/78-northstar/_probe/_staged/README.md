# 这些是什么

13 个沙箱盲测的产物副本（+ 2 份历史版本），共 456 KB。

## 为什么要入库

原本它们只是对账时的临时落地（`measure()` 的静态服务器以仓库根为根，
路径越出仓库会被拒绝，所以对账脚本要先把产物复制进来）。

2026-11-13 系统把整个 `C:\tmp` 清掉了，十案产物一次全丢 —— 而 `_staged/` 里的副本还在，
证据因此没丢。所以这两个目录不再 gitignore：**不能把唯一的证据只放在 tmp 里。**

## 重要：这些产物的有效性是**分类型**的，不是整体作废

它们是在一个**传参 bug** 下生成的：`Start-Process -ArgumentList` 传数组时，
PowerShell 用空格把元素拼成命令行串、不给含空格的元素加引号。
于是运行器的元指令 `$msg` 里每个空格都成了参数边界，`claude` 只收到第一个词 `Read`。

**但产品提示词是完整送达的，有两条独立通道：**

1. **`task.txt` 就是产品提示词，逐字节相同。**
   实测 `buildStylePrompt('S31')` 与 `blind/S31/task.txt` 都是 1971 字符、`===` 为真。
   沙箱那份是 `_blindbox-batch.ps1` 从 `blind/<id>/task.txt` 拷过去的。

2. **元指令也被模型读了回来。**
   模型调用 `Read C:\tmp\bb\S98\_run.ps1`，那个文件里写着 `$msg` 全文。
   argv 只吃掉了直达通道，绕道读文件补上了。

**最硬的因果证据**：S98 的 thinking 草稿里那 5 个 hex（`#F2F0EC #5F5B55 #DEDAD3 #55514B #8A857C`，
5/5 全中）**在沙箱里只存在于 `task.txt`**（`_run.ps1` 没有、仓库被 Deny ACE 挡住）。
它不可能靠猜命中这 5 个值 —— 只能是读了文件之后做到的。

### 所以正确的说法是

| 说法 | 对错 |
|---|---|
| 「不是按提示词做出来的，而是自己读了文件之后发挥的」 | ❌ **错**（这是本文件初版写的） |
| 「是按提示词做的，但不是按标准对话通道送达的」 | ✅ **对** |
| 「`Read` 返回的就是全文，与你粘进 ChatGPT 的文字没有区别」 | ✅ **对** |

### 分类型的有效性

| 结论类型 | 受影响吗 |
|---|---|
| **A 类**：产物内容 vs 提示词内容（配色命中、字号比、机制值） | **不受影响** —— 提示词完整送达 |
| **B 类**：行为与耗时（「想了 2 小时」「零产物」） | **受影响** —— 元指令是绕道拿到的，时序不同 |
| **C 类**：模型能力（「它做不出来」） | **受影响** —— 且模型身份本身也不可控 |
| **D 类**：内容层不稳（两次文案不同） | **不受影响** |

## 所以它们的用途是

- ✅ 可以用来检查**度量器**的行为（`measure.mjs` 在这些真实页面上量出什么）
- ✅ 可以用来复现「传参 bug 的后果」
- ✅ **A 类结论可用**：配色命中、字号比、机制值这些「产物内容 vs 提示词内容」的比对
- ❌ **B/C 类结论不可用**：「它想了多久」「它做不出来」这类
- ⚠️ 引用任何 `duration_ms` / 524 时间线 / `lastPrompt` / S98 草稿细节时，必须标 `UNVERIFIABLE`
  —— 那些数据在 `C:\tmp` 里，已被系统清空

详细证据见 `../29-prompt-truncation-bug.md` 与 `../27-rerun-critique.md` §7。

## 文件命名

- `<案号>-sandbox.html` —— 该案当时的产物
- `<案号>-oldverify.html` —— 更早一次运行的产物
- `<案号>-v<字节数>.html` —— 报告里引用过、但后来被重跑覆盖的版本
  （比如 `S13-v25730.html` 恰好 25730 字节，对应报告里那个数字）

## 复算

```bash
node deliverables/78-northstar/_probe/_batch-compare.mjs S31 S04 S08
```

它会优先读 `C:\tmp\bb\<案号>\out.html`，没有就回落到这里的副本。
