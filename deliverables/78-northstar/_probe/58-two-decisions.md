# 两个由我决定的事：保留 h1Size，不跑已填形态盲测

> 2026-11-17　主线程
> 用户授权「自己决定」。本文记录两个决定及其依据 —— **两个都不是我原先的判断**。

## 决定一：保留 `h1Size`（推翻我上一轮的建议）

### 1.1 我原来的判断是错的

`45-sentinel-test-dead-fields.md` 和 `52-next-round-plan.md` 里我写：

> `h1Size` 是死字段，0/35 渲染，建议删除或标注为中间量。

**这个判断不完整。** 它的依据是哨兵法 —— 把 `h1Size` 改成 `999px`，35 案提示词逐字不变。
那个实测是对的，但**只覆盖了主路径**。

### 1.2 它是「死分支里的活字段」

`prompt-copy.js:472-481` 有一条兜底：

```js
if (d.mechanism) {
  mech = "这个风格的签名动作：" + d.mechanism;
} else {
  var facts = [];
  if (d.radius === "全直角 0") facts.push("全站直角、零圆角");
  …
  if (d.h1Size) facts.push("首屏主标题取 " + d.h1Size + " 这一档");   // ← 活的
  mech = "这个风格的签名动作：" + s.plain + "。具体到实现：" + facts.join("；") + "。";
}
```

实测（把 S13 的 `mechanism` 清空）：

```
签名动作行：
  这个风格的签名动作：棉纸公函，条款标题压出凹痕。具体到实现：
  全站直角、零圆角；线宽只分 1px、1.5px、… 这几级；首屏主标题取 56px 这一档。
```

再把 `h1Size` 改成 `999px`，那句就变成「首屏主标题取 **999px** 这一档」。
**它确实会进提示词。**

### 1.3 为什么哨兵测出 0/35

因为 35 案的 `mechanism` 全部非空。链条是这样的：

| 层 | 状态 |
|---|---|
| `dna-clean.json` 的 `mechanism` | **25/35 案为空** |
| `build-prompts.mjs:135` 用 `MECHANISMS[id].text` 补 | 25/25 全补上（实测） |
| `check-prompts.mjs` 的 `mech-empty` 断言 | 任何一案取不到就报 |

两道闸门都正常，所以分支不执行。**但它是「两道闸门同时失效」时的最后兜底。**

### 1.4 结论

**删它不安全。** 保留的成本是 dna 里多一个字段（而且它有出处回看价值：裸 px 的
5 案里与 `h1SizeAt1440` 相同，clamp 的 30 案里是展开前原文）；
删除的代价是那条兜底路径静默残缺，而残缺只会在「mechanisms.mjs 少一条 + mech-empty 被放宽」时暴露。

已把 `build-prompts.mjs:403-424` 的注释重写成准确描述，并在
`check-prompts.mjs` 里加了 `mech-fallback-empty` 断言：
机制句缺失时，兜底拼出来的话不能是「具体到实现：。」这种空壳。

**实测**：清空 S13 的 mechanism → 只报 `mech-empty`，兜底正常产出，
`mech-fallback-empty` 不响（这是对的，因为兜底成功了）。

## 决定二：不跑已填形态盲测

### 2.1 成本

`20-reproducibility.md` §2.1 的实测数据（来自 `stream.jsonl` 的 `duration_ms`）：

```
十案合计 ≈ 35.1 小时串行、≈ $95
单案 0.47 h ~ 4.91 h，跨度 10.4 倍
```

跑一轮「已填形态」的重复盲测，需要同样的量级：**~35 小时 + ~$95**。

### 2.2 关键事实：已填形态与空槽形态几乎相同

实测 35 案的两种形态：

```
空槽总字数 69,595
已填总字数 69,770   差 175 字（0.3%）
已填独有的行：105 行 / 35 案 = 平均每案 3 行
```

那 3 行就是开头两行（「我经营 X。」「页面需要让访客 Y。」）加一句引导语
（「下面这份是这个风格的施工图，请照着做；素材和条目按下面的结构自己排。」）。

**提示词的其余 99.7% 逐字相同。**

### 2.3 所以盲测结论的适用范围

盲测测的是「AI 拿到这份提示词，做出来的东西像不像原型」。
已填形态与空槽形态差 3 行，而那 3 行**不是约束**，是背景信息（做什么生意）。

因此：

- **数值层结论**（配色 11/11、线宽 10/11、字号 11/11）**对已填形态同样成立** ——
  那些约束段完全一样，一字不差
- **内容层结论**（模型自填生意、两次做不同行业）**只对空槽形态成立** ——
  已填形态下用户给了 biz，模型不会自己编生意

也就是说：已填形态**恰好消除了**我们观测到的那个「内容不稳」，
因为那个不稳的来源就是「空槽让模型自由填」。

### 2.4 结论

**不跑。** 理由三条：

1. **花 $95 买一个已知答案**：99.7% 的提示词相同，已测的数值层结论直接适用。
2. **剩下的 0.3% 是可推理的**：已填形态下模型不会自填生意，
   所以「内容不稳」这个具体现象**不会重现**。
3. **真跑的话，测的也不是我关心的问题**：如果目的是「验证提示词在真实使用下稳不稳」，
   那应该测的是「同一个 biz/action，两次生成的东西像不像」——
   而那个问题的答案取决于模型的温度采样，不是提示词的属性。

### 2.5 如果将来要跑，该跑什么

不是「35 案各跑 2 次」，而是：

- 挑 **2 个案子**（一个 `fixed` 布局、一个 `auto-fit`），各跑 2 次
- 每次用**同一个** `{biz, action}`（已填形态）
- 比对：字形栈、字号、配色、图片数、正文 8-gram 重合
- 成本：约 **4 案次 × 3.5 h ≈ 14 小时、$40**

这能回答「同一份施工图 + 同一份背景，两次施工像不像」，而不是 35 案的全面普查。
