# 红队实测：两个能让闸门 FAIL=0 而提示词变坏的绕过

> 2026-11-17　主线程（agent 全部没启动，自己做的红队）
> 这两条不是「换个说法的变异」，是**具体可执行、后果真实**的绕过构造。
> 都已修复并固化成常驻变异。

---

| 角色 | 结果 |
|---|---|
| 规划 | 0 字节 → 8 分钟后停止 |
| 核实六条 | **运行 23 分钟、1.3MB 输出、未写出报告 → 停止** |
| 红队 | 0 字节 → 停止 |
| 产品优先级 | 0 字节 → 停止 |
| 逐字读提示词 | 0 字节 → 停止 |

结论：这个环境的后台 agent 当前不可用。所以本轮全部由主线程完成。

## 二、绕过一：⑪ 圈号能骗过验收比对

### 2.1 判据原文

```js
const antiCount = [...antiSec.matchAll(/^[①②③④⑤⑥⑦⑧⑨⑩]/gm)].length;
```

字符类只到 **⑩**。

### 2.2 绕过构造

给防退化加一条，用 ⑪ 写：

```js
"⑧ 动效只用本案机制句里写到的那一个动作，其余位置保持静止。",
"⑪ 第十一条额外要求。"
```

### 2.3 实测后果

```
防退化段末尾：
  ⑧ 动效只用本案机制句里写到的那一个动作，其余位置保持静止。
  ⑪ 第十一条额外要求。

验收第 3 问：
  3. 扫一眼：上面 8 条正面要求与第 3–5 条硬约束，是不是每一条都看得见？

闸门：FAIL=0
```

**防退化实际有 9 条，验收说 8 条，而闸门说没事。**

对产品的实际影响：AI 读到「核对上面 8 条正面要求」时，
只会核对前 8 条，**跳过第 ⑪ 条**。那条要求就等于没写。

### 2.4 修法

不做「把字符类扩到 ⑳」—— 那只是把洞往后挪一格（下次有人用 ㉑ 还是漏）。

改成两条：

1. **数任何行首圈号**：`/^([①-⑳㉑-㉟])\s/gm`
2. **要求圈号从 ① 连续递增**：`⑧` 后面接 `⑪` 是跳号，报新规则 `antidegrade-skips`

第二条独立于第一条：即使验收那句写对了（「上面 9 条」），
圈号跳号本身也是缺陷 —— 与本仓库 S34 断号、交叉引用差一位同源。

## 三、绕过二：圆角引用完全不检查

### 3.1 判据原文

`xref-wrong-target` 只覆盖 4 个主题：

```js
const THEMES = [
  { ctx: /线条|线宽|描边|刻线/, want: /线宽/, name: '线宽' },
  { ctx: /字号|标题大小|倍率/, want: /字号/, name: '字号' },
  { ctx: /配色|颜色|色值/, want: /配色/, name: '配色' },
  { ctx: /字体|字族/, want: /字体/, name: '字体' },
];
```

### 3.2 绕过构造

把引用写成：

```
⑤ 图形一律用本案线宽级别的线条画（圆角见第 5 条），没有对应线条时就只用文字。
```

上下文在讲**圆角**，第 5 条是**线宽**，明显的错位。

### 3.3 实测后果

```
闸门：FAIL=0
```

完全检测不到。

### 3.4 修法

补上圆角和阴影两个主题。同时在注释里写明：
**再发现新主题时不要只往这个数组里加一条** ——
那只是把同一个洞往后挪。真正的兜底应该是「上下文里出现任何硬约束段的名词，
而被引条目完全不含它」，但那个判据需要可靠的中文分词，本轮没做（记在遗留项里）。

## 四、验证

| 构造 | 修复前 | 修复后 |
|---|---|---|
| 加第 ⑪ 条 | FAIL=0 | `acceptance-count×35` + `antidegrade-skips×35` |
| 加第 ⑨ 条 | `acceptance-count×35` | `acceptance-count×35`（不变） |
| 「圆角见第 5 条」 | FAIL=0 | `xref-wrong-target×35` |
| 「阴影见第 5 条」 | FAIL=0 | `xref-wrong-target×35` |
| 原样（基线） | FAIL=0 | FAIL=0（零误报） |

两个绕过都固化成常驻变异：`antidegrade-skips`、`xref-round-corner`。
`--selftest` 现在 14 个变异全响。

## 五、遗留（本轮没做）

1. **主题白名单还是枚举式的**。补了圆角和阴影，但「栏数」「间距」「图片位」等
   主题仍未覆盖。真正的兜底需要中文分词，成本高。
2. **`section-missing` 的边界**：实测把「验收三问（做完自己检查）：」改成
   「验收三问：」会报 `section-missing×35`（正确拦住了）。但这条断言响的时候，
   依赖它切段的 `acceptance-*` 会**同时**全部跳过 —— 也就是说段名一改，
   验收那两条判据就静默失效了，只剩 `section-missing` 在响。
   这不是缺陷（有守卫），但下一层如果没人看 `section-missing`，就会漏。
