## 1. FAIL 3 徽标（`bf62a77`）

**问题**：S31–S35 的 `failIds` 是 `mono / hairline / few-pictures`。17 条 FAIL token
逐条对 `_CONTRACT.md` §9.15 允许表比对，**100% 落在表内**。而这 5 案的
`capacity.minPics` 是 `1,1,1,0,1` —— 全库最低，**是唯一为"手上没有摄影素材"
的店主做的五个案子**。界面上它们顶着红色 `FAIL 3`，而「真实图 1」就紧挨着它，
读起来是「缺图 → 所以不合格」，实际是「缺图 → 所以这是为你做的」。

**修法**：把 §9.15 里**可计算**的三条搬进 `app.js`：
- `few-pictures` / `hairline` —— 随 `minPics ≤ 2`
- `mono` / `font-count` / `palette-terracotta` —— 无条件

`gateVerdict()` 逐条判定每个 failId 是 exempt 还是 real。有真缺陷才标红并只写真的那几条；
全是契约允许的改写「检查 N · 契约允许」，title 逐条给理由。
筛选栏取值从「FAIL 0 / FAIL 2 / FAIL 3」改成「无真缺陷 / 契约允许 / 有真缺陷」。

**守卫**：`check-ui-copy` 新增断言 6 —— 两个实现的数据源不同
（`check-contract` 读 `minitems-parsed.json`，`app.js` 读 `prompts.js`），
实测 35/35 相等，但没有东西保证它继续相等。一旦分叉，两边各自自洽、双双报绿。
断言把两个源钉在一起，外加阈值一致性。`--selftest` 扩到 6 个变异体。

## 2. 1280/1366 列表崩成单字（`253f3e7`）

**问题**：`.row` 是固定三列 `62px minmax(0,1fr) 316px`，详情靠
`padding-right: 560px` 让位。窄一点的桌面档让完之后正文彻底不够：

| 视口 | `.row-main` | h3 盒 | 行高 | 被点行 top |
|---|---|---|---|---|
| 1440 | 146px | 100×23 | 467 | 309→1685 |
| 1366 | 72px | 72×46 | 647 | 309→2946 |
| 1280 | **8px** | **20×114** | 1053 | 309→5250 |

1280 档的 h3 是 20px 宽 × 114px 高 —— 「红黑斜排报」五个字每字一行。
而 1280×800 与 1366×768 是笔记本最常见的两档。

**为什么活这么久**：`probe-ui` 写死 1440×900，`inspect.mjs` 只滚不点，
仓库测量矩阵缺 1280/1366/1536 —— 崩溃点完整落在缺口里。

**修法**：让位断点从 981 改成 **1700**。判据不是"视口多宽"，是"让位后正文还剩多少"：
rail 固定 264px，`.main = 视口 − 264 − padding`，再减详情 560，`.row` 再减 62+20+截图列。
实测并排要到 1600 以上才不算局促。1700 以下改浮层。

**走的弯路（记下来，免得重犯）**：
- 第一版 `display:none` 隐藏截图列。正文宽度够了，但 1024 档行高 340→225、
  文档矮 4025px，滚动位置错位，被点行从 top=240 飞到 −567。**拿新缺陷换旧缺陷。**
- 第二版按档收窄截图列（316→180→132），1280 档正文仍只有 144px。
- 最终才明白：问题不在截图列多宽，在"并排"本身在这个宽度不可行。

**守卫**：`probe-ui` 第 18 条，自己换到 1366/1280/1440 三档量，判据两条 ——
h3 不得超过 2 行，且打开详情不得改变行高（后者是因为第一版"宽度够但行高变了"）。

## 3. 全局快捷键失效（`6ddfa97`）

**问题**：键盘处理器守卫是 `if (tag === 'button') return;`，理由是"焦点在筛选芯片上
按 J 会误开详情"。理由本身成立，但代价从没被量过：「复制 AI 提示词」是本页唯一的
交付动作，点完焦点停在那个 button 上，从此 `2` 不切视口、`j` 不换方案、
`/` 不定位搜索框、`Esc` 只 blur（面板还开着，要按第二次）。

**修法**：守卫拆三类 ——
1. Enter/Space：永远是按钮自己的（激活键）
2. Esc：先 blur，**再继续走全局**（收起详情）
3. 其余全局快捷键：放行（它们在 button 上没有默认行为，抢的从来只是全局逻辑自己）

原注释里"焦点在芯片上按 J 会误开详情"那条：那恰恰是用户按 J 的本意。

**守卫**：`probe-ui` 第 5b 条。第三条判据（Enter 仍激活按钮）是重点 ——
只验前两条的话，"把 button 整个放行"会顺带把 Enter/Space 吃掉。

## 4. 色带组与明暗组同一根轴（`eb274c3`）

**问题**：`axes.band` 的 8 条带，交叉表实测：

```
亮底 = 暖浅18 + 中间明度1 + 中性浅2 + 冷浅2
暗底 = 冷暗5 + 暖暗3 + 中性中1 + 纯中性暗1
中间调 = 中间明度2
```

**8 条带里 7 条完全被明暗决定**。两组一起选，24 种组合 15 种归零（62.5%）。
最刺眼的「暗底 + 暖浅色带」：角标写 18，点下去 0 行。

**修法**：换成按 `bg` 的 HSL **实际色相**分暖/冷/中性。为什么不用名字：
三个中间调案的 bg 分别是黄(#F5C842)、紫(#AE8ECD)、青灰(#4A6763)，全被旧标签
叫成「中间明度带」—— 名字把最明显的差异丢掉了。新版与明暗真正正交
（亮底 暖19/冷3/中性1，暗底 冷6/暖1/中性1，中间调 冷2）。

**附带修**：`chips()` 缺 null 守卫。做变异时把 id 改回 `flt-band`，
`$(host)` 返回 null，`box.innerHTML` 抛 TypeError，整个 IIFE 中断，
**列表一行都不渲染，页面白屏**。一个筛选组 id 拼错，代价是整页不可用。

## 5. 向导叫契约豁免项「不达标」（`081a30e`）

**问题**：`wizard.html` 只加载 `data.js`，**没有 `prompts.js`**。而 §9.15 的条件豁免
要靠 `STYLE_PROMPTS.schemes[].capacity.minPics` 判定。于是 `minPicsOf()` 恒返回 null
→ `lowPic` 恒 false → 这两条被判成"真缺陷" → 卡片写「⚠ 有 2 项没达到机械闸门的要求
（**不在契约豁免表内**）」，而事实是那 2 项**恰恰在豁免表内**。主台同一个案写的是
「检查 3 · 契约允许」。**漏一个 script 标签，把"契约允许"翻成了"不达标"。**

**修法**：补上 `prompts.js`；`wizard.js` 接入与 `app.js` 逐字相同的判据；
卡片文案跟着真缺陷走。`score()` 加真缺陷惩罚（×1000）——
目前全库真缺陷数都是 0，所以这一项暂时不改排名，它是防未来的。
原注释「向导不会因此改排名」已删：现在会改，留着就是新的假话。

**守卫**：`probe-ui` 第 16b 条。为什么断言 6 抓不到：那条比对的是两份数据是否相等，
而两份确实相等，只是页面**根本没加载**其中一份。**数据层一致 ≠ 消费层有效。**

## 6. 卡片缺三行决策信息（`b7105f3`）

| 字段 | 覆盖 | 卡上原有 | 为什么重要 |
|---|---|---|---|
| `scenesNo` | 35/35 | **0 字** | 作者自己已认定「负向信息比正向描述更硬 —— 用户常常先排除、再挑选」 |
| `minPics` | 35/35 | **0 字** | 卡上印的"真实图 N"是另一个东西（实际放了几张），两者 15/35 不相等 |
| `hard` | 4 案 | **0 字** | 唯一一个"选了会坏、而且看不出来"的字段 |

`hard` 的原文（prompt-copy）：「v0 会把 script 剥掉或改写，机制会消失，
而且看起来不容易发现哪里坏了」—— 这段话只存在于生成的提示词里，选型那一刻不可见。

**修法**：`rowFitHTML(r)` 输出三行，放在 `row-def` 之后（页脚是质检区，
308 个信息单元里 238 个是质检项，混进去等于被噪声埋掉）。`minPics` 只报
"这个版式要 N 张图"，不吓唬人 —— 它不是"至少需要几张"；只有 `have < need`
时才补一句「这个案自己只放了 N 张」（S03：要 8 张、自己 4 张）。

**守卫**：`probe-ui` 第 15b 条。`hard` 那条**双向验**：只验"该有的有"会放过
"所有卡都有"，而那是把警示色变成装饰（本仓库的老病：35 张卡都印 no-footage）。

## 7. 图片 5.03 MiB（`8f7188a`）

**问题一：超采样**。卡片实显 152×86 CSS px，@dpr2 需要 304×171；原图 1440×900 ——
只用到 4.0% 的像素，超采样 4.7×。

**问题二：懒加载永不再生效**。原来 `var lazy = vp === 'desktop' ? '' : ' loading="lazy"'`，
但 `shotFig` 现在只生成 desktop 一种，这个三元**恒为空串**：35 张全部 `loading="auto"`。
上一轮为省流量删掉 60 张被 `display:none` 的图，顺手让懒加载死了 ——
省下来的是"隐藏的图"，没省下来的是"超采样的图"，两个问题长得很像但不是同一个。

**修法**：新增 `prototypes/_build/make-thumbs.mjs`，为每案生成 `.thumb.jpg`
（宽 304，q72）。零依赖 —— 用仓库已有的 CDP 通道让 Chrome 自己解码→canvas 缩放→
重编码。装 sharp 会破坏"零 npm 依赖"这条铁律。
`app.js` 用缩略图 + `data-full` 回退（浏览器端无法查文件是否存在，只能靠 onerror）。

**结果**：

| | 改前 | 改后 |
|---|---|---|
| 首屏图 | 35 张 / 5.03 MiB | **7 张 / 0.06 MiB** |
| 滚到底 | 35 张 / 5.03 MiB | 14 张 / 0.10 MiB |
| 单张 | 147 KB | 7.6 KB |

**守卫**：`probe-ui` 第 7b 条，四条判据（是缩略图 / 有回退 / 全懒加载 / 首屏 ≤12 张）。
原有的 `no-hidden-screenshot-downloads` 自动反映了改进：「本次加载 7 张」。
