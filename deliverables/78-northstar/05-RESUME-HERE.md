## 零、一句话结论（2026-11-22 版）

**测量层这一轮被修好了三处，修完之后才发现之前报的「0 违规」是假的。**

三个数要分开看，它们覆盖的不是同一件事：

| 口径 | 数字 | 含义 |
|---|---|---|
| **盲测做过的案** | **21/35** | 磁盘上有产物的风格数（含 2 次重跑） |
| **当前提示词覆盖** | **1/35** | 带着 `audit` 段跑过的（只有 S21-r2） |
| **动效有对照证据的** | **1/35** | 两轮同案对比（S34 一对、S21 一对） |

产物按提示词分四代，不是两代：

| 代 | 提示词特征 | 案数 | 说明 |
|---|---|---|---|
| 最早 | 无动效段 | 4（S01/S13/S19/S34） | 2026-11-21 之前 |
| motion | 有动效段，无 `audit` 段 | 18 | 昨天到今天的绝大部分 |
| audit | 动效段 + `audit` 段 | 1（S21-r2） | `audit` 段效果的唯一样本 |
| **今** | 再加第四个字体槽 | **0** | **还没有任何产物用这版提示词跑过** |

**最后那个 0 必须一直显示着。** 它是现在最诚实的一条进度：产品这一轮改了
四处（`motion` / `audit` / 图片宽高 / 第四个字体槽），而**能证明改得对的样本
只有 1 份**（S21-r2，且混了三个变量，不能归因）。字体槽是刚加的，
一份验证都没有。

「今」那一代是 2026-11-22 加的 `fonts.latin`（见 §零 第四件事）。
`score.mjs` 会按提示词原文自动标出每份产物属于哪一代，不用人记。

### 这一轮查实的四件事

1. **正对照一直在跑产物，从没跑过原型。** `score.mjs` 的 `score(id, opts)`
   收了 `opts` 却硬编码 `join(BT, id)` —— 所谓「35 个原型 0 违规」，
   实际每次都拿盲测产物当「手工合格样品」。接上 `opts` 之后，
   立刻有 8 个原型被判违规，那些判据本身是错的。修完才是真的
   **35 原型 / 0 违规 / 1 条豁免（S19）**。

2. **评分器读不到 `<style>` 的第二块。** 正对照把 `style.css` 拼成第二个
   `<style>` 追加在 HTML 后面，而解析只取第一个 —— 渐变从头到尾没被读过，
   界面上却照样报「渐变受限×4」。**这是本项目第六类缺陷的教科书样本：
   判据在错误的解析层。**

3. **`motion` 字段曾经 0/35 进入交付物。** 已修，现在 35/35。
   **有对照证据**：S34 两轮产物，第一轮四项动效结构全无，第二轮全有，
   且降级段的 `104/96/112/88/120/92` 六个值逐字命中。

4. **`audit` 35 段全部改写成正面处方并接进提示词。** 11,365 字 → 6,075 字，
   内部编号 35 处 → 0 处。原因是「点名即加权」：arXiv 2601.08070（n=40,000）
   实测 87.5% 的违规发生在被禁词被**显式点名**时。原来那 35 段全是负面点名。

5. **`dna.fonts` 补了第四个槽 `latin`（2026-11-22）。** 原来只有
   display / body / mono 三个槽，而 **5/35 案**为一处局部拉丁字单独排了款字体
   （S01 Archivo / S03 Space Grotesk / S04 Unbounded / S16 Archivo Black / S19 Spectral）。
   三个槽全被占满时这一角色无处可去，整个从提示词里蒸发 ——
   而它此前挂在 `score.mjs` 的 `KNOWN_EXEMPT` 上，**把产品缺陷登记成了判据豁免**。
   补完之后正对照的豁免数从 1 降到 0（`KNOWN_EXEMPT` 现在是空对象）。
   解析详情见 `_probe/79` §四十五、§四十七。

## 一、现在有什么在跑 / 什么跑不了

**没有东西在跑。** 工作区干净，`quarter.mjs` **28 步**全过，
研究线 **19 项 / 27 条断言**全过。

**但盲测跑不了 —— 上游窗口是开合的。** 先跑这个确认：

```bash
node deliverables/78-northstar/_probe/_pipeline-health.mjs
```

它用最小请求测延迟，报绿/黄/红三档。**红的输出里写死了一句**：

> 这不等于"案太难"，也不等于提示词有问题。

因为那是最容易犯的误读。2026-11-22 实测同一个 5-token 请求：
**2.7s ~ 50s+，抖 20 倍**，且窗口是分钟级的 —— 刚才 S22 第二轮就吃了一次
「22.4s → 超时无产物」。产出一个 7–8 KB 的 HTML 约需 2–3 K token，
按坏情况要一个多小时。**超时是必然的，与案难度无关。**

### 两个必须分清的历史坑

- **`TaskStop` 停掉监控 shell 不等于停掉运行**。计划任务起的进程是独立的，会继续跑。
  S21 就是这样：06:25 停了监控，它跑到 07:12 写出产物，据此写了两版错误结论。
  判断「这一轮没产出」之前，先确认进程真的没了。
- **`acp-run.mjs` 报「超时」有两种原因**：会话建立了但上游没吐字（`_acp-events.json` 是 `[]`），
  或者会话压根没建立（连事件文件都没有）。两种都不等于「模型做不出这个案」。

## 五、为什么批量不能并行（重要基础设施约束）

Deny ACE 是**按账户**生效的，不是按进程：

```powershell
icacls <repo> /deny "ClaudeBlindBox:(OI)(CI)(RX)"
icacls <repo> /deny "ClaudeBlindBox:(OI)(CI)(W)"
```

所以并行跑 N 个案不会更快，只会互相挡住。
