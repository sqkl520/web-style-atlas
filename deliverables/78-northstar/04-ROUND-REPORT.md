## 一、修掉的真缺陷（都提交了，都有实测证据）

### 1.1 `measure.mjs` 三处静默失败（`7d87923`）

| 缺陷 | 后果 |
|---|---|
| 静态服务站点根 = HTML 目录 | `../_fonts/` 全部 404，**字体静默回退成系统字体**，字号字距量出来全错 |
| CLI 入口用 `argv[1].endsWith('measure.mjs')` | 任何以 measure.mjs 结尾的脚本 import 时也触发 CLI 分支，多跑一次测量 |
| favicon 404 | `Page.navigate` 被任一失败子资源触发 → 整页测量抛异常 |

第二条最阴：症状是「同一个函数打印两次 `[nav]`，一次路径对一次路径错」。
只看数字的话，它表现为「有时测的是别的案子」，且不报错。

修后实测：S01 得 4 栏 `div.columns`（比例 5/16, 4/16, 4/16, 3/16，与 CSS 吻合）。

### 1.2 S31–S35 的提示词是坏句（`8e99eeb`）

Q2 建这 5 个新案时没同步加进 `build-prompts.mjs` 的 HUMAN 手写表，取值落到
`HUMAN[d.id] || { plain: "" }` 兜底，**缺失被静默成空字符串**。后果三处，全部用户可见：

1. 提示词里出现 `请把整页做成这个风格：。` —— 没有宾语的病句
2. 选型台卡片的「人话版」是空白
3. `sceneIndex` 里这 5 案的场景全丢

而当时 **15 步季度体检全过** —— 没有一条断言问过「plain 是不是非空」。

补了数据，**并加了闸门 D1 + 变异测试**。修后：
`请把整页做成这个风格：只给读数不表态，刻度当骨架。`

### 1.3 S34 零图设计被要求放 3 张图（`4ef90b2`）

`build-prompts.mjs:327` 原写 `minPics: (cap && cap.minPics) || h.minPics`。
`0` 是 falsy，于是「实测 0 张图」被当成「没有实测值」，回退到人工估计 3。
S34「石墨零图索引」实测 `<img>` 数量是 **0**，提示词却写「至少要 3 个不同的图片位置」。

修后 S34 `minPics: 0`，`prompt-copy.js` 的 `s.minPics ? … : ""` 让那句正确消失。
**并加了闸门 D2 + 变异测试。**

### 1.4 `layoutKind` 只有生产者没有消费者（`7c04243`）

structure 补齐后全库审计发现 **13/35 案（37%）主容器是页头/页脚/导航**：
S09 S10 S14 S16 S17 S19 S20 S23 S25 S26 S33 S34 S35。

用 `measure.mjs` 重量这 13 案，**13/13 全部修正**。S17 的根因单独追到了：
`probe.mjs` 的画廊判据「子元素过半含图 ⇒ tracks=0」把 `.sheet` 误杀
（3 个子元素、2 个含图、**937 字正文**），真版心连候选都没进。

加了 `layoutKind` 区分 `fixed`/`auto-fit`/`no-column-layout`。但发现它
**只有生产者、没有消费者** —— 没有任何断言检查。这正是 §1.2 那个病的翻版。
补了 C7 断言，它**立刻抓到 S08 没被重渲染过**。

### 1.5 盲测提示词少一半约束（`4e0394c`）—— 这条是我自己的错

规划 Agent 复核时抓到一处真矛盾：我的 `blind-run.mjs` 写「不用任何图片文件」，
而产品提示词写「图片位置写成 `<img src="images/占位-N.jpg">`」，
而 `compare.mjs` 的「图片位」判据正是判这个。

实测同一案 S31：

```

缺：结构约束 5 条（含 minItems/minPics）、防退化 8 条、验收三问
```

改成直接调 `buildStylePrompt`。35 案重新生成，幂等性已验证。

**连带更正**：我曾据此发结论「图片数 0/35，这条判据不该存在」给正在改判据的 agent。
那是错的 —— 我扫的是自己拼的简化版，不是产品实际输出。真实覆盖率：

| 可度量 | 产品提示词覆盖率 |
|---|---|
| 字号比 / 线宽 / 配色 / 图片数 / 条目数 / 防退化 / 验收三问 | **各 35/35** |
| 栏数 | **16/35** |

**唯一缺指令的只有栏数。** 那个 agent 没有采纳我的错误建议，坚持了 `>= minPics` ——
它是对的。

## 二、生成侧：可行，但「盲」这个前提经历了证伪与重建

### 2.1 第一次尝试（失败的）与它证明的事

隔离方式：临时 HOME + 临时 cwd + `claude -p`。素材 S31，**704 秒**产出 414 行 HTML。

六个可测值全部命中：配色 5/5 精确、标题/正文比 6.50 对 6.50、机制句
`MAJOR=60 / MINOR=12 / 3px×34px / 2px×12px` 全部精确。

**但这套隔离后来被证伪**（§四）。所以这次实验只能说明「提示词能驱动复刻」，
不能说明「模型不知道答案」。

### 2.2 复现性测试失败得很重要

同一提示词、同配置跑第二次：**>28 分钟仍无产出**（第一轮 704 秒）。

生成任务是开放式的，模型自己决定页面做多长，耗时方差按倍计。
**所以正确表述是：可复刻，但成功率未知，需 N 次采样才能估。**
批量方案已按此调整：超时设 3600s，**超时不算失败**（超时后照样收 `out.html`）。

### 2.3 真隔离：机制已验证，但沙箱内产出尚未跑通

用 **NTFS Deny ACE + 独立本地账户**，内核级强制，`bypassPermissions` 也绕不过：

```
READ_REPO_DENIED              ← 以 claudeblindbox 身份读 D:\Web\style 被拒
READ_CONTROL_OK:CONTROL-OK    ← 同一进程读别处正常（证明不是环境坏了）
WHOAMI:win10pc-sqkl520\claudeblindbox
```

那条**对照文件**是关键：只有「读仓库失败」不能证明隔离，因为环境故障也会那样。
两者同时出现才成立。

**但沙箱内产出 HTML 没跑通。** 四次尝试：

| 尝试 | PATH | effort | 结果 |
|---|---|---|---|
| v3 | 不全 | max | 456 token 就停，无产物 |
| v4 | 不全 | max | 2274 行 stream，2 次工具调用全失败（`pwsh timed out`），无产物 |
| v5 | **完整** | max | 17347 行，**17329 个 thinking 事件**、4 次工具调用全成功、**0 错误**，仍无 `out.html` |
| v5b | 完整 | **medium** | 2899 行，**2891 个 thinking**，仍无产物 |

v5 的 `errors count: 0` 说明环境是通的 —— 模型读了任务、列了目录，
然后陷在思考里，17329 个 thinking 事件没有一次落到 Write。

**对照：管理员环境下同样的任务 704 秒完成**（414 行 HTML，六项约束全中）。

我停在这里，理由：隔离机制本身早已验证成立；剩下的问题是「模型在特定 HOME 下的行为」，
与隔离有效性无关；继续盲试的组合空间很大，每步 20–40 分钟。
**没有把它写成「已完成」。**

## 三、对账侧：判据现在真的能失败

`compare.mjs` 从 7 条变 8 条，旧版 4 条无法失败的判据全部处理：

| 旧 | 新 | 说明 |
|---|---|---|
| 主体栏数 `ok:true` 写死 | 拆成「分栏结构」（判分类）+「主体栏数」（自校准） | 数值会漂（中缝让 2 栏数成 3 轨），分类不会 |
| 主轴比例 只报不判 | 自校准 + 可信度门槛 | 加了「产物侧比原型侧更易选错元素」的守卫 |
| 线宽(stroke) `ok:true` 写死 | 删除，另立「线宽档位合规」 | 原判据判实现手段（用不用 SVG），硬改会把正确实现判红 |
| 图片位 `> 0` | `>= minPics` | 提示词 35/35 有这条指令 |

**变异测试 26/26 全绿**，并加了「8/8 条判据同时出现过 PASS 与 FAIL」的极性核对。

改后实测：

```
S03: 6/6（2 项无法判定）    S07: 8/8    S17: 7/8
S06 6/6  S14 5/5  S19 6/6  S23 6/6  S24 7/7  S26 6/6
```

S03 的 6/6 与旧的 7/7 **不是同一件事** —— 旧版 7 条里 4 条不可能红。

## 四、被证伪的三条（包括我自己的）

### 4.1 「隔离可行」—— 被红队证伪

三条独立理由：

1. **`--permission-mode` 是权限提示，不是隔离。** 改成 `bypassPermissions` 就能读任意文件。
2. **「shell 不可用」是误判。** 那只是 `PATH` 缺 `C:\Windows\System32`。
   **我把一个环境故障当成了安全控制。**
3. **我的隔离脚本抄错了 HOME。** `HOME=/tmp/...` 与 `USERPROFILE='C:\tmp\...'`
   在这台机器上是两个不同目录（`/tmp` → `AppData\Local\Temp`）。
   那份 98KB 的 `.claude.json` 从来没被加载过。

### 4.2 「图片数 0/35」—— 我自己的错误，已更正

见 §1.5。教训：**分析任何东西之前，先确认它是不是产品真正产出的那个东西。**

### 4.3 「重渲染只改 at 和 structure」—— 过强

结构补齐 Agent 实测：剥掉两键后对 HEAD 是 **28/35** 逐字节相同，
差异 7 案全在 `motion.*` / `filled[i]` / `page.height` / `textColors.share`。
反向实验证明这些**不是本次改动引入**（旧引擎连跑两次同样会抖）。
所以那句话在 S01/S17/S05 上成立，作为 35 案的普遍结论过强。

## 八、我的判断

**提示词是有效的**，这一点有硬证据：配色精确命中、字号比 6.50 vs 6.50、
机制句六个可测值全中。一个模型不可能猜出 `MAJOR=60, MINOR=12`。

**但「盲测」这个词现在还不能用**，因为：

1. 真隔离虽已验证，但单案还没产出，批量未做
2. 缺负对照 —— 无法排除「模型对任何风格描述都给一个通用好看页面」
3. 提示词里 18/21 个数值原样来自答案（红队实测），所以它测的是「照施工图施工」，
   这在你的定义下是正确的北极星，但**不能再说成「验证了提示词的信息量」**

**最有价值的下一步不是跑更多案子，而是加负对照。** 一个不存在的风格 S99，
如果模型也能做出一份像样的页面，那么现在所有的「命中」都要打折扣；
如果它对 S99 明显做不出结构，那 S31 的六个精确命中就有了真正的说服力。
