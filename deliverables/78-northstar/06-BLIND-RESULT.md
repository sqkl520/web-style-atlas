## 零、四个对照合起来说明什么

这是本轮全部的证据：

| 实验 | 数值 | 机制 | 结果 | 说明什么 |
|---|---|---|---|---|
| **S31** | 有 | 有 | 399 行，六值精确命中 | 数值 + 机制 = 可精确复刻 |
| **S99** | 有 | 有（虚构风格） | 459 行，9 值精确命中 | 数值通道与风格无关 |
| **S98** | 无 | 有 | **零产物**（2 小时，44,788 token） | 半个具体 = 卡死 |
| **S97** | 无 | 无 | 466 行，20853 字节 | 完全不具体 = 通用页面 |

一句话：

> **决定成败的不是「有没有数值」，而是「任务有没有可收敛的具体约束」。**
> 「具体到需要精确值、却没给值」比「完全不具体」更糟。

### 0.1 各自排除了什么

- **S99 排除了**「精确命中 ⇒ 风格被传达」。给任何一组精确数值，同一个模型都会精确命中。
- **S98 排除了**「文字描述足以承载结构」。删掉数值、保留全部文字，模型 2 小时没写出一个文件。
- **S97 排除了**「没数值就做不出东西」这个简单结论 —— 泛化描述反而能做出 466 行。

### 0.2 这对产品意味着什么

**好消息**：给足数值时，模型能精确复刻（S31 + S99，11 次验证）。
你的北极星是「测复刻保真度」，而数值通道非常可靠。

**真实的脆弱点**：机制句是绝大多数可测值**唯一**的承载处。
实测 35 案里 33 案的可测值只出现在机制句这一句话里，
结构化字段（`lineWidths` / `h1Size` / …）并不复述它们。
机制句一旦丢数字，提示词会静默失效 —— 读起来完全正常，模型却做不出来。

已加闸门 D3 拦住这个形态（机制句必须含至少一个带单位的可测值或 `a:b` 比例）。

### 0.3 我不能排除的

S98 的零产物也可能是「分析瘫痪」而非「不知道怎么做」。
从外部无法区分，但对产品的含义相同：**那份提示词用不动。**

## 二、隔离是怎么做的（这段决定上表可信不可信）

### 2.1 不是权限提示，是内核级拒绝

```powershell
icacls D:\Web\style /deny "ClaudeBlindBox:(OI)(CI)(RX)"
```

Deny ACE 优先于任何 Allow（包括 `BUILTIN\Users` 的继承权限），由文件系统层强制。
模型无论怎么要求 `bypassPermissions` 都改不了它。

**决定性证据必须两者同时出现**：

```
READ_REPO_DENIED              ← 以 claudeblindbox 身份读 D:\Web\style 被拒
READ_CONTROL_OK:CONTROL-OK    ← 同一进程读别处正常
WHOAMI:win10pc-sqkl520\claudeblindbox
```

只有 `READ_REPO_DENIED` 不能证明隔离 —— **环境故障也会那样**。
这正是我早先被判「隔离不可行」时的错：把 `pwsh timed out`（实际是 PATH 缺
`C:\Windows\System32`）当成了安全控制。

### 2.2 挡不住什么（必须如实说）

- **模型的先验知识**。S31 是「钟表修理铺 + 尺规刻度」，一个见过类似设计的模型
  可能凭先验做出四栏结构。这不是隔离能解决的，只能靠负对照测。
- **网络泄漏**。若 agent 能搜到本仓库的 GitHub Pages，隔离就失效。
  `WebFetch`/`WebSearch` 目前被**域名安全校验**挡住，但那是域名校验，不是网络隔离。

## 四、三个对照的完整结果

| 对照 | 做法 | 回答什么 | 结果 |
|---|---|---|---|
| **负对照 A（S99）** | 不存在的风格 + 精确数值 | 数值能不能被遵守 | ✅ 能，9/9 精确命中 |
| **负对照 B（S98）** | 删掉全部数值，只留文字描述 | 文字描述本身承不承重 | ✅ **不承重，2 小时零产物** |

前两个都做完了，结论已经在 §零。正对照还没做 ——
它的作用是定量「一个不含任何机制的通用描述能让模型做出多高」，用来校准 §零 里
「S98 零产物」的分量。但它不改变现有结论的方向。

### 4.1 S98 的实验细节（为什么可信）

S98 是 S31 的提示词，只改数值相关的内容：

| 项 | S31 | S98 |
|---|---|---|
| 机制句 | 主刻度每 60px、长 34px、3px 宽 | 主刻度的间隔宽、刻线长而粗 |
| 线宽 | 1px | 只用一级，全站同粗细 |
| 字号 | 正文 16px；最大标题 6.5 倍（约 104px） | 正文是常规阅读字号；最大标题压到正文的好几倍 |

**刻意保留配色 hex 与字体名**：它们是设计身份，不是尺寸参数。
保留它们能做内部对照 —— 如果产物仍精确用上那 5 个色，
说明「照着值做」这条通道本来是通的，那么结构做不出来就只可能来自数值缺失。
（这个对照没用上，因为零产物。）

自检：改写后全文**无任何 `px`、无任何「N 倍」**，配色行完整保留。40 行 / 5090 字节。

### 4.2 排除的替代解释

- **不是 API 故障**：我一度以为 stream 里有 205 处 `API Error 524`，
  逐条核查后发现那些 `524` 全部来自 UUID 和 `estimated_tokens:524`，**真实错误数 = 0**。
- **不是隔离失败**：它成功读了 `task.txt`。
- **不是任务书损坏**：5090 字节、40 行，格式与 S31 同构。
- **不是死循环**：thinking token 单调递增（15850 → 16432 → 17105），在持续推进。
