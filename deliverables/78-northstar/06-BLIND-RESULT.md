## 二、为什么这组数字算证据

### 2.1 六个目标倍率互不相同，而产物各自落在自己的目标上

```
S31 目标 6.5 倍 → 产物 6.50
S04 目标 4.2 倍 → 产物 4.24
S08 目标 4.9 倍 → 产物 4.88
S13 目标 3.7 倍 → 产物 3.73
S22 目标 4.7 倍 → 产物 4.76
S32 目标 6.3 倍 → 产物 6.31
```

**这是最硬的一条。** 一个「通用好看页面」不可能同时命中六个互不相同的目标倍率。
如果是碰巧，那它得碰巧六次，而且每次误差都在 1.3% 以内。

### 2.2 配色 26 个值全中，而历史上这里是真失败点

`prompt-copy.js:600-616` 记录过一次真实事故：

> 2026-11-04 的盲测发现：让模型只按提示词复刻 S17，它做出的页面缺了原型里的
> `#D6C9AC`（`--tone-hold`，悬停态）。根因是 `pickPalette()` 的上限是 7 色，
> 而该案 `:root` 有 8 色。逐案统计有 6/30 案存在这个截断。

而且当时的第一版修法是错的：加一句「需要状态色时从上述值调明暗」，
模型完全照做，仍然只用了列出的 7 个色 —— 因为**「调暗一点」可执行，
「调成 #D6C9AC 这个值」不可推断**。

这轮 26 个色值全中，说明上游修法（`clean-dna.mjs` 的 MAX 从 7 提到 9）是对的。

### 2.3 唯一的缺口是真偏差，不是判据问题

```
S13 提示词给 7 档线宽：1px、2px、3px、4px、9px、14.5px、1px
    产物用了 5 档，缺 9px 与 14.5px
```

提示词明写「线宽只用这几级」，产物少用两档。**这是真偏差。**
但语义上「少用两档」不等于「做错了」—— 可能那个设计里没有需要 9px / 14.5px 的地方。
所以建议记 **WARN 不记 FAIL**，处置留给产品判断。

## 三、隔离是怎么做的（这段决定上表可信不可信）

### 3.1 不是权限提示，是内核级拒绝

```powershell
icacls D:\Web\style /deny "ClaudeBlindBox:(OI)(CI)(RX)"
```

Deny ACE 优先于任何 Allow（包括 `BUILTIN\Users` 的继承权限），由文件系统层强制。
模型无论怎么要求 `bypassPermissions` 都改不了它。

**决定性证据必须两者同时出现**：

```
READ_REPO_DENIED              ← 以 claudeblindbox 身份读 D:\Web\style 被拒
READ_CONTROL_OK:CONTROL-OK    ← 同一进程读别处正常
WHOAMI:win10pc-sqkl520\claudeblindbox
```

只有 `READ_REPO_DENIED` 不能证明隔离 —— **环境故障也会那样**。
这正是我早先被判为「隔离不可行」时的错：把 `pwsh timed out`（实际是 PATH 缺
`C:\Windows\System32`）当成了安全控制。

### 3.2 挡不住什么（必须如实说）

- **模型的先验知识**。S31 是「钟表修理铺 + 尺规刻度」，一个见过类似设计的模型
  可能凭先验做出四栏结构。这不是隔离能解决的，只能靠负对照测。
- **网络泄漏**。若 agent 能搜到本仓库的 GitHub Pages，隔离就失效。
  `WebFetch`/`WebSearch` 目前被**域名安全校验**挡住，但那是域名校验，不是网络隔离。
