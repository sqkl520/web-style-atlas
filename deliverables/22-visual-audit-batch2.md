### 0.3 我发现自己工具的三个真缺陷（都会伪造"页面坏了"，已修并留 A/B）

1. **v1 断行探针把同一视觉行上的多个文本节点判成上下两行 → 假"行尾悬挂 `·`"。**
   机制：`lineInfo()` 按文本节点顺序把 `Range.getClientRects()` 的结果拼接，没有按 `top` 聚类。
   典型受害者：`<span class="ref">NARA · 公有领域 · <a>Wikimedia Commons</a></span>` ——
   「NARA · 公有领域 ·」与「Wikimedia Commons」**y 坐标完全相同**（同为 y=3974），却被当成第 1 行与第 2 行。
   A/B：**S14 v1 报 18 条"行尾悬挂"，v2 报 0 条**；S11 v1 报 12 条 → v2 报 0 条；S13 v1 报 12→v2 报 1 条。
   **本报告正文里的悬挂/孤字计数一律采用 v2（逐字）口径。**
2. **v2 遮挡探针漏了"覆盖层是文本自身的祖先/后代"这一过滤 → 报出十几条无意义的"祖先盖住自己"。**
   例如 `code ":~$ /tag pump-3 出口阀"` 被 `div.promptline`（自己的父元素）"覆盖"。修好后 S19-p 的命中从 28 → 0。
   （v1 `probe.mjs` 里有这条过滤，v2 `occ2.mjs` 我重写时漏了，v3 `occ3.mjs` 补回。）
3. **遮挡采样对"贴视口顶边的固定/吸顶条"天然误报**：内容滚到固定条下方是**正常行为**，不是缺陷。
   A/B：加进"最近定位祖先 + `rootRect.y ≤ 8` 才算正常"的过滤前后——
   **S15 d 22 / t 51 / p 77 条 → 0 / 0 / 0 条**；**S18 t 74 → 45 条**（剩下的全是"框宽字短"的采样误差，见下）。
   本报告 §S11/S13/S14/S16/S18 里"已排查"的那几段，就是这条规则的产物。
   附带一类残留假阳性：**块级元素框很宽但文字很短**（`h2 "一条纸不分页"` rect 宽 1285px、文字只占 200px），
   落在固定条上的采样点会被记成"文字被盖"。判据：目视该元素文字区域无遮挡即排除。

**另外两条已知但本次未触发的工具问题**：
- 对比度探针**不做祖先 `opacity` 合成**（我把 `ancOpacity` 采了但没并入计算）。本批 30 档里没有 `opacity<1` 且承载正文的元素，故未造成误判。
- CDP 库 `Page.captureScreenshot` 的整页上限写死 **16000px**：`S18-p`（页高 16547）、`S19-p`（16992）的整页图被截断，改用单片图复核末屏。

     文本行 `lineTop 1407 / lineBottom 1508`，容器 `boxTop 498 / boxBottom 1454`（文档坐标）→ **末行 54px 落在容器之下**。

**【S12-F3｜轻微｜日志里的错误态红字对比度 3.91:1（17px / 600）】**

## 4. 我最不确定的 3 条

1. **S19 的 `.dw__note` 到底算不算缺陷？（最不确定）**
   不确定在哪：一边是实测 **3.19:1（复份卡 2.67:1）**、15px 常规字、远超"可读"下限；
   另一边是本案的叙事就是"褪色手写批注层"，而且 §S19 的 `:216` 注释写的是"12% 褪色墨洗色"。

2. **S13-F4 的 1440 档「层级」列是"刻意竖排标签"还是"被挤出来的"？**
   不确定在哪：`index.html:243` 是整串文本、无 `<br>`、无 `white-space`，看起来是被 `table-layout:auto` 挤的；
