## ① 重测这件事值不值

### 判定：**不值。不是"性价比低"，是"测完等于没测"。**

三条独立的理由，任何一条成立就足以否掉：

**(a) 原件不是"某个 Agent 读代码得出的结论"，是一行注释加 9 个手写布尔值。**

```
build-prompts.mjs:113  // 不能大众化的 9 案（机制绑死行业数据结构）——如实标注，不硬接
build-prompts.mjs:114  const HARD_IDS = Object.keys(HUMAN).filter((k) => HUMAN[k].hard);
build-prompts.mjs:83,85,90,94,95,98,100,101,109   ← 9 处 hard: true
```

判据**一个字都没有落纸**。`deliverables/` 全库检索「不能大众化」「机制绑死」：`60-minitems-degrade-audit.md` 0 命中、`_specs/` 0 命中、`data.js` 0 命中。唯一书面表述就是 `:113` 那行注释，且**无逐案理由**。

这不是"标注"，是"口径"。**重测一个没有判据的判断，产出的只是另一批没有判据的判断。** 两批 Agent 分歧时无法仲裁——因为谁都没有可执行的定义可以拿出来对质。这不只是理论风险，它已经发生了：`62-audit/hard-vs-degrades.md:87` 判"9 案里只有 2 案站得住"，而 `62-plan/PLAN-three-tasks.md:48` 判"hard 是一个不可复验的人工判断"。同一批代码，两个 Agent，两个结论，**没有裁判**。

**(b) `hardIds` 是死字段。你计划里"最后重定 hardIds"这一步，改了不会改变任何东西。**

全仓库检索 `hardIds`：

```
prototypes/_selection/prompts.js:375   ← 生成处
（app.js / prompt-copy.js / index.html / wizard.js / templates/ / _build/ 全零命中）
```

驱动 UI 的是**每案的 `hard` 布尔**（`prompt-copy.js:471  var riskyTopic = !!s.hard;`），不是那个名单。你把 `hardIds` 从 9 个改成 7 个，选型台一个像素都不会动。要真改，得改 `build-prompts.mjs:83-109` 那 9 行 `hard: true`。

**(c) 这个警告在 30 案里出现 16 次（53%）。它不是异常信号，是背景噪音。**

`hard`(9) ∪ `degrades=yes`(13)，交集 6 → 16 案带警告，14 案说「粘给谁都行」。**一半以上的案子上这个位置都挂着黄字。** 一个出现率 53% 的警告，训练出的行为是"忽略这个位置"。

顺带：`prompt-copy.js:465` 注释写「两套口径只重叠 5 个」，实测是 **6** 个（`S05 S14 S15 S18 S20 S29`）。连审计注释里那个数字本身都没复算过。

### 那谁对？
**都不对，因为问题不在"谁读得更细"。** 9 案的 `dna.mechanism` 我逐条读了，没有一条能机械导出"绑死行业数据"这个属性：

```
S03: 264px 纵向刻度轴随滚动固定，9 栏高度按 30 秒曝光折成 28px 一档…
S10: 五栏按 6:7:9:8:5 分宽，红版相对黑版固定右下错 1px…
S20: 画布 1:1、边长取视口高减 96px，坐标格 0.2px 间距 8px…
```

这些全是**版面机制**。S03 的机制甚至根本不读数据（见 ⑤-A）。`hard` 这个名字许诺的是"语义依赖"，机制句描述的是"几何参数"。**两者之间没有推导路径，再多 Agent 也补不出来。**

## ② 替换实验的方法论问题

### 判定：**它测的是 degrades，不是 hard。而且它测不出 degrades 也能测——那已经有实测数据了。**

你的实验设计：把文案换成水果名，看版式崩不崩。三个漏洞：

**(a) 实验没有操纵"行业性"这一维。**

水果名列表和行业术语列表，在结构上是同构的——都是名词、都是等长条目、都是 N 条。你换掉的是语义，保留了长度、数量、结构。所以：

- 版式崩了 → 只证明它依赖**长度/条目数/坐标**，不证明它依赖**行业**
- 版式没崩 → 也不证明"换成非行业内容仍成立"，因为水果名同样是"名词列表"

**两个结果都不能证实或证伪"行业"这个自变量。** 这个实验的自变量选错了。要测"行业性"，得操纵"这条内容有没有真实编号体系/双重引用/量纲"，而不是换词。

**(b) 它测出来的东西，仓库里已经有一份更便宜的实测。**

"内容少于 N 条会崩"= `degrades`，13 案，来源 `_prompts/minitems-parsed.json`，是读 `style.css` 定位规则算出来的，一条命令可复算。你用"派多个 Agent + 跑替换实验"去重测一份已有的实测数据，成本高两个数量级，精度还更低（人工看"崩没崩"是二值判断，实测是坐标）。

**(c) 一个反例直接打穿：S03 的缺陷两个维度都测不到。**

`S03` 是 `hard=true` 但 `degrades=no`（`minitems-parsed.json` 实测）。它的真实缺陷是**版面尺寸**：

| 事实 | 位置 |
|---|---|
| 年代轴写死 `height: 640px` | `S03/style.css:131` |
| 8 条影像带高度 `--h:28px/42px/14px/56px/19px/37px/84px/23px` | `S03/index.html:71-99` |
| 合计 303px + 7×4px 间隙 = **331px** | 实测计算 |
| 对 640px 轴 → **空 309px** | 331 vs 640 |
| 年份是字面量数组，与带子零关联 | `S03/index.html:234-235` |
| 刻度循环用 `640` 写死 | `S03/index.html:229` |

换成西瓜、苹果、香蕉，那 309px 空洞**一寸都不会变**——它跟文案一个字的关系都没有。而它跟"行业数据"也没有关系，它是设计稿本身没排满。**这个实验对这案的两个可能缺陷都失明。**

### 结论
替换实验的产出会是「一份 degrades 的人工复测」。而 degrades 已有机器实测。**方法搞错了对象，且替代品更差。**

## ③ 字段 11 的真相（含重合度实测）

### 先纠一个事实错误：字段 11 不是「最难被复用到别的品牌的地方」。

字段 11 是**「可落地要点」**——CSS 思路、字体加载与子集预算、图片处理、性能预算。那句"最难被复用…"只是它**句尾的一句尾巴**，而且只有 21/30 案有。


| S11–S30 | **20/20** | 全部都有 |
| **合计** | **21/30** | |

### 与 HARD_IDS 的重合度实测

| 项 | 值 |
|---|---|
| 字段 11 有该句 | 21 案 |
| HARD_IDS | 9 案 |

这条同时否掉了你第 2 节的两个假设：
- 「hard 该不该直接从字段 11 派生？」—— 派生出来是 **21 案**，不是 9 案。名单会完全变样。

## ⑥ 如果只能做一件事

### 先直接回答你的二选一：**「字段 11 暴露给用户」比「重测 9 案 hard」值。但两个都别做。**

- 重测 hard：改的是死字段（①-b），产出是无法仲裁的第二批判断（①-a），对 UI 零影响。
- 字段 11 暴露：至少有真内容（21 案作者原话），但**它不是写给选型者的**——里面是 CSS 思路、字体子集 KB、LCP 预算。而且 21/30 都说"换品牌得重写"，暴露出来等于对 70% 的图集说同一句话，用户学到的是"全都难复用"= 零信息。

### 应该做的那一件：**把 hard 从 UI 删掉，把它想说的话改写进提示词正文。**

理由链：

1. **它没有判据**（①-a）→ 不配占一个用户可见的警告位。
2. **它与 `degrades` 重叠 6/13，且三案（S03/S10/S21）在 UI 上直接自相矛盾**（④-c）→ 留着就是在同一屏上说两句话。
3. **它指路指向 3.3 屏之外**（④-b）→ 用户拿到警告也拿不到解释。
4. **提示词里已经有成功的先例**：`prompt-copy.js:233-237` 已经把 `degrades` 按"手工排定 / 自动流"分化成两句**可执行**的约束——「这个版式的单元位置是手工排定的…不要留空槽，也不要为了凑数编造内容」。同样的手法可以对 hard 做：把「换普通内容会退化」换成「这案的记忆点依赖一组带真实编号/尺寸/年份的条目，请先确认你有这类数据，没有就换案」。
5. **可验证**：改完只需在 `prompts.js` 里 grep 那句话是否 30/30 出现。不需要派 Agent，不需要替换实验。

**一句话：让 AI 在生成时处理这件事，而不是让用户读一句 12px 的警告、再滚 3.3 屏去找解释。**
