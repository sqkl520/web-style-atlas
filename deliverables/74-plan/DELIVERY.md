## 0. 部署现状（先核实，结论：已经上线，但上的是旧产品）

判断：**不需要再开通 Pages，也不用改部署路径**。要改的是「首页是什么」。

但当前根入口有两处必须随首屏一起改掉，因为它们是陌生人第一次访问的真实第一步：

- `index.html:11` 的 meta refresh 把根地址做成一张空页（`index.html:22-27` 只有「正在前往选型台…」），后退键回不到根页、爬虫与屏读器读到的是空页；
- 产品页 `<title>` 与 H1 都在说作者的事（`prototypes/_selection/index.html:5`「30 个网站设计风格方案」、`:39`「三十个案，一条渲染口径」），没有一处说「复制一段提示词」。`deliverables/74-recon/ux.md:19` 已把这一条列为旅程第 1 步的断点。

**决定：把根 `index.html` 直接做成新的首屏**（不再跳转），`prototypes/_selection/` 保留为「全部方案」深链，供老链接与向导回跳。这样 30 这个数字、闸门、README 都能留在第二层，而首屏只负责把一件事说清。

## 1. 五秒测试：首屏该是什么

### 1.1 结论：**首屏是那个问题，网格是答案**

现在把 30 张卡直接摆在第一屏，等于让一个店主先做 30 次判断、再自己猜「选完之后会得到什么」。本仓实测的整数恰好说明这条路不成立：18/30 暖浅底、L 20–60 空、29/30 零圆角、「很安静」只有 2 案（`deliverables/74-recon/00-SYNTHESIS.md:74-78`），也就是说**摆 30 张卡，视觉上像摆了同一张卡的 18 个变体**；首卡在 390 档 top=402px、1440 档 top=483px（`deliverables/74-recon/ux.md:20-21`），首屏只够看到 1–1.5 张，撑不起「浏览一个图集」的承诺。

而 `wizard.html/js` 已经证明第一问可以不是「你喜欢什么风格」：`wizard.html:21-22` 的原话「不问…那个问题没人答得上来。问的是你的处境」。它是 5 问、同页逐条揭示（`wizard.js:87-90`），结果 3 推荐 + 3 排除，权重「未经真人回放测试」（`wizard.html:88`）。

所以首屏不搬整张向导（5 问太长、权重未验证），而是**只搬向导的第一问，并当场给答案**：

> 首屏问：「你是做什么的？」→ 用户点一颗行业芯片（或输入）→ 第一屏下半部立刻换成 3 张可用的方案卡 + 每张卡上明确的「复制 AI 提示词」。
> 30 张全量网格不再是首屏，而是首屏下方的一段「看全部 N 个方案 ↓」。N 从 `window.SCHEMES.length` 现算，不写死。

这一选择同时解决三件事：陌生人一进来就知道这里跟他有关；首屏不再需要 30 张截图（性能）；方案可自由增删归档，首屏文案一个字不用改。

### 1.2 逐像素的首屏规格（390×844 与 1440×900 共用一套 DOM）

```
┌────────────────────────────────────────────────────────────┐
│ 网站风格提示词     [看全部 N 个方案 ↓]   [这套东西怎么用]     │  顶栏 48px
├────────────────────────────────────────────────────────────┤
│ 给 AI 一段话，让它照这个风格做出你的店。                     │  H1，2 行内
│ 这里不是模板下载。你挑一种风格，复制一段提示词，             │  sub，2 行
│ 粘进 ChatGPT / Claude / v0，得到一份能改的单页 HTML。        │
│                                                            │
│ 你是做什么的？                        [看不懂？直接浏览 ↓]  │  问题行
│ [咖啡店] [餐厅] [花店] [设计工作室] [书店] [独立品牌] …       │  6–8 颗实心芯片
│ 还有 28 种行业只有近似款 · [展开]                            │  一行诚实附注
│                                                            │
│ ┌── 咖啡店 · 1 个直连风格 ─────────────────────────────┐    │
│ │ [1440 首屏截图，16:9，唯一一张 visible 图]            │    │  证据区
│ │ 昭和喫茶台账  ·  暖浅底 / 安静 / 亮底                  │    │
│ │ 适合：咖啡店、茶饮、需要慢慢看的店                     │    │
│ │ 不适合：要马上成交的促销页（先在下面看清楚）           │    │
│ │ [ 复制这段 AI 提示词 → ]   [ 看详情 ]                  │    │
│ └───────────────────────────────────────────────────────┘    │
└────────────────────────────────────────────────────────────┘
```

**必须在不滚动时可见的三样视觉证据**（缺一项就不算过 5 秒测试）：

1. **一张真实渲染截图**，来自 `.inspect/desktop-fold.jpg`（`data.js:98-102` 的 `shots.desktop[0]`），不是色卡、不是 CSS 插画。它是「这个风格真的被做出来过」的唯一凭据。
2. **一个「复制 AI 提示词」主按钮**，实心、与页面主色同级、≥44×44px，位置在截图卡内且在首屏内。不能只放在详情面板顶部（`prompt-copy.js:1201` 现在把它插到 `#d-body` 第一个子节点之前，仍然要用户先点开一张卡）。
3. **一句「不适合」**（`data.js` 的 `scenesNo`，见 §6），证明这里会帮人排除，不是把所有卡都夸一遍。

首屏文案（实际 UI 逐字）：

- 顶栏：`网站风格提示词` ｜ `看全部 N 个方案 ↓` ｜ `这套东西怎么用`
- H1：**给 AI 一段话，让它照这个风格做出你的店。**
- Sub：**这里不是模板下载。挑一种风格，复制一段提示词，粘进 ChatGPT / Claude / v0，得到一份能改的单页 HTML。**
- 问题：**你是做什么的？**
- 芯片：直接复用 `window.STYLE_PROMPTS.sceneIndex` 里 16 个 `direct` 非空的词（例如「咖啡店」「设计工作室」「书店」；真实词表见 `prompts.js:19-…`），默认只放 6–8 颗最高频，其余在「还有 N 种行业」里；**不写死行业名**，随索引现算。
- 附注：**实心＝为这行做过；虚边＝换文案也能用，但不是为这行做的。**（这句是 `prototypes/_selection/index.html:165` 现有图例，但今天被样式反转成谎言，见 §5-P1⑤）
- 结果头：**咖啡店 · 1 个直连风格 · 另有 2 个近似款**（数字全部由 `sceneIndex` 现算）
- 主按钮：**复制这段 AI 提示词 →**
- 次按钮：**看详情 / 换个行业**
- 折叠线：**看全部 N 个方案 ↓**（N = `window.SCHEMES.length`，30 只是今天的值）

**「一根主行动」纪律**：首屏只保留这一个实心主按钮。顶栏两项是文字链接，「看不懂？直接浏览 ↓」是文字链接，`wizard.html` 的 5 问入口降级为结果区底部一行「不想回答？走 5 问向导 →」（`wizard.html:21` 保留，但不再是第二条主路，因为它的权重未测）。`prototypes/_selection/index.html:43` 现在的「筛不出来？走选型向导」链接、`index.html:35-40` 的三条模板出口、`:53-58` 的报头四项统计、`:81-90` 的自闸门状态，全部移出首屏。

### 1.3 第一次滚动必须证明什么

第一次滚动（≈390 档 1 屏 / 1440 档 0.7 屏）只回答一个问题：**「换一种风格，成本有多低？」**

具体是「更多可复制的方案」段，至少 3 张卡、每张一张 desktop-fold 截图，卡片结构完全一致：

```
[截图]  风格名 · 一句话人话（prompts.js 的 plain，≤20 字，app.js:465-472 已在用）
        适合：…（scenesYes）   不适合：…（scenesNo）
        [复制这段 AI 提示词 →]  [看详情]
```

第一滚必须证明四件事，按可测量判据写：

| 要证明的 | 判据（可自动化） |
|---|---|
| 这不是只有一款 | 可见 ≥3 个不同 `data-scheme-id`，≥3 个不同的 `desktop-fold.jpg` |
| 这些风格真的不一样 | 3 张截图的底色 HEX 不全相同（今天 18/30 暖浅底，所以**必须按 `axes.band` 分组取**，不许连取 S01/S02/S03）；每卡印出 `bg`/`primary` 两个色块 |
| 每一款都能当场带走 | 每张卡都有独立复制按钮，且按钮在卡片首屏内（不要求先开详情） |
| 排除信息不是摆设 | 每卡都有 `scenesNo` 短句（`data.js:87` 等 30/30 有值） |

**第一次滚动不许出现**：闸门 FAIL/WARN 数字、截图总数、渲染口径、三档视口说明、README 链接、「怎么用」的 11 组筛选器、模板 M01/M02/M03、向导权重说明。这些都是作者侧的质检证据，店主不需要靠它决定下一步；它们整体沉到 `/prototypes/_selection/` 的「全部方案」页。

### 2.2 「用户知不知道自己拿到的是提示词」

**今天不知道，必须直说三遍**，且三遍内容不同、不重复：

1. 首屏 H1/Sub：「复制一段提示词，粘进 ChatGPT / Claude / v0，得到一份能改的单页 HTML」。
2. 每张卡按钮上方一行：**你复制的是一段文字，不是网站文件。**
3. 复制成功确认：**已复制 N 字提示词。现在去 ChatGPT / Claude / v0 粘贴；它给出的第一版 HTML 是起点，不是成品。**（逐字见 §3.2）

禁止的措辞：「下载模板」「拿到成品」「一键生成网站」「双击即对」（后一句现在在 `prototypes/_selection/index.html` 的模板出口块里，必须随该块一起移出首屏）。

### 2.3 12 段面板怎么改才够扫

不新增字段、不删数据，只做三件事（`app.js:1356-1395`）：

- **判决卡（新，一个 `<section>`，在 `<dl class="fields">` 之前）**：`r.plain`（prompt-copy `s.plain`，≤20 字）、`r.scenesYes`、`r.scenesNo`、`r.bg`/`r.primary` 两个色块、`capacityHTML(r)`（`app.js:482-515`）的「内容少于 N 条会留空位」警告。它就是用户判断「是我的店吗」的全部输入，≤180 字。
- **12 段全部进 `<details>`**：`field()` 第 4 参 `foldHint` 已是现成机制；把「字体策略」也折进去（今天为「够了就停」故意不折，`app.js:1364-1369`，但那是给作者看的判据，不是给店主看的），summary 上印字数与里面有什么，例如「字体策略 · 345 字 · 标题/正文/数字三档」。
- **顺序按判断成本排**：判决卡 → 适用场景（拆成 Yes/No 两行）→ 一句话视觉定义 → 配色 → 其余 9 段施工细节。删掉「反 AI 味审查点」「设计师签名式怪癖」在首屏的占位——它们对「买不买这个风格」零贡献。

判据：390×844 下 `#detail` 的 `scrollHeight` 从 2.85 屏降到 ≤1.5 屏，且复制按钮与判决卡同时在首屏内。

## 3. 修好交接：复制提示词这一下

这是产品唯一的转化点。设计目标是：**用户按一次，拿到一段他能核对、能在自己选的工具里粘、且知道自己接下来该干什么的文字；键盘与屏读器用户不因此丢失位置。**

### 3.1 控件结构（逐字 UI）

```
┌ 带走这个风格 ───────────────────────────────────────────────┐
│ 你经营什么          [例：只做手冲的咖啡店            ]      │
│ 访客要做的动作      [例：看完想直接加微信下单        ]      │
│ 填了会进提示词开头；不填就留 ＿＿ 横线，不替你编。          │
│                                                              │
│ [ 复制这段 AI 提示词 → ]   ← 唯一实心主按钮，≥44px          │
│ [预览全文 ⇄]  [下载 .md]  [ChatGPT ⌄] [Claude ⌄] [v0 ⌄] [Cursor ⌄] │
│ 约 1,600 字 · 这一案需要 JavaScript（见提示词第 0 节）      │
│                                                              │
│ <div role="status" aria-live="polite" aria-atomic="true">    │
│   已复制 1,642 字提示词。现在去 ChatGPT 粘贴；              │
│   它给出的第一版 HTML 是起点，不是成品。                     │
│ </div>                                                       │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 确认语（实际 UI 逐字，按 outcome 分三支）

- **成功**：`已复制 1,642 字提示词。现在去 ChatGPT 粘贴；它给出的第一版 HTML 是起点，不是成品。` 倒数第二句随用户选的工具替换（默认 `ChatGPT`，见 §3.3）。按钮内文字 `已复制 ✓`，`aria-live="polite"` 的 status 区同时播报，**但按钮文字不要放进 live region**（否则重排会读两次）。状态保持 ≥6 秒、不自动消失；再点一次复制会替换内容而不是叠加 toast。
- **需要手动**：`浏览器没让脚本写剪贴板。全文已展开并选中，按 Ctrl+C（Mac 用 ⌘C）即可。` 同一段文字进入只读 `<textarea>`，自动 `select()`，旁边有 `下载 .md` 与 `关闭`。**不许说「已复制」**——`prompt-copy.js:917-921` 的注释已实测 `execCommand` 返回 true 但剪贴板逐字节没变，成功判据只能是 `navigator.clipboard.writeText` 的 Promise（`:968-974`，这个顺序是对的，保留）。
- **无 clipboard API 且 exec 也失败**：`这段浏览器不支持自动复制，请下载 .md 或手动全选下面的文字。` 此时 `下载 .md` 升为主按钮。

### 3.3 目标工具：不做深链，做「同一段文字 + 一句上下文」

四个工具粘法确实不同，但**不能为它们生成四份不同提示词**（会立刻产生四份要维护的真源，正是本仓反复踩的病）。设计成「一份文本 + 一个工具选择」，工具只影响两件事：确认语里的工具名，和提示词首部的一段 1–2 行上下文：

| 工具 | 追加的首部（粘进去时一起复制） | 理由 |
|---|---|---|
| ChatGPT / Claude（默认） | 无额外上下文；照 `prompt-copy.js:836-843` 要单文件 HTML，直接粘即可 | 聊天窗口接受长文本与代码块 |
| v0 | `请生成一个可直接预览的单页：把下面的 CSS 与 HTML 放在同一个组件文件里，图片位用占位路径；不要拆成多文件。` | v0 的默认产物是组件/项目结构，而 `prompt-copy.js:838` 要求「不拆文件、不构建」，会冲突 |
| Cursor / 本地编辑器 | `请在当前项目里新建一个 HTML 文件，把下面这段实现出来；先列出你要新建的文件名，再给代码。` | 编辑器场景需要落盘位置，聊天窗口不需要 |

**不做**「一键打开 chatgpt.com 并自动粘贴」：跨域 URL 带 prompt 不可靠、各家参数随时变、还会把用户从本站送走而我们无法验证交付。工具选择存在 `localStorage`，下次默认；无存储时用 `ChatGPT`。四个工具名直接写 UI，不用图标。

### 3.4 30/30 都需要 JS，必须在复制前说清

`deliverables/74-recon/00-SYNTHESIS.md:89` 实测：**30/30 原型带 `<script>`（约 2,844 行内联 JS），提示词 DNA 里 0/30 提到 script/JavaScript**。S07 的镜像偏移靠 123 行 `getBoundingClientRect` + SVG 重排（`:91-92`），纯 CSS 做不到。而 `prompt-copy.js:838` 明写「只给一个完整单文件 HTML…不拆文件、不构建」，等于让 AI 复刻一个它没被告知要写 JS 的效果。

三层修法，顺序不能换：

1. **UI 标记**：每个方案在卡片与判决卡上印 `这一案需要 JavaScript`（数据由 `prompts.js` 生成器从 `prototypes/Sxx/index.html` 是否含 `<script>` 现算，新增 `needsJS` 布尔字段，不手填 30 份）。详情页加一行：**这个风格的核心动作靠脚本量几何/驱动，静态 HTML+CSS 只能得到外观近似版。**
2. **提示词正文加一段**（`prompt-copy.js:836-843` 的 `输出要求` 之后，仅 `needsJS===true` 时插入）：
   `这个风格的核心动作必须用内联 <script> 实现（在单个 HTML 文件内，不拆文件、不引框架）：先量出需要对齐的元素几何，再按下面的机制驱动；脚本失效时页面必须退化为静态可读版本。只给代码，不解释。`
   这一条把「要不要 JS」变成可执行指令，而不是让 AI 猜。
3. **不承诺成品**：确认语 + 提示词尾句都写「第一版是起点」。`prompt-copy.js:465` 现在写「请把整页做成这个风格」，容易让人以为一次到位。

已知残留要在 UI 里留一行（不藏）：`提示词的尺寸与机制描述逐案抽取，个别数值可能与原型 CSS 不完全一致（S03 的栏数、S07 的 5/7 栏、S17 的 96px 已列入待校正）。` 依据 `00-SYNTHESIS.md:101-105`、`113-124`。**在修好之前不许写「100% 照原型复刻」。**

### 3.5 要不要「下载 .md」——要，但只是第三顺位

- **提供**：`下载 <方案号>-<中文名>.md`，Blob 生成（无构建、无新文件），内容 = 同一 `buildPrompt(id, opts)` 的返回文本 + 一行 `# 风格提示词 · S06 昭和喫茶台账` 标题 + 生成日期。文件名用 `S06-showa-kissaten-ledger.md`（英文目录名已在 `data.js:6` `dir` 字段），避免中文文件名在部分浏览器下载时乱码。
- 用途：剪贴板被禁、想存档/发给同事、想先在本地编辑器改两行再粘。不是主路径，视觉上做成文字链接或次级按钮。
- **不提供** `.html` 下载、`zip` 模板包、「直接预览生成结果」按钮：本站不生成网站，提供这些就是把产品又变回模板画廊（§7）。

### 3.6 焦点与键盘（今天唯一的硬功能缺陷）

`prompt-copy.js:923-940 execCopySync()`：记录 `document.activeElement`，`ta.focus() → select() → execCommand → removeChild()` 之后用 `active.focus({preventScroll:true})` 还回去；若原元素是 `body`，还给详情头部的 `#d-close` 或复制按钮本身。删掉「exec 先跑」而不是删掉 fallback：把顺序改成 **`writeText` 优先 → 失败才在手势内同步 exec**（`file://` 与 http 下都实测可写，见 `:910-922`），这样绝大多数用户根本不经历焦点搬运。

`showManual()`（`:853-905`）：补焦点陷阱（Tab 循环）、`aria-modal` 已有、关闭时把焦点还回触发按钮、Esc 关闭；`tip` 里 `file://` 那句改成中性（Pages 是 https，不该对陌生人讲本地文件）。`prompt-copy.js:1000-1009` 的 keydown 拦截（防行卡吞 Enter）保留，别在重排中丢掉。

验收：CDP 打桩 `navigator.clipboard.writeText` 后，点复制前后 `document.activeElement` 必须是同一个按钮；`role="status"` 节点内容变化一次；手动框 Esc 后焦点回到按钮；键盘 Tab 不逃出手动框。

2. **首屏只 1 张图，其余全部 `loading="lazy" decoding="async"`**（再省约 2–3 MB）。新首屏按 §1 只渲染 1 张 `desktop-fold.jpg` + 第一滚 3 张；`app.js:438-448 shotFig()` 加 `loading` 参数，卡片图带 `width="640" height="360"`。给 30 张全量列表加 `content-visibility:auto` 或直接分页（每页 9 张）。

4. **剥注释**（省 ~85–98 KB gzip；用户给的数 ~85 KB raw 是保守估计，本轮实测 97,794 B gzip / 218,954 B raw）。`prompt-copy.js`、`app.js`、`style.css`、`index.html` 里的长注释已经变成一份 9 万行的考古档案；**保留数据/不变量的注释，移到 `deliverables/` 或同目录 `*.notes.md`（不被 `<script src>` 引用）**，源文件只留可执行代码与 ≤1 行意图注释。注意 `check-docs.mjs` 会剥注释数 `field('` 字面量（`arch.md:700`），剥注释不改变字面量个数，安全。
5. **方案数据按需**（省 ~100 KB gzip）。`data.js` 307,091 B → gzip 103,014 B，其中 `def/family/fontsSpec/layout/visuals/motion/audit/risk/landing/copy/quirk` 是给详情用的长散文。首屏只需要 `id / cn / en / plain / bg / primary / scenesYes / scenesNo / shots.desktop[0] / axes / needsJS`，把这份精简索引内联进新根 `index.html`（约 30 × 300 B ≈ 9 KB），`data.js` 改成只在「全部方案 / 详情」页加载。这一步同时让「方案自由增删」变得便宜：改一处生成器的输出，不再要求首屏同步 307 KB。
6. **图片格式**：`desktop-fold.jpg` 单张 76–293 KB（均 155 KB，`ux.md:77`），首屏那一张挑 ≤100 KB 的案，或在生成器里另出 `*-thumb.webp`（≤40 KB，**新增产物，不改现有截图**）。6 张 × 40 KB = 240 KB，落在预算内。

**总账**：11.3 MB − 4.84 MB（隐藏图）− ~3 MB（lazy/首屏减量）− ~1.6 MB（字体）− ~0.1 MB（注释）− ~0.1 MB（数据分拆）− ~0.5 MB（webp 缩图）≈ **1.1–1.2 MB**。

### 4.4 「没有构建步骤，只能改源码」是否可接受

**可接受，而且是这个项目的正确选择**，但有条件：

- Pages 是 `build_type:"legacy"`、`source: main /`（`gh api .../pages`）：push 即部署，没有 CI 能跑 minifier。加 bundler 会让「 strangers 不 clone 」这个前提下多出一份本地生成步骤，且每次改文案都要重新构建，违背季度路线图的低摩擦要求。
- 本轮实测证明**手工编辑足以达标**：真正吃字节的是 60 张被隐藏的 `<img>` 和 38 个字体，都是 HTML/JS 里几行 DOM 决策，不是压缩率问题；注释剥离可用一次性脚本执行（脚本放 `deliverables/74-plan/`，**产物是源文件本身**，不产生需要部署的 dist 目录）。
- **不可接受的是「手工维护两份副本」**：剥注释必须是对同一份源文件做一次性变换，而不是复制出 `app.min.js` 再让 `index.html` 指过去——那会立刻制造本仓最熟的「两个真源漂移」缺陷。若将来要加构建，优先加在 `prototypes/_build/` 里并由 Pages Action 输出，别在仓库里同时留 `src/` 与 `dist/`。

### 5.1 必须写进 UI 的产品边界（不是 README，不是折叠注释）

统一放在「这套东西怎么用」页 + 每个复制控件上方一行，逐字：

1. **你拿到的是一段提示词，不是网站。** 粘进 AI 工具后得到的是第一版单页 HTML，需要你自己改文案、换图、接支付和域名。
2. **这一案需要 JavaScript。** 核心动作靠脚本量几何/驱动；静态 HTML+CSS 只能得到外观近似版。（由 `needsJS` 现算，30/30 目前全为是）
3. **内容形状不一定装得下你的店。** 部分版式的单元位置是写死的，商品/栏目少于设计规模会留空位或需要整块重排——每张卡印 `capacityHTML(r)` 的实测警告（`app.js:482-515`），不藏在详情第 8 段。
4. **有些风格本来就不是为卖货做的。** 30/30 都写了「不适合的场景」（`data.js` 的 `scenesNo`）；把它放在「适合」旁边，别放在 2.85 屏之后。
5. **提示词是起点，不是成品，也不保证复刻原型。** 尺寸与机制描述逐案抽取，个别数值待校正（S03/S07/S17 已列）。
6. **本地打开（`file://`）会让 S04/S07 的 `mask-image` 失效**（`00-SYNTHESIS.md:78`）——但部署站是 https，这句**只对「下载原型」链接旁出现**，不要放到首屏吓陌生人。
7. **不做的事**：不代生成网站、不托管成品、不提供客服、不承诺 AI 输出可通过无障碍/性能验收。

诚实纪律：**任何数字都由现场数据现算**（`window.SCHEMES.length`、`sceneIndex`、`report.json`），不写「30」「44」「47」「10 段」「FAIL=0」这类硬编码——本轮 8 条缺陷里有 3 条就是硬编码数字腐化来的。

## 6. `scenesNo` 的裁决：**显示，而且放到判决位**

### 6.1 结论

**不删，显示。** 30/30 有值（`D:/Web/style/prototypes/_selection/data.js:87,171,254,…,2571`），且内容不是套话，是逐案写的可执行排除条件，例如：

- S01 `scenesNo`：「需要低决策风险的 B 端采购站、面向幼儿的亲和型产品页。」（`data.js:87`）
- S19：「以高清大图或视频为核心的艺术展览页…」（`data.js:1801`）
- S23：「必须在首屏完成购买或注册的商业站；信息密度极高的后台系统…」（`data.js:2058`）
- S30：「需要沉稳可信的金融与政务场景…必须做严格无障碍对比度校验的产品，因为荧光绿与冷白在部分区块的对比偏低」（`data.js:2571`）

这是全库**唯一一份由作者写的、能帮店主排除的负面证据**；`scenesYes`（`data.js:105-106`）只说谁适合，30 张卡读下来全是「适合」，用户反而无法决策。

### 6.2 为什么「删」是错的

- 删掉它就只剩正面描述，用户必须自己读 12 段施工细节才能发现「这是给内容媒体做的，不是给下单页做的」——而 `ux.md:93` 实测 7 段平铺、中位 650 字，没人会读到。
- 本仓已有一个反例：`scenes` 字段把「不适合」拼在 value 尾部（`data.js:104`），`prompt-copy.js:1105-1110` 的注释记着旧文案让用户「建议先看详情里的『不适合』」，结果那个字段根本不存在、真正那句在面板 1807–2118px 之下。**同一个信息被藏过一次，代价是信任**。
- 它与本产品的差异点直接相关：HTML5 UP / Minick / ThemeForest 只写「适用」，不写「不适用」（`00-SYNTHESIS.md:277`）。负面信息正是「选型工具」与「模板画廊」的分界。
- 方案可自由增删归档，`scenesNo` 是新方案入库时最便宜的质量检查：写不出「不适合谁」的风格，本来就不该上架。

### 6.3 显示在哪、写多少

三处，逐字与长度上限：

| 位置 | 形态 | 长度 |
|---|---|---|
| 结果卡 / 全量卡（首屏与第一滚） | `不适合：{scenesNo}` 一行，与 `适合：{scenesYes}` 并列；超 42 字在生成器里截到第一个句号/分号，加 `…`，`title` 属性给全文 | ≤42 字 |
| 详情「判决卡」（新，`app.js:1356` 之前） | `不适合这个风格的店` 独立一行，全文不截；下面接 `capacityHTML(r)` 警告与 `needsJS` 标记 | 全文 |
| 复制控件的提示词预览上方 | 一行 **复制前请确认：{scenesNo 首句}**；**不写进提示词正文**（负面词会按 `prompt-copy.js:701-727` 记录的「点名即加权」污染 AI 输出） | ≤30 字 |

**接线**：`D:/Web/style/prototypes/_selection/app.js:1356-1395` 的 `field('适用场景', r.scenes)` 改为 `field('适合', r.scenesYes)` + `field('不适合', r.scenesNo)`，并把这两行提到 `<dl class="fields">` 之外的判决卡；`D:/Web/style/prototypes/_selection/app.js:520-575 rowHTML()` 的 meta 行里加 `不适合：…`；`D:/Web/style/prototypes/_build/collect-schemes.mjs`（生成 `data.js` 脚本）保留 `scenesNo` 键（已有），另输出 `scenesNoBrief` 供卡片使用。删除 `r.scenes` 的合并版在详情里的重复渲染，避免同一句话出现两次。

**不要做的事**：不把 `scenesNo` 做成筛选轴（「排除含『电商』的方案」会误伤 29/30 案的近似款）、不做红色警告块（它是信息不是错误）、不写「不推荐你用这个」这种替用户下结论的句子。

### 6.4 与向导的关系

`wizard.js:226-228` 已有 3 个「明确排除」卡，但排除理由是**五维欧氏距离**，不是 `scenesNo`（`ux.md:545-560`）。两者不冲突，也不合并：向导结果卡加一行 `作者写明的不适合：{scenesNoBrief}`，让「距离远」和「作者说不适合」两种排除依据各自可见。向导的权重仍如实标「未经真人回放测试」（`wizard.html:88`），不因接入 `scenesNo` 就改口说「已验证」。

## 7. 部署站绝对不能变成什么

对照物：**HTML5 UP**（免费 HTML 模板，卡片 = 一个可下载的完整站，主行动是 Download）、**Minick Studio**（live-demo 目录，卡片 = 一个能点进去逛的成品，主行动是 Live Demo）。两者都是「看 → 拿走一个成品」。本站是「看 → 拿走一段指令」。任何把主行动改回「拿走成品」的设计都会让它读成又一家模板画廊。

### 7.1 明令禁止的设计动作

| 禁止 | 为什么（结合本项目证据） |
|---|---|
| **「下载模板 / 免费下载 / Download」作为主按钮** | 那是 HTML5 UP 的转化点。本站主按钮只能是「复制 AI 提示词 →」。`index.html:35-40` 现有「三个大众模板 M01/M02/M03（自包含、双击即对）」在首屏出现，等于给陌生人一条更像模板站的出口；整体移到「这套东西怎么用」页底部，并注明「这是另一条路，不是本站的产物」 |
| **「Live Demo / 预览成品」做成卡片主角** | Minick 的模式。原型截图在这里是**证据**（证明这风格被实现过），不是可交互的展厅。卡片上不放「打开原型」主按钮，详情里保留一个次级链接「看可运行原型 ↗」即可 |
| **等宽缩略图网格 + 价格/星级/分类徽章** | 典型主题市场皮。18/30 暖浅底、29/30 零圆角会立刻看起来像 18 张同一张卡；按 `axes.band` 分组取图、每卡印 `bg/primary` 两个色块与「不适合」，让差异是文字可判的 |
| **「30 个方案」「FAIL=0」「272 张截图」「同一条渲染口径」上首屏** | 这些是作者侧质检数字（`index.html:39`、`:53-58`、`:81-90`）。陌生人不会据此决策，只会读成「一个工程作品集」。全部沉到 `/prototypes/_selection/` |
| **README / 构建脚本 / 闸门报告作为主导航** | Pages 直接从 `main /` 供应，仓库里 10.5 MB 的 `deliverables/` 也在公开目录树里，但**不要链过去**。部署站的一级导航只有 3 项：`挑风格` `看全部方案` `这套东西怎么用` |
| **声称「一键生成」「成品可用」「1:1 复刻原型」** | 30/30 需要 JS 而提示词 0/30 提 JS（`00-SYNTHESIS.md:89`），S03/S07/S17 的机制句数值待校正（`:113-124`）。这类话今天就是假的 |
| **把 5 问向导做成首屏必经步骤** | 5 问同页堆（`wizard.js:87-90`）、权重未回放测试（`wizard.html:88`）。给它一条文字入口即可，不做 gate |
| **靠 `file://` 或本地命令验证** | `00-SYNTHESIS.md:78` 记着 `file://` 下 S04/S07 空白，README 自己判它「比页面本身的任何缺陷都严重」却只写进 README。部署站的验收必须在 `https://sqkl520.github.io/web-style-atlas/` 上跑（本轮已确认 200） |
| **为首屏引入框架/CDN/远程字体** | Pages 是 legacy 静态供应，没有构建、没有 CI；外链一挂就多一个陌生人侧的失败点，且 `prototypes/_CONTRACT.md` 本来就禁远程资源 |

### 7.2 反过来，必须强化「这不是画廊」的三处

1. 每张卡都有**可复制的文字**（主按钮 + 全文预览），而不是只有一张图和一个标题。
2. 每张卡都写**不适合谁**（§6）；模板画廊从不写这个。
3. 复制确认语点明**下一步是去 AI 工具粘贴、产出是起点**（§3.2）；这是本站与所有模板站的根本分界。

## 9. 一眼可记的决定清单

1. **根页就是产品首屏**，取消 meta refresh；首屏问「你是做什么的？」，30 张网格是答案/第二层。
2. 首屏只一个实心主按钮：**复制这段 AI 提示词 →**；必须同时可见一张真实截图、一句「不适合」。
3. 用户拿到的**是文字不是网站**；确认语说「现在去 X 粘贴，第一版是起点」。
4. 30/30 需要 JS：**标出来、写进提示词、别承诺复刻**。
5. `scenesNo` **显示**，放在卡片与判决卡；不进提示词正文。
6. 首屏 ≤1.2 MB：先不发 60 张隐藏图（4.84 MB），再砍字体 / lazy / 注释（~98 KB gzip）/ 数据分拆；**不引入构建步骤**，一次性改源文件。
7. 8 条缺陷按 §5 的 P0→P2 顺序修，每条都给 file:line；所有数字现场现算。
8. 不做模板画廊：不卖下载、不做 live demo 主角、不把闸门数字摆首屏。
9. 三个月 38 人天，M1–M6 均可独立 push 上线，M7 等真实数据。
