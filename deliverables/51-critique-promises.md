### §1-wizard 专审（任务 3）

**5 问 → 3 推荐 + 3 排除的真实机制**（wizard.js @0e28503 逐段）：

1. **输入侧是真实测**：`gate.words`（report.json 正文字数）、`gate.realPictures`（真实图片数）、`loudnessOf(palette)` 从 HEX 现算 HSL-S 取最大——三个输入无可争议。
2. **但归一化不是实测**：`stretch()` 用**全库 min/max 线性拉到 0..2**（L56-60）——每案的值依赖其他 29 案的值，语料一变全库距离重算。README 说"每条为什么都读实测值"（P11）时把归一化偷掉了；wizard.js 自己 L8 倒承认"我做的唯一一件事是把实测值归一化"。
3. **两处纯主观**：`TONE_BOLD` 表（L39-47）——「奢华暗黑/高定」打 1.5、「学术档案」打 0.5，无任何实测或声明依据，属"我替方案打分"的正定义；`fear = loud*0.6 + toneBold*0.4`（L73）权重拍板。**排除卡的第 5 条"为什么"引用「调性 X」，而调性→档位是主观表查出来的**——"排除"并不比"推荐"更确定。
4. **"排除"确实不是确定性的**：排除 = 距离最大的 3 案，且 `reasonsFor(v,false)` 的展示由 `TIGHT=0.75` 阈值决定。wizard.html L94 把"排除"定位成"更需要说清理由"，结果页脚注（L190）劝用户"把排除当主要参考，它们更直接"——**但排除的生成机制和推荐同一条流水线，只是取了另一端 + 换了阈值**；一个方案可以既"对上了 4 项"又进排除区，此时排除文案退化为"五项都接近你要的档位——它被排到最后是因为别人更近"（L142）——这句诚实，但和 README L73"3 个明确排除"的"明确"字面冲突：**排除可以是"没有明确理由的相对靠后"**。
5. **确定性排序成立**：等权平方距离 + 稳定 sort，`?load=2&...` 回放同答案必同结果 ✓（P12）。tie 时按 data.js 原序（S01 先），未声明。

**结论**：wizard 的"不替方案打主观分"是**夸大**（机制含 3 处主观参数）；"明确排除"是**措辞强于机制**；但结果页脚注的自曝（权重是拍的、推荐不可全信）**救回了七成诚实**——问题在于这句话藏在结果页，而 README/向导头版/`<meta description>`（wizard.html L7"得到 3 个推荐，以及 3 个明确排除——并说清为什么"）都在结果页之前。
