## 1. 攻击一：核心卖点在转移中损失 2/3 ——「提取实测的提示词」是描述性抽样的假象

### 证据

**[复算]** 提示词的生成路径是：`data.js` 的 12 段规格（`_specs/*.md` 的原文）→ `build-prompts.mjs` 只抽

我把「写进提示词」与「留在规格里」逐字对账。**30 案合计，`layout` + `visuals` + `motion` + `quirk`
四段里的带单位数字共 789 个 token，其中出现在自己提示词里的只有 269 个，34.1%。**

```
node 复算（脚本全文在正文下方）：

same tokens present verbatim in own prompt: 269 = 34.1%
```

**[源码]** 更狠的一条：`data.js` 的 13 个人写散文字段里，**没有一段被提示词原样引用**。

`quirk`（「每条目录末尾的引导点…行末那一个必须是宽度只有 50% 的半点」）——README 明确把它列为
**「12 字段」之一、并且是它自称区分「设计主张」与「配色皮肤」的支柱**——在 30/30 案里
**一个字都没进提示词**。

### S07 的实证：提示词教 AI 做出来的东西，不是 S07

S07 的 `def` 与 `layout`（`deliverables/04-schemes-01-10.md:263`，
`data.js:518` `:521`）写：

> 「跨页版心**左 5 栏右 7 栏**（栏宽 62px、栏沟 18px）…栏宽比 5:7」
> 「CSS 思路——双页用 `grid-template-columns: 5fr 7fr`」（`data.js:526`）

S07 的 `style.css` 实际是（`prototypes/S07-slate-ink-contents/style.css:74, 81, 82`）：

```css
.pages{grid-template-columns:5fr 1px 7fr}   /* 这是「两页的宽度比」，不是「栏数」 */
.page-recto .toc{column-count:2}
.page-verso .toc{column-count:3}
```

**[复算]** 1440 档：`recto` 566px 分 2 栏（每栏 274px）、`verso` 793px 分 3 栏（每栏 258px）。
`--module:62px` 在整份 CSS 里只出现在一条 `max-width` 计算里（`style.css:49`），**跟栏宽无关**。

于是提示词里的签名句是：

> 「同一段文字在纸背以 8% 至 14% 不透明度做镜像并整体偏移 1px，**正面 5 栏对背面 7 栏**、栏线 0.5px，
> 页码竖排 28px 行高——正反两面同时进入同一张版心。」

**一个 AI 严格照这句话做，会做出 5 栏 + 7 栏 = 12 栏的跨页目录。原型是 2 栏 + 3 栏 = 5 栏。**
这不是措辞含糊：`5fr 1px 7fr` 是**两页的宽度比**，被误读成了**栏数**，并且这个误读
一路写进了 `def`、`layout`、`landing`、机制句、`prompts.js`、以及用户复制到的提示词。
在 1440 档上，它让 AI 每一栏只有 113px 宽（而非原型的 258–274px）——
标题会当场碎成每行两个汉字，正是 `style.css:169-175` 那条注释里作者自己实测到的病。

**同类问题不是孤例**：`data.js` 的 `layout` 字段里有 5 案写死「栏宽 Npx」，其中 **3 个 N 在对应
`style.css` 里根本不存在**（S04 的 88px、S08 的 72px、S09 的 68px）。
S08 的 `72px` 早在 `deliverables/56-scratch/head/S08.spec.md` 就被审出过「`72px` 在 S08 整份 CSS
命中 0 次」，`deliverables/60-diagnosis-what-feels-wrong.md` §前记也复核过——**它被记录了，没被修**。

### 钢人反驳（我认真试过）

**反驳一：提示词本来就该是「风格」而不是「那一页」。** README 自己说得很清楚：
「提示词越长，越是在描述"那个具体页面"而不是"那个风格"」（`README.md:90`）。
按这个逻辑，丢掉 `62px 栏宽`、`7px 基线`、`1.4em 悬挂缩进` 是**设计选择**，不是缺陷。

我的回应：这个辩护能解释「为什么不留 62px」，**解释不了「为什么留下了一个错的 5 栏/7 栏」**。
一条错的具体数字比没有数字更糟——它把 AI 从"自由发挥"推向"精确地做错"。
而且被丢掉的恰恰是**比例的骨架**（栏宽比、栏数、基线、行长），这是「风格」这个词在排版语境里
唯一可执行的定义；留下来的却是「圆角 0」「无阴影」「不要紫蓝渐变」这类**任何 30 案都成立的
通用反 AI 条款**。换个说法：**它留下的是"不要做什么"，丢掉的是"这个风格是什么"。**

**反驳二：34.1% 这个口径对提示词不公平**，因为提示词用「约 16px」而不必逐字复制 `15px`。
我的回应：我把 `约/大约` 这类模糊词也算了进去（`p.includes(n)` 是子串匹配，`15px` 在
「约 16px」里匹配不上，这是对提示词**更严**的口径）。真正的问题不是精度，是**类别**：
丢的是 `12 列`、`6 栏`、`160px`、`0.95 倍` 这些**结构性比例**，不是小数点后一位。

**反驳三：`deliverables/03-uniqueness-matrix.md` 早就承认「提示词是 DNA 不是全规格」。**
我的回应：承认了不等于无害。README 的卖点是**「它不是套话，是从各案 style.css 实测抽取出来的」**
（`README.md:80`）——"实测抽取"这个词让用户以为拿到的是**该案的可执行摘要**，
而实际拿到的是**一份所有 30 案共享 38% 字符的模板 + 该案的色值与字体名**。
（**[复算]** 默认参数下 30 条提示词里出现在 ≥27 条中的整行合计 **748 字，占平均长度 1986 字的 37.7%**；每案真正独有的部分平均 1,198 字。）

### 结论

**「配色层不同」是真的，而且做得比大多数同类好**（114/115 唯一色）。
**「可见层不同」是假的**：底色 60% 挤在一个色相跨度 30°、明度跨度 12 点的暖米带里；
96.7% 全直角；83% 首屏无导航；同一批 22 个结构标签要撑 30 个案，8 对撞车；
「气质」只有 7 个词。

仓库自己的 `deliverables/60-diagnosis-what-feels-wrong.md` 把它写成了：
「**最好与最差的差距（极差 2.46、σ 0.64），小于"及格"与"优秀"的差距**」，
并把 `README.md:155` 那句「它不是配色皮肤，而是一份完整的设计主张」点名为**防线挪错了地方**。
`deliverables/29-critique-homogeneity.md` 更狠：蒙住家族名与骨架名后
**只剩 7 案不可替代**。

我对这三个结论的复核：**方向全部成立，具体数字要按判据报。**
`21-lead-verify-homogeneity.md` 自己就纠正过 19/26 → 18/30（S03/S18/S28 取错色），
而 README 在「18/30」这句话上又叠了 17%/60%/73% 三个不同分母——这段自曝
（`README.md:430`）写得比很多项目的正文还诚实，但它同时证明：**这个仓库关于"同质"的
每一个数字都换过口径，而换口径这件事本身没有让任何一案的底色被改。**
（`git log --since=2026-10-25 -- 'prototypes/S*/style.css'` 实测：**30 个案子里只有 6 个的
`style.css` 在最近 7 天被动过，其中 3 个是 S07/S13/S21 的 `<code>` 包字改动**。）

### 钢人反驳

**反驳一：「30 个互不相同」指的是**机制**层，不是可见层。** 举证：22 种结构标签、
15 F / 15 R、每案一条带数值的机制句（20 条有逐行 `style.css` 出处）、
我的复算证实**机制句里的数字 29/30 能在该案 CSS/HTML 里逐字找到**（唯一例外 S07 的 `0.5`，
它写的是 `0.5px` 而我按 token 匹配到了 `0.5`）。

我的回应：我接受"机制层是真的、而且是被校验过的"。但这恰恰让 §2 的攻击更锋利而不是更弱：
**机制层真、可见层假**，意味着这个库的价值是**可读的**（读那 12 段字段）而不是**可看的**（打开选型台挑）。
而产品的入口、README 的第一张图、选型台的主口号，全部押在"可看"上。
`deliverables/60` 说的「封面承诺 A、货架上 B」正是这件事。

**反驳二：60% 暖浅底是「载荷」不是「同质」**——档案纸、棉纸、硫酸纸、复写纸本来就是暖白。
我的回应：这个辩护对 **5–8 案**成立（S07 的省油墨中性灰 `#E7E7E0` 有实物理由、
S11 的复写纸、S15 的硫酸纸都有）。对 **18 案**不成立：把 S21（1974 年瑞士联锁簿）
和 S22（日式对折纸）和 S26（数据看板）放在一起，`#E4DCC9 / #DDDAD4 / #D3D1CA`
在 ΔE76 上是 3.7 与 4.8——**低于人眼在并排色块上的可辨阈**。
「实物有理由」是**每案各自的**理由，不是**30 案放一起看**的理由；用户看的是后者。

### 最刺眼的一条：仓库最重的数字是错的，而它的"守门员"放它过去了

**[源码]** `README.md:556`（中文 README 的英文摘要段）至今写着：

**[复算]** 同一份文件 `README.md:160` 写「**29 个闸门 FAIL=0**。剩下 1 个的 2 条失败」，

`README-EN.md:160` 是「29 pass the gate … The 2 remaining failures」。

**[复算]** 我用实现所声明的 `nums/gate` 正则和 `GATE_TAIL` 跳过规则，对 HEAD 原文逐字模拟：

```

其后的 tail = " pass the mechanical gate with FAIL = 0."
GATE_TAIL.test(tail) = true      → 这句话被当成"闸门句式"跳过
nums/gate 正则 /([\d]{1,3})\s*(?:个闸门 FAIL=0|pass(?:es)? the gate with FAIL\s*=?\s*0|案 FAIL=0)/gi
```

## 4. 攻击四：市场现实 —— 它卖的东西替代品免费且更好，唯一真实的客户是"agent 工作流搭建者"

### 真正的客户是谁（我的判断，比仓库自己的判断更窄）

**所以市场现实是：作为"风格图集"卖，客户不存在；作为"agent 风格语料开源范本"送，
客户存在但不会付钱。需求真实、付费意愿为零——这是最糟的定位。**

### 钢人反驳

**反驳一：开发者工具本来就不为付费设计，0 star 不代表没价值。**
我的回应：对。但开源要有别的分发机制：被引用、被 fork、进 awesome-list、被博客提到。
一个 **0 issue / 0 fork** 的 358 MB 仓库，连"被引用"都没发生。零分发不是"还没被发现"，
是**入口成本太高**（358 MB clone、中文为主、README 第一屏是"一条渲染口径"这种内部术语）。

**反驳二：Minick 只有 20 种且是商业导流，HTML5 UP 是通用模板，都不解决"我的站该长什么样"。**
我的回应：这是**唯一一条我认为它站得住的差异化**，也是 §11 要给的辩护：
"30 个互不相同的**机制**（22 种结构标签、20 条带出处数值的机制句、15F/15R）+ 三档真实截图 +
可复算闸门"这个组合，我核过的替代品里确实没有第二家。
但它是**"更深的深度"而非"更宽的宽度"**，而它对外卖的是宽度（"30 种风格"）。
**深度卖给了不会付费的人，宽度卖给了已有免费替代的人。**

## 5. 攻击五：「只做静态」不是克制，是把产品最该有的三个能力主动放弃了

### 证据

**[源码]** `README.md:397-415`「只做静态这一件事」三条论证：
「数据不出本机」——**本地 HTML 天然如此**，当卖点是自我加冕；
「零依赖、零网络请求」——对"当作品集"成立，对"帮我选一个风格"不成立；
「没有安装过程，也就没有遥测」——同上。

**[复算]** 逐条列出「静态」实际 foreclose 了什么：

| 放弃的能力 | 对"挑风格"这个任务的代价 |
|---|---|
| **跨案合成提示词** | 无服务端 ⇒ 无法把"用户已选的三个案 + 自己的内容"合成一条。而"S07 的目录感 + S21 的联锁逻辑"这种混合需求是真实存在的。 |
| **知道哪个案是废的** | 无埋点 ⇒ 无法知道 30 案里哪个被复制最多、哪个被跳过。`60-diagnosis` 只能靠 30 个 agent 扮演用户来**猜**——**因为静态约束让它无法真的知道**。 |
| **不重新部署就更新** | 提示词有错（见 §1 的 5 栏/7 栏）修完必须用户重新 clone 358 MB。**这是那个错误能活这么久的结构原因。** |
| **收藏 / 对比 / 协作** | `49` 记录：想收藏三个候选对比，只能截图。 |
| **提示词 A/B 与回归** | 见下。 |

### 最关键的一条：静态约束让核心卖点无法被持续验证

`deliverables/69-test/LEAD-similarity-finding.md` 是全仓最诚实的一份文件：

> 「机械判据 91.5%（S20 85.7% / S21 96.2% / S28 91.7%），**但视觉相似度只有 0.490**」

它把根因查得很准：提示词不给字号层级（29/30 案缺失、0/30 给字重）、色板给值不给配比
（S28 原型梅子紫占 31.6%、实现 0%）。`03f6fd4` 然后修了字号（`0ee3fb5`「字号 0/30 → 30/30」）。

**但是：`0.490` 这个数字在 10-30 之后再也没有被重测过。**
（`grep -rl "视觉相似度" deliverables --include="*.md"` 只命中 4 份，全部在 10-29 及之前。）

为什么没重测？**因为静态仓库没有"生成 → 比对"的流水线，每次测都要手工派 agent 做端到端复刻。**
一个动态产品会把这条测度做成 CI，每次改提示词自动重跑；静态仓库只能一次性实验，
然后**把结论写进文档、把文档当成结论**。

这就是攻击五的真身：**"只做静态"不是审美克制，它让这个产品最该被持续测量的指标，
变成了一次性的、无法回归的、写在 markdown 里的一个数字。**

### 钢人反驳

**反驳一：静态是分发策略，不是产品缺陷。** 零依赖 = 任何静态托管直接部署、fork 就能改、
没有 API key 没有后端维护成本。对一个 0 star 的个人项目，加后端等于加 10 倍维护负担，
且会让"clone 就能跑"这个最强优点消失。

我的回应：**这是最有力的一条辩护，我接受它的一半。** 但"静态"与"可测量"不冲突：
纯静态站点同样可以带一个 `npm run measure` 脚本，把 30 条提示词送进 Claude API、
拿到复刻、算相似度——**不需要后端，只需要一个 key**。仓库已有 91 个 commit、9 万行审计、
6 个 check 脚本，**却从没为它唯一的输出（提示词）建过自动回归**。
所以问题不是"静态"，是**"静态"被拿来当成了不做闭环的借口**。

**反驳二：加埋点会破坏"数据不出本机"这个面向内网/合规客户的卖点。**
我的回应：**这个客户在这个仓库里一个都没有**（0 star / 0 fork / 0 issue）。
为一个不存在的客户放弃唯一能验证产品的机制，是**用假想的约束换取真实的失明**。

## 7. 攻击七（最狠的一条）：坦诚变成了免责工具 —— 精确记录限制，正是让它不必被修的方式

### 证据

- `README.md:439` 自曝「13/30 案的 `index.html` 超契约目标区间」。
- `README.md:440` 自贬：「这是一个 **80 分**的标本库，不是 100 分的成品站。」

  说明豁免理由』处理，**不要靠改设计去讨好**）」。

**这就是病灶。「记录了 ⇒ 不必修」在这个仓库里是一个被制度化的反射。** 举证三条：

**(a) 豁免表成了真缺陷的收容所，而且它开始为收容自己而扩表。**
`_CONTRACT.md:201` 的 `palette-terracotta` 一行，为 S08 的琥珀主色申请豁免。

**一个为了让缺陷不被当成缺陷而存在的表，有一行是为它自己补的。**
同一行还记着：「2026-10-31 锐评实测：这里从前写『按本仓库 §7.4 自己的定义』，
但**契约里没有 §7.4**」。**治愈引用跳空的注记，本身是引用跳空。**
这是全仓库最精确的自我肖像。

**(b) 每一条"已知边界"都跟着一个"为什么不该修"的理由。**

`README.md:420-440` 九条限制，我逐条看它们的处置语：

| 限制 | 处置语 | 有对应的产品改动吗 |
|---|---|---|
| S08 两条 FAIL | 「两条都是**已知豁免**（理由见 §9.15）」 | **无**，写豁免 |
| 底色同质 18/30 | 「**报同质数字必须附判据**」 | **无**，改口径 |
| 首屏无导航 83% | 「⚠️ 该指标只数 `<nav>`…**量不到页内锚点**」 | **无**，指出指标不准 |
| 圆角 96.7% | 「这是 `report.json` 机械口径，换 grep 口径得到 76.7%」 | **无**，报两个数 |
| 安静档只有 2 案 | 「别把这组数当成 `tone`」 | **无**，澄清 |
| S28 素材零爵士 | 「缺口都写进了对应原型的 `CREDITS.md`」 | **无**，写进 CREDITS |
| `#888888` 灰块 | 「那是 `inspect.mjs` 自己的缺陷，不是页面真有灰」 | **无**（工具侧） |

| 不是设计系统 | 「要拿它当设计系统用的人会在第三天失望」 | 定位声明 |

**11 条里 0 条有对应的产品改动。全部处理方式是「把它写准」。**

而关于 `file://` 那条最扎心：它自己判了「**比页面本身的任何缺陷都严重**」——然后只是写在 README 里。
**[复算]** `grep -l mask-image prototypes/S*/style.css` 只命中 S04 与 S07；
S07 用它做"页边毛口"遮罩（`style.css:113`），失效后 `background:var(--deckle)` 会画出
一整条 14px 实色带而不是毛边。

**(c) 门面数字的"口径纪律"本身成了产品。**
`README.md:430` 那一大段关于 17%/60%/73% 与 ΔE76 的说明，读起来像一篇计量学论文。
它的功能是**让读者相信"这个数字是被认真对待的"**——从而不再追问
"那为什么 18 个案子的底色还是一样的？"
`60-diagnosis` 把这命名为「**病不在假，在错位**」，并算出读者价值占全仓 1.16%。
**我的复算是 0.86%（30 案产品）+ 1.52%（选型台）= 2.38%** ——口径不同，同量级。

### 钢人反驳

**反驳一：这是科学诚实，不是免责。** 一个项目愿意写"我有 18/30 同质、我的截图工具有 bug、
我的 measure 规则对中文假阳性"，这在开源里是稀缺品。绝大多数项目会直接删掉这些数字。

我的回应：**这是最强的一条辩护，也是我唯一想部分投降的地方。** 我投降的是：
这些坦诚**确实让这个仓库比同类更可信**，而且救了几条命——
`30-critique-assets-license.md` 的许可台账是真的在保护下游，`UNVERIFIABLE.md` 的
「35.8% 的约束没有对错之分」是真的在防止自欺。

**但核心判断我不投降，因为有一个可证伪的对照：同一个仓库，对"提示词有 5 栏/7 栏的错"
和"我混用过三个分母"的处理方式完全不同。** 前者没人发现、至今没修、`check-prompts` 判 PASS；
后者被写成 200 字的计量学说明并进了 README 正文。
**坦诚是有选择的：它对"自己造的测量"极其坦诚，对"自己造的产品"极其宽容。**
原因不神秘：**测量是它自己发明的，所以它知道自己哪里可能错；提示词是它照抄规格的，
所以它默认规格是对的——而规格（`_specs/S07.md` 字段 5）就是从同一个误读里来的。**

**反驳二：把它写准本身就是修。** 一条准确写进 README 的限制，读者就不会误用，这就是修复。
我的回应：对"读者会不会误用"成立，对"产品有没有缺陷"不成立。
`file://` 下 S07 变成空白——写进 README 之后它仍然变成空白，
而 README 自己说这"比页面本身的任何缺陷都严重"。**一句"这很严重"加零个动作，
等于把严重性转移给读者的阅读理解。**

## 8. 攻击八：它"30 个互不相同"在**用户能做的选择**这一层是 7 个，不是 30 个

### 证据

**[复算]** 30 案的可用筛选维度（`data.js` 的 `axes` 与选型台暴露的字段）：

| 维度 | 取值数 | 分布 |
|---|---|---|
| `axes.ground` | **2** | 亮底 22 / 暗底 8 |
| `axes.band` | 6 | 暖浅 **18** / 冷暗 5 / 暖暗 3 / 中性浅 2 / 中明 1 / 冷浅 1 |
| `axes.loud` | **3** | 就要扎眼 **19** / 有态度不吵 9 / **很安静 2** |
| `tone` | **7** | 最多 5 案、最少 2 案 |
| `structure` | 22 | **8 对撞车** |
| 圆角 | **1 档** | 25/30 是「全直角 0」，4 案只有一个特例（50% 圆点），96.7% 视觉上无圆角 |
| 阴影 | 4 | 17 无 / 6 inset / 6 drop / 1 混 |

**[复算]** 「很安静」只有 **2 案**。一个想要"安静的站"的用户，在这个号称给你 30 种选择的库里
**实际只有 2 个选项**。README 自己承认了这一点（`README.md:433`），紧接着说
「别把这组数当成 `tone`」——**承认了，然后把话题转走。**

更糟的是：**这三条轴（内容量、复杂度、安静度）恰好都是缩略图上看不见的维度**
（`README.md:433` 原句：「用户能用的筛选维度（内容量、复杂度）恰好都是缩略图上看不见的维度」）。
**看得见的是底色、字体、布局——而底色 60% 同族、96.7% 无圆角。**

### 钢人反驳

**反驳一：30 个"机制"是真的不同** —— 22 种结构标签、15F/15R、20 条机制句有逐行 CSS 出处。
我的复算证实：机制句里的数字 **29/30 能在该案 CSS/HTML 里逐字找到**。这是硬证据。

我的回应：**我完全接受，并认为它是这个项目最强的资产**（见 §11"最强理由"）。
但这恰好把问题推到最尖锐处：
**它真正的差异化是"读得出来的机制深度"，而它对外卖的是"看得出来的风格宽度"。**
前者需要用户读 12 段字段（`49` 实测：详情容器 1869px = 2.1 屏，7 段平铺 5 段折叠）；
后者 3 秒就能判断"这个我不喜欢"。**深度被藏在折叠里，宽度被摊在第一屏。**

**反驳二：7 个 tone 是"气质"不是"风格"，7 × 22 = 154 种组合够用。**
我的回应：这个乘法不成立，因为 `tone` 与 `structure` 在 30 案上是**共线**的：
「学术档案」5 案里 3 案是浅暖底 + 全直角 + 无阴影 + 半衬线；「机能冷峻」5 案里 3 案是深底/冷底 + 等宽数字。
用户感知的是**联合分布**，而那个联合分布的有效支撑集，`60-diagnosis` 用蒙眼实验测成
**7 案不可替代**。我的独立复算（`structure` 8 对撞车 + 底色 5 对 ΔE<5 近同 + 圆角 96.7% 单一）
给出同量级：**有效可选集 ≈ 7–10。**

## 9. 攻击九：**原型有 2,844 行 JS，提示词一个字都不提**

这一条不在原任务书的六个向量里，是我在核对「提示词到底传了什么」时撞上的，
而它的严重程度超过 §8。

### 证据

**[复算]** 30 个原型：

| 指标 | 实测 |
|---|---|
| 带 `<script>` 的原型 | **30 / 30** |
| 内联 JS 总行数 | **2,844 行**（S16 166 / S20 150 / S02 148 / S13 140 / S03 138 …） |
| 独立 `app.js` | 1（S07，123 行） |
| 提示词里出现 `<script>` / `JS` / `JavaScript` | **0 / 30** |
| 提示词里出现「滚动 / 悬停 / 指针 / 按下」 | **5 / 30**（且 4 条是在机制句里） |
| `dna.mechanism` 里需要交互才能成立的动作 | 4 / 30（S03 S06 S08 S13） |

**也就是说：这个号称"30 个能跑的风格，不是 30 张配色图"的库，它自己也把"能跑"里
最贵的那部分——2,844 行 JS——完全没交给用户。** 用户拿到的提示词只教他做**静态排版**。

### 这不是抽象指控，S07 自己就是标本

S07 的机制句（提示词第 5 行，用户直接复制的那句）说：

> 「同一段文字在纸背以 8% 至 14% 不透明度做镜像并整体偏移 1px…正反两面同时进入同一张版心。」

**这句话在纯 CSS 下做不到。** S07 的实现是 `app.js` 里 123 行：

- `buildGhost()`（`app.js:14-45`）：`getBoundingClientRect()` 逐行量每个目录项的
  `left/top/fontSize`，再 `document.createElementNS` 建 SVG `<text>`，套
  `transform: translate(W,1) scale(-1,1)`（`app.js:26`）；
- `deepen()`（`app.js:50-58`）：滚动时把 `--ghost-o` 在 0.08–0.14 之间重算；
- `MIRROR_BUDGET = 46`（`app.js:9`）：超过 46 行就报 `MIR-47` 错误——**那个错误状态是真的会触发的，
  不是画一个错误框**。

**提示词告诉 AI「做一面镜像层」，但没告诉它「镜像层必须在 JS 里按 getBoundingClientRect
逐行生成」。** 一个 AI 拿到这句话，能做出来的是 `transform: scaleX(-1)` 一整块镜像——
**行对不齐、字号不对、页码错位，而且它会以为自己做到了。**
这正是 `03f6fd4` 记录的"提示词自己就产不出那个风格"的一个未修复的实例。

同类的还有 4 个机制的交互动词被留在 `dna.mechanism` 里却没有任何实现说明：
S03（滚动推进年代轴）、S06（卡片沿斜轨漂移）、S08（滚动 200px 走 6px）、
S13（按下时方位角翻到 315°）。**这四条机制句对 AI 是纯口头承诺，没有一行实现约束。**

### 钢人反驳

**反驳一：提示词明确要求"只给一个完整单文件 HTML，CSS 内联在 `<style>` 里，
不引 React/Vue/Tailwind/Bootstrap"——它没说"不许写 JS"。**
我的回应：技术上对，实践上不成立。「CSS 内联在 `<style>` 里」这句给 AI 的唯一暗示是
"这是 CSS 活"。**30/30 条提示词里 0 次出现 `script` 这个词**，而 30/30 个原型都要 JS——
这不是"允许但没强调"，是**整类信息被结构性漏掉**。

**反驳二：`⑧ 动效只用本案机制句里写到的那一个动作，其余位置保持静止` 这条已经覆盖了。**
我的回应：**它恰好起了反作用。** 这句话的字面意思是"只做机制句里那一个动作"，
而机制句里的动作（滚动加深透印、按下翻光源）**需要 JS**。AI 读到"其余位置保持静止"，
最省力的解法**恰恰是不写 JS，只做静态外观**——于是机制句变成一句装饰性描述。
**提示词在这里制造了一个自我否定的指令：要求一个动作，同时给出了"静止"这个更容易的出口。**

**反驳三：静态库不需要"能跑"，用户要的是"长得像"。**
我的回应：**这是整个仓库的第一句口号所否认的。**「30 个能跑的风格，不是 30 张配色图」
（`README.md:7`）——"能跑"是它选择的战场。而在"能跑"这个战场上，
**2,844 行 JS 是它最主要的实现成本，也是它与 Minick/Awwwards 的真正差异，
却被 100% 排除在唯一的交付物（提示词）之外。** 这是这个项目最纯粹的一次自我否定：
**它用"能跑"来立论，用一个只能产出静态页的提示词来交付。**

## 10. 如果只能改一条：**把提示词的"可验证性"从文档搬到代码，先修 5 栏/7 栏**

### 为什么是这一条

因为它是**唯一一条同时污染所有其他结论**的错误：

1. **它污染产品**：用户复制到的提示词里，S07 的签名句写着「正面 5 栏对背面 7 栏」，
   而原型是 2 栏 + 3 栏。AI 照做会得到 12 栏、每栏 113px 的目录——正是 `style.css:169-175`
   注释里作者实测过的"标题被排成 4~5 行、每行 2 字"。
2. **它污染证据链**：`data.js` / `_specs/S07.md` / `04` / `11-compiled-30` / `prompts.js` /
   `prompt-copy.js` 六层都带着它，每一层都有"实测抽取"的注释为它背书。
   所以**任何一层做"一致性检查"都会判它一致**——它自洽。
3. **它证明守卫选错了对象**：`check-prompts.mjs` 核 hex/线宽/字号/字体/圆角/阴影，
   **不核栏数、栏宽、基线、行长**——而后者才是"版式风格"的本体。
   修这一条必然要求把"栏数/栏宽/基线/行长"加进 `check-prompts`，
   于是**顺手把整类"结构性比例从未被验证"的洞堵上**。
4. **它能被证伪**：不需要审美判断，只需要 `getComputedStyle` 数一下 `column-count`。
   这是这个仓库最擅长的事——它已经有 CDP 探针、有 30 案 `report.json`、有 272 张截图。
   **它有能力修，只是从没想到要量这一项。**

### 具体动作（三条，一天可完成）

1. **修 S07 的机制句与 `def`/`layout`/`landing`**：把「正面 5 栏对背面 7 栏」改成
   「正面 2 栏对背面 3 栏、两页宽度比 5:7」，`--module:62px` 改成它真实承担的语义
   （或直接删掉"栏宽 62px"这个说法）。
2. **给 `check-prompts.mjs` 加一条 `structure` 断言**：每条提示词里出现的「N 栏」，
   必须在对应 `style.css` 里能找到 `column-count:N`、`grid-template-columns` 有 N 轨、
   或 `repeat(N,`。跑一次 30 案。
3. **把 13 条"已知边界"里能变成断言的三条变成断言**：`file://` 的 `mask-image`（S04/S07）、
   「外投影 0 案」（当前是错的，改成"1 案有外投影并在提示词里写明"）、
   以及 README:556 那句 26/8。

### 为什么"不改这条，别的都白做"

这个项目的**全部价值**押在一句话上：「提示词是从真实 style.css 实测抽取的，不是套话」。
如果这句话在**最像"实测"的那一条**（具体到"5 栏 / 7 栏 / 62px"）上是错的，
那么它**在别的地方是否对，读者无从判断**——因为读者唯一能验证的手段，就是相信这句承诺。
205 份报告、9 万行审计、6 个 check 脚本，都在为这句承诺做担保；
而**这句承诺有一个可以被一条 `getComputedStyle` 推翻的反例，且它就在被推到首页的 S07 上**
（`README.md:58` 的 30 案清单里，S07 是被点名展示的那一行）。

**更准确的说法**：不改这条不会让项目归零，但会让**"实测抽取"从事实降级为口号**。
而降级之后，剩下的东西（30 个原型 + 3 个模板 + 一套反 AI 味判别器）仍然有价值——
只是那时它必须换一个自我描述，不能再叫"不是套话"。

## 11. 最强的、值得继续做的理由（我认真找过，不是客套）

### 理由一：它是**唯一一个把"风格的机制"写成可执行数值**的公开语料库

我核过替代品（Minick 20 种、HTML5 UP 44、ThemeForest 7,941、Awwwards 等），
它们给的是**结果**（一张图、一个可点的 demo、一个模板），**没有任何一个给"为什么这样能读"**。
而这个仓库给了：

- **22 种结构标签**（`MAG-TOC` / `VERSUS` / `CHRONO` / `CONSOLE` / `INTERLOCK` …），
  8 对撞车是缺陷，但 22 个标签本身是一套可用的分类法。
- **20 条带逐行 `style.css` 出处的机制句**（`mechanisms.mjs` 每条带 `source:` 字段，
  精确到 `:381` `:387-388` `:543-544`）。
  **[复算]** 机制句里出现的数字，**29/30 能在该案 CSS/HTML 里逐字找到**。
  这个自洽度是真的，而且我找不到第二家做过。
- **一份 92 KB 的反 AI 味判别规则**（`02-anti-ai-rules.md`），含 40 词黑名单与
  V-01–V-11 高危家族硬指标——**可以直接当 system prompt 用**。

**在"给 LLM 喂风格条件"这件事上，这是一份现成的、带自校验的语料。**
它的正确客户不是店主，是**做 agent 工作流的人**（`60-diagnosis` 已经摸到这一层）。
如果它按这个客户重写 README 第一屏，我会认为它有真实的、稀缺的位置。

### 理由二：它对"哪些数字不能信"的自我审查，是真的

`UNVERIFIABLE.md` 那句「**35.8% 的约束写得像判据、实际没有对错之分，而且 M 类 30.8%、
S 类 43.3%——精确感与可判定性负相关**」是全仓库最值钱的一句话。
**[复算]** 我用它的口径抽查了 §0 的分布表（1011 / 390 / 510 / 111），
以及它对「1327 条里 316 条是同一句话被拆成 4 条」的去重理由，**逻辑成立**。

同样值钱的还有 `29-critique-homogeneity.md` 对「17% / 60% / 73% 三个数分母互差 4 案」的
自我清算、`21-lead-verify-homogeneity.md` 开头那条「已更正，请按 18/30 读」的横幅。
**这种程度的自我纠错，我在商业设计工具里一次都没见过。**
它是这个项目最像"科研"的部分，也是它最该保留的品格。

### 理由三：它的三档真截图 + 真缺图状态，命中了一个真实的空白

`README.md:24` 说「不是你没审美，是你见过的样本全是渲染图：它不告诉你 1440 到 390 之间怎么塌，
不告诉你长文压不进栅格，也不告诉你照片缺了得重排」。
**[复算]** 我核了：30/30 案有 `@media` 断点（实测 30/30）、30/30 有 inline `<script>`（30/30），25/30 有明确空状态标记、
`data.js` 每案有 `shots.desktop/tablet/mobile` 各 3 张（共 273 处路径），
且状态是**真的**：S07 的 `#state-loading` / `#state-empty` / `#state-error`（`hidden`）/ `.disabled-line` 四种都在 DOM 里，配 `app.js` 的 `MIRROR_BUDGET=46` 截断逻辑（`app.js:9,40-42`）——**它真的会在第 47 行报错，不是画一个错误框**。
**"能塌、有状态、有真图"这三件事，Awwwards 与 Minick 都不给。**
这是一个真实的、窄的、别人没占的位置。

### 理由四（最私人也最硬）：它证明了一件事——**30 个手工艺品不能靠 agent 流水线变成设计系统**

它的失败模式本身就是产出：35,000 行审计、205 份报告、6 个 check 脚本，
产出了一个**自洽但不自证**的系统。最锋利的证据是我在 §3 找到的那个：
**13 条 PASS 全绿，而 README 第一屏的数字在闸门从 26 抬到 29 之后没再改过。**
这个案例（"agent 治理的极限在哪里"）对任何做 agent 编排的人都有直接价值——
**`deliverables/` 本身就该被当成"agent 审计的天花板标本"来读，而不是当设计文档。**
`49-critique-audit-theater.md`、`60-diagnosis-what-feels-wrong.md`、
`69-audit/UNVERIFIABLE.md` 三份，合起来是一篇尚未被写出来的论文的素材。

### 一句话

**它的产品值 3 分，它的语料值 7 分，它对"agent 治理能走多远"的记录值 9 分——
而它现在把 90% 的力气花在了给 3 分的东西做质检报告上。**
改法不是"再修 50 个缺陷"，是**换封面**：把"30 个风格让你挑"换成
"30 条带机制出处的风格条件 + 一套可复算的反 AI 味判别器 + 一份 agent 审计的天花板标本"，
然后把 README 前 100 行重写，把 358 MB 的 clone 成本砍到 60 MB（`.inspect/` 出仓，按需生成）。

## 附录 A：正文引用的四处补测

### 补 1：S07 的规格网格算术本身就不成立

`data.js:521` 与 `04-schemes-01-10.md:263` 写「左 5 栏右 7 栏（**栏宽 62px、栏沟 18px**）」。
**[复算]** 12 栏 × 62px + 11 条栏沟 × 18px = **942px**；而 `.pages` 在 1440 档的实际内容宽
（扣掉左右各 40px padding）= **1360px**。**差 418px。**
同一份规格又说 `.lede` 的 `max-width` 应是「module × 14 + gutter × 13」= **1102px**，
而 `style.css:49` 确实用了这个公式——**也就是说 `--module:62px` 只在 .lede 这一条上被当成"栏宽"用，
在真正排版目录的 `.pages` 上完全没参与。**
这不是"提示词没传过去"，是**规格本身把"两页宽度比 5:7"写成了"栏数 5:7"，
又把一个只用在标题栏宽上的 62px 写成了"栏宽"**。一个从 `_specs` 一路复制到
`04/05/06` → `11-compiled-30` → `data.js` → `prompts.js` → 用户剪贴板的错误，
每一层都有"实测抽取"的注释为它背书。

### 补 2：`check-prompts.mjs` 对这条错误判 PASS

我跑了它：

```
提示词闸门：检查 30 条提示词（源: prompts.js + prompt-copy.js vs prototypes/Sxx/style.css + index.html）
  长度 1814–2138，中位 1988  配色段 hex 合计 168
· [hex-outside-palette-line] 1 条（信息，不需动作）
合计 FAIL 0 / WARN 0
```

它只核 **hex / 线宽 / 字号 / 字体 / 圆角 / 阴影** 六类，**不核栏数、栏宽、基线、行长**。
所以"提示词与 CSS 一致性"这个门禁最强的地方，恰好是**它唯一不检查的地方**——
而那里躺着一个把 5 栏说成 7 栏、让 AI 把每栏做成 113px 的错误。

### 补 3：README 自己写的「外投影 0 案」也是错的，而这一条被显式地排除在守卫之外

**[源码]** `README.md:86` / `README-EN.md:86`：

> 「圆角、阴影哲学、线宽分级 | 统计全文件实际取值：**无阴影 18 案** / 只有 inset 6 案 /
> 只有 drop-shadow 6 案，**外投影 0 案**」

**[复算]** `prompts.js` 里 `dna.shadow` 的实际分布是：

```
{ '无阴影': 17, '只用 inset（凹槽，无外投影）': 6,
  '只用 drop-shadow（硬边厚度，无模糊投影）': 6, 'inset 与外投影混用': 1 }   // 合计 30
```

**不是 18，是 17；"外投影 0 案"不成立，S13 那一案就是"混用"。**
**[源码]** 而且 S13 真的有一条外投影在用：
`prototypes/S13-blind-debossed-dispatch/style.css:136` 定义
`--press-4: 0 -2px 3px rgba(36,31,23,.06)`，`:506` 把它挂在
`position:fixed; bottom:0` 的贴底签发栏上（`box-shadow: var(--press-4)`）。
`_CONTRACT.md:110` 自己承认这一点，但把它写成「1 处外投影（**落在小元素上，未进 `probe.mjs:314`
的 `big` 采样集**）」，于是「外投影 0 案」在**运行时判据**下成立、在**提示词的事实**下不成立。
最要命的是它进了提示词：S13 的提示词第 4 条原文是

> 「4. 阴影：**inset 与外投影混用**。」

而 README 对着用户说"外投影 0 案"。**用户读到的是承诺，AI 收到的是相反的事实。**

**[源码]** 而 `check-docs.mjs:560` 的 `OTHER_AXIS` 正则里**明写着 `阴影|shadow`**——
这条数字被**显式地排除在一致性守卫之外**。一条"错了也不会有人管"的数字，
正好是 README 用来证明"提示词真从 CSS 抽取"的四个证据之一（`README.md:84-86` 那张表）。

### 补 4：提示词的共享骨架是 37.7%，不是"每案一份"

**[复算]** 默认参数（不填业务）下：30 条提示词 min 1814 / max 2138 / avg 1986；
出现在 **≥27/30** 条里的整行共 **22 行、748 字 = 平均长度的 37.7%**。
每案真正独有的部分平均 **1,198 字**，其中包含：色值（4–7 个 hex）、三条字体链、
圆角/阴影/线宽/字号四行、一句机制、一句 plain、一句 tone、一段 risk（截到 220 字）、
以及数量与图片位两句。

**共享的 22 行里有 8 条是"防退化"正面要求**（面积分配 / 直角边界 / 首屏对齐 / 不等栏宽 /
线宽画图 / 不透明底色 / 明度差 / 只用一个动效）——**这 8 条对 30 案是同一套话**，
它们甚至和第 3–5 条硬约束部分重复。也就是说：**用户以为自己拿到的是"这个风格"，
其中约 4 成是"任何风格都这么说"。**
