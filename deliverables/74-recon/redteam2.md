## 1. 攻击一：提示词传输的是「同质的那一层」，丢掉的是「唯一不同的那一层」

这条不是"损失比例"，是**方向错了**。仓库真实的差异化在骨架与机制；提示词给的是配色、字体、圆角、线宽。

### 证据

**[复算]** 把 `prompt-copy.js` 的 `buildPrompt()` 在 node 里跑通（stub 掉 `document`），逐案检查
「`data.js` 的人写散文字段，有没有任何一个字进了提示词」（方法：取每段前 14 字做子串匹配）：

| 字段 | 进了自己提示词的案数 | 说明 |
| --- | --- | --- |
| `quirk`（设计师签名式怪癖） | **0 / 30** | README:157 把它列为「12 字段」之一（"一处**设计师签名式怪癖**"，第 12 个字段），并在第 155 行把「12 字段」当成「设计主张 vs 配色皮肤」的证据 |
| `motion`（动效机制 + 降级路径） | **0 / 30**（6/30 有任何动效词汇） | |
| `layout`（栅格与断点） | 0 / 30 | 判据是**逐字子串**：任一段前 14 字出现在自己提示词里 = 0 次。提示词里确实出现「4 栏」「栏沟 24px」这类**从机制句里带出来的**词（30/30 都有「栏」字，来自机制句或通用条款「不等的栏宽」），但 `data.js` 的 `layout` 段落本身**没有一个字**被引用；`grid` 出现 **0** 次、断点（768/1024/1440）出现 **0** 次 |
| `visuals` | 0 / 30 | |
| `audit` | 0 / 30 | |

**[源码]** `prototypes/S03-long-exposure-observatory/style.css:129-133` —— 这是该案的全部签名：

```css
.axis {
  position: sticky; top: 24px;
  height: 640px; padding: 16px 12px;
  background: var(--panel); display: flex; flex-direction: column; gap: var(--u);
}
```

**[复算]** S03 的提示词（1931 字，全文已导出）里 `sticky` / `固定` 出现 **0** 次。
机制句写的是 `<code>一条 264px 宽的纵向刻度轴随滚动固定</code>`——只有「随滚动固定」五个字，
没有 `top: 24px`、没有 `height: 640px`（轴高固定是它和影像带错位的唯一来源）、
没有 `.stream` 与 `.readouts` 在 1440 档变成三列的那条 `minmax(0, 540px)`。

**更硬的一条：影像带的高度根本不在 CSS 里。**
`style.css:149` 只写 `<code>.band img{...height:var(--h)...}</code>`，
而 `--h` 的取值是 **HTML 内联样式**，逐条写死：

```html
<figure class="band" style="--h:28px"> … 30 s
<figure class="band" style="--h:42px"> … 45 s
<figure class="band" style="--h:84px"> … 90 s
```
（`index.html:71,75,79,83,87,91,95,99`；**[复算]** 8 档高度 = 28/42/14/56/19/37/84/23）

提示词只说了「按 30 秒曝光折成 28px 一档」这一句公式，**而真实的映射是 8 个非等比的实测值**
（30→28、45→42、90→84 是 1:1 与 0.93:1，15→14、20→19 却是另一条曲线）。
照公式做的 AI 会做出一张**等比阶梯**；原型是一张**手量出来的表**。
这个机制的全部信息量在 8 个数字里，提示词给的是 1 个。

第二案，S21（`interlocking-release-book`）：

| 原型里存在的 | 在哪 | 提示词里有吗 |
| --- | --- | --- |
| 条尾墨点 `<code>right:calc(3.5px - (var(--i)+1)*.25px)</code>`，14 枚累计 3.5px | `style.css:577-585` | **无**（`0.25px` / `1.5px` 均 0 命中） |
| 右端斜切三档的真实多边形 `<code>polygon(0 0,56.7% 0,100% 100%,0 100%)</code>` | `style.css:558-560` | **无**（`56.7` / `75%` / `85.57` 全 0 命中） |
| 逐枚扣接 `<code>animation-delay:calc(var(--i)*70ms)</code>` + `steps(1)` | `style.css:595-599` | **无**（`70ms` 0 命中） |
| 释放路径 `position:sticky; bottom:48px`，必须与两张表同一行 | `style.css:491-501` | **无**（`sticky` / `48` 0 命中） |
| 钢料磨痕 `background-image:url('assets/texture-steel-grain.png')` | `style.css:530-537` | **无**（`texture` / `grain` 0 命中） |
| 每张表比路径低 9px（1.5 个基线） | `style.css:389` | **无** |

**[复算]** 30 条提示词之间：**733 字（38.0%）是 30 案逐字相同的整行**；两两最长公共子串
中位数在 470 字左右（S03 vs S10 = 470，且这段就是那 8 条「防退化」+ 图片位 + 首屏）。
**提示词 = 38% 全库共用的反 AI 条款 + 一个色板 + 三个字体名 + 一句机制 + 18%–25% 的案专属数字。**

### 钢人反驳（我认真试过）

**辩护一：README 自己说了「提示词越长，越是在描述那个具体页面而不是那个风格」（README:101）。**
所以丢 `640px`、`0.25px`、`70ms` 是**刻意的抽象**，不是缺陷。

我的回应：这个辩护成立的前提是「抽象保留了可判定的特征」。但被抽掉的不是"细节"，是
**"这个风格靠什么被认出来"**。S21 之所以是 S21 而不是"深色工业表格"，唯一原因是
「切口角度 = 互斥对数」这条编码关系；提示词确实保留了「30/45/60°」这三个角度值
（**[复算]** `30/45/60°` 在提示词里），却**没有保留"哪种对数配哪个角度"这一列数据**
（原型在 `index.html:294-317` 有一张完整角度表：4 对→60°→13.9px，3 对→45°→24.0px，2 对→30°→41.6px）。
一张只有三个角度的 AI 页面，和一张"角度是数据算出来的"页面，观感上是两种东西。
**抽象可以，但抽象到只剩形容词就是"配色皮肤"了 —— 而这正是标语否定的那件事。**

**辩护二：`quirk` 不进提示词是**对的**，因为它"无任何导航作用"，写进去只会让 AI 加装饰。**
（S03 的 quirk 原话就这么自陈：「它无任何导航作用，点击也不响应」。）
这条辩护很强，我接受一半：**`quirk` 确实不该逐字进提示词**。但由此产生的结论是反的 ——
如果 30 个"设计主张"的差异化支点是一个**不该被传输的字段**，那么"这是一份完整的设计主张"
这句话在**取用环节**就是空的。仓库自己把这个字段当成「主张 vs 皮肤」的分界线
（40 号报告 §2.4 的原话：「它不是配色皮肤，而是一份完整的设计主张」，README:155 沿用至今）。
**分界线本身不可传输，等于没有分界线。**

## 2. 攻击二：不是「30 个风格」，也不是「4 个结构的 30 种配色」—— 是 **两簇 + 一个孤点**

上一份红队（`74-recon/redteam.md` §2）给的是「可见层只有约 7 个」。我重算了，**7 这个数字判轻了**：
真实形状更像「两簇 + 一个孤点」，而**两簇之间的差异不在配色，在明暗制度**。

### 证据（全部可复算）

**[复算]** 底色明度分布（`palette[0]`，HSL 的 L）：

| L 区间 | 案数 | 说明 |
| --- | --- | --- |
| L ≤ 15（近黑/深色） | **8** | S02 S03 S05 S08 S12 S14 S18 S28 |
| 15 < L < 78 | **1** | 只有 S09（L=61，一堵蜡染黄墙） |
| L ≥ 78（浅色） | **21** | 其中 18 案同时满足 `H∈[28,72]`（暖浅带） |

**这就是"两簇"的机械形状：8 暗 / 21 浅 / 1 个孤点。中间调（L 20–60）是 0 案** —— 与仓库
`deliverables/29-critique-homogeneity.md` §4 的自述一致（"明度 20–60 整段 0 案"）。
一个声称覆盖"网站设计风格"的库，**没有一页中间调**。这不是"暖色偏多"，是**曝光只有两档**。

**[复算]** 暖浅带 18 案按 `ΔH≤3° 且 ΔL≤3°` 求连通块：**最大块 12 案**，成员
S01 S04 S06 S13 S16 S17 S19 S21 S22 S25 S27 S29。把 L 约束去掉只看色相，
块膨胀到 **16 案**（多进 S09 S10 S15 S20 S26）。
若把口径放宽到 `ΔE76≤5`：底色两两之间共有 **53 对**在 5 以内，而最远的一对（S09 黄墙 / S28 紫黑）
距离 **106.7**。**色空间的最长距离是 106，而 53 对挤在 5 以内。**

**[复算]** 结构标签 22 种真的（我数了，`CONSOLE`/`SPLIT`/`CHRONO`/`COLLAGE`/`MAG-TOC`/`VERSUS`/
`MANUAL`/`DOSSIER` 各 2 案，其余 14 种各 1 案）。但**同一结构标签 + 同一调性 = 完全重复的两案**：

| 调性 \| 结构 | 冲突的案 |
| --- | --- |
| 机能冷峻 / 工业 \| CONSOLE | **S05 / S21** |
| 冷静克制 / 工程感 \| VERSUS | **S10 / S26** |

而暖浅带内部还有 **4 组共享结构标签**：`MAG-TOC` S07/S25、`VERSUS` S10/S26、`MANUAL` S11/S29、
`DOSSIER` S13/S27 —— 也就是说，**"结构不同"这条最强防线，在 18 案暖浅带里只剩 14 种，其中 4 组是两案一对。**

**[复算]** 30 条提示词的字面相似度：**S03 与 S10 的最长公共子串是 470 字**，
内容就是那 8 条「防退化」（`prompt-copy.js:725-773`，30 案逐字相同）。
从"用户拿到的两段文字"这个视角看，**两条 1931/2000 字的提示词有 24% 是完全同一段**。

### 结论（我站的位置）

「30 个能跑的风格」在**产品层**是真的：30 个目录、30 份 350–960 行 CSS、30 套真文案、
30 个不同的首屏构图。这一条我不否认，也不认为它容易。
但「**不是 30 张配色图**」这句防守性主张是**打偏了目标**：真正的差异化在骨架
（22 种，其中 4 组重复）；而**用户实际拿走的东西**（提示词）里，骨架只剩一句话，
配色与字体全量给了、还额外给了 38% 全库共用的条款。
**它防住的是"配色图"这个指控，没防住"配色图 + 一句骨架描述"这个更准确的指控。**

### 钢人反驳（我认真试过）

**辩护一：22 种骨架、8 暗/21 浅/1 中、53 对 ΔE76≤5 —— 这些数字早就在仓库自己的报告里
（`29-critique-homogeneity.md`），README:429-434 逐条公开，还主动披露自己混用过 17%/60%/73% 三个分母。
一个把最难看的数据印在门口的库，不该被"同质"这根棍子打。**
这是**最强的一条辩护，我接受它的大部分**：在**披露**这件事上，这个仓库的诚实度高于绝大多数开源项目。
我的回应只有一句：**披露的位置在 README 第 429 行，主张的位置在第 7 行。**
第 7 行是引用块里的那句加粗标语，第 429 行是"做不到与已知边界"里的第九条 ❌。
一个只读前 20 行的人得到的是"30 种风格"，一个读到 429 行的人得到的是"18/30 同一个暖浅带"。
**这两句话之间不是补充关系，是互相抵消。** 一处诚实的披露不能抵消一处不诚实的封面 ——
它只是让封面变成"已经知道是假的封面"。

**辩护二：戏剧/设计谱系本来就是聚簇的，"两簇"不是缺陷。**
真实世界的品牌站也大量是"浅底 + 一个强调色"。30 案里有 8 个暗色、1 个中间调，
说明作者知道这条路存在，只是没走。

我的回应：**这条我部分接受，并且它让攻击变弱了一档** —— "只有两簇"本身不构成缺陷，
**"两簇之外是 0"才是**。仓库自己给出的诊断（29 号 §4）说得很准：缺的是**中间调（0 案）、
紫→品红 110°（0 案）、冷亮底（3 案）**。所以准确的指控不是"同质"，是
**"色空间的三个象限一个样本都没有，而这三个象限在 2020 年代的真实网站里非常常见"**。
这是一个**覆盖缺口**，不是一个**假货**。我把它降级为"重大覆盖缺口"，不降级为"不成立"。

## 3. 攻击三：机制句是**唯一**被送进提示词的结构描述，而**没有任何闸门读过它**

这是这一份最实的一条。`03f6fd4` 的 commit message 自己写：「查明『提示词自己就产不出那个风格』」，
并在 `prompts.js` 头部记下了 S07 的 5 栏/7 栏误读（`prompt-copy.js:196-207` 的注释链也引了它）。
**但那个缺陷到今天还在**，而且不是孤例。

### 证据

**[复算]** 我拿 30 条 `dna.mechanism` 里的每一个带单位数字，回各案 `style.css + index.html`
（剥掉注释后）做匹配：**162 个 token，11 个在源码里找不到（6.8%）**。分布：

| 案 | 找不到的 token | 真实情况 |
| --- | --- | --- |
| S03 | `9 栏` | CSS 只有 `<code>grid-template-columns: var(--axis-w) minmax(0,1fr)</code>`，**2 列**；`12 栏 / 9 栏` 只活在一行注释里（`style.css:120`） |
| S07 | `14%`、`0.5px` | `--ghost-o` 默认 `.08`，`.hot` 才是 `min(.14,…)`（`style.css:106-107`）；`0.5px` 栏线不存在 |
| S09 | `3.5px`、`5%`、`10%` | `3.5px` 是 SVG 的 `stroke-width:3.5`（`style.css:312`），`5%/10%` 缺口无对应声明 |
| S13 | `3%`、`14%` | 只在注释里（`style.css:13`），不是可执行值 |
| S17 | `1.2px`、`96px` | `1.2` 是 SVG `r=1.2` 圆孔半径；`96px` 金额列宽 **不存在**（`td.num` 是 `88px`，且只在 ≤1439 的块里，`style.css:320`） |
| S10 | `1px`（红版错位） | 无对应声明 |

**[源码]** S03 更硬的一处：机制句写「**游标随焦距比移动**」（`_specs/S03.md:15`、`prompts.js` S03 的 `dna.mechanism`），
而实现是（`index.html:302-310`）：

```js
cursor.style.transform = "translate(" + e.clientX + "px," + e.clientY + "px)";
```

**一个 1:1 跟随鼠标的十字线。没有焦距，没有比例，只有 pointermove。**
`grep 焦距` 在 S03 整个目录 = **0 命中**（只有 `_specs/S03.md:15` 那一句）。
读者复制到的提示词里有一句话描述了原型里**不存在**的东西。

**[复算]** 这一整类缺陷之所以能活下来，是因为**没有任何闸门读过 `dna.mechanism`**：

| 闸门 | 文件内 `.mechanism` 引用数 |
| --- | --- |
| `check-prompts.mjs` | **0** |
| `check-docs.mjs` | **0** |
| `check-contract.mjs` | **0** |
| `check-twolines.mjs` | **0** |
| `check-texture.mjs` | **0** |
| `check-stale.mjs` | **0** |
| `check-anchors.mjs` | **0** |
| `verify-prototype.mjs` | **0** |

而 `check-prompts.mjs` 存在**就是因为**"提示词内容没有保护"（其文件头第 4-8 行原话：
「30 条提示词重生成完全没有保护，改对改错都是绿的」）。它上线后保护了 **配色 hex / 线宽 /
字号**（`KEY_FIELDS = ['h1Size','lineWidths','radius','shadow']`，`check-prompts.mjs:379`），
**唯独没保护那句唯一描述"这个风格是什么"的机制句。**

### 这一条为什么比"提示词损失 2/3"更严重

上一份红队说的是"丢信息"。丢信息可以辩解为抽象。**这一条是"给假信息"。**
- 丢信息的下限：AI 自由发挥，做出一个"像但不精确"的东西。
- 给假信息的下限：AI 精确地做出一个**错的**东西，而且因为提示词是"实测抽取"的，
  **用户会以为自己拿到了权威摘要**。S07 的 5 栏/7 栏会让每栏只有 113px（原型 258–274px），
  标题当场碎成每行两字。S03 的"9 栏"会让 AI 去做一个 12 栏系统，而原型是 2 列 + 一个 readonly 侧栏。

### 钢人反驳（我认真试过）

**辩护一：`_specs` 是施工前写的文本，机制句是"设计意图"，不是"实现记录"。
实现偏离意图，是实现的锅，不是机制句的锅。**
我的回应：这个区分在**内部**成立，在**交付物**里不成立。`prompts.js` 的头部明写
「数据来源：各案 style.css 实测抽取（色值/字体/圆角/阴影/线宽），见 dna-clean.json」，
README:80 的卖点是「它不是套话，是从各案 `style.css` **实测抽取**出来的」。
用户被告知的是"实测抽取"，拿到的是"施工前的意图文本里抄的一句"。
**如果是意图，就该标"设计意图"；如果标的是"实测"，就必须过实测这道闸。**

**辩护二：6.8% 而已，8 处的量级不足以推翻"实测抽取"。**
我的回应：**分母选错了。** 全库 162 个 token 里 151 个能对上，这个比例确实高。
但**机制句是提示词里唯一的结构描述**（§1 已证：`layout`/`visuals`/`motion`/`quirk` 进提示词 0/30）。
所以真正该看的分母是「提示词里关于"这个风格怎么搭"的句子 = 30 句」，
其中 **6 案（S03 S07 S09 S10 S13 S17）至少有一个 token 对不上 = 20%**。
一句结构描述错了，不是丢 1/162 的信息，是这一案的**唯一**结构描述错了。

**我承认被削弱的部分**：S09/S13 的 `3.5px`/`3%` 是我口径太严 ——
`3.5` 以 `stroke-width:3.5`（无单位）存在，`3.1%` 在注释里且注释明确标了来源。
严格成立的是 **S03（9 栏 + 焦距）、S07（5 栏/7 栏）、S17（96px）** 三案，
占 10%。**结论从"20% 错"降到"10% 硬错、另有 7% 口径边缘"，但"零闸门覆盖"这一点不降级。**

## 4. 攻击四：审计剧场 —— 诊断书写对了，然后**证据库涨了 3 倍，产品涨了 6%**

上一份红队已经算过"散文/产品 = 350 倍"的窗口。这一份给一条更准、更难反驳的：
**仓库自己写出了正确的诊断，并给了正确的处方，然后做的事恰好是处方里说"要砍"的那一类。**

### 证据

## 5. 攻击五：市场 —— 唯一真实的客户是「agent 工作流搭建者」，而那条路要求的东西恰好被"静态"堵死

### 证据

**[文档]** 仓库自己做过唯一一次带外部数据的市场判断（`53 席`，收在 `60-diagnosis` §2.3）：

> 「stars/forks/watchers/issues = **0/0/0/0**，作者 1 人，生命周期 4 天。」
> 「Minick Studio **≈100% 同句级重叠**（「每个风格都是 live working demo」）；
> HTML5 UP 44 模板挂真实下载计数、合计 **2,147 万次** —— 同一条差事市场上有人付过 2100 万次动作。」
> 「niche 确实存在但不是声称的那个：四条合取（30 互不相同 × 可运行原型 × 机械闸门 × 双语）
> GitHub 实测无人做；可数人群 = **agent 工作流搭建者本人**（要风格条件语料 + AI 味判别器；
> 规模代理 UI-Prompt 419★）。53 裁定：**(b) 需求是编的 55% + (c) 被错误包装的语料资产 30% + (a) 15%。**」

**[复算]** 我独立核了 GitHub：`sqkl520/web-style-atlas` —— `stargazerCount: 0`、`forkCount: 0`、
`createdAt: 2026-10-19`、`licenseInfo.name: "Other"`（不是 MIT，因为 LICENSE 前 63% 是自定义排除条款）、
`diskUsage: 239503 KB`（**234 MB**）。91 个 commit 全部作者是 `sqkl520`。

### 逐类列出「谁需要它 / 他会选什么替代品」

| 声称的客户 | 他真实的需求 | 他会选的替代品（**不是这个库**） | 为什么 |
| --- | --- | --- | --- |
| **要上线一个小站的小老板** | 今天上线、能改字换图、能收表单 | **M02 那类模板**（他自己仓库里就有 3 个，26 KB 一个）、WordPress、Framer、Carrd | 30 案"搬走 8–16.5 h/案"（50 席实测，`60-diagnosis` §2.2 引用）；小老板没有 8 小时 |

| **要搭生产站的开发者** | 组件、token、可访问性、可维护 | **shadcn/ui + Tailwind、Radix、Tailwind UI** | 30 案明确"不是设计系统"（README:444 自陈）；没有 token 交付、没有组件库 |

| **想找"暖极简"感觉的人** | 一个好看的暖色落地页 | **直接问 ChatGPT「做一个暖极简的咖啡店网站」** | 零成本、零 clone、结果差不多 —— 这正是 §2 证明的：**本库的提示词在同质那一层传输，而那一层正是通用大模型最擅长的** |
| **agent 工作流搭建者** | 可机读的风格条件语料 + 可判定的"AI 味"判别器 | **目前没有现成品**（这是唯一的真空白） | 但这条客户要的是：结构化 JSON、可调用 API、可回归的相似度指标 |

### 结论（我站的位置）

**"这个库卖给谁"这个问题，仓库自己给出的答案是唯一站得住的：agent 工作流搭建者（53 席的 (c)）。
但那个客户要的三件东西，这个库恰好都没有：**

1. **结构化语料** —— 有（`data.js` 30×33 字段、`prompts.js` DNA），**这是真资产**。
2. **可调用的分发** —— 没有。产物是"复制到剪贴板的 1931 个字"，要人手动粘。
3. **可回归的质量指标** —— 没有。唯一的端到端指标是 `0.490 视觉相似度`，测于 10-29，
   **之后再没重测过**（`grep 视觉相似度 deliverables --include="*.md"` 只命中 4 份，
   全部在 10-29 及以前；而 `0ee3fb5` 在那之后改了字号接线的实现）。
   **[源码]** `deliverables/69-test/LEAD-similarity-finding.md:6` 「平均视觉相似度 **0.490**」。

**所以市场的真实形状是：产品（30 案 + 语料）是真的，客户（agent 搭建者）是真的，
而把两者连起来的那条链（可调用 + 可回归）是用 markdown 画的。**
"静态"在这条链上是**承重墙**，不是审美（见 §7）。

### 钢人反驳（我认真试过）

**辩护一：0 star / 4 天 / 一个人 —— 这不是"市场否决"，是"还没发布"。**
一个 10 月 19 日建、10 月 31 日最后一次 push 的仓库，没有推广、没有 HN 帖、没有 README 首页截图，
0 star 是**默认状态**，不是**判决**。用它论证"没人需要"是循环论证。

我的回应：**这条我完全接受，而且它推翻了本节最强的一句话。**
我撤回"没人需要"。0 star 说明的是"没被看见"，不是"不被需要"。
**但辩护一救不了替代品那张表** —— 那张表不依赖 star 数，它依赖"用户手边有什么"。
即使这个库明天上了 HN 首页，一个要给客户提案的设计师明天还是会打开 Awwwards，
因为 Awwwards 有 10 年积累的、被客户认可的名字。**这不是曝光问题，是资产性质问题。**

**辩护二：它的定位不是"替代 Awwwards"，是"提供 Awwwards 上拿不到的东西 —— 能跑的原型 + 字段"。**
Awwwards 只给你一张图；这个库给你一个能打开、能读 CSS、能拆 12 个字段的标本。
这个差异是真的，`README:26` 那段（"你翻收藏的设计网站，越翻越眼熟…不是你没审美，是你见过的样本全是渲染图"）
说得很准。

我的回应：**这是本报告里我认为最有力的一条辩护，我接受它作为这个项目的存在理由（见文末）。**
但它有一个致命的时间维度：**"样本全是渲染图"这个问题，2024 年之后正在被 v0/Lovable 解决** ——
它们给你的不是渲染图，是**你自己那个内容的**能跑的站。
这个库的答案是"给你 30 个**别人的内容**的能跑原型"。
前者随内容定制，后者要你自己搬 8–16.5 小时。**时间站在替代品那一边。**

## 6. 攻击六：LICENSE —— 「MIT」这三个字母在**照片**上不成立，账还是三本不同的

### 证据（全部 [源码] / [复算]）

**（a）LICENSE 文件本身。**
`LICENSE:1` 是 `MIT License`，但 **前 1745 字节（63%）是自定义排除条款**，MIT 正文从第 55 行才开始。
GitHub 因此把它识别成 **`"licenseInfo": {"key": "other", "name": "Other"}`**（[复算]，`gh repo view` 实测）。
**仓库 README 第 9 行却挂着 `License: MIT` 的绿色徽章。**
也就是说：**GitHub 说"Other"，README 说"MIT"。** 这不是我推断的，是同一份仓库的两个读数。

**（b）三处数字，三本账。** 同一个事实（有多少张位图没有署名）在三个地方是三个数：

| 出处 | 数字 | 覆盖的案 |
| --- | --- | --- |

| `README.md:524` | **46 个位图文件**（S04 26 + S07 9 + S08 6 + S17 5） | **4 案**：S04 / S07 / S08 / S17（S13 已补） |
| 各案 `CREDITS.md` 实测 | **S04 26 / S07 9 / S08 6 / S13 5 / S17 5 = 51** | **5 案**：多出 **S03 的 2 个**（`grain.png`、`vignette.png`） |

**[复算]** 我逐个 `awk` 数了每份 `CREDITS.md` 里「盘上存在但署名表里没有对应记录的位图」小节：


## 7. 攻击七：「只做静态这一件事」是**承重墙**，但它承的不是它自称的那面墙

### 证据

**[源码]** README:397-403 给的四条理由是：

> - 浏览与部署**零依赖**、**零网络请求**（无 CDN、无远端接口、无埋点）。
> - 没有账号，没有登录，没有后端，没有 `npm install`。
> - 没有安装过程，也就没有遥测。
> - 数据不出本机。

四条全部是**面向部署者/隐私**的论证。**没有一条是面向"用户拿到的 prompt 质量"的。**

### 它实际foreclose了什么（逐条，附仓库自己的证据）

| 被 foreclose 的能力 | 具体代价 | 证据 |
| --- | --- | --- |
| **提示词无法自动回归** | 唯一的输出质量指标（视觉相似度 0.490）是一次性手工实验，改完提示词无法重测 | `69-test/LEAD-similarity-finding.md:6`；`0ee3fb5` 之后没重测 |
| **修一个提示词错误，用户必须重新 clone 234 MB** | S07 的 5 栏/7 栏错误从 `d4f19ec` 活到今天（10+ 个提交），因为"改完要重走 30 案重渲染 + 重发" | `git log -S"正面 5 栏对背面 7 栏" → d4f19ec`（只有那一次） |
| **无法知道哪一案被复制、哪一案被跳过** | `60-diagnosis` 只能用 30 个 agent **扮演**用户来猜 | `60-diagnosis` §2.2（48/57 席） |
| **无法跨案合成提示词** | "S07 的目录感 + S21 的联锁逻辑"是真实需求，做不到 | `redteam.md` §5 |
| **无法把 30 条提示词 A/B 到 4 个模型** | "为什么不给 4 个 AI 写 4 套"（README:101）的答案是**分叉纪律**，不是**测量** | README:101 |
| **字体许可无法按需分发** | 见 §6(d)：871 个 woff2 没有一个带许可全文 | `_fonts/` 实测 |

### 结论（我站的位置）

**"静态"是承重墙，但它承的是"作者可以在 4 天里造 30 个原型"这面墙，不是"用户可以挑到风格"那面墙。**
- **对作者**：静态 = 不用搭后端、不用管部署、素材直接放目录、闸门可以 `file://` 跑。这是**生产方式**的优势，
  它解释了 30 个原型为什么能在 4 天里出现（`caefdd9` 一次提交 33,315 行产品代码，`redteam.md` §3 的表）。
- **对用户**：静态 = 拿到一段要手动粘的文字 + 要自己搬 8–16.5 小时的 HTML。**这是交付方式**的劣势。

仓库把"生产方式的优势"写成了"产品价值的论证"（"零依赖、无遥测、数据不出本机"），
而这些**没有一条是用户挑风格时在意的**。用户在意的是：像不像、能不能用、要花多久。
**静态让第三个答案（8–16.5 小时）无法改善，因为改善它需要一个"生成 → 比对 → 调参"的闭环。**

### 钢人反驳（我认真试过）

**辩护一：加一个 `npm run measure`（送 Claude API、拿复刻、算相似度）**不需要后端**，
只需要一个 key —— 所以"可测量"与"静态"不冲突，仓库只是没做。**
（这是上一份红队的反驳，我这里升级它：它是对的，而且成本极低。）

我的回应：**完全接受，而且这是我在这份报告里最想强调的一个"攻击自我坍缩"的地方。**
"静态"**不是一个物理约束**，它是一个**未被检验的取舍**。
仓库把它写成 virtue（README 用了 `[![Static-only](...)]` 徽章），
实际上它挡住的只有"后端"，而挡住产品闭环的是**没人写那个 measure 脚本**，
不是"没有服务器"。**这两件事被混为一谈了 91 个提交。**

**辩护二：`file://` 不能双击打开**这个限制（README:442，`mask-image` CORS）说明静态本身就是有代价的，
仓库已经付了价并且写清楚了。

我的回应：这是**同一面墙的另一块砖**，而且它证明了我的点：
为了保住"零依赖"，它接受了一个更严重的代价 —— **用户双击打开会看到页面坏掉**
（"5818 种颜色 vs 2 种颜色"）。一个为了纯度而接受"看起来像坏了"的产品决策，
只有在**纯度本身是产品**的时候才成立。而这里的纯度（零依赖）不是用户在买的东西。

## 8. 攻击八：「坦诚陷阱」—— 三处精确的记录，功能上是三处**免修证**

诚实在这个仓库里不是装饰，是**机制**：每一条限制都被记录到行号级，并给了"为什么不该修"的理由。
问题不是它不诚实，是**这个精度本身构成了一种停止条件**。我找了三处，每一处都能证明
「记录它」替代了「修它」。

### 第一处：`S13` 的 `empty-screens` —— 「余量很薄，属脆弱项」

**[源码]** `README.md:428`：

> 「该指标在最差屏是 **0.24**、阈值 0.20，**余量很薄**，无关扰动可能把它打回 FAIL，属脆弱项。」

这句话精确到小数点后两位，还给了因果（"余量很薄"）。**它读起来像尽职，功能上是弃权。**
一个 0.04 的余量意味着一件事：**这个案子的版心宽度选错了** —— 它要么牺牲行长（现在：42.7 汉字，
与 `_specs/S13.md` 字段 5 实质偏离），要么牺牲空屏率（余量 0.04）。
两个都是真实代价，而记录里说"两条都偏离规格一处，需产品判断"（`03f6fd4` 的 commit message 原话）。
**"需产品判断"= 一个 4 天做完 30 案的作者，在等一个不会来的产品经理。**

### 第二处：`09.15` 豁免表 —— 从「两条」长到「五行」

**[源码]** `_CONTRACT.md:194-201`。这张表的标题是
「**9.15 四条**对中文站结构性不利的规则」，正文却有 **5 行**（`mono` / `font-count` / `font-fallback` /
`measure` / `palette-terracotta`）。第 5 行是 2026-10-24 后补的，并且**自带一段自我说明**：
「此前 README 与『已知缺口』长期写『S08 琥珀是已知豁免，理由见 §9.15』，**而 §9.15 从来没有这一行**
——豁免被反复声称却从未落进允许表」。

**注意这里发生了什么：** 一个缺陷（S08 琥珀越界）本来应该被修或被拒。
它被**"补登记进豁免表"**处理 —— 于是它从一个 FAIL 变成一个 PASS，**代码一个字节没改**。
豁免表自己的注释诚实地记录了这次操作。**这是"精确记录"作为免修证的教科书案例：
它把一次"降低标准"写成了"补齐程序"。**

而 `ab02f43` 又给这张表加了一条更尖的自述：C5 断言实测 **「2/5 条只有 WARN 分支，豁免在逻辑上空转」**
—— 也就是说，五条豁免里有两条**豁免的东西根本不会 FAIL**。**一张豁免表，40% 的条目是空的，
而它的标题写着"四条"。**

### 第三处：`README.md:446` 的「80 分」

**[源码]** `README.md:446`：

> 一句自贬定位：**这是一个 80 分的标本库，不是 100 分的成品站。**
> （这两个分数是定位说法，**不是实测评分**——实测结论全在上面那 9 条里。）

括号里那句"不是实测评分"是全库最诚实的一句，也是最有用的一句免修证。
因为同一批工作里**有一个真实的分数**：

**[文档]** `60-diagnosis` 第 18 行（引用 56 席的盲测）：
> 「机械指标批均 8.15、**总监分 6.2/10**，且 30 案 CONS 极差仅 2.46、σ 0.64
> ——『最好与最差的差距，小于"及格"与"优秀"的差距』。」

**实测 6.2/10，自述 80 分。** 差 1.8 分（按 10 分制是 18 个百分点），
而这个差被"这两个分数是定位说法，不是实测评分"一句话合法化了。
**如果它写"实测 6.2 / 定位 8.0"，读者会问"为什么差 1.8"。写成"80 分（非实测）"，读者就不会问。**
这不是撒谎 —— 它明确说了不是实测 —— **这是用"声明的非实测"给一个比实测更高的数字上保险。**

### 三处的共同结构

| 处 | 记录了什么 | 记录替代了什么 |
| --- | --- | --- |
| S13 余量 0.04 | 「很薄，属脆弱项」 | 改版心宽度（取舍未定，等人拍板） |
| §9.15 五行豁免 | 「补登记，让引用变真」 | 拒掉 S08 的琥珀，或改工具窗口 |
| README 80 分 | 「不是实测评分」 | 用实测的 6.2 替换自述的 8.0 |

**这三处都不是"骗"，都是"精确"。** 而精确在这里的功能是：**把"还没做决定"包装成"已经交代清楚"。**
`60-diagnosis` 第 111 行自己写出了这个机制的名字（引用 58 席）：
**「停手前提：本轮阻断级新缺陷 0 条…所以：停止开新席，转修复。」**
诊断说了"转修复"，之后的 44 个提交里，`deliverables/` 涨了 135 份。

### 钢人反驳（我认真试过）

**辩护一：如果没有这些记录，情况只会更糟 —— 沉默的缺陷比记录的缺陷危险得多。
而且 `03f6fd4` 里 S13 那条是真的被修了（480→640px），代价也被如实标出。
"记录"和"修"不是互斥的，这个仓库两边都做了。**

我的回应：**这是本节最强的一条，我接受它作为对"审计剧场"整体指控的反驳，但不接受它对本节三处的反驳。**
三处的共同点是：**记录之后，改动停止了。**
- S13：改了（480→640），然后记录"余量薄"，**然后停在那里**，把剩余 0.04 留给"产品判断"。
- §9.15：**没改**，改成登记。
- 80 分：**没改**，改成加括号。

**"记录 + 修" 与 "记录 + 停" 的比例**，就是审计剧场的真实刻度。
按最近 22 个提交的宾语（§4 的表）：**7 个修、15 个记**。

**辩护二：一个个人项目没有产品经理，"需产品判断"是诚实的边界，不是借口。**
我的回应：**接受。** 但它反过来削弱了项目定位：一个连"版心 480 还是 640"都无法拍板的项目，
却在 README 里声称提供"完整的设计主张"，并生成 30 条"施工图"给 AI 执行。
**尺度不匹配**：对内的决定停在 0.04 的余量上，对外的输出却是 1931 字的确定性指令。

## 9. 攻击九（这一份最硬的）：`README.md:7` 与 `README.md:155` 之间，是**整份诊断的失败**

上一节说"记录替代了修"。这一节给一个可执行的检验：**诊断书点名要改的那一句，改了没有？**

### 证据

**[文档]** `60-diagnosis-what-feels-wrong.md:77`（§2.4，标题是「30 份完整设计主张不是真的」）：

> 「真正的病名…是 `README.md:115` 那句
> 『**它不是配色皮肤，而是一份完整的设计主张**』—— 配色层第 1 轮已认账，
> 这句把防线挪到了主张层，而**主张层这防线是漏的**。」

**[文档]** 同一份第 128 行，处方「重排」第 2 条：

> 「**30 案诚实定规模**：`README.md:115` 那句改为 52 给的诚实版本
> （「12 字段、22 种骨架、30 个不重复家族名；主张层约 23 条、**蒙名后 7 案不可替代**；
> 差异化真来源是骨架与材质，不是想法」）。」

**[复算]** 今天 HEAD 的 `README.md:155`：

```
**30 个设计方案**——它不是配色皮肤，而是一份完整的设计主张，12 个字段：
```

**逐字未改。**（`grep "它不是配色皮肤" → README.md:155`，与诊断前的文本相同；
行号从 115 漂到 155，是因为 T0 批次在它上面插了 40 行 —— 诊断书第 123 行自己预警过"行号是易腐引用"。）

而 52 席给出的诚实版本是：「**主张层约 23 条、蒙名后 7 案不可替代**」。
也就是说：**30 个方案里，把"美学家族名"和"骨架名"蒙掉之后，只有 7 个不可替代。**
这个数字在 README 的**任何**位置都没有出现（`grep "7 案不可替代" README.md` → 0 命中；
`grep "23 条" README.md` → 0 命中）。

### 这一条为什么比前面八条加起来更严重

因为前面八条都可以被"这是取舍"辩护，**这一条不能。**
它有一个**明确指定的动作**（改一句话）、一个**明确的替代文本**（52 席给的 7 案版本）、
一个**明确的理由**（诊断书 §2.4）、一个**明确的执行者**（作者本人，因为诊断书是他写的）。
成本：**改一行 README。**
结果：**44 个提交、135 份新报告、183 个文件之后，这一行没改。**

而这一行**恰恰是主标语「不是 30 张配色图」的兑现契约**：
- L7 说「30 个能跑的风格，不是 30 张配色图」（标语）
- L155 说「它不是配色皮肤，而是一份完整的设计主张」（论证）
- 诊断说：这个论证是**漏的**，请改成「7 案不可替代」
- 现状：论证原封不动，标语原封不动

**所以标语今天站在一个已经被自己的诊断书判定为不成立的论证上。**

### 钢人反驳（我认真试过）

**辩护一：诊断书说的是"降级为诚实版本"，而 `README.md:444` 已经有一条自贬
（「80 分标本库，不是 100 分成品站」）+ 第 429-434 行九条 ❌。读者读到的是完整的图景。
一句话没改不等于结论没披露。**

我的回应：**"披露在别处"与"论证是错的"是两件事。** L155 是一个**正面论证**，
读者读它时不会先读 429 行。而它**被作者自己的诊断判定为假**。
一个**正确的**页面会写「12 字段、22 骨架、7 案不可替代」——那仍然是一个好卖点，
甚至更可信。**它没改，不是因为改了会变差，是因为改它需要承认"30 份设计主张"这个卖点是虚的。**

**辩护二：也许"主张层约 23 条"这个数字后来被证伪了，所以没有采纳。**
我查了：`deliverables/60-diagnosis` 之后没有任何文件推翻 52 席的 23/7 结论。
相反，`03f6fd4` 的 commit message 引用了同一批结论（"机械判据 91.5%、视觉相似度 0.490"），
说明诊断的方法论被继续使用。**没有证据表明这个数字被撤回。**

**辩护三（我替它想的最强一条）：改 README 的一句话，会让 30 案的"设计主张"叙事塌掉，
而那正是这 30 个原型的**卖点**。如果写"7 案不可替代"，用户会问"那另外 23 个是什么"。
沉默比诚实更利于转化。**

我的回应：**这条辩护如果成立，那它就不是辩护，是自认。**
一个"对自己诚实的标本库"，其全部价值建立在"它告诉你的比渲染图多"（README:26-28）。
如果它在**最关键的那一句**上选择了转化率而不是准确度，
那么它和它批评的"渲染图"是同一类东西：**都给你一个看起来比实际更完整的门面。**
**这正是诊断书 §3 的裁决 C：不是假货，是贴错标签。而贴错标签的那张标签，就是 README:155。**

---

**[补一条]** 这句话在**英文版也一模一样**（`README-EN.md:155`）：
`**30 design schemes** —— not a colour skin but a complete **design argument**, written across 12 fields:`
而 `check-docs.mjs` 有一条断言叫 `i18n/facts`，专门查"中英两版的关键事实一致"——
**它会把这条错误判成 PASS**，因为两边错得一样。
（`check-docs.mjs:820-848` 实测的逻辑：`i18n/facts` 只核五组事实 —— 方案数 / 达标数 /

所以两边错得一样时必然全绿。「是不是配色皮肤 / 是不是完整设计主张」**不在这五组里**。）
这是一个**完整的自证结构**：诊断说这句话是假的 → 这句话中英同步保持原样 → 双语一致性闸门判绿。

## 11. 如果只能修一条，不修就白做的是哪一条

**不是 §9 的 README:155，也不是 §3 的机制句假数字。是这一条：**

### **给提示词的「签名机制」建一条机械闸门 —— 一个把 `dna.mechanism` 的每个带单位数字
回 `style.css` + `index.html` 校验的脚本（约 60 行），并把 S03 的「9 栏/焦距」、
S07 的「5 栏/7 栏」、S17 的「96px」当场判红。**

### 为什么是它（三条理由，按强度排）

**一、它是唯一一条"用户拿到的东西是错的，且用户无法察觉"的缺陷。**
其他所有缺陷（暖色同质、余量 0.04、LICENSE 三个数、散文 205 份）都是**仓库内部**的问题，
或者**读者能用自己的眼睛发现**的问题（打开页面就看到是暖色）。
而提示词是**一次性的、不可复核的交付物**：用户复制它、粘给 AI、AI 做出一个 12 栏的观测站、
用户看着有点怪但不知道为什么 —— **他没有第二个信源可以对照**。
仓库给了他 1931 字，其中 6.8% 的数字是错的，**而他被明确告知这些字是"实测抽取"的**。

**二、它把一个已经付过代价的教训，变成了唯一没被制度化的那一条。**
`03f6fd4` 花了 62 个文件、9062 行，就是为了查明"S07 的 5 栏/7 栏是错的"，
并在 `prompt-copy.js` 里留下了完整的事故记录。**然后没有为这件事写一个 check。**
七个 check 脚本里，`check-prompts.mjs` 保护配色/线宽/字号/圆角/阴影，
`check-docs` 保护文档数字，`check-contract` 保护豁免表，
**没有一行代码保护那句"这个风格是什么"。**
这不是能力问题 —— 是**"机制句被当成文学描述，而不是数据"** 这个分类错误的直接后果。

**三、它是唯一一条修完之后，能让整个"实测抽取"的卖点重新成立的。**
现在 README:80 那句「它不是套话，是从各案 `style.css` **实测抽取**出来的」
在**一个案子上是假的**（S03），在另外两个上是**半真的**（S07/S17）。
修完之后，这句话才有资格保留。**而它一旦被闸门守住，"实测抽取"就从一句声明变成一条可复算的事实** ——
这是这个仓库唯一一个可以真正兑现给用户的承诺。

### 为什么"不修它，别的都白做"

因为**提示词是这个项目唯一的产出物**。
30 个原型是**论据**（证明这个风格能跑），选型台是**目录**，205 份报告是**审计记录**。
用户带走的东西只有一样：**那 1931 个字**。
如果那 1931 个字里有 3 个案子在描述原型里不存在的东西，
那么这个库的**全部说服力**（"我真的做了 30 个，所以我知道这个风格该怎么做"）
在交付的那一刻就断了 —— **用户拿到的还是"一段听起来很专业的描述"，只是更长、更贵。**
主标语说「不是 30 张配色图」。**如果提示词把配色图 + 一句错的骨架描述交给 AI，
那么对用户而言它交付的正是"配色图"。**

## 12. 这个项目最值得做下去的理由（我认真找过，不是客套）

**它造出了一件这个生态里确实稀缺的东西：一份把"风格"从形容词变成可执行数字的语料。**

具体到能指认的三件事：

**（一）`dna` 这一层是真的、且别人没有的。**
30 案 × `{palette（带角色名）, fonts（display/body/mono + 完整兜底链）, radius, shadow, lineWidths,
h1SizeAt1440, mechanism, degrades, minItems, minPics, risk, reuse}` —— 这不是从设计稿里能猜出来的，
是**逐案量 CSS 量出来的**。`ab02f43` 修掉的那个细节最能说明它的价值：
`palette[0]` 的顺序不稳定（主色 16/30、底色 7/30、其它 7/30），
用规格字段 3 的面积百分比裁判，**它真正是最大面积色的只有 12/30**。
**这种"看起来对、实测才知道错"的知识，是这 91 个提交真正挣到的东西**，
而且它以 `prompts.js` 的注释形式**永久留在了代码里** —— 下一个做同类工具的人可以直接拿去用。

**（二）「反 AI 味」这套法典是被外部证据支持过的，不是品味。**
`02-anti-ai-rules.md` 的 R-07（Inter/Roboto/Arial 黑名单）、R-08/R-09、
以及 `prompt-copy.js:701-724` 引的 arXiv 2601.08070（"命名即加权"，87.5% 违规发生在点名被禁词时）
—— 这套"把负向禁令改写成正面唯一解"的方法，**在 30 条提示词上是可验证地执行了的**
（`prompt-copy.js` 里每条改写都附了原句、改写理由、信息量不变的验收）。
**这是全库最可移植的资产**：它不依赖这 30 个风格，任何写 prompt 的人都能用。

**（三）它证明了"一个人 + 一群 agent 在 4 天里能造出什么"，也证明了这件事的上限在哪。**
`caefdd9` 第一次提交 33,315 行产品代码、30 个能跑的原型。
这个产量本身是**一个可复用的方法论证据**（多 agent 编排能产出什么、产出物的同质化边界在哪、
闸门化的自证会怎样失控）。`60-diagnosis` 把这条上限写出来了，而且写得很准（6/10、边际 < 1 分）。
**知道自己上限在哪的项目，比不知道自己上限的项目活得久。**

### 一句话

**它的问题不是它做错了什么，是它做对的那些东西（`dna`、法典、闸门方法论）没有一条被接到了
用户唯一会带走的那 1931 个字上。**
把闸门接到提示词上（§11），这个项目就从"一份 80 分（自述）的标本库"
变成"一份可复算的风格语料"—— **后者才是它一直在做的事，也才是它值得做的事。**

## 附录 B：三处口径的自我限定（防止下一份红队再踩）

1. **「9 栏」的攻击对象是机制句，不是 CSS。** S03 的 CSS 注释确实写了「12 栏，左 3 栏…右 9 栏」

   我攻击的是：**这段"规格意图"被当成"实测"写进了用户复制的提示词**（`prompts.js` 的
   `mechanism` 字段，`dna` 层的其余字段确实都是实测的）。这个区别很重要 ——
   它意味着修复方向不是改注释，是**给机制句标来源**（实测 / 规格意图 / 作者原话），
   或者干脆按实测重写。
2. **「两簇」的判据是明度，不是色相。** 8 暗 / 21 浅 / 1 中 是按 `palette[0]` 的 HSL L 分的。
