# 撤回：S08 的「768 断点缺失」是假阳性

2026-10-31 · 由 P3 锐评 Agent 打穿，Lead 核实后撤回

---

## 1. 我原来报的是什么

在 `deliverables/73-exec/LEAD-P3-spec-conformance.md` §2 里我写：

> ### S08 是真偏差
> 规格说「<768px 转垂直堆叠」，实际是「<640px 才转」。
> **641–767px 区间**落在规格没有定义的区域——它会沿用 1023px 的规则，
> 即仍是等距横向布局，而不是叠加。

并把它标为本轮「唯一确凿的发现」。

## 2. 为什么这是错的

### 错在第一步：我编了一个规格里不存在的档

我读规格时把「1024–1439px」这一档的下界当成了「1023 以下还有独立一档」，
于是在报告里写出了四档：`<768` / `768–1023` / `1024–1439` / `≥1440`。

**规格只有三档。** 原文（`_specs/S08.md` 字段 5）：

```
≥1440px 六块板全显并保留右侧 220px 的工艺参数栏
1024–1439px 折为四块板、层间距压到 16px、参数栏并入底部
<768px 等距轴转为垂直堆叠
```

`<768` 与 `1024–1439` 之间的 **768–1023 是规格的空档**，不是我理解的一个"档"。

### 错在第二步：我没读 1023 块的 CSS 内容

我只看了 `@media` 的**条件**（`max-width: 1023px`），没有看它**改了什么**。
实际内容（`style.css:277-291`）：

```css
@media (max-width: 1023px) {
  .two-col { grid-template-columns: minmax(0, 1fr); }
  .iso-stage { height: auto; perspective: none; }     ← 等距透视关掉
  .iso-plane { position: static; }                     ← 平面回文档流
  .plate {
    position: static; width: auto; height: 54px; ...   ← 板变成普通块
    transform: none; animation: none;                  ← 位移与动画全取消
  }
  ...
}
```

**这就是「等距轴转为垂直堆叠」。**

### 错在第三步：方向搞反了

规格要求 `<768` 就堆叠，CSS 实际是 `<1024` 就堆叠。
**这是超集，不是遗漏**——641–767 早就已经是堆叠态了。

我却在报告里写「641–767 仍是等距横向布局」，把 1023 规则的内容**整个说反**。

## 3. 锐评 Agent 的无头实测

它用 Chrome 无头跑了 9 档宽度（`deliverables/73-verify/_p3out/s08-stack-probe.mjs`）：

| 宽度 | 状态 | 板的几何 |
|---|---|---|
| 500 | 堆叠 | 54px |
| 608 | 堆叠 | 54px |
| 668 | 堆叠 | 54px |
| **728** | **堆叠** | **54px** ← 我声称这里是等距横向的那个宽度 |
| 852 | 堆叠 | 54px |
| 992 | 堆叠 | 54px |
| 1008 | 堆叠 | 54px |
| 1388 | 等距 | 300px |
| 1408 | 等距 | 300px |

**分界正好在 1023/1024**，与 CSS 的 `@media` 条件一致。728px 落在 641–767 区间内，实测是堆叠。

## 4. 后果：如果我按原结论去改，会造成什么

我原计划把 `max-width: 640px` 改成 `767px`。实际会发生：

- 641–767 区间**从"堆叠"变成"仍是堆叠"**——因为真正让它堆叠的是 1023 块，不是 640 块
- 改动**不改变任何视觉结果**，但会：
  - 扰动一个已经取证、已有 2 条 FAIL 的案（S08）
  - 让 S08 的 `report.json` 与截图需要重新生成
  - 在 641–767 这个**没有截图基线**的区间引入未验证状态
- 最糟的是：它会掩盖真正该看的东西——`max-width: 640px` 那一块到底在做什么

## 5. 顺带查清 640 块的作用

`style.css:267-276`：

```css
@media (max-width: 640px) { ... }
```

它是 1023 之后**再收一档**（更窄的手机），不是"堆叠的起点"。堆叠早在 1023 就发生了。

## 6. 教训

**「@media 的条件在不在」和「@media 改了什么」是两件事。**

我只做了前者（正则抽 `min-width|max-width` 的数字），就下了「区间落在未定义处」的结论。
而真正的语义在后者——`perspective: none` 这五个字符才是"垂直堆叠"的证据。

这与本仓库 §9.15 那条自述是同一个病：**静态计数 ≠ 运行时判据**。
那里是"17 处 box-shadow ≠ 17 处违规"，这里是"缺 768 这个数字 ≠ 缺 768 这个行为"。
