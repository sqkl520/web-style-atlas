## 指控 1：D5「16 栏放 12 块每块最小 2 栏」是误读 —— ✅ 成立

### 上一轮的原始论断（`deliverables/69-test/REPORT.md`）

> D5 是**纯算术反证**：「16 栏放 12 块，最大 7 栏最小 2 栏」——`12 × 2 = 24 > 16`，不可能满足。这不需要跑浏览器。被标为「**必修**」。

### 实测：S28 的 CSS 注释直接否定了这个前提

`prototypes/S28-jazz-intaglio-wall/style.css:457-463`：

```css
/* 图版栅格：每张给死栏位（start / span）。两行分别 7+5+4 与 4+5+7，宽窄不重复 */
.plate--p1 { grid-column: 1 / span 7; }
.plate--p2 { grid-column: 8 / span 5; }
.plate--p3 { grid-column: 13 / span 4; }
.plate--p4 { grid-column: 1 / span 4; }
.plate--p5 { grid-column: 5 / span 5; }
.plate--p6 { grid-column: 10 / span 7; }
```

**`7 + 5 + 4 = 16`，每行恰好 16 栏，共两行。**

### 规格原文也从未说「12 块在同一行」

`prototypes/_specs/S28.md` 字段 5：

> 不对称方式：12 块拼贴面积不等（最大一块占 7 栏，最小一块占 2 栏），每块的裁切边各自错位 4–14px

只说「12 块面积不等」，**没有任何「同一行」的表述**。

### 结论

`12 × 2 = 24 > 16` 这个反证，**只在「12 块全部排在同一行」这个假设下成立**。而这个假设是推断出来的，不是文本里的。

**这是上一轮最严重的一个错误结论**：它被标为「必修」，如果照着改，会把本来正确的 S28 改坏。

**修正**：D5 应降级为「已验证不成立」，并留档防止下一个 Agent 重蹈。

## 指控 2：`check-docs` 对提示词内容零反应 —— ✅ 成立，我做了受控 A/B

### 实验设计（`LEAD-ab-checkdocs.mjs`）

1. 备份 `prompts.js`
2. 跑一次 `check-docs.mjs`，记录完整输出（基线）
3. 把 `prompts.js` 里 S19 的主色 `#4A5C3A` **篡改成 `#FF00FF`**
4. 再跑 `check-docs.mjs`，逐行对比
5. 恢复备份，验证 `git status` 干净

### 结果

```
基线   exit=0   PASS 11 / FAIL 0 / WARN 1
篡改后 exit=0   PASS 11 / FAIL 0 / WARN 1

新增的行: （无）
消失的行: （无）
```

**13 条断言逐字相同，包括 `nums/prompt-len`（提示词长度）这一条也没变——因为只改了色值，没改长度。**

而用户复制到的提示词，主色已经变成 `#FF00FF`（荧光品红）。

### 这意味着什么

**30 条提示词重生成完全没有保护。** 任何改动提示词内容的操作：
- 改错了 → `check-docs` 绿
- 改对了 → `check-docs` 绿
- 改出语法错误 → 可能连 `prompts.js` 都加载失败，但 `check-docs` 读的是文件文本不是运行时

### `check-docs.mjs` 的真实覆盖范围

它校验的是 **README 文档与数据的一致性**（方案数、达标数、场景词数、提示词长度区间…），**不是提示词内容本身的正确性**。

`nums/prompt-len` 那条只校验长度落在 1639–1998 区间、中位 1829——它管的是「文档里写的长度对不对」，不是「提示词内容对不对」。

### 这是本轮的 P0

批判 Agent 的建议顺序是对的：

1. **先建 P0 闸门**（秒级、30/30、独立来源对账）
2. 再改数据

因为：**没有尺子的时候，改数据等于盲改。**

### 三处需要我裁决的实质分歧

**分歧 A：配比该不该补**

- 我说「不能补」，理由是规格声称 41.6% 实测只有 1.4%（虚报 30 倍）
- 批判 Agent 说「该做」，理由是**规格 29/30 明写面积和 100，而 `dna-clean.json` 全文无 `pct/area/ratio/share` 字段**——提示词丢了一整类信息
- **两边都对，说的是不同的事**：我说的是「规格的百分比数值不可信」，它说的是「配比这个维度整类缺失」

**裁决**：批判 Agent 更准。我的「虚报 30 倍」是拿规格数值 vs 像素实测比，但**规格写的是设计意图，本来就不该等于渲染实测**。真正的问题是：**提示词应该传达「主色是视觉主导」这个关系**，而不是具体百分比。

**分歧 B：色板该不该补 11 色**

- 规划 Agent：补 11 色（ΔE≥3 且墨迹≥5%）
- 我：0 个真违规
- 批判 Agent：只有 12 个真新色相 / 7 案

**裁决**：三者的差异在判据严格度。规划 Agent 的「墨迹占比」判据最硬（一个色画了 30% 的字，它就是正文色）。但它把「同色相派生」也算进 MISSING 了。批判 Agent 的「真新色相 12 个」最接近我的判断。

**需要进一步核实这 11 色里有多少是「同色相派生」vs「真新色相」。**

**分歧 C：字号做不做**

- 我：改成补对比度比例
- 规划：抽 h1+正文+倍率+档数
- 批判：不做（+458 条约束）
- 检索：零证据

**裁决**：批判 Agent 的证据最硬（+458 条 = +35% 约束量，而 CSE 研究显示 20 条已在崩塌区）。但**`h1Size` 进提示词 0/30 是客观缺口**。

**折中方案**：只加 **1 条**约束（「最大标题是正文的 5–7 倍」），不加字阶表。这样 +1 条而不是 +458 条。
