## 根因链

### 第一层：`_prompts/` 数据链落后 3.5 天

| 文件 | 最后提交 | 日期 |
|---|---|---|
| `dna-raw.json` | `cea8436` | 2026-10-26 04:45 |
| `dna-clean.json` | `87a0235` | 2026-10-26 21:16 |
| `prompts.js` | `a56426e` | 2026-10-27 03:06 |
| 4 案的 `style.css` | `03f6fd4` | **2026-10-29 17:10（今天）** |

**`dna-raw.json` 比 S13 的 `style.css` 旧 5065 分钟（3.5 天）。**

受影响：**4/30 案** —— `S07`(4天) `S13`(4天) `S18`(1天) `S21`(4天)。

### 第二层：`check-stale.mjs` 不覆盖这条链

上一轮我刚给 `check-stale.mjs` 加了「产品入口」检查（`_entries.mjs`），让它管到了 `_selection/`。但它**仍然不知道 `_prompts/` 下的三个产物也依赖 `style.css`**。

**这是同一类缺陷的第二次出现**：

| 轮次 | 遗漏的东西 | 后果 |
|---|---|---|
| 第 69 轮 | `_selection/.inspect/report.json` 冻结 6 天，无检查器覆盖 | 闸门谎报 FAIL 0 |
| 第 70 轮（本轮） | `_prompts/dna-raw.json` 落后 3.5 天，无检查器覆盖 | 提示词数据基于旧 CSS |

**模式完全一样：生成物没有陈旧度守卫。**

### 第三层：`extract-dna.mjs` 不剥注释

`extract-dna.mjs:55`：

```js
for (const m of css.matchAll(/font-family\s*:\s*([^;}]+)/g)) {
```

**完全不剥 CSS 注释**（`clean-dna.mjs:43` 才剥，已在上游之后）。于是上一轮我为修 mono 问题写进 `S07/S13/S21` 的注释被当成字体名吞进来：

```
⚠ "monospace（Chrome 实测，见 deliverables/69-exec/EXEC-mono-empty.md §2.3），
   下面把这条与其余可能因引擎而异的默认值一并还原成继承值：换标记，不换排版。 */
code{fo"
```

S07 还有第二处：

```
⚠ "IBM Plex Mono\" /* taste-skill-ignore: 字段4 辅助数字，只用于页码/辑号/归档号 */"
```

**这是上一轮我自己造成的事故**：我往 `style.css` 里写了带 `font-family` 字样的注释，上游抽取器把它当数据了。

### 为什么 `prompts.js` 仍然一致

脏值只落进 `dna-raw.json` / `dna-clean.json`，而 `build-prompts.mjs` 不消费 `families`（它读 `fonts.display/body/mono`）也不消费 `shadowDetail`。所以下游产物恰好没被污染。

**这是运气，不是设计。**

## 一个值得记的模式

**这是连续第二轮出现「生成物无陈旧守卫」的同类缺陷。** 第 69 轮是 `_selection/.inspect/report.json`，本轮是 `_prompts/*.json`。

两者的共同点：
- 都是生成物（不是手写）
- 都被 git 跟踪（所以看起来"有版本"）
- 都依赖会变的源文件
- 都不在任何检查器的视野里

**建议**：给 `check-stale.mjs` 做一次系统性扩展，把所有"生成物 → 源文件"依赖都登记进去，而不是每次发现一个补一个。
