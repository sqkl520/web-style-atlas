## 我踩到的 5 个测量坑（每个都有对照证据）

这一节比结论更重要——前几轮同类结论反复出错，根源都在测量方法。

### 坑 1：静态扫文件会把「文字里提到的色」当成「使用了该色」

第一版我扫 `index.html` + `style.css` 的 hex 文本，报出 S28 有 `#A855F7`（Tailwind 紫）和 `#EC4899`（Tailwind 粉）。核查上下文：

```html
<p>...离开 UI 蓝 <code>71°</code>、离开 <code>#A855F7</code> <code>17°</code>、
离开 <code>#EC4899</code> <code>42°</code>。</p>
```

这两个色是**正文里写出来说明「我们的紫离 AI 默认紫粉有多远」的文字**，根本没画在屏幕上（`S28` 渲染实测只有 6 个色，不含它们）。

同一类误报还有：S19 的 `#dd0077` / `#dd1122` / `#ccaabb`——源码里完全不存在，是我第一版正则匹配了 `.md` 报告的残留。

**修正**：改用 CDP 真浏览器 `getComputedStyle` 采样，只统计真的画在元素上的颜色。

### 坑 2：`rgba(..., 0.5)` 被我截断成不透明 hex

第一版颜色解析把 `rgba(255, 244, 214, 0.5)` 按前三个分量转成 `#FFF4D6`，报 S08 有一个「100% 饱和度的浅黄新彩色，12 个元素」。

实测真相：

```
div.plate-glint.top   backgroundColor=rgba(255, 244, 214, 0.5)
div.plate-glint.left  backgroundColor=rgba(255, 244, 214, 0.5)
```

这是**玻璃板边缘的高光**，50% 透明叠在琥珀底上，最终像素颜色不是 `#FFF4D6`。

**修正**：解析颜色时必须保留 alpha；alpha < 1 的颜色不按 hex 计入色板，单独统计。

### 坑 3：`#000000` 是浏览器默认值，不是有人画的

29/30 案都「渲染出」`#000000`。核查源码：只有 S26 显式写过 `#000000`（`drop-shadow(1.2px 1.2px 0 #000000)`）。

其余 28 案是 `getComputedStyle` 在未设置颜色的属性上返回的默认值（`border-color` 默认为 `currentColor` 之外的初值、`text-decoration-color`、SVG 未设 fill 等）。

**修正**：先做「源码是否显式写过」的反查，只保留源码里存在的色。

### 坑 4：我的正则 `\b#` 在反引号后不匹配

第一版判「规格文件里一个 hex 都没有」（30/30 全 0），由此差点得出「规格不是色板来源」的错误结论。

真相：规格里 `#EFE7D7` 写作 `` `#EFE7D7` ``，反引号和 `#` 之间没有 word boundary。

**修正**：用 `#([0-9a-fA-F]{6}|[0-9a-fA-F]{3})(?![0-9a-fA-F])`，不加 `\b`。

### 坑 5：规格字段 3 有两种书写格式

| 格式 | 案 | 样例 |
|---|---|---|
| 同行 | S01–S10 | `3. 配色系统：\`#C1121F\` 朱红专色＝主色，14%...` |
| 标题换行 | S11–S20 | `**3. 配色系统**` 然后下一行正文 |
| 标题后同行 | S21–S30 | `3. **配色系统**：主色 \`#3E3A34\` 占 42%...` |

只处理格式 1 时，20/30 案解析失败，得出「字段3 解析不出声明 20 案」的假结论。

## 三层颜色数据的真实关系

```
层1  规格字段3 声明      121 个色   Σ=100%   设计决策，通常 3–5 个
层2  dna-clean.palette  167 个色            从 :root CSS 变量抽，含派生色
层3  渲染实测            253 个色            真正画在屏幕上的
```

关键：**层2 不是从层1 抽的**。

- `S01`：层1 4 个 = 层2 4 个 ✓（一致）
- `S19`：层1 5 个 → 层2 7 个（多了 `#D8CFB6` `#E9E3D2` `#3A3227` 三个派生纸色）
- `S25`：层1 4 个 → 层2 6 个
- `S14`：层1 4 个 → 层2 6 个

`clean-dna.mjs:510` 的 `pickPalette()` 从 `:root` 变量里挑，上限 7 个。所以**提示词色板 = CSS 变量表，不是规格声明**。这是设计上合理的（提示词要能指导实现，CSS 变量才是实现用的），但意味着「提示词漏了规格的色」这个判据本身用错了。

层1 声明但层2 缺的只有 6 个，且全是负向示例或旧值：

| 案 | 色 | 真相 |
|---|---|---|
| S13 S15 S16 S19 | `#6366F1` | 规格里写的是「反的是 `#6366F1`」——**负向示例**，本来就不该进色板 |
| S24 | `#6E8B7A` | 层3 实测渲染 80 个元素，但层2 `pickPalette` 没收录（**这是真 bug，抽取漏了**） |
| S26 | `#3B82F6` | 规格里是「反 `#3B82F6` 那一类默认蓝」——负向示例 |

## 53 个超纲色的分类

判据：
- **GRAY**：HSL 饱和度 ≤ 12%，近中性灰
- **DERIVED**：与某个 palette 色色相距离 ≤ 10° 且饱和度差 ≤ 22，即同族深浅派生
- **CHROMA**：无同族来源的新彩色

提示词原文（`prompt-copy.js:442`）：

```js
"1. 配色只用这几个值：" + d.palette + "。不新增更多彩色。",
```

**关键词是「彩色」**。灰阶深浅和同族明度派生不构成「新增彩色」。

### 灰阶 / 同族派生（47 个，21 案）— 不算违规

典型例子：

| 案 | 色 | 元素 | HSL | 派生自 |
|---|---|---|---|---|
| S19 | `#5E5443` | 103 | 38°/17%/32% | `#E4DECD`（纸色，色相差 6°）|
| S19 | `#534C3E` | 54 | 40°/14%/28% | `#E4DECD` |
| S19 | `#A79C82` | 45 | 42°/17%/58% | `#E4DECD` |
| S06 | `#5A3A1C` | 114 | 29°/53%/23% | `#85572A`（色相差 1°）|
| S15 | `#C3C9C7` | 133 | 160°/5%/78% | 近中性灰 |
| S30 | `#2B2B2B` | 467 | 0°/0%/17% | 纯灰 |
| S25 | `#4A423A` | 120 | 30°/12%/26% | 近中性灰 |

S19 的 `#5E5443` 最能说明问题。它在 `style.css:61` 是：

```css
--ink2: #5E5443;      /* 次级墨（小字） */
```

注释明确写着「对纸底 5.53:1」——**它是为满足 AA 对比度而算出来的次级墨色**，不是新加的设计色。把它补进提示词色板反而是错的：提示词应该说「次级文字用主墨色压到 5.5:1」，而不是给一个固定 hex。

## 我发现的真 bug（比「补色板」具体）

### Bug 1：S09 与 S21 的 skip link 用了浏览器默认蓝

30 案都有 `.skip` 规则（跳转链接，Tab 聚焦时出现）。但只有 S09 和 S21 **没有 `a { color }` 规则**，于是浏览器用默认色 `#0000EE` 渲染。

验证：
```
S01  skip规则=true  a{color}=false   ← 但 S01 渲染没有 #0000EE
S09  skip规则=true  a{color}=false   ← 渲染出 #0000EE(3)
S21  skip规则=true  a{color}=false   ← 需单独确认
其余 25 案 a{color}=true
```

S01 虽有 skip 但没暴露 `#0000EE`，可能被其它规则覆盖；S09 未覆盖。这是**用户按 Tab 会看到的、与风格完全不符的蓝色链接**——比补色板更值得修。

### Bug 2：S24 的 `#6E8B7A` 抽漏

层1 声明有、层3 渲染 80 个元素（`svg-stroke`），但层2 `pickPalette` 没收录。这是 `clean-dna.mjs:510` 的抽取上限（7 个）或挑选逻辑导致的真遗漏。

### Bug 3：`h1Size` 2/30 未解析

`dna-clean.json` 里 S01、S09 的 `h1Size` 仍是 `"var(--fs-h1)"` 字面量。（已派执行 Agent A 处理）

## 对「补进提示词」决策的影响

用户已裁决「补进提示词（改数据，30 条重生成）」。基于以上实测：

| 原设想 | 实测后 | 建议 |
|---|---|---|
| 补 55 个集合外颜色 | 53 个里 47 个是灰阶/派生，不该补；5 个是对比度派生；0 个真违规 | **不补**。改为在提示词里加一句「次级文字/状态色按对比度派生，不受色板限制」 |
| 补 S24 的 `#6E8B7A` | 是真遗漏 | **补**（1 个） |
| 修 S09/S21 skip link 默认蓝 | 真 bug | **修**（改原型 CSS，1 行） |

**核心判断**：提示词的配色约束本身是对的，问题在于**约束的边界没写清**——它没说明「同一色相的明度派生」和「为对比度派生的状态色」是允许的。AI 读到「只用这几个值」会不敢派生任何色，从而做出扁平、无层次的页面；而参考原型自己大量使用派生色。**这是提示词与原型之间的表达不一致，不是数据错误。**
