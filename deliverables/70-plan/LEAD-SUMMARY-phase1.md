## 一、色板：「20/30 案超纲」这个前提基本不成立

### 严格测量结果

| 判据 | 数 |
|---|---|
| 渲染出「有份量的超纲色」（≥3 元素） | 22/30 案，53 个色 |
| 其中**灰阶或同族派生** | **47 个** |
| 其中无同族来源的「真彩色」 | 6 个 |
| 这 6 个里是半透明叠加（不是实色） | 1 个 |
| 这 6 个里是为满足 AA 对比度派生的状态色 | 5 个 |
| **真正属于设计违反的** | **0 个** |

### 提示词原文（`prompt-copy.js:442`）

```js
"1. 配色只用这几个值：" + d.palette + "。不新增更多彩色。",
```

**关键词是「彩色」。** 灰阶深浅和同色相明度派生不构成「新增彩色」。

### 最典型的例子：S19 的 `#5E5443`（103 个元素）

它在 `style.css:61`：

```css
--ink2: #5E5443;      /* 次级墨（小字） */
```

注释明确写「对纸底 5.53:1」——**这是为满足 AA 对比度算出来的次级墨色**，不是新设计色。把它补进提示词色板反而错：正确写法是「次级文字用主墨压到 5.5:1」，而不是给一个固定 hex。

### 5 个「真彩色」全是同类

| 案 | 色 | 真相 |
|---|---|---|
| S24 | `#3C5F48` | `--moss-2` 注释：「对最深的浅底 `#C9D8E4` 也有 4.94:1」 |
| S12 | `#FF9AAB` | `.log-line.is-error` 错误态，注释：「对底实测 8.08:1」 |
| S15 | `#F0E4D8` | `.strip__item--fault` 故障态 |
| S16 | `#FFF2E9` | `.state-error` 错误态，注释：「对朱红 5.11:1」 |
| S08 | `#FFF4D6` | 实为 `rgba(255,244,214,0.5)` 半透明高光 |

### 真正的判断

**提示词的配色约束本身是对的，问题在边界的表述没写清**：它没说「同色相明度派生」和「为对比度派生的状态色」是允许的。

AI 读到「只用这几个值」会不敢派生任何色 → 做出扁平、无层次的页面。而参考原型自己大量使用派生色。

**这是提示词与原型之间的表达不一致，不是数据错误。**

## 二、字号：「补字号」的论证被推翻了一半，但换了个靶子

### 原论证

> 提示词从不给字号（29/30 缺失），所以 AI 不知道标题该多大 → 补上就好。

### 实测：复刻的档数并不少

| 案 | 原型档数 | 复刻档数 | 原型 H1 | 复刻 H1 |
|---|---|---|---|---|
| S20 | 6 | **7** | 72px | **19px** |
| S21 | 7 | **6** | 86px | **26px** |
| S28 | 9 | **8** | 92px | **44px** |

**档数比 1.17 / 0.86 / 0.89——不是"只用 2–3 档"，是接近原型的。**

### 真正缩水的是排版对比度

我排除了「复刻内容少所以字号小」这个混淆因素。S21 是最好的对照：

| 指标 | 原型 | 复刻 | 比值 |
|---|---|---|---|
| 每屏字符 | 576 | **554** | **0.96** ← 密度几乎相同 |
| 正文字号 | 16px | 12px | 0.75 |
| **最大/正文比** | **5.38** | **2.17** | **0.40** |

三案的最大/正文比全线崩：**5.54→1.58（0.29×）、5.38→2.17（0.40×）、7.08→3.67（0.52×）**。

**复刻实现者不是"不知道该分几档"，是"不敢用大字"。**

### 30 案真实字号数据

| 指标 | 值 |
|---|---|
| 档位数 | min=5，**中位=8**，max=9 |
| H1 字号 | min=56，**中位=81**，max=107px |
| 正文主导字号 | 13px 或 16px（二者占 26/30 案的绝对主导）|

### 修正后的做法

| 原计划 | 应该改成 |
|---|---|
| 补 6 档字号表（"13/16/17/22/34/72"） | 补**排版对比度**（"最大标题是正文的 5–7 倍"）|

**理由**：复刻内容量只有原型 9–23%，抄 absolute 尺寸会导致大标题挤压内容。比例关系才可迁移。

**证据强度要诚实**：「复刻对比度显著低于原型」是 n=3 实测（B 级）；「补对比度信息能改善」**未经验证**。

### 顺带更正一个既有错误

既有说法「复刻只有 2.3 档字号」**是错的**，实测是 6–8 档。它可能来自「字号分布相似度 0.03」的误读——那个指标算分布相似性，不是档数。

## 三、配比：规格里的百分比虚报 **30 倍**

### 决定性对比

| 案 | 规格声称 | 真实像素实测 | 差距 |
|---|---|---|---|
| **S16** | 主色 `#C52C0F` **41.6%** | **1.4%** | 虚报 **30 倍** |
| **S21** | 主色 `#3E3A34` **42%**、背景 34% | 背景 **85.3%**、主色 **11.4%** | 主色虚报 3.7 倍 |
| **S07** | 背景 `#E7E7E0` **56%** | **90.2%** | 少报 1.6 倍 |
| **S25** | 主色 `#914A27` 26% | **10.6%** | 少报 2.5 倍 |

### 而且规格的百分比本身在混用多种含义

11/30 案的声明面积和 ≠ 100%（S16 是 123.8%、S26 是 121.7%）。

原因：规格字段 3 里混着「色相 44.3°、饱和 10.1%、明度 84.9%」这些 **HSL 分量**，和真正的面积占比共用百分号。

### 真实规律：单底色 + 极少量强调

top8 像素覆盖 ≥90% 的 8 个案，主导色占比全部在 **67–92%**：

```
S07 90.2%  S08 88.4%  S10 89.0%  S12 67.4%
S16 92.2%  S17 79.4%  S21 85.3%  S25 73.6%
```

**这与「主色 60/30/10」的经典说法根本不同**——这些设计是「一个底色铺满 + 极少量强调」，不是三色均衡。

### 结论：配比这件事先别做

理由：
1. 现有数据源（规格）虚报 30 倍
2. 真实像素占比口径未定（首屏/全页/含不含照片）
3. 检索 Agent 查到「60-30-10」在 AI 生成场景**零证据**，且是 over-fitted 术语，可能触发套路解
4. 约束集已过载（20 条，CSE 研究：>10 条进崩塌区）

## 四、线宽：唯一有硬证据该做的

| 判据 | 数 |
|---|---|
| 实际用到「声称之外」的线宽 | **15/30** |
| 声称了但页面完全没用到 | **12/30** |
| 全库不同线宽值 | **22 种** |

最严重：**S25 声称只有 `3px`，页面实际用 1px 和 1.2px，一次 3px 都没用。**
最混乱：**S13 声称 7 级，实际 5 级，其中 1.5 和 5 从未声称，2/5.5/7/14.5 没用过。**

### 根因已定位到行

`prototypes/_prompts/extract-dna.mjs`：

```js
  // ---- 线宽分级 ----
  const widths = new Set();
  for (const m of css.matchAll(/(?:border(?:-(?:top|right|bottom|left))?|outline)\s*:\s*([0-9.]+)px/g)) {
    widths.add(m[1]);
  }
```

**四个缺陷**：
1. 只匹配简写 `border: 1px`，不匹配 `border-top-width: 1px`
2. 完全不扫 `stroke-width`（CSS + SVG 属性）→ S19/S20/S24/S29 漏抽
3. 不处理 `@media` 覆盖
4. 不处理 `var()` → `border: var(--rule)` 抽不到

**还有设计层面问题**：抽出来的是「渲染实测值」（`1.1px`、`3.2px`、`3.6px`），不是「设计分级」。提示词是给 AI 的施工图，`3.6px` 毫无意义，`1px 和 3px` 才有。

### 顺便：那句话自相矛盾

```js
"5. 线宽只用这几级：" + d.lineWidths + "，不要自创第三级。",
```

列了 4 级、7 级，却说「不要自创**第三**级」。

## 五、检索 Agent 的独立结论（与我的实测交叉验证）

它打通了 arXiv API + OpenAlex（web_search 全程 402 欠费）。**证据面偏学术，工程博客缺失**——这个限制它自己披露了。

| 修法 | 支撑度 | 判定 |
|---|---|---|
| 修线宽 | ★★★★★ | 该做（修错，不是补维度；且**减少**约束数）|
| 补色板 | ★★★☆☆ | 该做但改法要对：补**封闭性**，不是更多色值 |
| 补字号 | ★☆☆☆☆ | **没有证据，这是赌** |
| 补配比 | ☆☆☆☆☆ | **纯赌，零证据** |

**三个关键实证**：
1. CSE（arXiv 2608.12426，369,753 次检查）：最强模型 7 条约束时跌破 50%。**当前 20 条已在崩塌区。**
2. Semantic Gravity Wells（arXiv 2601.08070，n=40,000，有 activation patching）：**87.5% 的违规发生在「明确点名被禁词」时**。即「不要用 #6366F1」会**提高** AI 使用它的概率。
3. arXiv 2604.24712：**under-specification 有时提升正确率**，机制是打断 over-fitted terminology 触发的套路解。

它建议的最高优先项**不在这四件里**：把 8 条负向指令改成「正向唯一解 + 让禁项名彻底不出现在文本里」。

**这与我的色板发现完全吻合**——我实测发现提示词的边界表述有问题（「只用这几个值」没给派生余地），它的建议正好是修这个。
