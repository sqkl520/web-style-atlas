## 议题 2（高）｜18 号方案的记忆点分配在矩阵、02 号文件与执行指令之间出现三方冲突

**三份文本各自的规定**

1. 矩阵表 18 号「材质/动效」列（冻结分量）：**扫描线余晖 + 字符敲入**；矩阵 C 节 18 号施工提示：独有记忆点为「字符以逐字敲入方式出现；磷光粉余晖只允许出现在字符外沿 1px」，最易撞车 5、20。
2. `02-anti-ai-rules.md` B-8 处理动作：**5 号正文禁止使用「余晖、拖尾、字符敲入」措辞；18 号正文禁止使用「面板、拨杆、状态灯」措辞**。即：由 18 号占有「余晖 / 字符敲入」，由 5 号占有「面板 / 拨杆 / 状态灯」。
3. 本轮执行指令：**18 号禁止使用「余晖 / 拖尾 / 字符敲入」（理由为那是 5 号的记忆点），改用「面板分区 + 拨杆 + 状态灯 + 硬纸调度板」方向**。

第 3 条与第 1、2 条在**归属上完全相反**，且第 3 条给出的替代物件集恰好是另外两个方案的独有记忆点：

- 「面板分区 + 拨杆 + 状态灯」= 矩阵给 **5 号**（F CONSOLE，面板分区加读数加状态灯拨杆）与 **21 号**（瑞士铁路扳道，面板分区加刻度读数加扳杆）写死的记忆点；
- 「硬纸调度板」= 矩阵给 **21 号**写死的媒介质感。

**若照第 3 条执行会产生的新风险**

18 号将同时与 5 号、21 号在关键视觉元素上产生 2 个以上语义重复（面板分区、拨杆、状态灯），命中总规格 F.3 栅栏第三条与 V-06；而 V-06 的判罚后果是「两方案中较晚编号者重写」，即 18 号会被判重写，形成死循环。

**临时处理方式（当前文件已按此写，未采用任何一方的原措辞）**

保留矩阵锁定的结构分量 `R（TERMINAL）` 与布局范式「单列命令流 + 光标锚定」，保留媒介质感「磷光 CRT」与字体气质「等宽点阵荧黑」；同时**不使用**被执行指令点名的三个词（余晖 / 拖尾 / 字符敲入），也**不使用**其建议的替代物件（面板 / 拨杆 / 状态灯 / 调度板），改用第三个机制承担记忆点：**曳引式连续打印纸（两侧 8px 喂纸边孔、12px 孔距、每 20 行一道折页压痕）+ 行尾 8×14px 锚定光标 + 回执挂牌（24×12px 牛皮纸牌，印三位回执号）**，动效主机制为「走纸」而非「读数」或「拨动」。并在 18 号字段 8 第三条显式写出与 5 号、21 号的机制隔离声明，供审查官直接核对。

**请 Lead 裁定（三选一）**

- 方案 A：认可第三机制处理，维持现状；同时由 Lead 决定是否把 `02-anti-ai-rules.md` B-8 的措辞归属表述与执行指令对齐（两份文本目前互相矛盾）。
