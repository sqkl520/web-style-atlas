## §0 我的人设与任务

**我是谁**：给自家精品咖啡品牌做官网的人。会一点 HTML（能改改颜色、能看懂 class），不多。老板的原话是"找个不俗气、有设计感的风格"。我有 **30 分钟**，过了这 30 分钟我就去干别的了。

**我为什么在这里**：我在搜"网页设计风格参考"，撞见一个自称"30 个能跑的风格"的仓库。我不信。这种话我见过太多次——通常是 30 张 Figma 导出图配一句"每个方案都经过深度打磨"。

**我要干什么（按 README 教我的路走）**：
1. 翻 README（中英都翻）→ 第一分钟我在找"怎么打开、在哪儿看、跟我这个咖啡店有没有关系"。
2. `npx serve .` → 打开选型台 → 筛"咖啡/餐饮/暖调" → 点开一个案子看详情 → 想"拿它怎么办"。
3. 试 `wizard.html` 五问向导，按我咖啡店的处境答题。
4. 挑一个我真想用的案子（M02 模板或某个 S 案），按 README 教的路径去用它：我该改哪几个变量？素材会不会踩坑（署名、字体）？
5. 记下所有"这他妈是什么 / 为什么要给我看这个 / 我该看哪"的时刻。

**我的判断标准**：30 分钟后我手上有没有能直接拿去用的东西。不是"这仓库很严谨"——那对我没有用。

**这次走查我实际跑了什么（都可复算）**：
- 自建静态 server：[serve.js](deliverables/48-scratch/serve.js) → `node deliverables/48-scratch/serve.js` → `http://127.0.0.1:8099`。我没用 `npx serve .`（原因见 §2 第 6 条）；我也没碰 `prototypes/_build/`，那两个目录有别的 agent 在改。
- 无头 Chrome（`--headless=new --dump-dom` / `--screenshot`）抓选型台、向导、S04、S07、M02 的真实渲染，产物在 `deliverables/48-scratch/shots/` 与 `dom-*.html`。
- 布局实测：[measure.html](deliverables/48-scratch/measure.html)、[measure2.html](deliverables/48-scratch/measure2.html) 把选型台放进 1440×900 与 390×844 的 iframe 里量真实几何（不是目测）。
- 搜索命中复算：[probe-selection.js](deliverables/48-scratch/probe-selection.js) 加载 `prototypes/_selection/data.js` 并逐字复制 `app.js:136-140` 的索引逻辑。
- 字体载荷：[probe-fonts.js](deliverables/48-scratch/probe-fonts.js)。
- 提交态核对：`git show HEAD:prototypes/_selection/app.js` / `.../wizard.js`，存到 `deliverables/48-scratch/HEAD-app.js`、`HEAD-wizard.js`。

## §4 "不对劲"的三个候选解释

> 用户说的是"感觉还是有些不对"。感觉是准的，下面三个解释按我认为的因果顺序排：**A 是根因，B 和 C 是 A 漏到表面上的两种痕迹。**

### 解释 A（我认为的主因）：这座仓库的**生产口径**是"被对抗性审查"，而它**宣传口径**是"帮你选风格上线"。两者不是同一件事，中间没人修路。

证据不是我的印象，是文件的分布：

- README 432 行里有 **39 行**带 `❌ / ⚠️ / 豁免 / 口径 / 复算 / 已修 / 未修 / 不得`（实测计数）。它最长的肌肉是"我这句不算错"。
- `deliverables/` 里入库 **57 份审查文件**（3.7 MB），编号排到 41 号；README L355 以此为荣："上面每一条边界数字都能回指到某一号文件"。
- README L366-372 给"提 issue 的人"三条复算命令；但**全文没有一条"选完之后你怎么办"**——第一次告诉我"只想取用某一个原型"要带 `_fonts/`，出现在**第 237 行 = 全文 55% 处**（实测 `Select-String` 定位）。
- **`git ls-files "prototypes/S*/README.md" = 0`**（实测）。30 个案子，0 份使用说明；只有 30 份 `CREDITS.md`（授权账，不是用法）。
- 界面上甚至出现"对读者说错话"的实例：`prototypes/_selection/index.html:83` 那段"怎么用"，原样渲染出 Markdown 星号，并且向我——一个来挑风格的人——解释 `_build/collect-schemes.mjs` 的抽取对 S12/S15/S19 失效（实测 DOM 里 `**` 与 `` ` `` 是字面量，见 §1 第 9 行）。**这是工单，不是文案。**

## §5 裁定

**裁定 1：用户的"感觉还是有些不对"是真的，而且不是审美问题，是路线问题。**
我按 README 教的主线走（README L49-53 → L72-74 → L140-171），30 分钟走完的结果是：**主线的前 4 步（打开、筛、搜、看详情）我都走通了，第 5 步"拿它怎么办"在主线里不存在**。我是第 15 分钟擅自跳出路线、直接翻到模板层，才拿到一个能上线的东西。这不是"我没耐心"——是这条路上确实没有出口（`_selection/` 全目录 grep `templates|M0` = 0 命中，实测）。

**裁定 2：这个仓库当前只对两类人有用，而 README 承诺的是第三类人。**
- **有用**：① 要"证明这不是随手生成"的同行（272 张三档截图 + 可复算闸门 + 回指文件编号的边界表，这是全仓库最扎实的部分）；② 会读源码、自己承担字体与授权风险的设计师（把 `_specs/Sxx.md` 当配方、把原型当参照）。
- **没用**：README 第 22-25 行亲手描绘的那个人——"手上有一个要上线的站，对方张口就要高级感"。**那个人就是我。** 我为他读的 README，他为我在第 22 行被邀请进来，然后我在第 12 分钟发现这条路的终点是"回去再看一遍 30 个案子"。
- 换句话说：**README 用第二类人的验收标准，向第一类人（其实是第三类）做承诺。**"30 个能跑的风格，不是 30 张配色图"（L7）这句话承诺的是"能跑＝能用"。实测：**能跑 ≠ 能拿走**——30 个案子里 29 个没有 `README.md`/`TOKENS.md`，`style.css` 里 S06 有 22 个 `:root` 自定义属性（全文件 83 处 `--x:`），没人告诉我改哪几个。

**裁定 3：如果要我用一句话回答"到底哪不对"——它把"可审计"当成了"可用"，并且在两处让前者反噬了后者。**
反噬点 1：诚实到**把工单印在门面上**（index.html:83 的未转义 Markdown + 构建脚本失效说明，直接给路人看）。
