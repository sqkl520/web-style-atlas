## §1 五分钟实测记录

脚本化走一遍"打开 → 想选 → 找到 3 个候选"，机械耗时 16.8 秒，但**五次卡住**。下表是逐步流水，"卡住"按它破坏"五分钟"的程度排序。

| 步 | 我做了什么 | 实测数字 | 判定 |
| --- | --- | --- | --- |
| ⓪ | 打开选型台 1440 | 页面总高 **13635px = 15.2 屏**；左栏高 **900px**（正好占满首屏，与主列同时出现）；首屏可见文字 **519 字** | 通过 |
| ⓪.5 | 找"我该从哪开始" | 左栏顶部 `rail-lead` 写着"照下面**四组**问题挑"，而栏内实际有 **9 组**带芯片的组 + 1 组"怎么用"（实测 `groupTitles` 10 条） | 轻微误导 |
| ① | 点"亮底"+"很安静" | 命中 **22 → 2**（S15 渔场平面簿、S22 糊窗对折册）。这是全页最有效的一次点击 | 通过（真能收窄） |
| ② | 看这 2 个候选 | 两行加起来 4 张截图，底色 `#E7EBE9` 与 `#DDDAD4`：**ΔL=12、ΔH=110**——两行看起来是同一张灰纸（见 `bench-1440-2hits.jpg`） | **卡住点 1**：能收窄，但收窄后仍分不出差别 |
| ③ | 想按"我这行能不能用"筛：搜"餐饮 / 金融 / 政务 / 课程" | **四个词各命中 0 行**。行卡上有 288~292 字可见文本，其中**没有任何"适合/行业/场景"字样**（`rowShowsIndustry=false`，30/30 行） | **卡住点 2（最硬）**：用户第一个会问的问题，在界面上没有入口，也搜不到 |
| ④ | 展开第 1 行详情，想据此排除它 | 详情滚动容器 `.detail` 高 900，内容高 **3461**；10 个字段从 **y=1044** 才开始；**"适用场景"在 y=3078 = 3.42 屏**（390 档 **4.65 屏**）。一案详情正文 **2463 字** | **卡住点 3**：想回答"适合我吗"必须滚 3.4 屏；想读完一案约等于把五分钟预算再用掉 1.5 遍。30 案逐个读不可能 |
| ⑤ | 想把范围再收窄一点，结果撞上 0 命中 | 造 0 命中后点"清空筛选"：**命中仍是 0**，空状态提示"清空筛选，或换一个关键词"仍在，而 **32 颗芯片全部显示未选中**（`aria-pressed=true` 计数 0）。再点一次那颗芯片反而回到 9 行 | **卡住点 4（最危险）**：界面开始说谎——状态还活着但显示已经清空，而它给的恢复建议正好指向那个坏按钮 |
| ⑥ | 转向导，答 5 问 | 机械 4.0 秒；向导页总高仅 1084px（1440 档），第 1 问的三个按钮全在首屏内（top=504）；390 档选项高 82px、无横向溢出 | 通过（向导本身很利索） |
| ⑦ | 点推荐卡上的"到选型台看它的三档截图" | `href="./#index-S23"` → 落地 `#index-S23`，**详情面板未开**（`hidden=true`，`#d-no="—"`），列表回到 30 行顶部、`scrollY=0`。截图与"没动过的选型台"**逐字节相同** | **卡住点 5**：向导给出的 3 个候选，**通向证据的唯一一条路是死链** |

**结论**：向导能在 2 分钟内给出 3 个**名字**（这条辩护员说得对）；但"选出 3 个候选"要的是能排除的**证据**，而证据链在第 ③、④、⑦ 步都断了。**按"五分钟能不能选出 3 个候选"判：向导路径 ≈ 3–4 分钟但拿到的 3 个可能是同一格的纸；纯选型台路径失败**（卡在 ③，且 ④ 的成本超出预算）。

## §3 逐列裁定

行卡实际渲染的字段（实测 `.row` 子元素）：`编号 / 中文名 / 英文名 / 结构类型 tag / 门槛 tag / 调性 tag / 一句话定义 / 美学家族 / 4 个色块 / 错误码 / 三档截图 / 脚注`。行高平均 **434px**（30 行合计 **13005px = 14.4 屏**，页面总高 13635px = 15.2 屏）；展开详情后列表被压到 564px 宽，行高升到 461–517px（中位 475）。每行可见文本 249–292 字。

| 列 | 裁定 | 依据（实测） |
| --- | --- | --- |
| 编号 `S01` | **保留** | 深链 `#S07` 直接可用，搜索 `S07` 命中 1 行；`S01` 是标识不是装饰序号，这是对的 |
| 中文名 + 英文名 | **保留** | `镶金对称厅 / Gilded Symmetry Salon` 是行内最有效的识别信息 |
| 结构类型 tag `F 型 · NEWS-FRONT` | **改** | F/R 无释义（§2）；`NEWS-FRONT` 是内部骨架名，用户读不出它意味着什么。要么给出"内容主导 / 形式主导"的一句话解释，要么把 tag 换成人话（"像报纸头版"） |
| 门槛 tag `门槛低` | **改** | 换成向导的问句（"三秒知道点哪"） |
| 调性 tag `混乱活力 / 街头` | **保留** | 行内最像"风格"的字段，也是用户唯一有词汇的维度 |
| 一句话定义（`def`） | **保留** | 30/30 行都有，107–150 字，是行内信息密度最高的决策材料 |
| 美学家族（`family`） | **弱保留** | "苏联构成主义印刷"回答的是来源考据，不是"我该不该选它"。建议保留为次要行的灰字，别占视觉权重 |
| 4 个色块 | **改** | 第一个色块是底色，但**19/30 行的第一个色块是浅米/灰白**（判据 L≥180 且 R≥B 且 R−B≤60）；4 个 20px 方块之间看不出关系。建议改成一个 24px 高的**底色长条 + 主色块**，让"这是不是同一张纸"一眼可见 |
| 错误码 `TRACE-36` | **删（移到详情）** | 30/30 行各有一个唯一值（`n=30`），像 `P-03 / BOOK-409 / MASK-05`，对"选哪个风格"提供 **0** 信息 |

| 脚注（`FAIL 0 / WARN 2 / 桌面 11 屏 · 真实图 10 · 横向溢出 0 / WARN：font-count no-footage`） | **拆开**：闸门部分**删**，"桌面 N 屏 / 真实图 N / 横向溢出 0"**保留并加人话单位** | **脚注占每行可见文字平均 27%**（92/292、66/249…），且 **30/30 行**都挂着 `WARN：no-footage measure` 这类**只有作者读得懂的 id**。而"桌上 11 屏 / 真实图 10"恰恰是决策信息（要准备多少张图、页面有多长），现在被淹在噪音里 |

**行上缺的四样关键信息（这是"决策要用到但界面上找不到"的正面回答）**：

3. **底色带 / 明暗**——同上（`hasBand=false`）。
4. **能不能装具体东西**（价格表 / 表格 / 长目录 / 图集）——数据层没有这个字段，但 `20-style-axes.md` 轴 4 的"可重复单元 + 是否可编号检索"就是它，且已在文档里逐案判定完（4A=2 / 4B=7 / 4C=14 / 4D=7），**没有回填到 data.js**。

| F 一屏 / 不用图 / 很安静 / 三秒 / 怕做错 | **S07** 铅灰油墨目录、**S22** 糊窗对折册、**S17** 税票存根联 | S29、S28、S18 |

**合理性与不合理性都在表里**：B 组（要"很安静 + 不用图 + 很多栏目"）给出 S15/S22/S18，**其中 S18 磷光检修台是全库最长（1212 字）也最吵的一页**（`彩度 56%`，卡片自己写着"1212 字正文（对上你要的「很多栏目」项）"，而它是答案"很安静"下唯一能凑出来的第三名）——这就是"凑够 3 个"。

### 4.2 "同一格里的三张纸"——用 162 组答案全枚举量出来

我把 `wizard.js` 的打分逻辑（`stretch` 归一 + `TONE_BOLD` + `fear = 彩度×0.6 + 调性×0.4` + 五项等权欧氏距离 + `slice(0,3)`）**逐字复算**，3 组随机答案与浏览器实测结果**完全一致**（交叉验证 `match: true`），然后跑了全部 **3×3×3×2×3 = 162** 组答案：

- 162 组答案产生 **127** 个不同的推荐集合 → **向导确实在做区分**，这一条辩护员可以说它对。
- **其中 42 组（25.9%）的三个推荐同属一条底色带——而且 42 组全部落在"暖浅色带"**（就是那 18 个案挤在一起的那一格）。例：答案 C/D 得到 S06 `#ECDEC6` / S23 `#DCDCC8` / S27 `#E8D7B5`，两两 ΔL ≤ 5、ΔHue ≤ 22。**每四组答案就有一组拿到"同一格里的三张纸"**（`wizard-result-1440.jpg` 上那三条推荐卡的色块就是三块米黄）。
- 反复出现的集合：`S22,S07,S06` 出现 5 次、`S07,S22,S17` 4 次；**S26 在 43/162 组里进过前三**，而 **S11 铁窗打字本、S14 零重力发射序在 162 组里一次都没进过前三**，S20 只进 2 次、S29 5 次、S09 6 次——**推荐面严重偏斜**。
- **第 3 名与第 4 名的分差（四项欧氏距离平方）**：中位 **0.1724**，最小 **0.0017**；**6 组答案分差 < 0.01、25 组 < 0.05**。也就是说约 **15% 的答案里，"第三个推荐"和第 4 名基本同分**，而界面上没有任何不确定性提示——它把第 4 名包装成"明确排除"，把第 3 名包装成"推荐"，读者会以为这两者差距很大。

### 4.3 只改一问，推荐会变吗（单问灵敏度，基线 = 中/中/中/三秒/两头不偏）

| 只改这一问 | 结果 | 判定 |
| --- | --- | --- |
| 内容量 0/1/2 | {S12,S06,S01} → {S23,S06,S27} → {S27,S26,S23} | 有效，三个档三个集合 |
| 图片 0/1/2 | {S07,S27,S12} → {S23,S06,S27} → **{S06,S23,S27}** | **半失效**：`几张就够` 与 `图是主角` 得到**同一组三张纸**（只换了顺序）。这正好是 D 组与 C 组实测的结果 |
| 安静度 0/1/2 | {S22,S07,S06} → {S23,S06,S27} → {S27,S23,S30} | 有效 |
| 首屏引导 0/1 | {S23,S06,S27} → {S24,S26,S10} | 最有效（两档全换） |
| 更怕 0/1/2 | {S07,S22,S06} → {S23,S06,S27} → {S23,S27,S12} | 有效 |

**结论**：5 问里 **4 问有效、1 问（图片）在"几张就够 / 图是主角"之间不改变候选集合**。同时，用户看不到"我的第 5 问被折算成了 `彩度×0.6 + 调性×0.4`"——它被印成"调性「温暖手作 / 人味」（对上你要的「**怕没记忆点**」）"（实测 6 句里 6 句都这么印，A 组与 D 组各 3 句），这是**类别错位的句子**：拿"调性"去对上"怕不怕"，读者读不通。

### 4.4 它的自我批评是否属实：**属实，而且可以给出三个可复核的证据**

向导自己印着"这套权重是本项目做得最弱的一环——它是拍的，没有经过真人回放测试"。我验证的结论是：**这句话不是谦虚，是精确描述**，并可具体化为：

1. **无去重 → 25.9% 的答案返回同一格的纸**（§4.2，42/162，全部在暖浅色带）。
2. **权重从不体现为"证据强度"**：分差中位 0.17，"推荐"与"明确排除"之间没有量级差（15% 的答案里第 3/第 4 名同分）。
3. **第 5 问是一个隐藏合成量**，印出来的理由句在语义上说不通（"调性 X 对上你要的 怕没记忆点"）。

### 4.5 向导与选型台**口径不一致**（辩护员最难答的一条）

同一句人话，两个界面给不同的名单（实测：把"选型台自己的芯片分类"与"向导认为对上该档"的集合逐案对比）：

| 同一句话 | 选型台芯片给出 | 向导认为"对上" | 差 |
| --- | --- | --- | --- |
| 有态度不吵 | **9** 案 | **23** 案 | 多 14 案（2.6 倍） |
| 很安静 | **2** 案 | **4** 案 | 多 S07、S19 |
| 一屏说清 | **10** 案 | **17** 案 | 多 7 案 |
| 三五屏 | **11** 案 | **24** 案 | 多 13 案 |
| 很多栏目 | **9** 案 | **8** 案 | 少 S22 |
| 就要扎眼 | **19** 案 | **19** 案 | 一致 |
| 认知门槛低/中/高 | 11 / 12 / 7 | 11 / 12 / 7 | **完全一致（唯一对齐的一轴）** |

**两条页面自己印出来的直接冲突**：
- **S23 剥落年代墙**：选型台芯片把它归进"**就要扎眼 19**"（`axes.loud=就要扎眼`，彩度 68%）；向导在答案"有态度不吵"下把它列为推荐，理由逐字是"**彩度 68%（对上你要的「有态度不吵」）**"。
- **S07 铅灰油墨目录**：选型台把它归进"有态度不吵 9"（彩度 29%）；向导在答案"很安静"下把它列为推荐第 1，理由逐字是"**彩度 29%（对上你要的「很安静」）**"。

原因不神秘：选型台用"档位"，向导用"τ=0.75 的连续距离"，中档口径被放大了 2–2.6 倍。但对读者来说，这就是**两个界面在回答同一个问题时互相打脸**。

### 4.6 向导其余可分享性 / 可重现性 / 移动端

- **带答案链接回放：可用。** `#wz-share` 产出 `?load=2&img=0&loud=0&guide=1&fear=0`，打开后 3 个推荐与答案按钮的 `aria-pressed` 与原始运行**完全一致**（`S15,S22,S18` → `S15,S22,S18`）。
- **向导卡片链接：死链。** `href="./#index-S23"`，而选型台的 `hashchange` 只认 `/^S\d{2}$/`（`app.js:436`）→ 落到 30 行顶部、详情不开（§1 步骤⑦，两张截图逐字节相同）。
- **向导 390 档：可用。** 无横向溢出（`scrollWidth=390`），第 1 问三个选项全在首屏（top=371，选项高 82px），结果卡 358px 宽，推荐集合与桌面一致。

## §5 具体改法（按优先级，每条都可执行）

**P0-1｜修"清空筛选"不清四组用户轴**
【文件】`prototypes/_selection/app.js`（`#reset` 处理器，L390–L395）
【改成】在 `state.fr.clear(); … state.gate.clear();` 前加 `state.ground.clear(); state.band.clear(); state.load.clear(); state.loud.clear();`
【为什么排第一】它是唯一一处**界面主动说谎**的缺陷：0 命中状态下点"清空筛选"仍 0 命中（实测 `before=0 → after=0`），而 **32 颗芯片全部显示未选中**（`aria-pressed=true` 计数 **0**）——用户看到的是一个"没有任何筛选却什么都筛不出来"的页面，而空状态给他的建议正是"清空筛选"。这是 5 分钟内最可能让人直接关页的一步。
【预估收益】消灭死循环；空状态的那句恢复建议恢复有效；改动 1 行。

**P0-2｜修向导 → 选型台的死链**
【文件】`prototypes/_selection/wizard.js`（`card()` 里 `'<a href="./#index-' + r.id + '">…'`，L164）
【改成】`'<a href="./#' + r.id + '">…'`（或让 `app.js:436` 的正则同时接受 `index-S\d{2}`）
【为什么排第二】向导是**唯一能在 2 分钟内给出 3 个候选**的入口，而它通向证据的唯一链路是死链——实测落点画面与"从未打开过选型台"逐字节相同。第 ③④ 步（行业/详情）的成本是信息架构问题，这一步是**功能坏了**。辩护员如果要主张"向导管用"，这条必须先修，否则向导的输出只是三个无法追查的名字。
【预估收益】向导的 3 个推荐从"名字"变成"可立刻看三档截图的候选"；改动 1 个字符串。

**P1-3｜加"适合干什么"轴 + 让 `scenes` 可搜**

## §7 本次审查的限制

1. **没有真人**。所有"读多少字要多久"的换算是我按字数估的（519 字首屏、2463 字一案详情），不是计时实验。机械步骤耗时有秒表（16.8s 全程），阅读成本是估计。
