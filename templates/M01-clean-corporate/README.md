# M01 清爽企业站（Clean Corporate）

一个**单页企业站模板**：适合律所、咨询、软件服务、设计工作室、代理商这类"专业服务型公司"。
拿到就能用，改完就上线：**两个文件、零外部依赖、零构建步骤、不联网也能跑**。

```
index.html    全站内容（所有要改的文字都在这里）
style.css     全站样式（最上面 12 个变量管全部颜色和宽度）
README.md     你正在看的这份：怎么打开、怎么改、这一层为什么这么设计
TOKENS.md     12 个变量逐个说明：作用 / 默认值 / 改成什么会怎样
```

---

## 1 三分钟上手

**打开看效果**：双击 `index.html`。就这样 —— 不需要装 Node、不需要命令行、不需要联网。

**改内容**：用任意文本编辑器（VS Code、Notepad++、记事本都行）打开 `index.html`，
按 `Ctrl+H` 查找 `换成你的`，一个一个替换成你自己的文字。全站共 **84 处**标记，从公司名到备案号都有。

**改颜色**：打开 `style.css`，只改第 15–30 行那一组变量。改完存盘，刷新浏览器就能看到。

**上线**：把 `index.html` 和 `style.css` 两个文件上传到任何静态空间（GitHub Pages、对象存储、服务器上的 Nginx 目录）即可。
没有需要编译的东西，也没有需要在服务器上跑的程序。

## 2 每处要改什么（按页面顺序）

| 位置 | 标记长什么样 | 说明 |
| --- | --- | --- |
| 浏览器标签标题 | `【换成你的：公司名】｜【换成你的：一句话业务定位】` | 出现在搜索引擎和标签页上 |
| 顶部导航 | 品牌名 + 5 个菜单名 + 导航按钮 | 菜单项要增删，就复制/删除 `<li>` 整行 |
| 主视觉 | 行业标签 / 主标题 / 介绍段 / 两个按钮 / 三条短事实 | 主标题**越短越好**，一行最好、两行也可以 |
| 图片占位框 | 灰底格子里的 `主视觉图 · 16 : 10` | 换成你自己的照片，见第 4 节 |
| 三项服务 | 服务名称 / 说明 / 了解更多 | 三张卡片的文字长度差不多时最整齐 |
| 客户与资质 | 5 个 `【客户 logo N】` + 一行资质说明 | 只做 3 个也行，删掉多余的 `<li>` |
| 成果数据 | 4 个数字（现在是 1,240+ / 98% / 11年 / 4小时）+ 指标名 + 口径 | **数字现在是编的示例值**，换成你的真实数据；口径说明写清时间范围 |
| 柱状图 | 2020–2025 的 6 根柱子 | 数据也是编的。不需要整张图就删掉整个 `<figure class="chart">` |
| 服务流程 | 4 步的标题与说明 | 写清"客户准备什么、你交付什么、几天" |
| 常见问题 | 4 个问题与回答 + 电话/邮箱 | 问答用原生 `<details>` 做的，点标题展开，不需要 JavaScript |
| 结尾行动区 | 结尾标题 + 两个按钮 | 写清"你会怎么回应、多久回应" |
| 页脚 | 公司名 / 介绍 / 地址 / 电话 + 3 栏链接 + 备案号 | 页脚链接指向的锚点就是页面各段（`#services` 这种） |

**写作建议**（模板最容易失败的地方）：说明里凡是有具体数字、具体时间、具体对象，
页面就会显得可信；凡是形容词（可靠、专业、高效）都会显得空。占位标记里已经给了写法示例。

## 3 换色：只改这几个 HEX

`style.css` 顶部：

```css
:root{
  --brand:      #1B3A5C;   /* 主色 */
  --brand-ink:  #12283F;   /* 主色的深一档 */
  --brand-soft: #EAF1F8;   /* 主色的极浅一档 */
  ...
}
```

**换一整套色的规矩**（照做就不会翻车）：

1. `--brand` 换成你想要的主色。**它必须够深**——把 HEX 三个通道（每两位一个）当成三个 0–255 的数，
   平均值 ≤ 110 时，白字放在上面是安全的（本模板默认 `#1B3A5C` 的平均值是 59）。平均值超过 130，
   按钮上的白字就会看不清，这时你得同时去 `style.css` 里把 `.btn-primary` 的 `color:#fff` 改成深色。
2. `--brand-ink` = 同一个色相再深一档，用来做按钮悬停色和页脚底色。偷懒做法：把主色每个通道乘以 0.7。
3. `--brand-soft` = 主色调到几乎白（92% 白）。图标底、结尾区底色用它。

三个现成配方（都算过对比度，白字都在 10:1 以上）：

| 风格 | `--brand` | `--brand-ink` | `--brand-soft` |
| --- | --- | --- | --- |
| 默认：深石板靛蓝 | `#1B3A5C` | `#12283F` | `#EAF1F8` |
| 砖红 / 律所 | `#8C3A2B` | `#63281D` | `#F7EDEA` |
| 墨绿 / 咨询 | `#244F3F` | `#18362B` | `#E9F1ED` |
| 炭黑 / 设计工作室 | `#23272B` | `#15181B` | `#EFF1F3` |

`--bg`（页面底）和 `--bg-2`（交替分区底）建议保持接近白，`--ink` / `--ink-2` 保持深灰：
正文对比度就自动达标（见第 6 节）。

## 4 换图：把 SVG 占位框换成 `<img>`

页面上所有"图"现在都是**内联 SVG 占位框**：灰底网格 + 裁切角标 + 比例标注 + 一把比例尺，
看上去是一张刻意画的版式说明，不是"图片挂了"。

**换主视觉图**：在 `index.html` 里找到 `<figure class="shot">`，把里面那一整段 `<svg>…</svg>` 删掉，
换成：

```html
<img src="hero.jpg" alt="描述这张照片拍的是什么" width="1200" height="750">
```

* 比例 **16:10**（1200×750 或 1600×1000），宽度别小于 1200px，否则手机和大屏上会糊。
* `alt` 必须写，写"图里有什么"，不要写"图片"。
* 照片建议：真实的工作场景、产品、团队、场地。**不要用图库里那种"几个人围着笔记本微笑"的通用照片**——
  那是企业站最容易被一眼看穿的地方。

**换客户 logo**：5 个 `<svg class="logo-ph">…</svg>` 每个都换成
`<img src="logo-1.svg" alt="客户名" width="200" height="64">`（灰度或单色最整齐）。
只放 3–4 个也行，删掉多余的 `<li>` 整行即可。

**换 logo 标识**：顶部和页脚各有一个 `<svg class="brand-mark">`，换成
`<img src="logo.svg" alt="公司名" width="32" height="32">`。现在那个方形标志用的是 `currentColor`，
会跟着 `--brand` 一起变色。favicon 需要的话自己放一个 `favicon.ico` 并在 `<head>` 里加一行 `<link rel="icon">`。

## 5 响应式与浏览器

三档都实测过（用真实浏览器渲染，不是估算）：

| 视口 | 内宽 | 页面总高 | 横向溢出 |
| --- | --- | --- | --- |
| 桌面 | 1440px | 4607px | 0 |
| 平板 | 768px | 5768px | 0 |
| 手机 | 390px | 7698px | 0 |

* **手机导航**：右上角三条横线的按钮，点一下展开菜单（纯 CSS，用 `<input type="checkbox">` 实现，
  没有 JavaScript）。键盘用户按 Tab 也能聚焦到它，焦点有蓝色描边。
* **手机上那张柱状图**：它在自己的框里可以左右滑（最小显示宽度 620px）。
  这是故意的 —— 如果跟着屏幕缩到 390px，坐标轴的字会小到 6px，还不如能滑。整张图不需要就删掉。
* 断点：600 / 640 / 768 / 880 / 900 / 1000px。想改版心宽度只改 `--maxw`，不要动这些断点。
* 支持的浏览器：任何 2020 年后的 Chrome / Edge / Safari / Firefox。不支持 IE。

## 6 无障碍：这一层自己定的底线，都实测过

| 底线 | 实际 |
| --- | --- |
| 正文对比度 ≥ 4.5:1 | 正文 `#141B23` 对白底 **17.34:1**；次级文字 `#4C5966` 对白底 **7.17:1**（对浅灰底 6.67:1）；主色白字按钮 **11.63:1**；数据区白字对主色 **11.63:1**；页脚 `#CBD9E7` 对 `#12283F` **10.43:1**（最弱一处是页脚次要文字 8.13:1） |
| 正文 ≥ 16px | 段落 16–17px；说明行 / 图片说明 / 页脚链接 15–15.5px（都属于次要文字，不是正文） |
| 按钮点击区 ≥ 44px | 主/次按钮 48px；导航项、问答标题、页脚链接 44px 以上 |
| 键盘焦点可见 | 全站 `:focus-visible` 蓝色 3px 描边（白底 3.49:1、深色页脚 4.30:1，都过非文本 3:1） |
| 语义标签 | `header / nav / main / section / footer`、`aria-label` 给每个导航区、页脚地址用 `<address>`、标题层级 h1→h2→h3 不乱 |
| 图片有替代文字 | 每个内联 SVG 占位框都写了 `role="img"` + `aria-label` + `<title>`（内联 SVG 的 alt 等价写法；换成 `<img>` 时改用 `alt`） |
| 动效降级 | `prefers-reduced-motion: reduce` 时关掉全部过渡与平滑滚动；本模板本身没有入场动画 |
| 跳转链接 | 页面第一个可聚焦元素是"跳到主要内容" |

## 7 这一层豁免了哪些条款，以及为什么

工作区里的 `deliverables/02-anti-ai-rules.md`（R-01–R-40 反 AI 味法典）与
`prototypes/_CONTRACT.md` 是给 **`prototypes/S01–S30` 那 30 个方案**定的。
那 30 个方案的目标是**被记住**（30 个必须彼此不撞、必须一眼认得出），所以它们必须躲开所有"统计众数"。

本模板层（`templates/Mxx`）的目标是**不犯错、拿起来就能用**。同一批做法，在这一层的用途完全不同，
所以下面这些条款在这一层**明示豁免**，豁免范围写清楚，理由不是"因为大众所以豁免"。

| 被豁免条款 | 豁免范围（本模板里的具体做法） | 为什么这一层必须这么做 |
| --- | --- | --- |
| **R-12 / C-1.3** 禁"居中大标题 + 三张等宽卡片 + 底部 CTA" | 服务区是三张等宽卡片；结尾是独立 CTA 区（hero 保住了不对称：左文右图） | 这三段是**访客的任务顺序**：这是谁 → 你能做哪几件事 → 怎么联系。模板面向的是"已经有生意的公司"，它需要把最多的信息塞进最短的路径；打破这个顺序要多付真金白银的转化损失。而"等宽"的价值是**可比性**：客户要在三项服务之间做比较，不等宽就没法比。法典镇压这句话的前提是"没有设计理由地居中"——这里是按访客动线选的骨架，并且我保留了 hero 的不对称与流程区、数据区两条非卡片结构，不是整页只有这一种节奏 |
| **R-13 / C-2.14** 禁 3/6/9 重复 feature grid 当主体 | 三项服务就是 n=3 的等宽卡片（三列宽度相等，内容长短不一） | 不给自己找理由：这里就是标准的 3 格网格，n=3 成立。法典允许的"非等量处理"（首格跨双栏、某格留空）在本层不适用 —— 那种处理要求作者知道三格内容谁重谁轻，而模板作者不知道买家会把哪项服务写长。等宽三格是唯一对未知内容长度都成立的做法。加上本层没有"30 个方案彼此不撞"的约束：模板的价值恰恰在于它是**同一套东西**，用户改内容、不改编排 |
| **R-05 / C-1.6** 禁白 / 浅灰 section 交替铺底 | 客户条与问答区用 `--bg-2 #F4F7FA`，数据区用主色实底，其余白底 | 交替底色在大众站点里承担**拇指滑动时的定位作用**：一眼看出"换章节了"。法典反对它的理由是"零信息量的分区"，但这条批评成立的前提是作者**还有别的分区手段可用**——分隔线要求内容对齐、栏外编号要求有编号系统，而这些都依赖未知内容的长度。本模板不能假设用户会写多长，底色交替是唯一与内容长度无关的分区手段。而且它不是唯一手段：数据区反白、流程区 2px 主色横规线、页脚深色，一共四种机制 |
| **R-04 / C-2.15** 禁纯白底 + 纯黑字 + 单强调色 | 白底保留；**没有用纯黑字**（用 `#141B23`）；除主色外还有 `--brand-soft` / `--bg-2` / `--ink-2` 承担色阶 | 纯白底是模板的**可预期性资产**：用户换成任何照片都不会串色。但法典点名的"纯黑字"被换掉了 —— `#000000` 在屏幕上过硬，这里用 `#141B23`（偏中性灰的近黑，白底上 17.34:1，留了余量）。也正因为多出 `--brand-soft`、`--bg-2`、`--ink-2` 三档灰蓝，全站层次不是"一个强调色包打天下"。单强调色的理由是模板会被不懂设计的人反复改，颜色越少越改不坏 |
| **R-16 / C-2.11** 禁 24px 圆角 + 柔和投影的"卡片浮起" | `--radius:10px`（本层规格要求 8–12px）+ 一段很浅的两层阴影 `0 1px 2px` + `0 16px 30px -24px` | 圆角加淡阴影是十年移动 UI 建立起来的"这里是一张可以点的卡"的符号。模板必须让第一次见到它的人立刻知道**哪里能点**，这种符号化的成本最低。法典反对它的理由是"柔和阴影在物理上不成立"——那条批评针对的是**印刷物/材质**语境（R-03、R-39 都在讲实物材料）；屏幕 UI 的判据是可理解性，不是物理性。另外我们把它压在 10px 半径和负扩散阴影上，不是 24px + `shadow-lg` 那种浮起高度 |
| **R-07 / R-08 / V-02** 禁 `Inter`/`Roboto`/`Arial`/`system-ui` 等系统栈 | `--font` 就是系统字体栈，且同时出现 `system-ui`、`-apple-system`、`Segoe UI`、`Roboto`、`Helvetica`、`Arial`、`PingFang SC`、`Microsoft YaHei`、`Noto Sans SC` | **这一条不是审美选择，是交付约束的唯一解**：本层的硬要求是"两个文件、零外部依赖、双击就跑"。任何 webfont 只有两条路 —— 从 CDN 取（破坏自包含、断网即回退），或 base64 内嵌（把 19KB 的 `style.css` 变成 1MB 以上，用户再也改不动）。中文更极端：思源黑体全字集 8MB 起，塞不进"两个文件"。而系统栈同时满足零依赖与中文不缺字。30 案能禁用系统栈，是因为它们有 `prototypes/_fonts/` 共享字体缓存这条基础设施；这一层按定义没有 |
| **R-26 / V-05** 禁占位文案 | 全站文案是 `【换成你的：…】` 标记 | 30 个方案是**设计稿**：占位符意味着设计师没想过内容，落地必崩，所以该禁。本模板是**模具**：占位符就是模具的型腔。而且这一层的"真实文案"换了个位置——**写在标记里的写作说明**（"写清周期，例如『4 周内交付 3 版方案』"）是真实可用的内容，它比一段示例文案更有用：示例文案在模板站最常见的失败模式就是被原样上线，而说明会迫使买家写出自己的东西。注意：法典词表里点名的 `此处填写`、`待补充`、`点击这里`、`Lorem ipsum` 一个都没用 |
| **R-17 / C-2.17** 禁毛玻璃吸顶导航 | 只豁免"吸顶"：导航用 `position:sticky` + **实心白底** + 1px 底线；`backdrop-filter` 一次都没出现 | 这么列是故意的：法典把这条写成"毛玻璃 + 吸顶 + 背景模糊的堆叠"，我们只碰了吸顶那半条。访客在任何滚动位置都需要入口，而半透明模糊在屏幕上会让底下的文字透出来（本层要求"文字和底色不能同色看不见"，模糊正好在制造这类问题） |
| **R-01 / R-02** 禁紫蓝渐变与 AI 默认色值 | 允许用冷色主色；**实际一个 CSS 渐变都没有**，主色 `#1B3A5C` 也不在法典点名的 11 个 HEX 里 | 允许不等于要用。渐变会让不懂 CSS 的人在换色时把两端的色值改歪（最常见的求助就是"改了主色渐变变得很奇怪"），所以在这一层直接不用，改色只需要动 3 个 HEX |

**反过来，这些条款在这一层照样成立，而且是硬要求**（没有豁免）：

* **R-21 / V-03 禁 Emoji 作图标**：全站 0 个 Emoji（用脚本扫过渲染文本里的
  `U+2600–27BF`、`U+2B00–2BFF`、`U+1F300–1FAFF`，命中 0）。图标是三个自绘 SVG（文档 / 柱状 / 盾牌），
  线条宽 2.4px，颜色跟着 `--brand` 走。页面上唯一被当作符号使用的非中文字符是链接尾部的 `→`
  （法典 §9.13 明确允许箭头）。
* **第 7 节 40 词黑名单**（赋能 / 一站式 / 无缝 / 极致 / 全链路 …）：命中 0。
  本层文案是自己写的说明句，不是生成的营销腔。
* **不得横向溢出**：三档实测 `scrollWidth == innerWidth`（0px 溢出）。
* **正文不得 < 15px**、**对比度 ≥ 4.5:1**：见第 6 节实测表。
* **无远程资源**：`index.html` / `style.css` 里没有任何 `http://` / `https://` 的 `src` 或 `url()`，
  也没有 `<link>` 到任何 CDN。断网、离线打开都正常。
* **无构建步骤**：没有 package.json、没有打包器、没有需要生成的产物。

**为什么写这段**：不是给法典打补丁，是把口径分清楚。
法典第 1.2 节把 AI 味定义成"统计众数"，第 1.4 节第 1 条写着"本法定的是下限，不是上限"——
它惩罚的是**没有理由地回到众数**。本层对每一条豁免都给出了用途级理由（访客任务顺序、可比性、
零依赖交付、拇指滑动分区、可点性符号）。真正的问题是：**如果不写这段，下一批作者会拿 30 案的清单来判 M 层，
或者反过来把 M 层这些做法带回 30 案**——后者才是真的破坏那 30 个方案。
两层的目标不同（被记住 / 不犯错），所以豁免范围必须落在文件里、逐条可查，而不是靠口口相传。

## 8 我知道的两处最弱的地方

1. **手机上那张柱状图要横向滑动，是一个妥协不是优点。**
   真正的解法是给窄屏单独画一套"条形列表"版图表（CSS 画的行内横条，跟着屏幕自适应），
   但那等于在模板里维护两套图表代码，买家换数据要改两处、更可能改错一件。
   现在这个做法（最小 620px、字号 15px 左右、容器内可滑）是在"字能看清"和"只有一份数据源"之间选的后者。
   它是本模板里唯一一处需要用户理解"为什么它跟我预期不一样"的地方。
2. **目前没有任何入场动效，全站是静态的。**
   本层规格没有要求，但真到 2026 年上线，一整页 0 动效在浏览器的观感是"没做完"。
   我选择了不做而不是做得潦草：动效要做对，需要处理"进入视口触发 + 位移距离 + 缓动 + 降级"，
   而在纯静态、不吃任何 JS 库的前提下，最省事的做法会退化成 `transition` 一条 opacity 淡入，
   那反而是模板站最典型的廉价感来源。落地建议：把 `section` 的入场交给用户自己的框架或
   IntersectionObserver 十行原生 JS，别在模板里预留半成品。

**两个次要的**（不算最弱，但你可能想知道）：
* 页脚三栏链接全部指向本页锚点（`#services` 这种）。真的做成多页时，你需要把它们改成 `services.html`。
* 客户端 logo 是一行 5 个等宽占位框。实际 logo 的长宽比各不相同，塞进等宽框里会显得有的被压扁 ——
  换图时建议统一导出成 **高 64px、透明底、横向自由宽**的 PNG/SVG，观感最整齐。
