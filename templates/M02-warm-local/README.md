# M02 暖调门店站（Warm Local）

给**本地实体店**用的一页式官网模板：餐厅、咖啡馆、烘焙、民宿、理发店、花店都能套。暖米白底、烤色深褐主色、标题衬线正文无衬线，一眼看上去像一家真店。

**两个文件就能跑**：`index.html` + `style.css`。没有图片文件、没有字体文件、没有 JS、没有 CDN。改文字和改颜色都不需要写代码以外的任何工具。

## 1. 这个目录里有什么

| 文件 | 干什么用的 | 你需要动它吗 |
| --- | --- | --- |
| `index.html` | 页面结构和全部文字。所有要改的文字都带【换成你的：…】标记 | 要动（改文字、换图） |

## 2. 打开 / 预览 / 发布

**预览**：双击 `index.html`。因为本模板**不引用任何外部文件**，`file://` 直接打开就完全正常，不需要装 Node、不需要起本地服务器、不需要联网。

> 这一条和仓库里 `prototypes/` 那 30 个原型不一样：那些原型引用了 `prototypes/_fonts/` 里的自托管字体，必须走 HTTP 才能看到正确字体。本模板故意不做这件事——系统字体栈 + 无图片文件，就是为了让店主双击就能看。

**发布**：把 `index.html` 和 `style.css` 传到主机的**同一个目录**，用浏览器访问 `index.html` 就行。没有构建步骤，没有要编译的东西。

**换域名后记得改 3 处**：

1. `<title>` 里的店名（浏览器标签页上的字）；
2. `<meta name="description">` 那句介绍（搜索结果里显示的摘要，建议 60 字以内）；
3. 页脚版权行的店名 / 公司全称。

## 3. 改文字：搜「换成你的」

在 `index.html` 里搜「**换成你的**」，会命中全部要替换的位置。按页面顺序：

| 位置 | 要改的内容 | 页面上的样子 |
| --- | --- | --- |
| 顶部 | 店名、品类副标题、订位电话 | 「【换成你的：店名】」 |
| 主视觉信息带 | 街区/品类标签、一句招牌主张、一句话说清你卖什么、今天营业时间、所在区街、人均 | 压在大图上的那块深褐带子里 |
| 菜单 | 4 个分类名、每道菜名、价格、标签（招牌/素食/限量/无糖）、点单补充说明 | 点线引导的价目表 |
| 到店 | 每周营业时间、最后点单、休店日说明、街道地址、电话、微信、地图链接、地铁/公交/自驾/无障碍四行「怎么来」 | 左时间右位置 |
| 店内 | 一段 40 字左右的描述 + 三张图的说明文字 | 三张环境图 |
| 评价 | 3 条顾客原话 + 每位顾客的称呼与身份 | 三列 |
| 订位 | 订位规则、电话/微信/邮箱/座位/包场/带娃与宠物 6 行、表单里的占位提示 | 左信息右表单 |
| 页脚 | 店名、地址、页面链接、社交账号链接、开票与停车说明、版权行 | 深色页脚 |

**价格和营业时间现在是「示例值」，不是占位标记**（比如菜价 ¥38、周一至周四 11:00–21:30）。这样做的原因：价目表必须排成一张真能读的价目表，把价格写成「¥【换成你的】」就没有价目表可看了。类别名、菜名这类真正属于你的内容则是【换成你的】标记。**请把示例值也一并替换掉**。

**为什么这个模板到处是【换成你的】标记？** 这是本层产品的一部分：你不会写代码，标记就是施工单。仓库里 `prototypes/` 那 30 个原型相反——它们被明确禁止使用占位文案，因为它们要拿去做风格评审。两层的目标不同，所以规则不同，详见 §7。

## 4. 换图片：页面上一共 4 个图片位

| 位置 | 比例 | 建议尺寸 | 现在的样子 |
| --- | --- | --- | --- |
| 主视觉（1 张） | 16:9 | 2000 × 1125 px | 灰底虚线框 + 相机图形 + 左上角「图片位 · 16:9」 |
| 环境大图（1 张） | 3:2 | 1600 × 1067 px | 同上，跨两列 |
| 环境方图（2 张） | 1:1 | 1200 × 1200 px | 同上 |

**怎么换**：找到对应的 `<figure class="ph …">`，把里面的 `<svg>…</svg>` **和** `<figcaption>…</figcaption>` 一起删掉，换成一行 `<img>`。外面那层 `<figure>` 留着，比例框就还在。

```html
<!-- 换之前（主视觉） -->
<figure class="ph ph-16x9">
  <svg class="ph-art" …>…</svg>
  <figcaption class="ph-tag">图片位 · 16:9 · 建议 2000 × 1125 px</figcaption>
</figure>

<!-- 换之后 -->
<figure class="ph ph-16x9">
  <img src="images/店面.jpg" alt="傍晚的店面，木门与暖黄灯光" width="2000" height="1125" loading="lazy">
</figure>
```

三条注意：

1. **`alt` 必须写**：一句话说清这张照片是什么（不是「图片1」）。它决定了盲人用户和搜索引擎能不能读懂你的页面。
2. **照片先压到 200KB 以内**（手机拍的照片常有 4–8MB）。压图可以搜「在线图片压缩」，或者用系统自带的看图工具导出为 80% 质量的 JPG。宽度不用超过 2000px。
3. **不要在这里贴外链图片**（`https://…`）。外链图会拖慢打开速度、平台换了地址就会变成破图；把照片放进和 `index.html` 同级的 `images/` 目录里最稳。

**为什么现在是灰阶虚线框而不是一张示例照片？** 两个原因：① 模板里带第三方照片，等于把别人的著作权一起送出去（仓库里的原型照片都是带署名的第三方素材，不能转授）；② 灰阶框本身是有意为之的施工标记——它同时告诉你「这里要放图」「要放什么比例」「建议多大像素」。

## 5. 换颜色 / 换宽度：只改 12 个变量

打开 `style.css`，**开头第 1 节**就是全部可调项：

```css
:root {
  --paper:      #FDF7EE;   /* 主底色：米白 */
  --paper-2:    #F7EADA;   /* 分区底色：奶油，用来区分段落 */
  --ink:        #241A12;   /* 正文与标题：深暖褐 */
  --ink-soft:   #55432F;   /* 次要文字：导航、说明、页脚小字 */
  --brand:      #7A3B12;   /* 主色：烤色深褐，按钮与品牌字 */
  --brand-deep: #2B1A0F;   /* 最深底：主视觉信息带、页脚 */
  --accent:     #9C4A16;   /* 强调色：价格、手绘线、焦点框 */
  --rule:       #CBB69C;   /* 点线与分隔线（纯装饰，不承载文字） */
  --radius:     8px;       /* 圆角 */
  --page-max:   1120px;    /* 版心最大宽度 */
  --font-serif: Georgia, "Times New Roman", "Songti SC", "SimSun", "Noto Serif CJK SC", serif;
  --font-sans:  system-ui, -apple-system, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", "Source Han Sans SC", Arial, sans-serif;
}
```

两套备选配色（照抄替换对应 4 行即可）：

| 想要的感觉 | --brand | --brand-deep | --accent | --paper | --paper-2 |
| --- | --- | --- | --- | --- | --- |
| 现成的（烤色深褐） | `#7A3B12` | `#2B1A0F` | `#9C4A16` | `#FDF7EE` | `#F7EADA` |
| 橄榄油 / 素食 | `#4A4A1E` | `#22220E` | `#5F6B24` | `#FBF9EF` | `#F0EFDF` |
| 皮革红棕 / 酒馆 | `#7A2E1B` | `#2A1211` | `#A33A22` | `#FCF6F1` | `#F2E6DE` |

**改色的注意**：

- **正文和标题的颜色（`--ink`）不要往浅了调**。深底浅字、浅底深字，反过来就一定看不清。
- **`--accent` 同时当文字色用**（价格、小标题）。它压在 `--paper` 上必须 ≥4.5:1，压在 `--brand-deep` 上**一定不合格**（默认值只有 2.71:1）——所以页脚和主视觉带子里的链接被单独指定成奶油色，你换色时**不要**去改那两处。
- **`--brand` 要够深**：按钮上的字是奶油色，压在 `--brand` 上要 ≥4.5:1。默认 `#7A3B12` 是 8.03:1。
- **改完自己核一遍**：搜「对比度检查」，随便打开一个网站（WebAIM Contrast Checker 等），把前景色和背景色两个值填进去，正文要 ≥4.5:1。`TOKENS.md` 里已经算好了默认值下所有配对，照表核最快。
- **`--rule` 是纯装饰**（点线、分隔线），对比度只有 1.66–1.84:1，这是故意的：菜单的点线本来就该是"隐隐约约的引导"。**不要**把文字设成 `--rule` 这个颜色。
- `--page-max` 调到 `1320px` 会让版心更宽、更接近大店；调到 `960px` 更像小店的精致感。

## 6. 表单怎么接（订位表单）

现在的表单是**纯静态**的：`<form class="book-form" action="#" method="post">`，点了「提交订位」不会发出去任何东西。三种接法，挑一个：

1. **你有后端**：把 `action="#"` 改成 `action="https://你的域名/api/booking"`，字段名已经起好了（`name` / `tel` / `date` / `time` / `people` / `note`），直接收。
2. **你没有后端**（最常见）：用一个表单服务（Formspree、飞书多维表格表单、腾讯问卷、金数据之类），它会给你一个提交地址；把 `action` 换成那个地址，然后**删掉**服务商不需要的字段，页面样式不用动。
3. **干脆不要表单**：把 `<form …>…</form>` 整段删掉，只留左边的电话、微信、邮箱。对多数小店来说这一条其实最省事——让客人打电话比让他填表格更可能真的来。

**要知道的**：本模板没有做「提交成功 / 失败」的提示，因为那需要 JavaScript。如果你用第 2 种接法，服务商一般可以设置"提交后跳转到一个致谢页"，用它代替提示。**不要**指望用户提交完还停在原地——他会以为没提交成功而重复提交。

## 7. 本层豁免了哪些条款，以及为什么（重要）

### 7.1 这是一个独立的层，目标不同

| | `prototypes/S01–S30`（30 个个案） | `templates/M0x`（本层） |
| --- | --- | --- |
| 目标 | **被记住**：一眼区分、有签名式怪癖、有材质成因 | **不犯错、拿起来就能用**：任何人拿到就能改成自己的店 |
| 规则来源 | `deliverables/02-anti-ai-rules.md`（R-01–R-40，含 11 条一票否决） | 本文件 + 你手上这份任务书 |
| 内容 | 12 字段全文，全是**具体内容**，禁止占位文案 | 全文**【换成你的】**占位标记 |
| 素材 | 自托管字体 + 第三方真实照片（带署名） | **零外部依赖**：系统字体栈 + 灰阶 SVG 图框 |
| 验收口径 | 反 AI 味闸门 FAIL=0，30 案之间必须互不相同 | 对比度 / 字号 / 点击区 / 语义标签 / 三档响应式 |

**豁免范围仅限 `templates/M0x/` 目录。** 把本模板拿去跑 30 案那把闸门，你会看到 FAIL（`eyebrow`、`hairline`、`few-pictures`、`still-page` 等），**那是预期结果，不是缺陷**：那些规则就是 30 案那一层"要像有脾气的手作"的规则，而本层的立命之本是"不要有脾气"。详见 §8.3 的实测记录。

### 7.2 逐条：豁免了什么，本层实际怎么做

| 被豁免的条款（30 案口径） | 它禁的是什么 | 本层为什么必须违反 | 本层实际用的 |
| --- | --- | --- | --- |
| **R-05** 白 / 灰 section 交替铺底（对应总规格 C-1.6） | 用两种底色交替分段 | 这是本地店铺站最常见的分段方式，也是**不会做错**的分段方式；店主不会调间距，靠底色分段最稳 | 米白 `--paper` 与奶油 `--paper-2` 交替（不是白/灰，但同一类做法） |
| **R-07 / R-08** 主字体黑名单（`Inter`/`Roboto`/`Arial`/`system-ui`）、全栈系统字体（**一票否决 V-02**） | 用系统字体栈当主字体 | 模板必须零依赖：引用字体文件就要带目录、离线就打不开、不同机器还会跳字。系统栈在任何人的电脑上都**立刻正确显示** | 标题 `Georgia/Times/宋体` 衬线栈，正文 `system-ui/Segoe UI/苹方/微软雅黑` 无衬线栈 |
| **R-26** 禁止占位文案（**一票否决 V-05**） | Lorem ipsum 和「此处填写」 | 本层的占位标记**就是产品功能**：它是给不会写代码的人的施工单。删掉它，模板就变成"要你自己找哪句该改" | `【换成你的：招牌菜名】`、`【换成你的：营业时间】`，并配一句「下面每一行的名字、价格、标签都照你自己的改」 |
| **R-24** 设计师签名式怪癖 | 没有怪癖就不合格 | 本层不追求被记住；稳妥优先 | 只保留两处行业惯例级的"手艺感"：**价目表的点线引导**、**手绘风格强调线**（不是签名，是这一类的通用做法） |
| **R-14 / R-15** 骨架互不相同、同骨架换色近似度栅栏 | 30 案之间必须互斥 | 本层只有 3 个模板（M01/M02/M03），是独立口径，不参与 30 案的唯一性矩阵 | 骨架按行业默认阅读序：顶部导航 → 主视觉 → 价目 → 到店 → 环境 → 评价 → 订位 → 页脚 |
| **R-23** 通用图库情绪照片占位 | 不许拿图库情绪照充数 | 本层一张照片都不带。**同时这也避开了授权问题**：第三方照片不能随模板转授 | 灰阶 SVG 图框（带比例与建议像素），位置与比例即施工说明 |

### 7.3 本层**没有**违反、仍然守住的条款（说明豁免是有限的）

豁免不是"放开手脚"，能守的照守：

| 仍然守住的 | 本层做法 |
| --- | --- |
| 不用 24px 圆角 + 柔和投影的"卡片浮起"（R-16） | 圆角只有 `8px`，**全站零 `box-shadow`** |
| 不用紫蓝 / 粉紫 AI 感渐变（R-01 / R-02） | 全站**没有任何渐变**，颜色都是实色 |
| 不用毛玻璃吸顶导航（R-17） | 顶部是纯色 + 1px 分隔线，**没有 `backdrop-filter`** |
| 不用 Emoji 当功能图标（R-21，一票否决） | 图形全部是内联 SVG（相机、折角箭头、手绘线），零 Emoji |
| 不用空洞营销词（R-25，一票否决） | 文案是「步行 6 分钟」「出餐约 15 分钟」「每月第一个周一休店」这类具体句 |

### 7.4 关于「暖底」这件事，我核过同一层的另外两个模板（结论：没问题）

`deliverables/08-audit-differentiation.md` 第 7 节记载：30 个案里 **18 个（60%）**的底色挤在同一个暖米纸族——所以"又来了一个暖底"这句话必须先自证。本层的口径是独立的（3 个模板、服务"本地实体店"这个题材、目标是不犯错），但这还不够，我顺手（**只读**）核了同一层的另外两个模板：

| 模板 | 页面底色 | 分区底色 | 定位 |
| --- | --- | --- | --- |
| `templates/M01-clean-corporate` | `#FFFFFF` | `#F4F7FA` | 冷（白 + 石板靛蓝），企业/服务 |
| **`templates/M02-warm-local`（本模板）** | `#FDF7EE` | `#F7EADA` | 暖（米白 + 烤色深褐），本地门店 |
| `templates/M03-bold-creator` | `#0e0e10`（近黑） | `#17171a` | 暗（近黑 + 橙色），创作者 |

**三个模板三个色温（白 / 暖 / 黑），没有重现"60% 挤在一个色族"的问题。** 另外这三个的字体分工也不同（M02 是"标题衬线 + 正文无衬线"的唯一一个）。所以本层用暖底是安全的——但**如果以后往这一层继续加模板，请继续守这条线：三个模板不要有第二个暖底**。

页高和"横向溢出"两个数来自真实运行：① `style.css` 里没有任何固定宽度，`--page-max` 之外全靠 `clamp()`；② 用 CDP 的 `Emulation.setDeviceMetricsOverride` 在 1440/768/390/360 四个宽度量 `document.documentElement.scrollWidth` 与 `clientWidth`，四档都相等（差 0）；③ 唯一"越界"的元素是离屏的跳转链接（`left:-9999px`，向右不产生滚动条）。

**一个必须知道的环境坑**：`--window-size=390,844` 在 Windows 上**不会**真的得到 390px 的布局宽度——Chrome 的窗口有约 500px 的最小宽度，布局按 500px 走、截图却按 390px 裁，于是右边被切掉一块（看起来像"横向溢出"，其实是截图工具的假象；判据：截图里 4vw 的内边距会算出 20px 而不是 390px 该有的 16px）。**正确的 390 三档验收请用 CDP 的 `Emulation.setDeviceMetricsOverride`**（仓库自带的 `tools/taste-skill/skills/taste-skill/scripts/inspect.mjs` 就是这条路，它输出的 `report.json` 里 `horizontalOverflow` 三档都是 0）。

## 9. 我知道的两处最弱的地方

1. **占位文案让首屏看起来像半成品。** 【换成你的：店名】摆在最显眼的顶部和主视觉上，对"拿它当施工单的店主"是正确的，对"拿它当成品给别人看的人"是减分的。我**没有**做"一键从示例内容切到占位标记"，因为纯 HTML/CSS 做不到；折中办法是你先把 §3 表里的内容替换成自己的真实文案，标记自然就没了。
2. **窄屏为了可读性牺牲了氛围。** 主视觉的"大图压字"在 ≤880px 时会把信息带移到图片下方（整条深褐面板），并且顶部导航在窄屏不再吸顶。这样手机上每句话都读得清、也不会被折叠菜单盖住内容，代价是手机上少了一点"大图压字"的气势。
3. （顺带一提，不算最弱但你要知道）**环境图在桌面上很大**：3:2 那张满宽、两张 1:1 各占半宽，单张高度就有 530px 左右。如果你要放 6 张以上环境图，页面会变得很长，本模板没有做瀑布流或点击放大。

## 10. 常见问题

**Q：为什么字体不是我想要的？**
A：本层刻意只用系统字体（零依赖，任何电脑打开都立刻正确）。想换只能换成**你自己系统里装了的**字体：改 `--font-serif` / `--font-sans` 两个变量，把字体名写进去（中文记得留 `"SimSun"`/`"Microsoft YaHei"` 这类回退）。

**Q：为什么没有动效？**
A：本层不做出场动画和滚动特效。原因：手机上会晃、老电脑会卡、还容易被"减少动效"设置的用户嫌。唯一的动效是 hover 变色，并且在 `prefers-reduced-motion` 下全部关掉。

**Q：手机号、微信、地图链接在哪改？**
A：搜「换成你的」都会命中。**电话链接要改两处**：显示的文字，和 `href="tel:+860000000000"` 里的号码。地图按钮的 `href="#"` 要换成你的地图分享链接（高德/百度/苹果地图都行）。

**Q：菜单里的点线在手机上怎么不见了？**
A：≤560px 时点线引导换成"标签一行、内容一行"（`.way-row` / `.fact-row` 的窄屏规则）。窄屏上点线会把文字挤成很窄的柱，两行更易读。

**Q：我能加 JavaScript 吗？**
A：能，但**别让内容依赖它**。本模板的立命之本之一是"脚本失败也全都能读"——标题、价目、地址、电话全都是静态 HTML。

**Q：能加第 5 个菜单分类、第 6 张环境图吗？**
A：能。菜单：复制一个 `<ul class="menu-list">` 和它上面的 `<h3 class="menu-group">`，放进任意一列 `.menu-col`。环境图：复制一个 `<figure class="ph ph-1x1">…</figure>` 放进 `.gallery`（3 张图会自动排成"一张宽的 + 若干方形"，4 张以上会排成两列）。**别去动 CSS 的网格定义**，它已经适配好了三档。
